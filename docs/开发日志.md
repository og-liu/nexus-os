<summary><b>2026-10-15 15:10 · CI/CD 骨架落地</b> —— 自动化部署全套文件入库，发布包端到端验证通过</summary>

<br>

**目标**

按「直接上 CI/CD」的方向，把自动化部署所需的全部文件做出来，并证明发布包真的能跑。

**进展**

- 从 GitHub 仓库页面拿到仓库地址，确认主人已在阿里云购买域名与服务器
- 新增流水线 `.github/workflows/deploy.yml`：CI（装依赖 → 生成路由类型 → 类型检查 → 规范检查 → 构建 → 组装发布包）+ CD（SSH 传包 → 触发服务器端切换）
- 新增部署物料：`deploy/nginx/nexus-os.conf`、`deploy/systemd/nexus-os.service`、`deploy/scripts/release.sh`（含回滚）、`deploy/scripts/bootstrap-server.sh`（服务器一次性初始化）
- `next.config.ts` 开启 `output: "standalone"`；新增 `.npmrc` 设 `node-linker=hoisted`
- **在本地完整跑通 CI 全部步骤**，并对发布包做端到端验证：解包 → 以生产模式启动 → HTTP 200 → 页面与 Tailwind 样式均正常
- 清理 dev server（构建与 dev 共用 `.next`，会互相干扰）；`.gitignore` 补 `release.tar.gz` 与 `.idea/`

**决策**

| 决策点 | 选择 | 理由 | 否决的备选 |
|---|---|---|---|
| 产物形态 | `output: "standalone"` | 自带最小运行依赖，服务器不需装 pnpm、不需 install；发布包仅 12 MB | 传完整 `node_modules`（否决：3 Mbps 上传太慢）；服务器上 install（否决：服务器要装 pnpm 且每次发布联网） |
| 依赖布局 | `.npmrc` 设 `node-linker=hoisted` | 必须：默认软链布局会让 standalone 追踪器漏拷文件（见「问题」） | 保持默认布局（否决：产物缺文件） |
| 发布切换 | `releases/<时间戳>/` + `current` 软链接原子切换 | 新旧共存，切换瞬时，回滚只需指回上一个 | 原地覆盖（否决：发布失败即全站挂、无法回滚） |
| 运行身份 | 服务 `nexus`（不可登录）、部署 `deploy`（只授权一条命令） | 服务不以 root 跑；CI 密钥泄露也只能触发发布脚本 | 全用 root（否决：密钥泄露等于交出整机） |
| 手工基准的替代 | `release.sh` 做成幂等、可手动重跑 | 跳过手工部署阶段后，仍需一个能随时手动复现的排障入口 | 无（这是对「跳过手工部署」这一决定的补偿设计） |

**问题**

| 现象 | 根因 | 处理 |
|---|---|---|
| 清空 `.next` 后 `tsc --noEmit` 报 `Cannot find name 'LayoutProps'` | `LayoutProps` 等类型由 Next 生成到 `.next/types/`，不在仓库里；本地因跑过 dev/build 才没暴露 | 流水线在 `tsc` 前加一步 `pnpm exec next typegen`；已写入 workflow 注释 |
| 发布包解包后启动即崩：`Cannot find module '@swc/helpers/esm/_interop_require_default.js'` | Next 的 standalone 追踪器在 pnpm 默认软链布局下漏拷文件 —— 实测同一 `@swc/helpers@0.5.23`：真实 556 个文件，产物里只有 8 个，整个 `esm/` 丢失 | `.npmrc` 设 `node-linker=hoisted` 改用扁平布局；改完重新验证，`esm/` 与关键文件都在，服务正常启动 |

> 教训：**「构建成功」不等于「产物能跑」。** 这两条都是构建与检查全绿、但实际部署会崩的问题。若跳过本地端到端验证直接推 CI/CD，第一条会让流水线红在类型检查、第二条会让服务器启动即崩且报错难懂。**产物必须真的启起来点一次。**

- `deploy/nginx/nexus-os.conf`、`deploy/systemd/nexus-os.service`
- `deploy/scripts/release.sh`、`deploy/scripts/bootstrap-server.sh`
- `.npmrc`、`next.config.ts`（`output: standalone`）
- `docs/部署方案.md`（更新：新增「已踩的坑」章节）
