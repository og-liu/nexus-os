**目标**

Agent 从占位页变成能用的第一版：在 `/agent` 里打一句话，模型流式回答，带思考过程与 token 用量。

先定的是**做多少**：九期推进（对话 → 落库 → 工具 → 规划 → 补问 → 状态一致性 → 体验层），这一轮只做第 1 期。第 0 期「施工图」（数据模型 / 状态机 / 事件协议）挪到第 2 期之前补——先让这条线跑通，再定地基。

**进展**

- **先补两块地板**：`.env.example` 与《技术栈说明》§4.3 登记 `DEEPSEEK_API_KEY`；`resolveDatabasePath()` 的空值容错（`??` 换成 `?.trim() ||`，加 4 个用例）

**决策**

| 决策点 | 选择 | 理由 | 否决的备选 |
|---|---|---|---|
| 流式接口用什么 | **Route Handler + `ReadableStream`** | Server Action 的返回值必须整块序列化，做不到边生成边显示；Next 16 文档把这类场景指向 Route Handler | Server Action（做不到真流式）· 轮询（延迟高） |
| 传输格式 | **SSE** | 单向推送、普通 HTTP、Nginx 与浏览器天然认得 | WebSocket（双向、要握手，用不到） |
| 前端怎么读 | **fetch + 手工解析** | 必须 POST 带整段历史；`EventSource` 只能发 GET | `EventSource` |
| 第一版做不做存储 | **不做** | 一次只背一个问题；先接存储会同时背「状态机怎么设计」 | 一起做 |
| 界面从哪里来 | **只搬右栏** | 左栏的全部意义是多会话切换，没存储就是永远空的抽屉 | 整页搬（带一堆假数据）· 重画 |
| 系统提示词 | **写死「你没有工具能力」** | 模型会顺着「帮我看看待办」编出一份很像真的清单——幻觉比报错危险 | 不写限制 |
| `model` 参数 | **白名单校验，非法值回落默认** | 前端传的字符串直接拼进请求体，等于让浏览器挑模型 | 直接透传 |
| `.env.local` 与模板的关系 | **逐字副本**（除开头身份说明） | 主人指出「模板就该能复制」；复制不了它就只是文档 | 各写各的（已证明会漂移） |

- **`??` 不拦空串。** `.env.example` 里 `DATABASE_PATH=` 是「留空」的写法，但 dotenv 把它解析成**空字符串**不是 undefined，`??` 会原样放行 → 数据库路径变空串。实测确认后改成 `?.trim() ||`。这条直接决定「模板能不能逐字复制到本地」。
- **同一件事的落脚点又漏了。** 改 `SESSION_COOKIE_SECURE` 的口径时，第一刀只改了 `.env.example` 与 §4.3 两处，漏了 `current-user.ts` 的注释和 `.env.example` 里另一句「上线后再改成 true」——这是第 N 次犯。**动一个决定前先 grep 全部落脚点。**
- **日期凭印象写错了。** 我按会话开头的时间写了 `2026-10-26`，实际今天是 10-29（这个会话跨了三天）。写进 8 个文件后才发现，全量替换了一遍。**文档里的日期、线上状态、数量都必须现场实测，不能从别处推断。**
- **`deepseek-v4-flash` 不存在。** 旧项目代码里是这个名字，实际接口返回的是 `deepseek-flash`。差一个 `v4`，直接 404 级别的错。**模型名以 `/models` 接口返回为准，不抄任何旧代码。**

**产出**

- 代码：`src/lib/agent/providers.ts`、`src/lib/agent/models.ts`、`src/app/api/chat/route.ts`、`src/components/agent/agent-chat.tsx`、`src/app/(app)/agent/page.tsx`

<summary><b>2026-10-24 14:59 · 页签栏：把「走过的页面」变成一条横条</b> —— 照 Vue 的 tagsView 做，但砍掉它最有名的那个能力</summary>

<br>

**目标**

在工具详情页之间互相跳转时，不用「回工具中心 → 再点进去」。形态对照一份 Vue 后台的 tagsView 多页签：打开过的页面留一个标签，点一下就过去。本阶段只出设计（功能文档 + 界面规范），实现交给 DSH。

**进展**

- 需求两轮收敛。第一轮先确认「这是什么东西」——多页签导航（Vue 生态叫 `tagsView`，Ant Design Pro 叫「多页签」）；它不是浏览器标签，是应用内自己维护的一份路由历史
- 摸现状：`(app)/layout` → `AppShell` 是客户端组件、常驻不卸载；`<main>` 是独立滚动容器；`PageHeader` 由每个页面自己渲染、不在外壳里；标题来源本来有两处（侧栏 `navItems`、工具目录 `tool-catalog`）
- 写 `docs/功能/页签栏.md`（设计真相源）+ 登记功能清单 + 《界面设计规范》新增 §7.22，§5.1 结构图 / §5.2 尺寸表 / §6 各补一行，《功能/应用外壳》结构图同步

**决策**

| 决策点 | 选择 | 理由 | 否决的备选 |
|---|---|---|---|
| 要不要连页面状态一起保留 | 只做导航，不做 `keep-alive` | 两个真工具的数据在 SQLite，切回来重拉就是最新的；丢的只有未提交的输入，为它把页面改成客户端组件 + API 取数不划算 | React 19.2 的 `<Activity>`（技术上能做，但要翻掉取数架构） |
| 固定标签几个 | 只有「总览」一个 | 「钉住」的价值是「这是我随时能回去的那一个」；七个一级入口全钉住等于没钉住 | 七个一级入口全固定（栏一开始就满） |
| 移动端怎么办 | 整条不渲染 | 手机放不下一排可点标签，8px 的 `×` 是误触机器；系统级返回手势比页签栏更快 | 横滑标签条 · 页头「最近」下拉（都要多造一层概念，且页头右侧是页面级控件的位置） |
| 标签文字从哪来 | 白名单映射表 | 一个真相源；404 与未登记页面不污染栏；加页面是显式决策 | 读 `document.title`（时机不可靠，会闪）· 按布局段推断（`/tools/[slug]` 推不出中文名） |
| 关当前标签后去哪 | 右邻居 → 左邻居 → `/` | 与浏览器关标签的行为一致，不用学第二套 | 回首页（跳得太远，关一个标签像被弹出去） |
| 关标签用 push 还是 replace | 关标签后 `replace`，点标签仍用 `Link` | 历史里不留指向已关页面的记录，按返回不会回到幽灵页 | 全用 `push`（历史堆满已关闭的页面） |

**问题**

- **Vue 的 tagsView 是「一个组件」，Next 里是两条独立的事。** 标签列表、登记、渲染都能一一对应，唯独 `<keep-alive>` 没有等价物——App Router 的页面是服务端组件，路由跳转就是整树替换，没有「藏起来但还活着」的位置。这点必须早说，否则实现时会被当成「标签栏怎么这么简单，缓存呢」。
- **我第一版推荐的「七个一级入口都钉住」是错的。** 钉住的前提是「只有少数几个」；七个全钉住既占满栏，又让「钉住」不再传递信息。收敛成一个（总览），顺手把「最后一个标签不能关」的边界也解决了。
