# 项目目录结构说明

> 本文只回答一件事：**文件该放在哪、每个目录负责什么。**
> 技术选型、版本、工程门禁见《技术栈说明》；本文只管「位置的规矩」。
>
> 维护规则：目录结构发生变化时，**先改本文，再改代码**。

---

## 一、总览

```
nexus-os/
│
├── src/                        # 全部源代码
│   ├── app/                    #   路由层：页面与 HTTP 接口
│   ├── components/             #   组件层：UI 与业务组件
│   ├── lib/                    #   逻辑层：通用能力、数据访问、第三方适配
│   ├── hooks/                  #   自定义 React Hook
│   └── types/                  #   跨模块共享类型
│
├── docs/                       # 项目文档
├── public/                     # 静态资源（不经构建，按原样提供）
├── data/                       # 本地数据文件（不入 Git）
│
├── package.json                # 依赖与脚本
├── pnpm-lock.yaml              # 依赖版本锁定
├── pnpm-workspace.yaml         # pnpm 行为配置
├── tsconfig.json               # TypeScript 编译配置
├── next.config.ts              # Next.js 配置
├── postcss.config.mjs          # PostCSS / Tailwind 集成
├── eslint.config.mjs           # ESLint 规则
│
├── .nvmrc                      # Node 版本固化
├── .env.example                # 环境变量模板（键名与获取方式，入库）
├── .env.local                  # 真实环境变量与密钥（不入库）
├── .gitignore                  # Git 忽略规则
│
├── AGENTS.md / CLAUDE.md       # 给 AI 编码助手看的项目约定
└── README.md                   # 项目说明（面向人）
```

**分层原则：按职责分层，不按页面堆文件。** 页面是薄薄一层接线，逻辑住在 `lib/`。

## 三、目录详解

### `src/app/` —— 路由层

**职责：把「URL」映射到「页面」，把「请求」映射到「处理函数」。只做接线，不写逻辑。**

| 路径 | 作用 |
|---|---|
| `src/app/layout.tsx` | **根布局**。全站唯一的外壳：`<html>` / `<body>` 属性、字体加载、全局元信息。所有页面都被它包住 |
| `src/app/page.tsx` | **根路由页面**（访问 `/` 时渲染） |
| `src/app/globals.css` | **全局样式**。Tailwind 引入 + 主题 CSS 变量 + 全局基线样式 |
| `src/app/<段>/page.tsx` | 其他路由页面。目录名即 URL 段 |
| `src/app/api/<段>/route.ts` | HTTP 接口。导出 `GET` / `POST` / `PATCH` / `DELETE` 等函数 |

**规矩**

- 页面文件里**不写业务逻辑**：数据获取与处理放 `lib/`，页面只负责组合组件、传参。
- 需要浏览器交互的文件顶部才加 `"use client"`，并且尽量下沉到叶子组件。
- 路由目录名用 `kebab-case`。

### `src/components/` —— 组件层

| 路径 | 作用 |
|---|---|
| `src/components/ui/` | **基础组件**：由 shadcn/ui 生成后归本项目所有的通用组件（按钮、卡片、输入框…）。源码在仓库里，可直接改 |
| `src/components/layout/` | **布局组件**：全站外壳、页头、侧边栏、页脚等 |
| `src/components/<领域>/` | **业务组件**：按领域分目录，**一个组件一个文件** |

**规矩**

- 基础组件（`ui/`）只关心样式与交互，**不知道任何业务概念**。
- 业务组件按领域分目录，避免所有组件平铺在一个目录里。
- 组件文件命名 `kebab-case.tsx`，与 shadcn/ui 的生成规则保持一致。
- 优先命名导出。

### `src/lib/` —— 逻辑层

**职责：所有不属于「界面」的东西。** 数据访问、第三方服务适配、纯函数工具、共享类型。

| 路径 | 作用 |
|---|---|
| `src/lib/utils.ts` | 通用小工具（如合并类名的 `cn()`） |
| `src/lib/<领域>/` | 某个领域的逻辑，按目录聚合：数据读写、规则、编排等 |
| `src/lib/<服务>/` | 外部服务的适配层（把第三方 SDK / HTTP 细节收敛在一处，业务代码只调统一入口） |
| `src/lib/*.test.ts` | **与该模块同目录**的单元测试 |

**规矩**

- `lib/` 里不出现 JSX，不 import React 组件 —— 逻辑与界面互不反向依赖。
- 访问密钥的代码只活在服务端（`lib/` 默认是服务端；要进浏览器必须显式声明）。
- 一个文件只承担一个职责，超过约 300 行就拆。

### `src/hooks/` —— 自定义 Hook

存放可复用的 React Hook（`use-xxx.ts`）。**只在多个组件需要同一份状态逻辑时才抽出来**，不要为了一次性使用提前抽象。

### `src/types/` —— 共享类型

只放**被两个以上模块共用**的类型。某个模块专属的类型就放在那个模块的文件里，不要全往这儿堆。

### `docs/` —— 项目文档

| 文件 | 作用 |
|---|---|
| `技术栈说明.md` | 用什么技术、什么版本、为什么 |
| `项目目录结构说明.md` | 本文件：文件放哪、目录干什么 |
| `部署方案.md` | 怎么上线、怎么自动更新，含执行清单与进度 |
| `开发日志.md` | 按时间倒序记录每次推进：目标 / 进展 / 决策 / 问题 / 产出 |

### `public/` —— 静态资源

按原样提供的文件（favicon、图片、字体、下载物）。**不会经过构建处理，也不会被哈希化**，所以不要在这里放需要被打包优化的代码。源码里用绝对路径引用：`/logo.svg`。

### `data/` —— 本地数据

运行时产生的本地数据文件（数据库文件等）。**已加入 `.gitignore`，永不入库**——它是用户数据，不是源码。

## 四、新文件该放哪（判断流程）

按顺序问自己：

1. **它是一个 URL 对应的页面，或一个 HTTP 接口吗？** → `src/app/`
2. **它会渲染出界面吗？**
   - 通用、无业务含义 → `src/components/ui/`
   - 属于全站外壳（页头 / 侧边栏 / 页脚）→ `src/components/layout/`
   - 有业务含义 → `src/components/<领域>/`
3. **它是一段可复用的状态逻辑吗？** → `src/hooks/`
4. **它是「被多个模块共用」的类型声明吗？** → `src/types/`
5. **以上都不是**（数据读写、算法、第三方适配、纯函数）→ `src/lib/`
6. **它是文档吗？** → `docs/`
7. **它是静态文件，构建时不需要处理吗？** → `public/`

> 卡住的时候默认进 `src/lib/`：**宁可先放逻辑层，也不要塞进页面。**

## 五、命名约定

| 对象 | 规则 | 示例 |
|---|---|---|
| 组件文件 | `kebab-case.tsx` | `page-header.tsx` |
| Hook 文件 | `kebab-case.ts`，以 `use-` 开头 | `use-toast.ts` |
| 其他 TS 模块 | `kebab-case.ts` | `plan-store.ts` |
| 测试文件 | 与被测文件同名 + `.test.ts` | `plan-store.test.ts` |
| 路由目录 | `kebab-case` | `app/user-profile/` |
| 文档 | 中文名 `.md` | `技术栈说明.md` |
| 路径引用 | 一律用别名 `@/*` | `@/lib/utils` |

**不用相对路径穿目录**（`../../lib/xxx`）——别名写起来更短，移动文件时也不会断。

## 六、红线

以下情况一经出现就应当修正，不是风格偏好：

1. **页面文件里写业务逻辑** —— 逻辑属于 `lib/`。
2. **单个文件超过约 300 行** —— 拆。
3. **密钥硬编码 / 提交 `.env.local`** —— 一旦进 Git 历史就等于泄露。
4. **把 `node_modules/` / `.next/` / `data/` 提交进仓库**。
5. **`lib/` 里 import 组件，或组件里直接读写数据库** —— 依赖方向必须单向：`app → components → hooks`，`app → lib`。
6. **跨目录相对路径** —— 用 `@/*` 别名。
7. **修改生成物**（`next-env.d.ts`、`tsconfig.tsbuildinfo`） —— 它们会被重新生成覆盖。
