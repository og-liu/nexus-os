# 界面设计规范

> 本文只回答一件事：**界面长什么样。** 色彩、排版、圆角、布局骨架、组件形态。
> 技术选型与依赖版本见《技术栈说明》；文件放哪见《项目目录结构说明》；本文只管「视觉的规矩」。
>
> 维护规则：改界面前，**先改本文，再改代码**。文中的每个色值与类名都可直接照抄。

---

## 一、设计基调

四条基本主张，所有具体规则都是它们的推论：

1. **黑白灰 + 直角。** 界面不表达色彩偏好，颜色只留给「状态」和「当前选中」。
2. **层次靠底色深浅交替，不靠投影和描边。**
   `灰页面（#ECECEC） → 白卡片（#FFFFFF） → 灰内嵌块（#F5F5F5） → 白图标底（#FFFFFF）`。
3. **高信息密度。** 12px / 13px / 14px 是主力字号，10px 也在使用；界面宁可紧，不要松。
4. **应用内装饰为零。** 没有渐变、没有彩色阴影、没有玻璃拟态、没有圆润大圆角。唯一的「装饰」是分组标题前的黑色短竖条。**唯一例外是入口页（登录 / 注册）**——那是用户还没进屋的门厅，允许极轻的 CSS 装饰与入场动效（见 §7.16 与 §12），且必须在系统开启「减少动态效果」时自动消失。

## 二、色彩

### 2.1 背景层次

| 用途 | 色值 | Tailwind |
|---|---|---|
| 浏览器窗口底色（`body`） | `#F5F7FA` | `bg-[#F5F7FA]` |
| 主内容区 | `#ECECEC` | `bg-[#ECECEC]` |
| 侧边栏 / 页头 / 卡片内嵌块 | `#F5F5F5` | `bg-[#F5F5F5]` |
| 页脚 | `#ECECEC` | `bg-[#ECECEC]` |
| 卡片 | `#FFFFFF` | `bg-white` |
| 页头右侧控件容器 | `#ECECEC` | `bg-[#ECECEC]` |

> 内嵌块（统计块、工具块、图标底、便签、代码块）在**白卡片内部**用 `#F5F5F5`；白卡片内部再嵌一层白（图标底）时用 `bg-white`，形成「灰—白—灰—白」的交替节奏。

### 2.2 文字层级

| 语义 | 色值 | 用途 |
|---|---|---|
| 主文本 | `#000000` | 标题、正文、数值、当前选中项 |
| 卡片内图标 | `#1F1F1F` | 32/40px 灰底图标块里的图标 |
| 次要文字 | `#666666` | 可交互的次级图标与文字、默认态控件文本 |
| 辅助文字 | `#8A8A8A` | 字段名、描述、副标题 |
| 弱化文字 | `#999999` | 时间戳、计数、占位符、单元后缀 |
| 最弱文字 | `#A0A8B4` | 页脚、极不重要的说明 |
| 反白 | `#FFFFFF` | 黑底之上的文字与图标 |

### 2.3 状态与强调色

全站唯一有色彩倾向的「面」是导航激活底色，其余色彩只以**点**或**小面积**形式出现。

| 语义 | 色值 | 形态 |
|---|---|---|
| 运行中 / 正常 | `#22C55E` | 状态点 |
| 未配置 / 已暂停 | `#D0D0D0` | 状态点 |
| 错误（Toast） | `#B91C1C` | 图标 |
| 警告（Toast） | `#9A6B0A` | 图标 |
| 危险等级（知识条目） | `red-500` | 状态点 |
| 导航激活底色 | `#d5e3f6` | 面（侧边栏与二级栏） |

**状态一律用「1.5px 圆点 + 灰色文字说明」表达，不使用彩色徽章（Badge）。** 圆点尺寸固定 `h-1.5 w-1.5 rounded-full`。

### 2.4 边框与分隔

| 用途 | 色值 |
|---|---|
| 侧边栏右边框、二级栏右边框、输入框描边 | `#E5E5E5` |
| 页头下边框 | `#E8E8E8` |
| 列表分隔线（`divide-y`）、KPI 分隔线（`divide-x`）、进度条槽 | `#F0F0F0` |
| 虚线空状态描边、未选中的复选框边框 | `#D9D9D9` / `#D0D0D0` |

### 2.5 交互态

| 元素 | 规则 |
|---|---|
| 黑底按钮 hover | `hover:bg-[#333333]`（底色变深，文字保持纯白） |
| 黑底小按钮 hover | `hover:opacity-85`（图标类小按钮可用，视觉更轻） |
| 灰底元素 hover | 加深一档：`#F5F5F5 → #ECECEC`，或 `#ECECEC → #EDEDED` |
| 二级/弱化文字 hover | 变为 `text-[#000000]` |
| 侧栏导航 hover | `hover:bg-[#ededed]`（非激活）、`bg-[#d5e3f6]`（激活） |
| 侧栏导航点击 | 激活色（`#d5e3f6`）涟漪从中间铺开（§12.4） |
| 侧栏底部用户区 hover | 与导航项同款 `hover:bg-[#ededed]`；菜单展开中保持（§7.18） |
| 可点击元素光标 | **手型**：显式声明 `cursor-pointer`——Tailwind 4 预置里 `button` 默认是箭头光标、shadcn 菜单项默认 `cursor-default`，都要覆盖。项目约定：**可点 = 小手** |
| 输入框 focus | 描边由 `#E5E5E5` 变纯黑：`focus:border-[#000000]`；**不加外发光（ring）** |
| 禁用态 | `disabled:opacity-30` ~ `disabled:opacity-50`，鼠标 `cursor-not-allowed` |
| 工具卡 | 默认**实灰卡**（`bg-[#F5F5F5]`）+ 浅灰图标块（`bg-[#ECECEC]`），文字保持全对比；hover 转白卡（`hover:bg-white`）+ 图标块反色为黑。**不用整体透明度表达默认态**（文字被冲淡会被读成「禁用」）；图标块不用纯白（比卡面更亮的块会抢视线、显突兀）。不按状态区分，见《功能/工具中心》 |

## 三、圆角与阴影

### 圆角

| 形态 | 值 | 适用范围 |
|---|---|---|
| 默认 | `rounded-[2px]` | **一切矩形容器**：卡片、按钮、输入框、标签、图标底、气泡、下拉项、搜索框 |
| 圆形 | `rounded-full` | 本身就是圆形的元素：状态点、黑胶唱片、圆形播放按钮、手机端筛选 chips、计数徽标 |
| 例外 | `rounded-xl`（14px） | **仅**侧边栏与二级栏的导航项高亮块 |

> 2px 是这套界面的性格所在：既不是尖角（会显得廉价），也不是圆角（会显得松软）。不要用 `rounded-md` / `rounded-lg`。

### 阴影

| 场景 | 值 |
|---|---|
| 可交互卡片 hover 抬起 | `hover:-translate-y-0.5 hover:shadow-[0_4px_12px_rgba(0,0,0,0.08)]` |
| 全局提示（Toast） | `shadow-[0_16px_48px_rgba(0,0,0,0.18)]` |
| 手机端抽屉 | `shadow-xl` |
| 下拉菜单 / 浮层 | 用 shadcn 默认 |

**常规卡片不带阴影、不带边框。** 阴影只表示「这个东西浮起来了或可以点」。

## 四、排版

### 4.1 字体

| 字体 | 加载方式 | CSS 变量 | 用途 |
|---|---|---|---|
| Noto Sans SC（可变字体） | `next/font/local` 自托管 | `--font-noto-sans-sc` | 中文正文（第一优先） |
| Geist Sans | `next/font/google` | `--font-geist-sans` | 西文正文（中文回退后的第二选择） |
| Geist Mono | `next/font/google` | `--font-geist-mono` | 代码、等宽数字 |
| Sekuya | `next/font/local` 自托管 | `--font-sekuya` | 品牌名 `NEXUS OS`（装饰性，仅此一处） |

字体回退链在 `globals.css` 的 `@theme inline` 中定义：

```css
--font-sans: var(--font-noto-sans-sc), var(--font-geist-sans), sans-serif;
```

根节点统一挂 `antialiased`。品牌名用内联 `fontFamily: "var(--font-sekuya)"` + `letterSpacing: "0.1em"`。

### 4.2 字号阶梯

| 字号 | Tailwind | 用途 |
|---|---|---|
| 10px | `text-[10px]` | 角标、时长、标签内小字、次级元数据 |
| 11px | `text-[11px]` | 节日/状态小徽标、极简提示 |
| 12px | `text-xs` | **主力**：字段名、描述、副标题、时间戳、计数、按钮小字 |
| 13px | `text-[13px]` | 紧凑正文：会话标题、便签正文、工具名、下拉项 |
| 14px | `text-sm` | **主力**：正文、卡片标题、列表主文本、按钮 |
| 15px | `text-[15px]` | 会话列表项、Toast 文本 |
| 20px | `text-xl` | 页面主标题（桌面）、KPI 数值、问候语 |
| 30px | `text-3xl` | 仪表盘时钟（唯一一处） |

### 4.3 字重与数字

- 字重三档：常规 `400`（正文）、中等 `500`（按钮、列表主文本）、半粗 `600`（标题、KPI 数值、当前选中项）。不用 `700` 及以上。
- **一切会变化的数字用 `tabular-nums`**：时钟、KPI、进度百分比、计时、计数。等宽数字防止刷新时宽度跳动。
- 时钟、代码、时长等本身是「机器数字」的，用 `font-mono`。
- 正文行高：紧凑列表靠间距控制（不加 `leading-*`）；阅读型文本用 `leading-relaxed`（1.625）或 `leading-7`。Markdown / 快照阅读区用 `line-height: 1.7 ~ 1.8`。

## 五、布局骨架

### 5.1 整体结构

```
┌────────┬──────────────────────────────────────────┐
│        │  页头 PageHeader（h-16，吸顶，bg #F5F5F5）   │
│ 侧边栏  ├──────────────────────────────────────────┤
│ 图标栏  │                                          │
│  w-20  │   主内容区（overflow-y-auto，bg #ECECEC）   │
│ 常驻   │   普通页：px-4 py-4 md:px-6 md:py-6         │
│        │   满高页：h-[calc(100%-4rem)]，左右栏各自滚动 │
│  (人)  │  ← 侧边栏底部用户区（§7.18）                │
│        ├──────────────────────────────────────────┤
│        │  页脚 Footer（bg #ECECEC，py-3，text-xs）    │
└────────┴──────────────────────────────────────────┘
```

整页 `flex h-screen overflow-hidden`，**禁止整页横向滚动**。

### 5.2 尺寸表

| 部位 | 值 |
|---|---|
| 一级侧边栏（桌面） | `w-20`，`border-r border-[#E5E5E5]`，`bg-[#F5F5F5]`，`hidden lg:flex` |
| 侧边栏导航项 | `rounded-xl px-4 py-4`，图标 `h-6 w-6` |
| 侧边栏 Logo | `h-9 w-9`，居中 |
| 侧边栏底部用户区（桌面，§7.18） | `p-3`，无分割线；用户图标与导航项同格（`rounded-xl`，图标 `h-6 w-6`，hover / 展开中 `bg-[#ededed]`） |
| 抽屉底部用户区（手机，§7.18） | `px-3 pt-3 pb-[max(12px,env(safe-area-inset-bottom))]`，无分割线；整行 `rounded-[2px]`、图标 `h-5 w-5` |
| 二级栏（页面内左栏） | `w-[260px]`，满高 `overflow-y-auto`，`border-r border-[#E5E5E5]`，`bg-[#F5F5F5]` |
| 页头 | `sticky top-0 z-20 h-16`，`border-b border-[#E8E8E8]`，`bg-[#F5F5F5]` |
| 页脚 | `px-4 py-3 md:px-6`，`text-xs text-[#A0A8B4]`；内容依次为 `© <年> Nexus OS v<版本号>` · ICP 备案号 · 公网安备号；窄屏纵向 `gap-1`，`lg` 起横向 `gap-4` |
| 手机抽屉 | `w-64`，`shadow-xl`，遮罩 `bg-black/25 backdrop-blur-sm`（§5.4），打开时锁 `body` 滚动 |

### 5.3 内容区规则

- **内容容器不设 `max-width`**，100% 铺满内容区，只留内边距。内部元素自行限宽（消息气泡 `max-w-[70%]` 桌面 / `max-w-[85%]` 移动）。
- 板块间距：仪表盘 `space-y-4`；分组式长页面（工具中心）`space-y-8`，组内 `space-y-3`。
- 网格间隙统一 `gap-3`（紧凑卡片）或 `gap-4`（信息卡片）。
- 卡片内边距统一 `p-5`（大卡）/ `p-4`（列表卡）/ `p-3`（内嵌小块）/ `p-2`（紧凑块）。
- 图标底块尺寸：`h-8 w-8`（列表行、快捷工具）或 `h-10 w-10`（工具卡）。
- **页脚版本号**：形式 `v<package.json 的 version>`，紧跟在 `Nexus OS` 后面，同 `text-[#A0A8B4]`、同字号，不加「版本」二字、不单独分隔。版本号在构建时从 `package.json` 内联进来——它同时是**线上部署是否成功**的肉眼凭据：`release` 上把版本号 +1（见《Git 协作规范》§五 ⑧），部署成功后页脚立刻变号，没变就是没上去。

### 5.4 浮层遮罩

桌面模态框与手机抽屉（§5.2）共用同一套遮罩：**`bg-black/25` + `backdrop-blur-sm`**。

| 项 | 值 |
|---|---|
| 遮罩底色 | `bg-black/25` |
| 背景模糊 | `backdrop-blur-sm`（8px） |
| 层级 | 遮罩在下、内容卡片在上（卡片 `relative z-10`） |
| 点击行为 | 点遮罩关闭；点内容区不关闭 |

**为什么不是更浓的纯色**：40% 以上的纯黑会把背景压成一块死灰，用户失去「我还在哪一页」的上下文；25% 加 8px 毛玻璃让背景退后一层，但轮廓还认得出。

**为什么两处必须一样**：抽屉和模态框是同一类东西——盖住当前页、把注意力收到一个面上。两处浓度不同，用户会觉得「刚才那个更暗」却说不出哪里怪。

**点击怎么绑**：绑在**遮罩层本身**，用 `event.target === event.currentTarget` 判定；不要绑在最外层容器上——移动端全屏形态没有遮罩，绑容器会把「点输入区旁边的空白」也当成关闭。

## 六、响应式

以 Tailwind 内置断点为准，核心分界是 **lg（1024px）**。

| 档位 | 宽度 | 布局 |
|---|---|---|
| 移动 | < 1024px | 抽屉导航 + 汉堡按钮；卡片单列；chips 横滑筛选 |
| 窄屏 PC | 1024–1279px | 常驻图标栏；紧凑控件（搜索收成图标、筛选收成下拉） |
| 宽屏 PC | ≥ 1280px | 完整搜索栏、标签并排、网格多列 |

**前缀归类规则（重要，别用错）：**

| 类别 | 前缀 | 说明 |
|---|---|---|
| 结构性布局 | `lg:` | 显隐、排列方向、栏宽 — 在 1024px 整档切换 |
| 字号 / 间距 / 内边距 | `md:` | 768px 起生效，保证平板上的文字密度 |
| 宽屏增量增强 | `xl:` | 完整搜索栏、网格列数。**不用它做显隐分界** |

典型写法：

```tsx
"grid grid-cols-1 gap-4 px-4 py-4 md:px-6 xl:grid-cols-3"
"hidden lg:flex"          // 桌面常驻侧边栏
"text-base md:text-xl"    // 页头标题：排版档用 md
```

**每个页面必须给出至少三档断点的版式安排（移动 / 平板 / 桌面），而不是只把桌面版压扁。** 判断标准很简单：某个断点下如果只是宽度变了、布局逻辑没变，那就等于没做响应式。可参照国外产品（Stripe / Linear / Supabase / Clerk 等）在断点之间的**重构**方式——栏位方向翻转、容器与留白换一套比例、触控尺寸放大，而不是等比缩放。

## 七、组件形态

以下模式是这套界面的「零件库」。实现时直接照抄类名，不要即兴发挥。

### 7.1 卡片

```tsx
<div className="rounded-[2px] bg-white p-5">
```

无边框、无阴影。可点击的卡片才加抬起效果：

```tsx
className="group rounded-[2px] bg-white p-4 transition-all hover:-translate-y-0.5 hover:shadow-[0_4px_12px_rgba(0,0,0,0.08)]"
```

### 7.2 分组标题（SectionTitle）

卡片内所有分组标题统一此形态，是界面唯一的装饰语言：

```tsx
<div className="flex items-center gap-2">
  <div className="h-3.5 w-[3px] bg-[#000000]" />
  <h2 className="text-sm font-semibold text-[#000000]">标题</h2>
</div>
```

右侧可跟**弱化计数**或**跳转链接**：

```tsx
<span className="text-xs text-[#999999]">12</span>
<Link className="flex items-center gap-1 text-xs text-[#8A8A8A] transition-colors hover:text-[#000000]">
  查看全部 <ArrowRight className="h-3 w-3" />
</Link>
```

### 7.3 主操作按钮（CTA）

页面/区块的主操作一律黑底白字，直角：

```tsx
className="flex items-center justify-center gap-2 rounded-[2px] bg-[#000000] px-4 py-2 text-sm font-medium text-white transition-colors hover:bg-[#333333]"
```

尺寸档：`px-2.5 py-1 text-xs`（行内小操作）、`px-3 py-2.5 text-sm`（二级栏顶部通栏按钮）、`px-4 py-2 text-sm`（常规）。
二级栏顶部是**通栏黑底按钮**：`flex w-full items-center justify-center gap-2 rounded-[2px] bg-[#000000] px-3 py-2.5 text-sm font-medium text-white`。

**次要按钮（对话框底部）**：取消 / 置顶保存 / 删除等与主操作同排的次要动作，用灰底 `bg-[#F5F5F5]` + `text-[#666666]`，与主操作同高、同圆角、同字号（`h-7 rounded-[2px] px-3 text-xs font-medium`），**不加图标与描边**；hover 不改变底色。主操作黑底白字，只有它 hover 加深。

**破坏性操作（删除）**例外一条：同样灰底，但文字用错误色 `text-[#B91C1C]`——删除不可撤销。点它不直接删，而是在按钮行上方就地带出**确认条**：`rounded-[2px] border border-[#E5E5E5] bg-[#F5F5F5] px-3 py-2`，左边一句 `删除后无法恢复，…？`（`text-xs text-[#666666]`），右边「取消」（`h-6` 白底灰字）+「确认删除」（`h-6` 黑底白字）；不做独立确认弹窗、不加红色底色、不做撤销 Toast（2026-10-22 起，便签与待办的编辑弹窗内）。

### 7.4 hover 反色（可点击图标块）

常态「浅底深图标」，hover 反转为「黑底白图标」：

```tsx
<div className="group flex items-center gap-3 rounded-[2px] bg-[#F5F5F5] p-2 transition-colors hover:bg-[#ECECEC]">
```

### 7.13 全局提示（Toast）

全局单例：`ToastProvider` 挂在 `(app)/layout`，业务组件用 `useToast()` 取 API（`info` / `success` / `warn` / `error`），**不引第三方库**。

**两种形态按断点切换**（2026-10-22 起）：

| 断点 | 位置 | 宽度 |
|---|---|---|
| `≥ md`（桌面 / 平板） | **屏幕右下角**，从下往上堆叠、右对齐（`md:items-end md:justify-end md:p-6`），不挡内容 | `md:w-auto`，上限 400px |
| `< md`（手机） | **水平垂直居中**，像一张小弹窗——居中才不会被拇指挡住 | `max-w-[min(64vw,240px)]`（375 屏约 240px，两侧各留 ~67px） |

手机上**不撑满整宽**：整宽会变成一条细长条，收窄之后文案自然换成两三行，整块更方（2026-10-22 联调）。

卡片：

```tsx
className="pointer-events-auto flex w-full animate-fade cursor-pointer items-center gap-3 rounded-[4px] border border-[#E5E5E5] bg-white p-3 text-left shadow-[0_16px_48px_rgba(0,0,0,0.18)] md:w-auto md:px-4"
```

- **图标 = 黑底白图标块**（`h-8 w-8 rounded-[2px] bg-[#000000]` + `h-4 w-4 text-white`），与 §7.4 的图标块、黑底按钮同一套黑白语言；**类型只靠图标形状区分**（CheckCircle2 / Info / AlertTriangle / XCircle），不再按类型上色——全站唯一带彩的地方是状态点，提示卡里加彩色和整体不配套（2026-10-22 联调）
- 文本 `text-sm leading-relaxed text-[#1F1F1F]`
- **入场动画按形态区分**：PC 用 `md:animate-slide-in-right`（从屏幕右侧向左推进来，0.28s）；手机居中形态用 `animate-fade`（纯淡入）——居中卡片若也从右边滑入，会先贴着屏幕右缘再跳到中间，看着像闪一下
- **3 秒自动消失**；点一下就立刻关；最多同时 3 条（第 4 条顶掉最旧的）
- **不做全屏遮罩**：它是「做完了」的回执，不该拦住下一步操作
- 透明浮层容器 `pointer-events-none`、卡片 `pointer-events-auto`——否则这层会吃掉整页点击
- `aria-live="polite"`：出现时读屏念一遍，但不打断当前朗读
- 文案里的可变部分（便签正文 / 待办标题）必须先过 `formatDeletedMessage()`：压成一行、超 24 个字符截断

### 7.16 登录 / 注册页

**全站布局的唯一例外，也是第一处真正的响应式重构**：不进应用外壳（无侧边栏、无页头、无页脚）。两页同构，只有字段数量、标题与底部链接不同。

三档各司其职，**一次只变一件事**——这是这页「从手机拖到宽屏很顺」的全部原因：

```
< md（手机）                    ≥ md（平板）                    ≥ lg（窄屏 PC / 宽屏）
┌────────────────────┐        ┌──────────────────────┐        ┌────────────┬──────────────┐
│ 白底品牌块          │        │ 灰底品牌块            │        │ 黑底品牌栏  │ 灰底表单区    │
│  ■ NEXUS OS        │        │  ■ NEXUS OS          │        │  w-[44%]   │  白卡 420px  │
│  让工具成为能力，    │        │  让工具成为能力，     │        │  xl:w-[46%]│              │
│  让 AI 成为助手。   │        │  让 AI 成为助手。     │        │  ■ (白底)   │  登录        │
│  ──────────────    │        │  ──────────────      │        │  NEXUS OS  │  [字段]      │
│  NEXUS OS · 个人…   │        │  NEXUS OS · 个人…     │        │  让工具…     │  [按钮]      │
│  登录 / 表单（铺满） │        │  ┌────────────────┐  │        │  ──────    │              │
└────────────────────┘        │  │ 白卡：登录 / 表单│  │        │  PERSONAL… │              │
                              │  └────────────────┘  │        └────────────┴──────────────┘
                              └──────────────────────┘
```

| 部位 | < md | ≥ md | ≥ lg |
|---|---|---|---|
| 品牌区 | `mx-auto w-full max-w-[420px] px-5 md:px-8`：品牌标（黑方块 `h-8 w-8` + Sekuya 品牌字 `text-xs`）+ **34px 口号** + 1px 线 + 等宽脚注 | 同一列，口号 **40px**、留白放大；底色随整页转灰 | 换成**左侧黑栏** `w-[44%]`（`xl:w-[46%]`）、`px-14 py-12`、上下两端对齐：上＝白方块 `h-14 w-14`＋品牌字，下＝ 20px slogan + 1px 线 + 等宽版本字 |
| 整页底色 | 白 `#FFFFFF` | `#F5F5F5` | 同左（表单区） |
| 表单容器 | 与品牌块同一列 `mx-auto w-full max-w-[420px]`；边距由卡片自带（`px-5`），无底色无边界 | 同一列，卡片转为白卡：`md:rounded-[2px] md:bg-white md:p-8` | 同左，卡片在右栏水平 + 垂直居中 |
| 输入框 | `h-11 text-base` | `h-10 text-sm` | 同左 |
| 主按钮 | `h-12` | `h-11` | 同左 |
| 字段间距 | `space-y-5` | `space-y-4` | 同左 |

- **「一次只变一件事」**：底色与卡片在 **md** 切换，版式方向在 **lg** 翻转。两件事压进同一个断点，1024px 附近会同时跳底色、跳卡片、跳方向——那才是突兀的来源。
- **底色统一写在外层容器**，品牌区与表单区都不自带底色：手机整页白、md 起整页灰，中途不会出现一条白灰分界。
- **窄屏到平板之间是「一列 420px」**：品牌块与表单卡都 `mx-auto max-w-[420px]`，两边的内容左边距逐档一致（文字块 `px-5 / md:px-8`，卡片 `px-5 / md:p-8`），所以**永远同轴**。中间宽度最容易露馅（例如 700px）：卡片被 `max-w` 收窄了，容器却还贴在 `px-5` 上，右边空出一大片——这就是"没有水平居中"的来源。
- **手机上的大口号不是装饰，是配重**：那一屏表单只有 400 多像素高，没有上面这句 34px 的字，整页就会头重脚轻（早期版本靠底部补一行小字撑住，现在不需要了）。
- **黑底品牌区只许出现在入口页**：它是全站最大的一块黑色面，黑底之上一律反白（Logo 用白底方块包着）。不向应用内部扩散。
- **移动档的输入框用 16px（`text-base`）**：iOS 在输入框字号小于 16px 时聚焦会自动放大整页，那一下缩放比字号本身难看得多。桌面档回到 14px。
- **移动档不给表单套卡片**：铺满时卡片边界就是屏幕边缘，套上只剩多余的留白。
- 本页是全站**唯一允许装饰**的地方，且全部用 CSS 画（网格 / 柔光 / 入场动效），不引图片、不引 SVG 文件——见 §12。

- **字段行**：`label` 在输入框上方（`text-xs text-[#8A8A8A]`，与输入框间距 `mt-1.5`），字段说明（规则、格式要求）在输入框下方（`mt-1.5 text-xs text-[#999999]`）。
- **字段级错误**：替换说明文字，颜色转 `#B91C1C`，同时输入框描边转 `border-[#B91C1C]`。
- **表单级错误**（如「用户名或密码不正确」）：灰色内嵌块 + 红字，`rounded-[2px] border border-[#E5E5E5] bg-[#F5F5F5] px-3 py-2 text-xs text-[#B91C1C]`，位于按钮上方。
- **一次失败只出现在一处**：能归到某个字段的失败，**只**用字段级提示（红字 + 红描边）；归不到任何字段的（整体失败如「用户名或密码不正确」、限流锁定）才用表单级灰块。同一件事两处都提示，会被读成两个不同的错误——用户会以为除了用户名被占用还另有问题。
- **文案陈述事实，不给建议**：`该用户名已被占用`，而不是「换一个用户名试试」——用户看到"被占用"自然知道要换，建议是多余的噪音，还会让提示变长、淹没信息本身。
- **错误提示的生命周期**：字段级与表单级错误都是**上一次提交的快照**，不随输入变化自动消失。规则是——某个字段被编辑过，它的旧错误立即隐藏；表单里任意字段被编辑过，表单级错误立即隐藏；下一次提交时全部清空，由服务端重新判定。理由：用户把 7 位密码改成 8 位后，「密码至少 8 位」还挂在下面，读到的就是「我明明改对了，它却说我不对」——这是提示的错，不是用户的错。实现见 `src/hooks/use-dirty-fields.ts`。
- 页面级标题不是页头组件（§7.10）——这是本形态对「页面必须有统一页头」的**显式豁免**。

- 卡内 3 条便签块：`rounded-[2px] bg-[#F5F5F5] px-3 py-2.5`，**一条只占一行**——正文 `text-[13px] text-[#000000]` 单行截断（`truncate`），时间 `text-[10px] tabular-nums text-[#999999]` 放正文右侧、`shrink-0`；块间距 `gap-2`；排序为置顶优先、置顶组内按 `pinned_at` 倒序，其余按更新时间倒序。**卡内分栏按卡片自身宽度（容器查询）：容器 ≥ 448px（`@md`）2 列，否则单列**——首页这张卡固定约 430px 时为单列三行；卡片变宽（拼回主区 2/3）会自动回到 2 列。
- 无便签时，卡内给一块同款灰底空态：「还没有便签」+「写一条 →」入口。
- 登出入口在外壳里、不在本页：桌面在侧边栏底部徽标、手机在抽屉底部整行（§7.18），本页不再自带按钮。
- 本页与其余一级页同构（Agent / 知识 / 文件 / 自动 / 设置同为占位；工具页已是真实页面，见《功能/工具中心》）。

**每日一句卡（2026-10-22 起；设计见《功能/每日一句》）**：逐块一行里的第四块，限宽 430px。

- 白卡 `rounded-[2px] bg-white p-5` + 分组标题「每日一句」（§7.2）+ 右上「每天更新」`text-xs text-[#8A8A8A]` + 「换一句」图标按钮（`RefreshCw`，`h-7 w-7`，默认灰、hover `bg-[#ECECEC] text-[#000000]`，请求中旋转并禁用）。
- 正文 `mt-4 text-[15px] leading-7 text-[#000000]`，署名 `mt-2 text-xs text-[#8A8A8A]`（`—— 作者`）；正文块 `min-h-[3.5rem]`、署名行 `min-h-4`——换句或接口缺作者时卡片高度都不跳。
- 内容来自内置句子库（365 条正能量句子，按上海日界轮换），不请求任何外部接口。

### 7.18 侧边栏底部用户区（用户菜单）

账户区（用户名 / 登出）钉在侧边栏底部、不随页面变化；页头右侧留给页面级控件（§7.10）。两档形态各自定做，点开的是同一个向上弹出的菜单：

```
≥ lg（图标窄栏）                    < lg（手机抽屉）
┌────────┐                        ┌──────────────────┐
│  ⋮ 导航 │                        │  ⋮ 导航           │
│  (人)   │ ← 用户图标（点开）        │ (人) 用户名    ⌃⌄ │ ← 整行（点开）
└────────┘                        └──────────────────┘

用户菜单（两档共用，向上弹出）：
┌─────────────────┐
│ 用户名           │ ← 身份行：窄栏里放不下的全名在这里补齐
│ ─────────────── │
│ ⏻ 退出登录       │ ← 目前唯一的菜单项；账号级动作以后加在这里
└─────────────────┘
```

- **图标 = 通用「用户」图标（lucide `UserRound`）**，与导航图标同风格、同尺寸——不做头像、也不做首字母徽标；将来接入真实头像时，这一块才是替换点。
- **桌面（≥ lg）**：`aside` 底部 `p-3`，与导航区之间**不设分割线**（靠「钉在底部」的位置区分账户与导航）；可点块与导航项完全同格——`flex items-center justify-center rounded-xl px-4 py-4`（56×56）、图标 `h-6 w-6`，hover / 菜单展开中 `bg-[#ededed]`，`title` 提示用户名。
- **手机抽屉（< lg）**：底部整行 `flex items-center gap-3 rounded-[2px] px-4 py-3` = 用户图标（`h-5 w-5`，与抽屉导航图标同尺寸）+ 用户名（`text-[15px] truncate`）+ 右侧 `ChevronsUpDown`（`h-4 w-4 text-[#8A8A8A]`）；容器 `px-3 pt-3 pb-[max(12px,env(safe-area-inset-bottom))]`，留出手机底部手势条的安全区。
- **菜单**：`side="top"` 向上弹出、`min-w-56 rounded-[2px]`；内容 = 身份行（**只有用户名**，`text-[13px] font-medium`）+ 分隔线 +「退出登录」项（`text-[13px]`，带 `LogOut` 图标；**不套红色**——红色是错误色，登出不是错误）。
- 行为由 Base UI 菜单原语提供（键盘导航、外点关闭、焦点管理）；登出复用既有 Server Action。两个触发器与菜单项显式 `cursor-pointer`（§2.5）。点击用户图标**不播涟漪**——涟漪表达「页面要切了」，弹菜单不是（§12.4）。
- 两档都「底部钉住、不随导航滚」：导航区 `min-h-0 overflow-y-auto`、底部块 `shrink-0`——矮屏（横屏手机 / 小窗口）下导航可滚，账户块必在。

### 7.19 勾选行（待办）

一行一件事，**整行可点**——不是只有 16×16 的方块能点：

```tsx
<div className="group flex w-full cursor-pointer items-center gap-2.5 rounded-[2px] p-2 text-left transition-colors hover:bg-[#F5F5F5]">
  <span className="flex h-4 w-4 shrink-0 items-center justify-center rounded-[2px] border border-[#D0D0D0] bg-white transition-colors">
    {/* 完成态：border-[#000000] bg-[#000000] + <Check className="h-3 w-3 text-white" /> */}
  </span>
  <span className="min-w-0 flex-1 truncate text-sm text-[#000000]">{/* 完成态：text-[#999999] line-through */}</span>
  <span className="shrink-0 text-[10px] tabular-nums text-[#999999]">{/* 创建时间 YYYY-MM-DD HH:mm，放右侧 */}</span>
</div>
```

| 元素 | 未完成 | 完成 |
|---|---|---|
| 勾选框 | `border-[#D0D0D0] bg-white` | `border-[#000000] bg-[#000000]` |
| 勾 | 不渲染 | `Check h-3 w-3 text-white` |
| 标题 | `text-sm text-[#000000]` | `text-sm text-[#999999] line-through` |

- **行高**：首页卡内 `p-2`；工具页用的是 96px 卡片（见《功能/待办清单》§2.2），不套这一行。
- **这一行只负责勾选**：整行可点；删除放在工具页卡片的右上角（桌面 hover / 触屏常显），不在首页行内出现。
- **行本身不能用 `<button>`**：一旦行内还有按钮，`<button>` 里嵌 `<button>` 是非法 HTML，浏览器会提前闭合外层、点击行为错乱。行用 `<div>` 绑点击；卡片上的勾选 / 删除 / 编辑是三个兄弟按钮。
- **一条只占一行**：标题单行截断（`truncate`），创建时间 `text-[10px] tabular-nums text-[#999999]` 放**标题右侧**、`shrink-0`，格式 `YYYY-MM-DD HH:mm`（UTC+8）。时间放标题下面会把每行撑成两行、3 条就把卡拉得很高（2026-10-22 联调要求）。
- **完成态只改颜色与删除线**，不加动画、不加背景块——勾选是高频动作，动效会拖慢连续勾选的节奏（§12.3）。
- **离场是另一段节奏**（§12.5）：勾选后停留 800ms（期间可撤销、连续勾选顺延），再淡出 / 收起 200ms，然后才从列表移除；首页卡同时用服务端返回的板补上第 4 条。

### 7.20 便签卡（正方形）

工具页的便签卡固定为正方形（`aspect-square`），宽随网格列宽、高自动等于宽：

- 网格 `grid-cols-2 gap-3 md:grid-cols-4 lg:grid-cols-5 xl:grid-cols-6`，`≥ 1400` 再一档 `grid-cols-7`；`1280–1399` 保持 6 列——再密一档，底部一行会挤出卡片。
- 正文最多 5 行（`line-clamp-5`），占满整卡宽度；卡片内边距 `p-3 md:p-4`。
- 底部固定一行：左侧时间 +「已置顶 / 未置顶」文字按钮，右侧删除按钮（桌面 hover、触屏常显）；操作按钮不占右侧一整列，正文因此不再需要 `pr-14`。
- 点卡片任意位置打开编辑弹窗；置顶文案与删除按钮浮在上层，不触发编辑。

## 九、禁令

以下写进代码即视为违规，不是风格偏好：

## 十二、动效与装饰

**本节分两块：入口页的入场动效与装饰（12.1–12.3），和应用内的功能型过渡（12.4 侧栏涟漪、12.5 勾选离场）。** 共同约束：全部都要能在系统开启「减少动态效果」时自动失效。

### 12.1 动效 token

全部定义在 `globals.css` 的 `@theme` 里，用 Tailwind 类名调用：

| 类名 | 用途 | 时长 / 缓动 |
|---|---|---|
| `animate-rise` | 主要入场：淡入 + 上移 14px | 0.55s · cubic-bezier(0.22,1,0.36,1) |
| `animate-fade` | 纯淡入（副文本） | 0.6s · ease-out |
| `animate-scale-in` | 浮层出现：0.97 → 1 | 0.5s · 同上 |
| `animate-grow-x` | 1px 线从左向右生长（配 `origin-left`） | 0.9s · 同上 |
| `animate-slide-in-right` | PC 端全局通知从右侧滑入（`translateX(100%)` → 0，带淡入） | 0.28s · cubic-bezier(0.22,1,0.36,1) |
| `animate-drift` | 背景柔光缓慢漂移（全站唯一的循环动画） | 30s · alternate |

- **交错入场用内联 `animationDelay`**（如 40 / 140 / 280 / 400ms），不要为每个元素另写 keyframes。
- 时长一律 < 600ms；`drift` 是唯一例外——它慢到察觉不出在动，只是让静止的暗面不死。
- 动画一律 `both` 填充，慢加载时不会先闪一下再归位。

### 12.2 装饰纹理

同样定义在 `globals.css`：

| 类名 | 用途 |
|---|---|
| `bg-grid-fine` | 黑面上的极细网格（白 3% / 34px；手机上自动降为 2.2% / 44px——屏幕小了网格密会像稿纸） |
| `bg-grid-fine-light` | 白面上的极细网格（黑 3.5% / 28px） |
| `bg-glow-dark` | 暗底上的径向柔光（左上角，白 12% → 透明） |

- 全部用 CSS 画，**不引图片、不引 SVG 文件**。
- 纹理一律加在装饰层上，该层必须 `pointer-events-none`，绝不挡交互。

### 12.3 两条硬约束

1. **`prefers-reduced-motion: reduce` 优先于一切**：`globals.css` 末尾有一段全局降级，命中时所有动画时长归零。动效是加分项，不是功能。
2. **动效不得延迟用户**：入场只影响「看见」的顺序，不影响「能点」的时间；不做 loading 表演、不做循环炫技。

### 12.4 侧栏导航涟漪（导航反馈）

点击侧栏任一**非当前**导航项时，该项内叠一层「激活色涟漪」：`absolute inset-0 origin-center animate-ripple bg-[#d5e3f6]`，从中间向两侧铺开、末段淡出，动画结束后移除（`onAnimationEnd`）。作用：让「点下 → 页面切换」之间有一帧可知的反馈。

- keyframes 与 token 定义在 `globals.css`：`--animate-ripple: ripple-expand 580ms ease-out forwards`；关键帧为 `scaleX(0→1)`，70% 处铺满，100% 淡出。
- 桌面图标栏与手机抽屉两个版本共用同一行为；点击**当前**项不播（没有要去的地方）。
- 同样受 §12.3 的 `prefers-reduced-motion` 全局降级约束——系统关闭动效时自动失效。

### 12.5 勾选离场（功能型过渡）

勾选待办后的离场不是为了好看，而是为了「给回执、又不打断连续勾选」：

| 阶段 | 时长 | 做了什么 |
|---|---|---|
| 停留 | 800ms | 卡片 / 行留在原位变灰划线；回执 + 撤销窗口；连续勾选会重置计时器（debounce） |
| 离场 | 200ms | 工具页收起网格行高 + 淡出；首页卡行淡出。动画结束才真正移入已完成 / 补位 |
| 结算 | — | 「未完成 / 已完成」计数同一刻更新；首页卡用 action 返回的整块板补上第 4 条 |

- 两个时长定义在 `src/lib/todos/leave.ts`（`TODO_LEAVE_DELAY_MS` / `TODO_LEAVE_ANIMATION_MS`），首页卡与工具页共用。
- 离场中的卡片 / 行禁用，避免点到一个正在消失的目标。
- 受 §12.3 的 `prefers-reduced-motion` 约束：系统关闭动效时过渡直接生效，但 800ms 的停留与撤销窗口保留。
- 不做「飞向已完成区」的长距离动画：已完成区可能在屏幕外，长距离移动反而让人不知道它去了哪。
