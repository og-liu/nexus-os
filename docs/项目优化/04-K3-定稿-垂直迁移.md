## 一、目标结构（往后的唯一合法形态）

```
src/features/<工具>/
├── client/            ← 浏览器：带 "use client" 的组件
├── server/            ← 服务端：page、actions、数据访问、服务端组件
│   └── api/           ← 仅抖音/音频/音乐：Route Handler 实现本体
└── shared/            ← 两端共用：纯函数（只碰纯数据，不碰 db/网络/密钥）
```

**归位规则（看文件头顶三行就能判）：**

| 文件特征 | 去哪层 |
|---|---|
| 带 `"use client"` | `client/` |
| 带 `"use server"`（actions） | `server/` |
| 数据访问（碰 db） | `server/`，且顶部加 `import "server-only"` |
| 无标记的组件（RSC 服务端组件，如 page、部分卡片） | `server/` |
| 无标记的纯函数（不碰 db/网络/密钥） | `shared/` |

**示例（便签，标记全部实测过）：**

| 现位置 | 标记 | 新位置 |
|---|---|---|
| `app/(app)/tools/sticky-notes/page.tsx` | 无标记（服务端 RSC） | `server/page.tsx` |
| `components/tools/sticky-notes/` 4 个组件 | `"use client"` | `client/` |
| `components/dashboard/sticky-notes-card.tsx` | 无标记（服务端组件） | `server/card.tsx` |
| `lib/sticky-notes/actions.ts` | `"use server"` | `server/actions.ts` |
| `lib/sticky-notes/notes.ts` | 数据访问 | `server/notes.ts` + `server-only` |
| `lib/sticky-notes/validate.ts`、`format.ts` | 纯函数 | `shared/` |
| 3 个测试文件 | — | 跟着各自源文件走 |

**app/ 只剩两种壳（均已实测全绿）：**

```ts
// app/(app)/tools/<工具>/page.tsx —— 一行壳
export { default, metadata } from "@/features/<工具>/server/page";

// app/api/**/route.ts —— 三行壳，segment config 必须留壳
export const runtime = "nodejs";
export const dynamic = "force-dynamic";
export { GET, POST } from "@/features/<工具>/server/api/<名>";
```

`lib/` 收缩为基础设施层（auth / secrets / db / agent / datetime / quote / navigation / toast / settings 九个目录 + 根下 `format.ts` / `format-bytes.ts` / `http.ts` / `content-disposition.ts` / `zip.ts` / `utils.ts` 六个共享模块，全部原地不动）。

> **（Lingda 补，2026-11-05，ogliu 授权）** 以下两块是 #02 评审的收尾——不补，worker 搬第一个工具就会卡住。

**跨工具共享的组件（工具页公共层，同样不搬）：**

`src/components/tools/` 下有 4 件是**所有工具共用的**，不属于任何一个工具，搬迁时留在原地，`features/` 允许 import：

| 文件 | 被几个文件引用 | 是什么 |
|---|---|---|
| `tool-catalog.ts` | 12 | 工具目录数据（slug / 名称 / 分类 / `QUICK_TOOL_SLUGS`） |
| `tool-header.tsx` | 7 | 工具页标题条（无标记 = 服务端组件） |
| `tool-mobile-bar.tsx` | 6 | 工具页移动端底栏（`"use client"`） |
| `tool-bar.tsx` | 2 | 工具页工具栏（`"use client"`） |

`tool-filter.ts` / `category-chips.tsx` / `tool-card.tsx` / `tools-view.tsx` 是「工具中心」这一页自己的组件，同样不搬。

**`components/dashboard/` 按文件区分，不整目录搬：** `quote-card`（每日一句）、`quick-tools-card`（常用工具）、`datetime-panel`（时间面板）都不是工具，留在原地；`sticky-notes-card.tsx`（无标记）和 `music-card.tsx`（`"use client"`）属于便签 / 音乐播放器，**跟着对应工具走**（见 §三 对照表）。

## 二、铁律（写进《项目目录结构说明》重写版 + CI 拦截）

1. **features 之间禁止互相 import**；跨工具共用只许去 `lib/shared/`（纯函数）或 `lib/` 基础设施层；
2. **`client/` 和 `shared/` 禁止 import 任何 `server/`**（同工具内也不行）——纯函数要数据，由 server 层调好后传进来；
3. import 方向：`app/` → features / components / lib；`features/` → lib、`components/ui`（shadcn 原件）、`components/tools/` 的四个公共件（`tool-catalog` / `tool-header` / `tool-bar` / `tool-mobile-bar`）；`features/` ↛ 其他 features、↛ `app/`、↛ `components/` 的其他目录；
4. `server/` 下碰 db 的文件必须带 `import "server-only"`（构建期兜底）；
5. **新工具一律按 §一 结构落地**，不允许再散进 app/components/lib 三层。

**CI 最小实现**（grep 即可，可换等价方案）：
- `src/features/*/client/**` 与 `src/features/*/shared/**` 里出现 `server` 的相对/别名引用 → 报错；
- `src/features/A/**` 里出现 `@/features/B/`（B≠A）→ 报错。

**每个工具的固定动作：**

1. `git mv` 文件进 `features/<工具>/`，按 §一 归位规则分到 `client/` / `server/` / `shared/`；
2. 首页卡（便签/待办/日历/音乐）一并搬（按标记归位），改 `app/(app)/page.tsx` 对应几行——规定动作；
3. app/ 留壳（page 壳 / route 壳）；
4. 数据访问文件加 `import "server-only"`（开工前先 `pnpm add server-only`，唯一新增依赖）；
5. **3 个混合体拆分**（vault、markdown/tags、html/tags）：纯函数部分 → 该工具 `shared/`，数据访问部分 → `server/` + `server-only`；
6. **音乐播放器附加项**：改 `components/layout/app-shell.tsx:8-9` 的 `PlayerOrb`/`PlayerProvider` 引用路径（两者都带 `"use client"`，归 `client/`）；7 条路由实现搬 `server/api/`。

## 四、明确不做（控风险）

- **只搬不拆**：23 个超 300 行文件原样归位，不拆分；名单登记进《项目目录结构说明》例外登记表（按新路径），拆不拆以后单议；
- 不改文件名（每层目录已给出归属，规范化以后单议）；
- 不动 Agent 域（`agent-chat.tsx`、`api/chat` 原地）；不动 auth/secrets/db；不动业务逻辑——**diff 里只许出现路径变化和 server-only 标记**。
