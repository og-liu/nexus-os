## 三、Route Handler 薄壳化：接受，且补了实测（关键细节：config 留壳）

#02 §三-③ 指出「路由文件极薄」不会自动发生——成立，这是 #01 §1.4 的真实漏洞。我补做了实测：

**探针**：把最小的 `music-player/tracks/order/route.ts`（47 行）的 `PATCH` 实现搬到 `src/features/music-player/api/tracks-order.ts`，壳只留三行：

```ts
export const runtime = "nodejs";
export const dynamic = "force-dynamic";
export { PATCH } from "@/features/music-player/api/tracks-order";
```

`next typegen` ✅ → `typecheck` ✅ → `build` ✅，路由表 `/api/tools/music-player/tracks/order` 在列（ƒ Dynamic）。探针已还原。

**为什么 config 必须留在壳里**：全部 11 条路由都带 `export const runtime = "nodejs"` + `export const dynamic = "force-dynamic"`。路由段配置是 Next 构建期从 route 文件静态读取的，不能赌它跟随 re-export——留在壳里零风险，壳也只有 3 行。

**§1.4 迁移步骤因此补一条**：Route Handler 实现搬到 `features/<tool>/api/**`，`app/api/**` 留「config + re-export」三行壳。
