## 一、问题①：读懂一个工具要跳好几处

### 1.1 根因：组织轴错了，不是文件错了

现在的代码按**技术层**组织——`app/` 放页面、`components/` 放组件、`lib/` 放逻辑。这是「维护整个系统的人」的视角。而你是「一次读一个工具的学习者」。

以最小程序便签为例，实测它的完整实现链：

| 目录 | 文件 | 角色 |
|---|---|---|
| `app/(app)/tools/sticky-notes/` | `page.tsx`（33 行） | 服务端入口：取数 + 挂组件 |
| `components/tools/sticky-notes/` | `sticky-notes-view.tsx`、`note-dialog.tsx`、`note-editor.tsx`、`note-card.tsx` | 浏览器交互 |
| `lib/sticky-notes/` | `actions.ts`、`notes.ts`、`validate.ts`、`format.ts`（+3 个测试） | 服务端逻辑与数据 |
| `components/dashboard/` | `sticky-notes-card.tsx` | 仪表盘卡片 |

**一个最小工具 = 横跨 4 个目录、10 个源文件（不含测试）。** 10 个工具全是这个结构。跳转不是因为你笨、也不是因为文件写得差——是因为「一个工具」在这套目录里根本不是一个物理存在。

### 1.2 方案：垂直切片——让「一个工具」成为一个目录

```
src/features/sticky-notes/
├── page.tsx        ← 从 app/ 搬来（服务端入口）
├── view.tsx        ← "use client"，从 components/ 搬来（交互）
├── actions.ts      ← "use server"，从 lib/ 搬来（写操作）
├── notes.ts        ← 数据访问，加 import "server-only"
├── validate.ts     ← 纯函数，前后共用
└── format.ts       ← 纯函数，前后共用
```

`app/(app)/tools/sticky-notes/page.tsx` 只留一行薄壳：

```ts
export { default, metadata } from "@/features/sticky-notes/page";
```

**技术前提已实测**（不是推演）：我在云端克隆真实搬了便签 page，`pnpm typecheck` ✅、`pnpm build` ✅、路由表 `/tools/sticky-notes` 原样在列，`metadata` 随壳转发。探针已还原。

**承重墙不动**：依赖方向完全保持——界面不碰数据库、`lib` 不 import 组件、密钥只在服务端。搬的是文件位置，不是依赖关系；期 3 的 Agent 循环直调 `(db, userId)` 领域函数，签名一行不改。

**配套新铁律**（替代被废掉的「按职责分层」轴）：

> **features 之间禁止互相 import；跨工具共用的代码只许去 `lib/shared/`（纯函数）或 `lib/` 基础设施层（auth / secrets / agent / db）。**

`lib/` 收缩为基础设施层保留，不拆。

### 1.3 代价（全账，不藏）

| # | 代价 | 缓解 |
|---|---|---|
| 1 | **全貌打九折**：11 条 Route Handler 必须留在 `app/api/`（SSE、音频提取、抖音、音乐×7），带 API 的工具要看两处 | 预期设对；路由文件极薄，指向 features |
| 2 | **迁移中间态更乱**：一半工具已搬、一半没搬时是最差态 | 批次小、节奏快；利用期 2 前空窗集中搬完；worker 在飞分支先交干净 |
| 3 | `git blame` / `log` 在移动点断（`--follow` 可追，不完美） | 提前知情，小代价 |
| 4 | 《项目目录结构说明》要重写，AGENTS.md 要同步 | 随迁移同批做 |
| 5 | 新铁律不立，features/ 三个月后长成蜘蛛网 | 铁律写进文档 + CI 拦截（ESLint `no-restricted-imports` 或十行 grep） |

### 1.4 迁移步骤与验收

1. **试点便签**（约半天）：按 §1.2 搬好，app/ 留壳；
2. **验收标准只有一条，评委只有你**：打开 `features/sticky-notes/`，问自己「我还要跳吗」；
3. 通过 → 分批搬其余 9 个工具（每批一个工具一个 PR，肉眼回归 + 门禁五项）；lib 基础设施收尾；不满意 → 停损，成本半天。

### 1.5 顺带收割：300 行规则

现网 14 个文件超 300 行（最大 `player-provider.tsx` 908 行）。垂直切片搬迁时组件本来就要过手——**顺手把超标的组件按职责拆开**（如 `note-editor` / `note-card` 已是正确粒度），并建立例外登记表：拆不掉的登记「为什么不拆」，CI 拦新增。规则从口号变成可审美的清单。

## 二、问题②：分不清哪里是前端、哪里是后端

### 2.1 根因

RSC 全栈单体把前后端放进同一棵文件树，边界只剩一行 `"use client"`——对有前后端分离经验的人反而最不友好，因为你的经验里「边界 = 目录/服务」，而这里「边界 = 文件内的一行 pragma」。

### 2.2 方案（三层，随垂直切片自然落地）

1. **命名即边界**：切片后同一目录内——`*.view.tsx`（或 `note-*.tsx`）= 浏览器；`page.tsx` / `actions.ts` = 服务端；`notes.ts` = 服务端数据层；`validate.ts` / `format.ts` = 前后共用纯函数。**层写在文件名上，不用猜。**
2. **三行人话对照表**（写进《技术栈说明》开头）：`page.tsx`/`actions.ts`/无标记的 `lib/` 文件在服务端跑；带 `"use client"` 的在浏览器跑；共用纯函数两边都跑、但只许碰纯数据。
3. **server-only 安全线**（这是安全工程，不是可读性工程，但和迁移同一批做最省）：现网有 31 个 lib 模块被客户端值导入，其中 3 个混合体（`vault/vault.ts`、`markdown/tags.ts`、`html/tags.ts`）靠巧合安全——拆出纯函数到 `shared.ts`，数据访问层加 `import "server-only"`，让 `pnpm build` 当裁判。密钥泄露这件事从此由构建器守门，不靠运气。

### 2.3 验收

你在 `features/sticky-notes/` 里随便点开一个文件，三秒内说出它跑在哪一端——说不出来说明命名约定失败，打回。

## 三、问题③：文档给 AI 看还是给人看

### 3.1 根因

你的直觉是对的，而且比你说的更对：这个项目的文档受众其实是**三层**，现有 docs/ 是按单一受众（人）写的。

### 3.2 方案：三层受众各归其位

| 受众 | 载体 | 动作 |
|---|---|---|
| **运行时模型**（期 3 的 Agent） | 工具契约：`description` 就是 prompt | 期 3 新建《工具契约》文档体裁；文档只指路、不复制原文——腐化的注释误导人，腐化的契约让模型行为悄悄漂移 |
| **协作者 AI**（Lingda / worker / 我） | `AGENTS.md` | 扩充规则 + 指针；避开文件头 `BEGIN:nextjs-agent-rules` 自动重写块（`next dev` 会覆盖块内内容，动手前先跑一次 `pnpm dev` 确认） |
| **人（你）** | 现有 docs/ + 垂直切片本身 | 切片落地后大概率不需要额外导览文档——先试，真不够再补，一行都别提前写 |

## 四、暗线：为 Agent 期 2~8 铺路（不喧宾夺主，但要排期）

这条线不解决你的三个问题，但它是项目的未来主线，三件准备必须卡在期 2/期 3 之前：

1. **期 0a（期 2 前）**：`agent_events` 事件表（一表三用：断点恢复 / 用量统计 / 回放调试）+ usage 落库三列（`input_tokens` / `output_tokens` / `reasoning_tokens`，独立成列是为了期 5 能写 SQL 聚合）；
2. **期 0b（期 3 前）**：运行状态机 + 工具契约 + 测试策略；
3. **三个硬约束**（全部实测过）：
   - **缓存绕过**：8 个领域的 `actions.ts` 都靠 `revalidatePath` 刷页面——Agent 直调 lib 不触发它，页面会读旧数据。解法：抽领域常量（如 `STICKY_NOTES_PATHS`），Action 与 Agent 循环共用；
   - **Nginx 300s**：`proxy_read_timeout 300s` 卡死单次运行上限，最大迭代数必须按「300s ÷ 单步实测耗时」反推，是可计算的表达式，不是拍的数；
   - **2 核服务器**：单用户单 run 锁，期 3 顺手做比期 7 补便宜得多。

**垂直切片与这条线天然对齐**：期 3 的工具契约以「一个工具」为边界，切片后「一个工具 = 一个目录 = 一份契约」，Agent 的工具注册表就是 features/ 的目录清单。
