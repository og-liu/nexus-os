# 日期时间面板

| 状态 | 开始日期 | 最近更新 |
|---|---|---|
| 🚧 设计中 | 2026-10-22 | 2026-10-22 |

> 一句话：把总览页最顶上那条信息带**重做**一遍——问候语带上登录用户名，公历日期 + 农历 + 当天**全部**节日与节气，秒级时钟，年度进度条。功能照旧版全保留，实现按本文重来，不搬旧代码。

命名约定：中文「日期时间面板」，代码 `datetime-panel`；其内部年度进度子块叫 `year-progress`。

---

## 一、要什么

**做：**

- **一块横跨整宽的信息卡**，钉在总览页（`/`）页头之下、便签卡与待办卡之上
- **问候语**：`{登录用户名} {问候词}`，例 `ogliu 中午好`；问候词按小时分 6 档
- **日期行**：`10月22日星期四 · 农历九月十三`（农历用中文数字）
- **节日 / 节气**：公历节日 + 农历节日 + 当日节气**三源合并、全部渲染**，多标签自动换行
- **时钟**：`HH:MM:SS` 24 小时制、等宽数字、每秒更新；页面在后台时暂停
- **年度进度**：百分比（1 位小数）+ 进度条
- 三档响应式版式（宽屏 / 平板 / 手机），见第二节

**不做（主动放弃，附原因）：**

| 放弃项 | 原因 |
|---|---|
| 天气、温度、空气质量 | 需要外部 API 与密钥，属于另一个信息域；塞进来会把这块变成「杂项面板」 |
| 公历以外的节日体系（国际日、纪念日） | 底层库的 `getOtherFestivals()` 会给「国际地雷行动日」这类条目，一天几十个，渲染出来就是噪音 |
| 节日详情页 / 点击展开 | 旧版就是纯展示；点开去哪没有需求支撑，先不做 |
| 秒表、倒计时、番茄钟 | 那是「专注工具」，属于工具页，不是总览信息带 |
| 年度目标完成度（自定义目标） | 需要新表与设置界面；这里的「年度进度」是时间刻度，不是业务目标 |
| 农历节日/节气的年份区间查询 | 只显示「今天」，不做日历视图 |

## 二、界面

### 2.1 位置

总览页 `page.tsx` 里，`<PageHeader>` 之后、现有两卡所在的 grid 之前；它自己占一行、横跨内容区整宽（不进那个 `xl:grid-cols-3` 的栅格）。

### 2.2 卡片内部（≥ lg）

单个 `<section>`，白底 `rounded-[2px]` `p-5`（《界面设计规范》§7.1）：

```
┌──────────────────────────────────────────────────────────┐
│  ogliu 中午好                              13:37:26       │
│  10月22日星期四 · 农历九月十三                            │
│  [国庆节] [中秋节] [寒露]                                 │
│  2026 年度进度                                    80.7%   │
│  ███████████████████████████████░░░░░░░░░░░░░             │
└──────────────────────────────────────────────────────────┘
```

- 左区（`flex-1`）：问候语 `text-xl font-semibold`；日期行 `text-xs` 次要色 `#8A8A8A`；两者 `mt-1` 间距
- 右区：时钟 `font-mono text-3xl font-semibold tabular-nums`，与左区垂直居中对齐（§4.2 已把 `text-3xl` 定义为「仪表盘时钟，唯一一处」）
- 标签组：左区下方 `mt-4`，`flex flex-wrap gap-2`；形态见 §7.9 的小标签，白字黑底 `text-[11px]`
- 年度进度：标签组下方 `mt-4`；一行「左说明 + 右百分比」`text-xs`，下方 `h-1` 进度条（§7.8：槽 `bg-[#F0F0F0]`，填充 `bg-[#000000]`）

### 2.3 响应式

| 断点 | 版式 |
|---|---|
| ≥ lg | 一行两区（左问候+日期 / 右时钟），标签组与进度行各占一行；时钟 `text-3xl` |
| md – lg | 同卡两行：第 1 行左问候 + 右时钟（`text-2xl`），第 2 行日期，之后标签组、进度 |
| < md | 竖排：问候（`text-lg`）→ 日期 → 标签组 → 时钟（`text-2xl`，左对齐）→ 年度进度 |

**DOM 顺序必须等于视觉顺序**：只用 `flex-col` / `flex-row` 切换，禁止 `order-*` 翻转（否则 Tab 焦点顺序与眼睛看到的相反）。

### 2.4 内容规则

| 元素 | 规则 |
|---|---|
| 用户名 | 取 `users.username`（登录用户的展示名，保留原始大小写）；不新增字段、不改表 |
| 问候词分档 | `<6` 夜深了 · `6–8` 早上好 · `9–11` 上午好 · `12–13` 中午好 · `14–17` 下午好 · `≥18` 晚上好（按 Asia/Shanghai 小时） |
| 公历日期 | `M月D日星期X`，不带年份（年份在进度行） |
| 农历 | `农历{月}月{日}`，日与月都用中文数字；例「农历九月十三」，不写「农历九月13日」 |
| 节日来源 | `Solar.getFestivals()` + `Lunar.getFestivals()` + `Lunar.getJieQi()` 三源合并、按名去重 |
| 节日顺序 | 公历节日 → 农历节日 → 节气 |
| 节日数量 | 全部渲染、`flex-wrap` 换行；不截断、不折叠「+N」 |
| 节日为空 | 整个标签组不渲染（不留空行、不占高度） |
| 时钟 | `HH:MM:SS`，24 小时制；`document.hidden` 时停表，可见时立即同步一次 |
| 年度进度 | `(今年已过毫秒 / 今年总毫秒) × 100`，`toFixed(1)` |

## 三、数据模型

不涉及。本功能只**读**已有数据：登录用户的 `users.username`（见《数据库设计》· `users` 表）。无新表、无新列、无迁移。

## 四、关键决策

| 决策点 | 选择 | 理由 | 否决的备选 |
|---|---|---|---|
| 放在哪 | 横跨整宽、两卡之上 | 它是页头级信息，横跨一行才不会把便签的 2/3 版式切碎；移动端也自然排第一 | 占左 2 列（便签被挤成两块）· 占右 1 列（430px 内容挤进 1/3 宽） |
| 农历/节日在哪算 | **只在服务端算**，作为 props 传给面板 | 这些东西一天只变一次，没有理由让浏览器每秒算；`lunar-javascript` 打包体积约 **436KB**，进浏览器是纯浪费 | 客户端算（每秒重算 + 436KB 进 bundle）；原生 `Intl`（能给农历，但**节气与农历节日给不了**） |
| 农历数据源 | 新增 `lunar-javascript`（^1.7.7） | 唯一能同时给出「公历节日、农历节日、二十四节气」的方案，且纯 JS、无 DOM 依赖 | 原生 `Intl.DateTimeFormat('zh-CN-u-ca-chinese')`（实测只到「九月13日」，无节气无节日）· 自建节日表（节气每年日期要自己算，等于重写这个库） |
| 时区口径 | 固定 `Asia/Shanghai`，显式传入 | 线上是 UTC 机器，用系统默认时区会在 23:00 就翻篇；用户在东八区，日界必须按东八区 | 用运行环境默认时区（服务端 UTC、客户端本地，两边日界不一致） |
| 节日显示范围 | 全量，但**排除** `getOtherFestivals()` | 「国际地雷行动日」这类条目一天几十个，进来就没法看 | 只显示第一个（旧版做法，会漏掉同时出现的节日） |
| 时钟精度 | 秒级 | 需求原样保留；且它是这块唯一的「活」元素 | 分钟级（省电，但少了秒的呼吸感） |
| 首屏渲染 | 服务端给出完整值，客户端首帧用同一份 props，挂载后接管 | 避免水合不匹配，同时避免旧版「`--:--:--` / 你好」的跳变 | `suppressHydrationWarning`（掩盖问题，时间仍会跳）· 占位符（首屏闪一下） |
| 与旧实现的关系 | 需求全保留，实现重写 | 旧实现有四个硬伤（见第七节），照抄等于把债搬过来 | 复制旧 `GreetingCard`（把客户端算农历、只显示第一个节日一起搬过来） |

## 六、验收标准

1. 访问 `/` → ≥ lg 宽度下，页头之下是横跨整宽的一张卡，便签与待办两卡在它下面
2. 卡片 ≥ lg 时左追问候、右侧时钟，两端对齐；秒数跳动时时钟宽度不变（等宽数字）
3. 问候语为 `{用户名} {问候词}`；换一个账号登录 → 名字跟着变
4. 问候词分档：注入 05:59 / 06:00 / 08:59 / 09:00 / 11:59 / 12:00 / 13:59 / 14:00 / 17:59 / 18:00 十个时刻 → 依次是 夜深了 / 早上好 ×2 / 上午好 ×2 / 中午好 ×2 / 下午好 ×2 / 晚上好
5. 日期行形如 `10月22日星期四 · 农历九月十三`；农历为中文数字
6. 2026-10-01 → 标签含「国庆节」；2026-09-25 → 含「中秋节」；2026-02-04 → 含「立春」；2026-02-17 → 含「春节」
7. 人造同日（国庆 + 中秋 + 节气）→ 三个标签全部出现、按「公历→农历→节气」排序、窄屏换行不截断
8. 无节日的普通一天 → 标签组元素数为 0，卡片高度相应变矮
9. 时钟每秒跳一次；切到别的标签页 30 秒再切回 → 直接显示当前时间，不出现连跳
10. 年度进度百分比 = `(今天 − 1月1日)/(明年1月1日 − 1月1日)` 手算值，误差 ≤ 0.1
11. 服务端时间置于 23:59:30（Asia/Shanghai）→ 00:00 后页面自动换成新日期、新农历、新进度（跨天 refresh 生效）
12. 375 / 768 / 1440 三个宽度：栏数与时钟位置符合 2.3 表；Tab 键顺序与视觉顺序一致
13. 读屏：时钟不被逐秒朗读；进度条可读出百分比
14. 门禁五项全绿（typegen / typecheck / lint / test / build）

## 七、已知的坑

| 坑 | 机制 | 对策 |
|---|---|---|
| 水合不匹配 | 服务端渲染时刻与浏览器时刻必然差几毫秒到几秒 | 服务端给出完整字符串当初值，客户端首帧用同一 props，挂载后才能改；不用 `suppressHydrationWarning` 掩盖 |
| UTC 机器提前跨天 | 服务器时区是 UTC，`new Date().getDate()` 在 16:00 UTC 就已经是「明天」 | 日界一律用显式 `Asia/Shanghai` 计算，不碰系统默认时区 |
| 农历库进浏览器包 | 它是 436KB 的未压缩源码，client 组件里 import 会整包打进去 | 只在 Server Component / 服务端函数里 import；客户端组件不碰它 |
| 每秒重算农历 | 旧版把 `now` 放进 `useMemo` 依赖，每秒跑一次 `Solar.fromYmd` | 农历、节日、进度全部服务端算好，客户端只跑时钟 |
| 冷门节日噪音 | `getOtherFestivals()` 返回国际日、纪念日等几十条 | 只取 `getFestivals()`，明令不碰 `getOtherFestivals()` |
| 节气只在当天有值 | `getJieQi()` 在非节气日返回空串（实测 2026 清明只在 4/5） | 空串就不渲染该标签；不要用「最近节气」代替 |
| 数字宽度抖动 | 1 和 8 在比例字体里宽度不同，秒数跳时整块会晃 | `tabular-nums` + `font-mono` |
| 秒级刷屏读屏 | 每秒变化的文本会被辅助技术反复播报 | 时钟容器 `aria-hidden="true"`，另给 `<time dateTime>` 语义 |
| 后台仍在跑定时器 | 旧版没有页面可见性判断，切走也每秒 setState | 监听 `visibilitychange`，隐藏时清定时器、可见时立即同步一次 |
| 农历数字格式 | 原生 `Intl` 输出「九月13日」，与中文习惯不符 | 统一交给 `lunar-javascript` 的 `getDayInChinese()`，不自己拼 |
| 农历库是 CJS 单文件 | 1.7.x 无 ESM/类型声明 | 服务端 import 即可；如遇类型报错写一个最小 `.d.ts` 声明，不要 `any` 满天飞 |
