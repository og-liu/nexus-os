# 待办清单

| 状态 | 开始日期 | 最近更新 |
|---|---|---|
| 🚧 设计中 | 2026-10-20 | 2026-10-20 |

> 一句话：把首页那张「今日待办」假卡接上真实数据——能加、能勾、能删，并给它一个看得全的工具页。

---

## 一、要什么

**做：**

- **首页常驻卡**：右栏立起「待办清单」卡，**界面逐字照搬旧界面那张**（16×16 方块、整行可点、黑底白勾、右上 `1/3` 计数），但数据来自数据库，且卡上可直接勾
- **工具页** `/tools/todo-list`：全量列表 + 顶部回车连续录入 + 行内删除 + 已完成折叠
- **落库**：新表 `todos`，每条待办归属到用户；标题上限 200 字
- **目录同步**：`tool-catalog` 里待办清单的状态从「开发中」改为「可用」
- 两处各自做三档响应式（见 2.3）

**主动放弃（本版不做，不是遗漏）：**

| 放弃项 | 原因 |
|---|---|
| 到期日 / 提醒 | 一有日期就要回答逾期怎么标、时区怎么算、要不要推送提醒；提醒还要定时任务 + 通知通道，代价远超一张卡。卡名随之从「今日待办」改成「待办清单」——不假装有日期 |
| 编辑标题 | 旧界面没有；打错字删了重加只要两步。要加就得引 `updated_at`、编辑态、`⌘Enter` / `Esc`，为一个低频操作压上一整块状态 |
| 优先级 / 标签 / 多清单 / 分组 | 都是「整理待办」的功能，不是「做待办」。优先级一旦存在，全标高优先级就等于没有优先级 |
| 拖拽排序 | 排序规则只有一条（创建时间倒序），不必存位置 |
| 单项撤销 / 回收站 | 要软删除与清理策略；原位二次确认已经把误删挡在前面 |
| 搜索 / 筛选 | 个人待办量级小，一屏扫得完 |
| 多端同步 / 分享 | 单机 SQLite、个人使用 |
| 完成时间显示 | 旧卡没有时间，工具页也不加，保持极简（`completed_at` 仍要存——它是完成状态的判据与排序依据，只是不展示） |

## 二、界面

### 2.1 首页常驻卡 `/`

**这一张卡是照搬，不是新设计。** 旧界面首页右栏第 3 张卡就是它，只是数据写死在数组里、刷新即还原。本单把它换成真数据，视觉一个字不动，只改标题。

**但首页骨架要动一下。** 现在首页只有便签卡一块真内容，它是满宽占满的（卡内 `< md` 1 列 / `md` 2 列 / `xl` 3 列）——那是「首页只剩一块内容」时的临时形态，加进第二块之后前提就不成立了：两张卡各自满宽纵向叠，待办卡只有 3 行却横跨 1360px，成了一条空荡荡的横幅。

所以本单把首页还原成旧界面的骨架——**主区 2/3 + 常驻栏 1/3**：

```
≥ xl（grid grid-cols-3 gap-4）
├─ 左 2 列（xl:col-span-2）：便签卡，卡内 md 起 2 列（宽度变小，不再需要 3 列）
└─ 右 1 列：待办卡

< xl：单列 —— 待办卡在前、便签卡在后
```

便签卡要为这张新卡让出右 1/3，是本单唯一「改已上线的东西」，理由见 §四 决策「首页骨架」。

卡片本身：

```
白卡 rounded-[2px] bg-white p-5
├─ 分组标题「待办清单」（§7.2）
├─ 右上：「管理 →」 + 完成计数「1/3」
└─ mt-3 space-y-1
   └─ 待办行（整行可点，点哪儿都能勾）
```

行内结构（逐字照旧界面）：

| 元素 | 类名 |
|---|---|
| 行 | `flex w-full items-center gap-2.5 rounded-[2px] p-2 text-left transition-colors hover:bg-[#F5F5F5]` |
| 勾选框 | `flex h-4 w-4 shrink-0 items-center justify-center rounded-[2px] border`；未完成 `border-[#D0D0D0] bg-white`，完成 `border-[#000000] bg-[#000000]` |
| 勾 | `Check h-3 w-3 text-white`（只在完成态渲染） |
| 标题 | `text-sm`；完成 `text-[#999999] line-through`，未完成 `text-[#000000]` |

- **卡片本身唯一一处对旧界面的偏离**：卡右上原本只有计数，本单在计数**左侧**补一个「管理 →」（与便签卡同款：`text-xs text-[#8A8A8A] hover:text-[#000000]` + `ArrowRight h-3 w-3`，指向 `/tools/todo-list`）。不加的话工具页没有任何入口——工具中心的卡片统一不可点。
- **计数口径是全局的**：已完成数 / 全部待办数，与卡里显示几条无关（旧界面 `1/3` 就是全部 3 条里 1 条完成）。卡里显示 3 条而计数是 `3/10` 是对的。
- **显示哪 3 条**：未完成里创建时间最新的 3 条。
- **空态分两种**（旧卡是假数据，永远有内容，所以旧界面没有空态；真数据必须有）：
  - 一条待办都没有 → 灰底块 `rounded-[2px] bg-[#F5F5F5] p-3`：「还没有待办」+「加一条 →」指向 `/tools/todo-list`。
  - 有、但全勾完了 → 同一块灰底：「都做完了」+「再加一条 →」。
- **卡上能直接勾**：点整行立即生效（Server Action），勾完该条**留在原位变灰划线**，不立刻从卡里消失（见 §四 决策「勾选后是否立即移出」）。
- 首页 `< xl` 时这张卡排在便签卡**之前**（「今天还剩什么」比「随手记」更该第一眼看到）。

### 2.2 工具页 `/tools/todo-list`

套用应用外壳，与便签工具页同构。

```
页头（PageHeader，§7.10）
├─ < md：汉堡按钮
├─ ← 返回箭头 → /tools
└─ 标题：「工具」；右侧无主操作（新建入口在内容区顶部）

内容区（px-4 py-4 md:px-6 md:py-6）
├─ 工具信息条（与工具详情页同构：黑底白图标 h-12 w-12 + 名称 / 描述 / 分类 chip / 状态点「可用」）
├─ 新建行
└─ 列表容器（max-w-[720px]）
   ├─ 白卡 p-4：未完成区（全部未完成，space-y-1） 
   └─ 同一张白卡底部：已完成折叠条（border-t border-[#F0F0F0] pt-2 分隔）
```

**新建行**（在工具页顶部，不在页头）：

```
┌────────────────────────────────────────────┐
│ ⊕  添加待办，回车保存                  [+] │
└────────────────────────────────────────────┘
```

- 输入框 `rounded-[2px] border border-[#E5E5E5] bg-white`（§7.14），左侧 `Plus` 图标 `h-4 w-4 text-[#999999]`，右侧 `+` 小主操作（`px-2.5 py-1 text-xs`）。
- **回车 = 提交**：落库、清空、**保持焦点**，可以连着敲三四条；`Esc` 清空并失焦。
- 提交中按钮 disabled，输入框忽略回车（防连按重复建条）。
- 空标题（`trim()` 后为空）不提交、不报错——什么都没输，回车等于没按。

**待办行**（行形态与首页卡完全一致，多一个删除按钮）：

- **行不能用 `<button>`**：整行可点 + 行内还有一个删除按钮，`<button>` 里嵌 `<button>` 是非法 HTML。行用 `<div>` 绑 `onClick`，删除按钮 `stopPropagation`。
- 删除按钮：`Trash2 h-3.5 w-3.5 text-[#999999] hover:text-[#000000]`，`ml-auto shrink-0`，**桌面 hover 才显、触屏常显**（与便签卡同一条规矩）。
- 删除确认：**原位二次确认**——行内容换成「删除这条待办？」+「删除 / 取消」两个小按钮，不弹全局对话框。

**已完成区**：

- 折叠条（行是按钮，不是文字）：左侧「已完成 N」（`text-xs text-[#8A8A8A]`），右侧可点区域带 `ChevronDown`（展开时转 180°）+「清除已完成」（`text-xs text-[#8A8A8A] hover:text-[#000000]`）。**默认收起**；没有已完成时整条不渲染。
- 展开后按 `completed_at DESC` 排（最近做完的在上面），行形态与未完成一致，勾选框已勾、文字灰划线；删除照旧。
- 折叠状态是纯前端 state，刷新回到收起（不落库）。

**空态**：没有任何待办 → 虚线框「还没有待办」+ 一行灰字「在上面输入框敲一条，回车保存」（§7.12）。

### 2.3 三档响应式

| 档位 | 工具页 | 首页卡 |
|---|---|---|
| 移动 < md（375 起） | 单列；页头有汉堡；信息条纵向（图标上、文字下）；新建行通栏；删除按钮**常显**；行 `py-2.5`（拇指更好按） | 单列第一块，在便签卡**之前**；最多 3 条待办行；「管理 →」保留 |
| 平板 md ~ lg | 单列；信息条仍纵向（与工具详情页同构——`lg` 起才横向）；删除按钮常显（触屏平板无 hover） | 单列（< xl），待办卡在便签卡之前 |
| 窄屏 PC lg ~ xl | 信息条横向；页头无汉堡，只剩返回箭头；删除按钮改为 hover 显示 | 同上 |
| 宽屏 ≥ xl | 列表限宽 `max-w-[720px]` 左对齐——单列列表铺满 1400px 会让视线横跨整屏，扫读反而更慢（§5.3 允许内部元素自行限宽） | 右 1/3 栏独立成卡；便签卡在左 2/3（主区 + 常驻栏，回到旧界面骨架） |

三档用互斥显隐（`hidden md:flex` / `md:hidden`）而不是 JS 断点判断——首屏 SSR 不闪（同《工具中心》）。hover 分档用 `[@media(hover:hover)]:opacity-0` + `group-hover:opacity-100`，与便签卡同一条做法。

## 三、数据模型

```sql
CREATE TABLE IF NOT EXISTS todos (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id      INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  title        TEXT    NOT NULL,
  completed_at INTEGER,                    -- 完成时刻（毫秒）；NULL = 未完成
  created_at   INTEGER NOT NULL            -- 毫秒时间戳
);

CREATE INDEX IF NOT EXISTS idx_todos_user_id ON todos(user_id);
```

设计要点：

- **不存 `done` 布尔，只存 `completed_at`**：完成状态与完成时间是同一个事实。分成两列就可能写出「`done = 1` 却没有完成时间」这种自相矛盾的行，而且没有任何约束拦得住。查询写成 `WHERE completed_at IS NULL`（未完成）/ `ORDER BY completed_at DESC`（已完成），一处真相。
- 便签的 `pinned` 反过来用布尔——因为**置顶没有「什么时候置顶的」这个需求**，而「什么时候做完的」有（决定已完成区的顺序）。同一个项目里两种写法不是不一致，是两件事的语义不同。
- **没有 `updated_at`**：本版不支持编辑标题，这一列没有写入时机，存着就是一行永远不会更新的谎话。将来加编辑，按《数据库/README》§六 的幂等 `ALTER` 补列即可。
- **`title` 上限 200 字**：服务端校验兜底（Server Action 是公开端点），客户端 `maxLength` 只是体验。超过 200 字说明它该写成便签或笔记。
- **排序**：未完成 `ORDER BY created_at DESC, id DESC`（新加的在上，刚想到的事立刻看见）；已完成 `ORDER BY completed_at DESC, id DESC`。末尾 `id DESC` 是稳定排序的兜底——毫秒会撞车。
- 表名 `todos` 与路由 `todo-list`、工具目录 slug 三处对应。

字段逐个解释与常用查询见《数据库/待办表》。

## 四、关键决策

| 决策点 | 选择 | 理由 | 否决的备选 |
|---|---|---|---|
| 首页骨架 | 恢复 **主区 2/3 + 常驻栏 1/3**（左便签、右待办） | 旧界面首页就是这个骨架；现在便签卡满宽是「首页只剩一块内容」时的临时形态，加进第二块后前提消失。待办是短行列表，天然适合窄栏；便签是块状内容，宽栏能多放 | 两张卡各自满宽纵向叠（3 行待办横跨 1360px，像横幅）；待办满宽在上、便签在下（同上，主区还是一块空地） |
| 完成状态怎么存 | 只存 `completed_at`，NULL = 未完成 | 一个事实一个地方，不可能自相矛盾；顺带白拿「什么时候做完的」 | `done` 布尔 + `completed_at` 两列（能写出坏行）；只存 `done`（已完成区没有顺序可依） |
| 首页卡标题 | 「今日待办」→「待办清单」 | 旧卡没有任何日期字段，叫「今日」是文案不是行为。真数据进来后，这个名字要么长出到期日（连带逾期 / 时区 / 提醒），要么改掉。改一个字换掉一整片复杂度，且与工具目录同名 | 加 `due_date` 保住「今日」（拖进日程工具的地盘）；保留原名（标题继续撒谎） |
| 首页卡 UI | **逐字照搬旧界面**，只改标题 | 旧界面对主人是满意的成品，这张卡已经定稿；重画等于推翻一个已验收的设计 | 按工具页的样式重做（首页上两张卡长得不一样，右栏立刻散） |
| 首页卡显示哪几条 | 未完成里最新的 3 条 | 与便签卡的「3 条封顶」同构；已完成的不占卡位——待办的价值是「还剩什么」 | 混排（旧卡假数据是 1 条已完成 + 2 条未完成混着，真数据下会让卡里长期挂着做完了的事） |
| 勾选后是否立即移出 | **不移**，原地变灰划线；刷新或重进页面才归位 | 勾一条跳一条，手指会点到下一行的位置上——连续勾选时误触率极高 | 立即重排（跳位、误勾）；等下次刷新才生效（点了没反应，像坏了） |
| 首页卡能否直接勾 | 能 | 卡就在第一屏，这张卡的用法本来就是边看边勾；只读卡会逼人为了勾一下跳到工具页 | 只读 +「去工具页处理」（多一跳，旧界面也不是这么用的） |
| 完成计数口径 | 全局：已完成数 / 全部条数 | 与旧界面 `1/3` 一致；它读作「今天的进度」，与卡里显示几条无关 | 按卡内条数算（`0/3` 会随显示内容变，像 bug） |
| 新建在哪 | 工具页顶部一条输入框，回车落库并保持焦点 | 待办常一次冒出好几条，连录的顺滑比「显式保存」值钱（与便签相反：便签长、误存代价高） | 页头「新建」按钮 + 弹窗（多两次点击，打断连录）；首页卡原地新增（卡只有 3 条位置，且首页是新用户第一屏） |
| 删除 | 行内 hover 垃圾桶 + 原位二次确认，另加「清除已完成」 | 与便签卡同一套语言（原位确认，不弹全局框）；已完成区给一个批量出口，避免清单越用越长 | 只做单项删除（已完成会永远堆着）；软删除 / 回收站（要清理策略和一处不漏的 `deleted_at` 过滤） |
| 编辑标题 | 本版不做 | 旧界面没有；打错字删了重加只要两步 | 行内点击即编辑（待办只有一行字，误触率高，且要新增编辑态） |
| 宽屏列表宽度 | `max-w-[720px]` 左对齐 | 单列列表铺满 1440px，一行要从左扫到右，比窄栏难读 | 铺满（视线跨度太大）；居中（与工具信息条、便签页的左轴对不齐） |
| 工具页要不要信息条 | 保留，状态改「可用」 | 58 个工具页同构，从列表点进来先确认「我在哪」 | 去掉（省一屏，但与其余工具页不同构） |

## 五、文件落点

结构由实现者判断（写代码的人更清楚代码），只给五条硬约束：

1. 不新增运行时依赖（`package.json` 的 `dependencies` / `devDependencies` 都不变）。图标用已装的 `lucide-react`（`Check` / `Plus` / `Trash2` / `ChevronDown` / `ArrowRight`）。
2. 表结构的唯一权威仍是 `src/lib/auth/db.ts` 的 `initSchema()`——新表加在那份 `SCHEMA` 里，不另起建表脚本、不写迁移框架。
3. `src/lib/` 下不许 import React 组件（数据访问与 Server Action 可以，视图组件不行）。
4. 路由必须落在 `src/app/(app)/tools/todo-list/`；首页改 `src/app/(app)/page.tsx`（加两栏网格）与 `src/components/dashboard/sticky-notes-card.tsx`（只去掉 `xl:grid-cols-3`，卡内 `md` 起 2 列；顺手改掉文件注释里「首页右栏」的说法——它已经回到左 2/3 了）。
5. 数据访问放在**新的领域目录** `src/lib/todos/`（不塞进 `auth/`，也不复用 `sticky-notes/`）。**首页卡与工具页共用同一个查询函数**——两处各写一条 SQL，排序规则迟早不一致。

`src/lib/sticky-notes/format.ts` **不动**：待办不显示任何时间（旧卡没有时间，工具页也不加），那套「今天 / 昨天」格式化在本功能里没有使用者。

## 六、验收标准

**正常路径**

1. 打开 `/tools/todo-list`：出现工具信息条（名称「待办清单」、状态「可用」）与空态「还没有待办」。
2. 在新建行输入「买牛奶」→ 回车 → 列表出现一行未完成；输入框清空且仍聚焦，直接敲「交电费」→ 回车 → 两条都在，**最新的在上**。
3. 点「买牛奶」这一行的任意位置（不只是勾选框）→ 勾选框变黑底白勾、文字变灰划线；行**不移动**。
4. 刷新页面：「买牛奶」进入已完成区（默认收起，折叠条显示「已完成 1」）；展开后可见，仍是勾选 + 灰划线。
5. 取消勾选 → 回到未完成区，按创建时间排在该有的位置（不是跑到最前）。
6. 首页 `/`：卡标题「待办清单」，右上计数 `1/2`，卡内显示未完成的「交电费」。
7. 在首页卡上直接勾「交电费」→ 立即变灰划线、计数变 `2/2`；该条不移出卡片。
8. 全部勾完 → 刷新首页 → 卡内显示「都做完了」+「再加一条 →」，点它进 `/tools/todo-list`。
9. 一条待办都没有 → 首页卡显示「还没有待办」+「加一条 →」。

## 七、已知的坑

| 坑 | 机制 | 对策 |
|---|---|---|
| 整行可点 + 行内删除 → 按钮嵌套 | `<button>` 里再放 `<button>` 是非法 HTML，浏览器会提前闭合外层，点击行为错乱、React 报警告 | 行用 `<div>` 绑 `onClick`；删除按钮 `stopPropagation` |
| 触屏上删除按钮永远不出现 | `group-hover` 在触屏没有 hover | 默认可见；只在 `@media (hover: hover)` 设备上收起 |
| 首页卡勾完立即消失，会跳 | 卡的数据是「未完成前 3 条」，勾完它就不再是未完成 | 本地乐观状态：勾了原地变灰、**不立即移出**；计数立刻更新；下次进页面自然归位 |
| 乐观更新与真实数据打架 | 回滚式的全量刷新会让刚勾的条目闪回未勾 | 失败时回滚到服务端返回值，不要整页 revalidate 覆盖整卡 |
| 连按回车重复建条 | 请求还在飞时用户又敲了一次 | 提交中禁用按钮、忽略重复提交 |
| 空标题绕过校验 | 全角空格、换行都不等于 `""` | 服务端 `trim()` 后判空 |
| Server Action 被直接调用 | 它是公开 HTTP 端点，`maxLength` 不是防线 | 服务端再校验：长度、非空、归属用户 |
| 毫秒撞车导致顺序不稳 | 同一毫秒内两条待办 `created_at` 相等 | 排序末尾补 `id DESC` |
| 折叠区状态刷新后丢失 | 纯前端 state | 可接受：展开是临时动作，不落库 |
| 首页漏掉登录检查 | 检查在页面里而不在 layout | 保留首页自己的 `requireUser()` |
| 演示数据残留 | 手动测过的待办会被当成真数据 | 验收结束前清掉测试行 |
