# 待办清单

| 状态 | 开始日期 | 最近更新 |
|---|---|---|
| ✅ 已上线 | 2026-10-20 | 2026-10-22 |

> 一句话：把首页那张「今日待办」假卡接上真实数据——能加、能勾、能改、能删，并给它一个看得全的工具页。

---

## 一、要什么

**做：**

- **首页常驻卡**：右栏立起「待办清单」卡，显示未完成里最新的 3 条；卡上可直接勾，勾选后**停留一拍再离场**，第 4 条自动补位
- **工具页** `/tools/todo-list`：卡片网格 + 弹窗新建 / 编辑 + 原位删除 + 已完成折叠 + 清除已完成
- **落库**：新表 `todos`，每条待办归属到用户；标题上限 1000 字
- **目录同步**：`tool-catalog` 里待办清单的状态从「开发中」改为「可用」
- 两处各自做三档响应式（见 2.3）

**主动放弃（本版不做，不是遗漏）：**

| 放弃项 | 原因 |
|---|---|
| 到期日 / 提醒 | 一有日期就要回答逾期怎么标、时区怎么算、要不要推送提醒；提醒还要定时任务 + 通知通道，代价远超一张卡。卡名随之从「今日待办」改成「待办清单」——不假装有日期 |
| 优先级 / 标签 / 多清单 / 分组 | 都是「整理待办」的功能，不是「做待办」。优先级一旦存在，全标高优先级就等于没有优先级 |
| 拖拽排序 | 排序规则只有一条（创建时间倒序），不必存位置 |
| 单项撤销 / 回收站 | 要软删除与清理策略；原位二次确认已经把误删挡在前面。勾选后的 800ms 是「撤销窗口」，不是持久化的回收站 |
| 搜索 / 筛选 | 个人待办量级小，一屏扫得完 |
| 多端同步 / 分享 | 单机 SQLite、个人使用 |
| 完成时间显示 | 卡片只显示**创建时间**；`completed_at` 仍要存——它是完成状态的判据与已完成区的排序依据，只是不展示 |

## 二、界面

### 2.1 首页常驻卡 `/`

**骨架是旧界面的**：主区 2/3 + 常驻栏 1/3；数据、创建时间与交互是本版补的。

```
当前（2026-10-22 起，过渡形态；2026-10-23 起五块统一 430px）：所有宽度都是逐块一行
├─ 日期时间面板  max-w-430px
├─ 工作日历卡    max-w-430px
├─ 待办卡        max-w-430px
├─ 便签卡        max-w-430px
└─ 每日一句卡    max-w-430px

拼图补齐后：按旧版栅格拼回去（主区 2/3 + 常驻栏 1/3）
```

卡片本身：

```
白卡 rounded-[2px] bg-white p-5
├─ 分组标题「待办清单」（§7.2）
├─ 右上：「管理 →」 + 完成计数「1/3」
└─ mt-3 space-y-1
   └─ 待办行（整行可点，点哪儿都能勾）
```

行内结构（**一条只占一行**：标题单行截断，创建时间放标题右侧）：

| 元素 | 类名 |
|---|---|
| 行 | `flex w-full items-center gap-2.5 rounded-[2px] p-2 text-left transition-colors hover:bg-[#F5F5F5]` |
| 勾选框 | `flex h-4 w-4 shrink-0 items-center justify-center rounded-[2px] border`；未完成 `border-[#D0D0D0] bg-white`，完成 `border-[#000000] bg-[#000000]` |
| 勾 | `Check h-3 w-3 text-white`（只在完成态渲染） |
| 标题 | `min-w-0 flex-1 truncate text-sm`；完成 `text-[#999999] line-through`，未完成 `text-[#000000]` |
| 时间 | `shrink-0 text-[10px] tabular-nums text-[#999999]`，`YYYY-MM-DD HH:mm`（UTC+8），在标题右侧 |

> 时间原来放在标题下面（`mt-0.5 block`），一行被撑成两行、3 条就把卡片拉得很高；2026-10-22 联调改成右侧同行。

- **卡片右上**：「管理 →」（`text-xs text-[#8A8A8A] hover:text-[#000000]` + `ArrowRight h-3 w-3`）指向 `/tools/todo-list`；计数 `text-xs tabular-nums text-[#999999]`，形如 `1/3`。
- **计数口径是全局的**：已完成数 / 全部待办数，与卡里显示几条无关（旧界面 `1/3` 就是全部 3 条里 1 条完成）。卡里显示 3 条而计数是 `3/10` 是对的。
- **显示哪 3 条**：未完成里创建时间最新的 3 条。
- **空态分两种**（真数据必须有）：
  - 一条待办都没有 → 灰底块 `rounded-[2px] bg-[#F5F5F5] p-3`：「还没有待办」+「加一条 →」指向 `/tools/todo-list`。
  - 有、但全勾完了 → 同一块灰底：「都做完了」+「再加一条 →」。
- **卡上能直接勾，勾完留一拍再走**（见 §四 决策「勾选后怎么离场」）：
  1. 点一下先原地变灰划线，计数暂时不动；
  2. 停留 800ms，期间再点一下就是撤销；连续勾选会顺延；
  3. 时间到 → 行淡出 200ms → 用 action 返回的**整块板**重新取未完成前 3 条：第 4 条自动补进来，计数在离场那一刻一起变。
- 首页 `< xl` 时这张卡排在便签卡**之前**（「今天还剩什么」比「随手记」更该第一眼看到）。

### 2.2 工具页 `/tools/todo-list`

套用应用外壳，与便签工具页同构：**没有 PageHeader**，工具名与状态在内容区的信息条里；手机上「汉堡 + 新建」住在页面顶部那一行。

```
移动端导航行（< lg）：汉堡 + 新建待办
内容区（px-4 py-4 md:px-6 md:py-6）
├─ 工具信息条（黑底白图标 h-12 w-12 + 名称 / 描述 / 分类 chip / 状态点「可用」）
│   └─ 右侧「新建待办」（≥ lg；< lg 的入口在顶部导航行）
├─ 吸顶工具栏（ToolBar，与便签页共用）
└─ 列表
   ├─ 「未完成 N」分组标题
   ├─ 卡片网格（grid-cols-1 gap-3 md:grid-cols-2 xl:grid-cols-3）
   └─ 「已完成 N」折叠区（默认收起；没有已完成时整条不渲染）
```

**新建 / 编辑弹窗**（`TodoDialog` + `TodoEditor`）：

- 标题「新建待办 / 编辑待办」，正文是一块 `textarea`（`rounded-[2px] border border-[#E5E5E5]`，自动长高，`maxLength=1000`）；
- **回车保存，`Shift + Enter` 换行**，`⌘/Ctrl + Enter` 同样保存，`Esc` 取消；
- 编辑已有待办时左下角显示「创建于 `YYYY-MM-DD HH:mm`」，接近 1000 字时与字数提示用 ` · ` 并列；
- 底部按钮：**删除**（灰底 + 错误色文字 `#B91C1C`，**只在编辑态出现**）/ 取消（灰底灰字）/ 保存（黑底白字）。待办没有「置顶保存」。
- **删除成功会弹全局提示**（2026-10-22 起）：`待办「标题摘要」已删除`（`formatDeletedMessage()`，超 24 字符截断）；桌面右下角、手机居中，3 秒自动消失（§7.13）。卡片上的删除同样会提示。
- **删除要一次确认**：点「删除」先出确认条（`删除后无法恢复，确定删除这条待办？` + 「取消」/「确认删除」），确认后才真删并关闭弹窗；删除不可撤销（不做撤销 Toast）。

**待办卡片**（`TodoTile`，96px 高，与便签卡同一套语言）：

- 白卡固定高度、hover 出黑描边；点卡片正文 = 编辑弹窗；
- **勾选框是独立按钮**，点它只切换完成态、不打开编辑；
- 左下角是创建时间；删除按钮在右上角，桌面 hover 才显、触屏常显；
- 删除走**原位二次确认**：卡片内容换成「删除这条待办？」+「删除 / 取消」，不弹全局对话框；
- 勾选后卡片先变灰划线，800ms 后原地收起（网格行高 + 淡出，200ms），再从「未完成」移入「已完成」；离场中的卡片不可再点。

**已完成区**：

- 分组标题「已完成 N」（§7.2）+ `ChevronDown`（展开转 180°）+「清除已完成」；**默认收起**；
- 展开后是同一个卡片网格，按 `completed_at DESC` 排（最近做完的在前），卡片已勾、文字灰划线；删除照旧；
- 「清除已完成」走原位二次确认，不弹全局对话框；
- 折叠状态是纯前端 state，刷新回到收起（不落库）。

**空态**：没有任何待办 → 虚线框「还没有待办」+「新建待办」按钮（§7.12）；只有已完成时，未完成区不渲染、已完成区仍在。

**勾选节奏（工具页与首页卡共用）**：

1. 勾选后立刻给回执（黑勾 + 灰划线），卡片留在原位；
2. 停留 800ms（`TODO_LEAVE_DELAY_MS`）——期间再点一下是撤销，连续勾选会重置计时器（batch）；
3. 时间到 → 卡片收起 / 行淡出 200ms（`TODO_LEAVE_ANIMATION_MS`），动画结束后才真正移入已完成；「未完成 / 已完成」两个计数在这一刻一起变；
4. 离场中的卡片 / 行禁用；已完成区取消勾选仍然立刻归位；
5. `prefers-reduced-motion` 下过渡不做动画，但节奏不变。

### 2.3 三档响应式

| 档位 | 工具页 | 首页卡 |
|---|---|---|
| 移动 < md（375 起） | 单列；顶部导航行有汉堡 + 新建；信息条纵向；卡片删除按钮**常显** | 单列第一块，在便签卡**之前**；最多 3 条待办行；「管理 →」保留 |
| 平板 md ~ lg | 两列；信息条仍纵向；删除按钮常显（触屏平板无 hover） | 单列（< xl），待办卡在便签卡之前 |
| 窄屏 PC lg ~ xl | 信息条横向；顶部导航行收起；新建在工具信息条右侧；删除按钮改为 hover 显示 | 同上 |
| 宽屏 ≥ xl | 三列；内容间距放大到 `xl:space-y-6` | 右 1/3 栏独立成卡；便签卡在左 2/3 |

三档用互斥显隐（`hidden lg:flex` / `lg:hidden`）而不是 JS 断点判断——首屏 SSR 不闪（同《工具中心》）。hover 分档用 `[@media(hover:hover)]:opacity-0` + `group-hover:opacity-100`，与便签卡同一条做法。

## 三、数据模型

```sql
CREATE TABLE IF NOT EXISTS todos (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id      INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  title        TEXT    NOT NULL,
  completed_at INTEGER,                    -- 完成时刻（毫秒）；NULL = 未完成
  created_at   INTEGER NOT NULL            -- 毫秒时间戳
);

CREATE INDEX IF NOT EXISTS idx_todos_user_id ON todos(user_id);
```

设计要点：

- **不存 `done` 布尔，只存 `completed_at`**：完成状态与完成时间是同一个事实。分成两列就可能写出「`done = 1` 却没有完成时间」这种自相矛盾的行，而且没有任何约束拦得住。查询写成 `WHERE completed_at IS NULL`（未完成）/ `ORDER BY completed_at DESC`（已完成），一处真相。
- **便签的 `pinned` 与 `pinned_at`** 是另一种情况：置顶既有「是不是」，也有「什么时候置顶的」的排序需求，所以它现在也是双列；两列只在 `setNotePinned` 一处一起写。
- **没有 `updated_at`**：编辑标题走弹窗，但本版不展示「最后编辑时间」；存一列永远不会被读的 `updated_at` 是谎话。将来需要时按《数据库/README》§六 的幂等 `ALTER` 补列即可。
- **`title` 上限 1000 字**：服务端校验兜底（Server Action 是公开端点），客户端 `maxLength` 只是体验；与便签正文同档。
- **排序**：未完成 `ORDER BY created_at DESC, id DESC`（新加的在上，刚想到的事立刻看见）；已完成 `ORDER BY completed_at DESC, id DESC`。末尾 `id DESC` 是稳定排序的兜底——毫秒会撞车。
- 表名 `todos` 与路由 `todo-list`、工具目录 slug 三处对应。

字段逐个解释与常用查询见《数据库/待办表》。

## 四、关键决策

| 决策点 | 选择 | 理由 | 否决的备选 |
|---|---|---|---|
| 首页骨架 | **过渡形态：逐块一行**（2026-10-23 起五块统一 430px：面板 → 工作日历 → 待办 → 便签 → 每日一句，所有宽度单列） | 2026-10-22 联调推翻 10-20 的「主区 2/3 + 常驻栏 1/3」：拼图只有四五块时，硬拼成一行每块都被挤窄。等拼图补齐再按旧版栅格拼回去，尺寸口径已对齐参考图 | 恢复「主区 2/3 + 常驻栏 1/3」（10-20 的旧决策，三块挤一行的版本被联调否掉）；两张卡各自满宽纵向叠（3 行待办横跨 1360px，像横幅） |
| 完成状态怎么存 | 只存 `completed_at`，NULL = 未完成 | 一个事实一个地方，不可能自相矛盾；顺带白拿「什么时候做完的」 | `done` 布尔 + `completed_at` 两列（能写出坏行）；只存 `done`（已完成区没有顺序可依） |
| 首页卡标题 | 「今日待办」→「待办清单」 | 旧卡没有任何日期字段，叫「今日」是文案不是行为。真数据进来后，这个名字要么长出到期日（连带逾期 / 时区 / 提醒），要么改掉。改一个字换掉一整片复杂度，且与工具目录同名 | 加 `due_date` 保住「今日」（拖进日程工具的地盘）；保留原名（标题继续撒谎） |
| 首页卡显示哪几条 | 未完成里最新的 3 条 | 与便签卡的「3 条封顶」同构；已完成的不占卡位——待办的价值是「还剩什么」 | 混排（旧卡假数据是 1 条已完成 + 2 条未完成混着，真数据下会让卡里长期挂着做完了的事） |
| 首页卡怎么补位 | 离场后用 action 返回的**整块板**取前 3 条 | 首页初始只拿 3 条，勾掉一条后第 4 条不在本地；服务端 action 返回全量 open，`slice(0, 3)` 就是新的「最新 3 条」 | 首页一次查全量（首页是摘要，没必要）；只查 4 条（连续勾选时补不满） |
| 勾选后怎么离场 | **留一拍，再走**：800ms 停留（可撤销）→ 200ms 收起 / 淡出 → 移入已完成 | 立即移走会吞掉「勾上了」的回执，也会在连续勾选时让行在指针下面跳；一直不移又会让列表越来越不真实 | 立即重排（跳位、误勾）；等刷新才归位（点了没反应，像坏了） |
| 连续勾选怎么办 | 计时器重置（debounce），批量一起离场 | 手还在点时行不动；停下之后一次结算，视觉上更安静 | 每张卡各走各的计时器（连续勾选时行会在手边陆续消失） |
| 计数什么时候变 | 离场那一刻一起变（未完成 -1、已完成 +1） | 卡片还在原位时它仍属于「未完成」；同一刻改两个数，不会出现「卡还在列表里、计数已经算完成」的矛盾 | 勾选瞬间就改计数（短暂双算）；完全不改（用户以为没生效） |
| 新建 / 编辑在哪 | **弹窗**（`TodoDialog`） | 与便签一致；待办也可能写成一段，1000 字以内需要空间；弹窗把编辑态与列表分开，列表高度不跳 | 页头「新建」+ 页内输入行（要另做一套编辑态，和便签不一致）；卡片原地展开（撑高卡片） |
| 删除 | 原位二次确认 +「清除已完成」 | 与便签卡同一套语言（原位确认，不弹全局框）；已完成区给一个批量出口 | 只做单项删除（已完成会永远堆着）；软删除 / 回收站（要清理策略和一处不漏的 `deleted_at` 过滤） |
| 完成时间显示 | 不显示 | 卡片只承担「还剩什么」；已完成区按完成时间排序，但不需要把时间印在卡上 | 卡片上显示完成时间（信息变密，且与创建时间抢位置） |
| 工具页要不要信息条 | 保留，状态「可用」 | 58 个工具页同构，从列表点进来先确认「我在哪」 | 去掉（省一屏，但与其余工具页不同构） |

## 五、文件落点

1. 不新增运行时依赖（`package.json` 的 `dependencies` / `devDependencies` 都不变）。图标用已装的 `lucide-react`（`Check` / `Plus` / `Trash2` / `ChevronDown` / `ArrowRight`）。
2. 表结构的唯一权威仍是 `src/lib/auth/db.ts` 的 `initSchema()`——新表加在那份 `SCHEMA` 里，不另起建表脚本、不写迁移框架。
3. `src/lib/` 下不许 import React 组件（数据访问与 Server Action 可以，视图组件不行）。
4. 路由必须落在 `src/app/(app)/tools/todo-list/`；首页改 `src/app/(app)/page.tsx`（两栏网格）与 `src/components/dashboard/sticky-notes-card.tsx`（卡内 `md` 起 2 列）。
5. 数据访问放在**独立领域目录** `src/lib/todos/`：`todos.ts`（数据访问）、`validate.ts`（校验）、`actions.ts`（Server Actions）、`leave.ts`（首页卡与工具页共用的离场节奏）；首页卡与工具页共用同一个查询函数。

`src/lib/format.ts` 是共享的时间格式化（`formatDateTime`，UTC+8）；待办卡片与便签卡共用这一份。

## 六、验收标准

**正常路径**

1. 打开 `/tools/todo-list`：出现工具信息条（名称「待办清单」、状态「可用」）；没有待办时显示「还没有待办」空态。
2. 点「新建待办」→ 弹窗；输入「买牛奶」→ 回车 / 点「保存」→ 列表出现一张卡片，卡片上同时显示标题与创建时间（分钟级）；弹窗关闭。
3. 点卡片正文 → 编辑弹窗，左下角显示「创建于 …」；改成「买牛奶（两盒）」→ 保存 → 卡片更新；再打开改回并按 `Esc` → 数据库不变。
4. 输入 1000 字保存成功；1001 字被服务端拒绝（弹窗内给出提示，行数不变）。

## 七、已知的坑

| 坑 | 机制 | 对策 |
|---|---|---|
| 勾选后立即移出会让手指点到下一行 | 列表在指针下方重排 | **留一拍再走**：800ms 停留 + debounce；连续勾选时行不动 |
| 首页只拿到 3 条，勾掉后没有第 4 条 | 初始数据是限量查询 | 用 action 返回的整块板取 `open.slice(0, 3)` 补位 |
| 卡片 / 行离场后键盘焦点落回 body | 被移除的元素持有焦点 | 已知未处理；需要时把焦点移到下一张卡或「未完成」标题 |
| 勾选后 800ms 内打开删除确认，卡片仍会离场 | 离场计时器不感知确认态 | 已知未处理；避免在离场窗口内删除已勾选的卡片（可在已完成区删） |
| 触屏上删除按钮永远不出现 | `group-hover` 在触屏没有 hover | 默认可见；只在 `@media (hover: hover)` 设备上收起 |
| `pending` 把整卡 / 头部按钮变半透明 → 闪烁 | 卡片和「新建」按钮曾带 `disabled:opacity-50`，动作几十毫秒内来回切 | 卡片与工具头部按钮去掉这层变暗，`disabled` 逻辑保留 |
| 乐观更新与真实数据打架 | 全量刷新会让刚勾的条目闪回未勾 | 失败时只回滚这一行；离场时才用服务端板替换列表 |
| 连点保存 / 回车重复建条 | 请求还在飞时用户又提交了一次 | 提交中禁用按钮、忽略重复提交 |
| 空标题绕过校验 | 全角空格、换行都不等于 `""` | 服务端 `trim()` 后判空 |
| Server Action 被直接调用 | 它是公开 HTTP 端点，`maxLength` 不是防线 | 服务端再校验：长度、非空、归属用户 |
| 毫秒撞车导致顺序不稳 | 同一毫秒内两条待办 `created_at` 相等 | 排序末尾补 `id DESC` |
| 折叠区状态刷新后丢失 | 纯前端 state | 可接受：展开是临时动作，不落库 |
| 首页漏掉登录检查 | 检查在页面里而不在 layout | 保留首页自己的 `requireUser()` |
| 演示数据残留 | 手动测过的待办会被当成真数据 | 验收结束前清掉测试行 |
