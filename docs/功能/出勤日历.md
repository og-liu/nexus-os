# 工作日历

| 状态 | 开始日期 | 最近更新 |
|---|---|---|
| 🚧 设计中 | 2026-10-23 | 2026-10-23 |

> 一句话：一张月历，把「这天到底上不上班」按**周六制度（单休 / 双休 / 单双休）**自动推出来，公司跟制度对不上的日子由主人自己点一下覆盖；首页有一块本月紧凑月历，打开就能看到今天和这周的状态。

命名约定：中文「工作日历」（2026-10-23 由「出勤日历」改名），代码标识仍是 `attendance-calendar`——slug、路由、表名、文件名都没跟着中文名改；首页那块叫「工作日历卡」（`attendance-card`），工具页叫「工作日历页」。

---

## 一、要什么

**需求原文**（ogliu 2026-10-23）：

> 我公司是单双休机制，另外加上各种节假日可能还会调休，也就是说星期六、星期天到底上不上班，我总是记不住，每周都要去问同事。能不能做一个工具来做记录，让我打开 Nexus OS 一眼就能看到，休息还是上班？

**做：**

- **月历视图**：周一起始、7 列、固定 42 格（6 行），一屏看完一个月
- **每格显示**：日期数字 + 农历/节日名（工具页）+ 状态角标「班 / 休」（两档都挂）
- **周六制度自动推算**：设置里选「单休」「双休」或「单双休（大小周）」，**全年周六按它算**，不用一周周录；单双休要指定从哪一周起算（本周单休还是双休）
- **手动覆盖**：任意一天可以点成「上班」或「休息」，**优先级最高**——改了就一直是它，换制度也冲不掉
- **一键还原**：覆盖掉的日期可以选「跟随自动」，回到推算值
- **首页工作日历卡**：本月紧凑月历（日期 + 班/休角标 + 今天圆点）；**点某一格可当场改这一天的状态**（快捷操作），「管理 ›」进工具页
- **工具中心登记**：作为一个独立工具出现在 `/tools`（`attendance-calendar`，分类「生活」），走显式路由 `/tools/attendance-calendar`——总览卡只是它的展示面，不是它的全部
- **工具页控件**：年切换、月切换、「今天」按钮、点某天改状态、周六制度设置

**不做（主动放弃，附原因）：**

| 放弃项 | 原因 |
|---|---|
| 全国法定节假日 / 调休数据（第三方 API） | 公司不按国家安排放假，导进来反而是噪音。国定假期那几天，主人自己点成「休」——一年十几个动作，比维护一条数据通道便宜得多。这一条是主人 2026-10-23 明确砍掉的 |
| 节假日放假天数、调休补班、假期余额 | 属于 HR 系统的范畴，与「这天去不去」无关；塞进来会让一张月历变成排班表 |
| 打卡、工时、迟到早退、请假 | 同上 |
| 消息提醒 / 每天早上推一句 | 需求是「打开就能看到」，不是「被通知」；且需要常驻进程（本项目现在没有） |
| 农历节日以外的国际日、纪念日 | `getOtherFestivals()` 一天几十条（「国际地雷行动日」这种），进月历就是噪音。《日期时间面板》已因同一原因排除过 |
| 跨月视图（一次显示两个月）、周视图、日程视图 | 首版只要「这个月哪几天休」，多视图会把组件撑成通用日历库 |
| 多人共享 / 团队排班 | 每个账号各存各的，公司统一的排班表不做 |

## 二、界面

### 2.1 两个入口，两种密度

同一份数据，两处展示，**密度不同、职责不同**：

| 位置 | 路由 | 密度 | 能做什么 |
|---|---|---|---|
| 首页工作日历卡 | `/` | 紧凑：日期数字 + 班/休角标 + 今天圆点 | 看 + **改某一天**（快捷操作）；年月切换、制度设置不出现，跳工具页 |
| 工作日历页 | `/tools/attendance-calendar` | 完整：日期 + 农历/节日 + 休/班双角标 + 年月切换 + 今天 | 看 + 改 + 管（切年月、设单休/双休/单双休、清制度） |

**分工口径与便签 / 待办一致**：总览卡是「展示 + 高频小动作」，管理动作跳工具页——待办卡能直接勾、便签卡能直接删，但「加待办」「新建便签」这类动作在卡上只是一行入口。工作日历卡同理：**改一天是高频小动作，留在卡上；切年月、设周六制度、清制度是低频管理动作，只在工具页**。它是工具目录里的一个独立工具（`attendance-calendar`，分类「生活」），不是总览页的附属块。

**为什么拆两档**：卡片宽 430px，7 列每格约 56px（手机上 43px），放得下日期数字和一个小角标，放不下农历小字和节日名（那要每格约 120px，只有整页有）。主人最初给的参考截图是**整页**形态，先说明这个落差，避免做完被问「为什么首页卡不像图里那样」。

### 2.2 首页工作日历卡

宽度 `max-w-[430px]`，与待办卡 / 便签卡 / 每日一句卡同宽；屏窄于 430 时满宽。**插在日期时间面板之后、待办卡之前**——它是「今天」的即时信息，跟面板同属页头级信息。

```
┌────────────────────────────────┐
│ 工作日历                 管理 › │
│ 今天 周五 · 休息                 │
│                                │
│  一  二  三  四  五  六  日      │
│  5班 6班 7班 8班 9班 10班 11休 │
│  12班 13班 14班 15班 16班 17班 18休│
│  19班 20班 21班 22班 23班• 24休 25休│
│  26班 27班 28班 29班 30班 31班  1休│
└────────────────────────────────┘
```

- 角标两态：**班**（黑底白字）/ **休**（浅灰底灰字）。默认制度（单双休）自动生效，所以不会出现「未定」

- 标题行：「工作日历」`text-sm font-medium`；右侧「管理 ›」`text-xs text-[#666666]`（与便签卡的「管理 →」同一模式），点它进 `/tools/attendance-calendar?ym=<卡片当前月份>`
- 第二行：`今天 周五 · 休息` —— `text-xs text-[#8A8A8A]`，「休息 / 上班」用全对比黑字
- **快捷操作**：点任意日期格 → 弹出与工具页完全相同的状态弹层（§2.4），可直接改这一天；改完本卡与工具页读的是同一份数据
- **卡片上不出现**：年月切换、「今天」按钮、制度设置、清制度——这些是管理动作，只在工具页
- 整卡不再「点哪都跳」：因为格子里有真实操作，跳转只能靠「管理 ›」，否则点格子想改状态却跳走了
- 月历表头：7 个单字星期 `一 二 三 四 五 六 日`，`text-[10px] text-[#999999]`，居中
- 格子几何与工具页同一套：白格 + `border-[#F0F0F0]` 细网格线（容器画左/上边，格子画右/下边，相邻格只 1px）
- 日期格：`text-xs`（手机 `text-[11px]`），靠左上 `pl-1 pt-0.5`
- **每格都挂状态角标**（右上角）：上班 → 黑底白字「班」；休息 → 浅灰底灰字「休」。没设过制度时走内置默认（单双休），所以不会空着
- 今天：格子**右下角一个 1.5px 黑圆点**（2026-10-23 联调把 2px 黑框换掉——框在两个月的交界处太抢眼），不加「今」字（放不下第二个元素）
- 跨月（补齐的上月末 / 下月初）：日期 `text-[#D0D0D0]`，但**照样按制度挂「休」**——42 格都是真日子，只有日期灰一档做区分
- 整卡高度：表头 + 6 行 × 28px + 标题区 + 内边距 ≈ **275px**，**任何月份都一样**（42 格固定）

**为什么是角标而不是整格底色**（2026-10-23 联调改的）：上一版是「整格黑底 = 上班、浅灰 = 休息」，做完一看，工作日连成一条黑杠，主人原话「这也太丑了吧，黑一片」。改成与工具页同一套「白格 + 右上角小角标」，班 / 休 都标（主人后来补了一句「总览的UI界面上班的『班』字标识还是带上吧」）——黑白里去色之后，小角标是唯一不糊成一片的做法。

### 2.3 工作日历页

**版式与便签 / 待办两个工具页完全一致**（2026-10-23 联调第四轮改的）：

1. 手机一行 `ToolMobileBar`（汉堡 + 主操作「今天」）；桌面同一个动作住在 `ToolHeader` 右侧——
   和便签页「汉堡 + 新建便签 / 右侧新建便签」是同一套排法。**不再有 `PageHeader`**：
   上一版用了「‹ 工具 + 返回」的页头，跟别的工具页长得不一样，被主人一眼看出来。
2. `ToolHeader`：图标块 + 「工作日历」+ 描述 + 分类「生活」/ 状态「可用」。
3. 内容区两栏（≥ xl）：**左**工具栏 + 表头 + 月历，占满剩余宽度（整页外框 `max-w-[1360px]` 居中）；
   **右** 300px 侧栏放概览与图例。
   - 上一版限宽 820px 左对齐，1440px 屏幕上右边空一大片（主人原话「大屏幕的时候全部堆在左边」）。
   - 小屏单列，顺序「概览 → 图例 → 日历」——宽度不够时概览与图例在上面、日历详情在下面
     （2026-10-23 联调主人要求）；说明跟着图例走，不用滚到页面最底部才看见。
4. **主区一张白卡包住「工具栏 + 表头 + 月历」**：只把月历留白、工具栏与表头落在页面灰底上时，
   中间那一横条像被掏空（2026-10-23 联调主人指出「中间镂空不好看」），连成一片才是一个完整的日历。
5. 概览按**卡片自己**的宽度排（容器查询 `@container`）：
   - 窄卡片（手机、右栏 300px）：**一行一条**「标签 …… 值」，三行就够；
     上一版是「标签一行 + 值一行」，六行把手机屏幕吃掉一半（2026-10-23 联调主人要求压缩）；
   - 宽卡片（平板单列时约 900px）：`@lg` 起转成三列，标签在上、值在下。
   用视口断点会犯「窗口宽、卡片窄却排三列」的错。
6. 图例：班 / 休 / 今天（右下角圆点）/ 手动改过（日期下方小横条）四个小样 + 一行操作说明——今天与「改过」的标记形状不同，一眼能分开。
7. 工具栏的药丸用 `#F5F5F5`：它现在住在白卡里，按 §2.1「白卡内部的内嵌块用 `#F5F5F5`」的规则。
   （中间那一版工具栏在灰底页面上，药丸也是 `#F5F5F5`，糊成一色——主人提过；包进白卡后就没这个问题了。）

```
┌──────────────────────────────────────────────────────────────┐
│  ‹ 2026 年 ›        ‹ 10 月 ›                          设置   │
│                                                              │
│    一      二      三      四      五      六      日         │
│  ┌──────┬──────┬──────┬──────┬──────┬──────┬──────┐          │
│  │  28  │  29  │  30  │  1   │  2   │  3   │  4   │          │
│  │ 十八 │ 十九 │ 二十 │国庆节│ 廿二 │ 廿三 │ 廿四 │          │
│  └──────┴──────┴──────┴──────┴──────┴──────┴──────┘          │
│  …（6 行）…                                                   │
└──────────────────────────────────────────────────────────────┘
```

| 元素 | 规格 |
|---|---|
| 工具栏 | 一行：年切换（`‹ 2026 年 ›`）、月切换（`‹ 10 月 ›`）、右侧「设置」文字按钮（配 `Settings2` 图标，`h-3.5 w-3.5`）；药丸 `bg-[#F5F5F5]`、hover `bg-[#ECECEC]`（白卡内部的内嵌块，§2.1）。主操作「今天」不在这里——桌面在 `ToolHeader` 右侧、手机在顶栏（与便签 / 待办同构） |
| 表头 | `一 二 三 四 五 六 日`，`text-xs text-[#8A8A8A]`，居中，`pb-2` |
| 格子 | `min-h-[76px]`，白底，格子之间 `border border-[#F0F0F0]`（细网格），`p-2`，内容左对齐靠上 |
| 日期 | `text-base tabular-nums`；休息日 `text-[#666666]`，上班日 `text-[#000000]` |
| 农历/节日行 | 日期下方 `text-[10px] text-[#999999]`，**只有一行**，放不下就 `truncate` |
| 角标 | 格子右上角 `absolute top-1 right-1`：休 → `bg-[#F5F5F5] text-[#666666]`；班 → `bg-[#000000] text-white`；`text-[10px] px-1` |
| 已改标记 | 手动覆盖的日期，日期数字下方补一根 `h-1 w-3 rounded-full bg-[#000000]` **小横条**，鼠标悬停 `title="已手动调整"`。用横条不用圆点：今天已经在格子右下角占了一个黑圆点，两个黑点分不清谁是谁（2026-10-23 联调主人指出） |
| 今天 | 日期旁「今」`text-[10px]` + 格子**右下角 `h-1.5 w-1.5` 黑色圆点**（2026-10-23 联调：2px 黑框太抢眼，换成圆点） |
| 整月高度 | 42 格 × 76px + 表头 + 工具栏 ≈ **560px**，恒定 |

**为什么现在又把整块包进白卡**：初版不给月历包白底，理由是「格子本身已是白底网格，再套一层是卡里套卡」。但那是**只有月历**时的判断；工具栏与表头加进来之后，它们落在页面灰底上、月历是白的，中间那一条就成了「镂空」——2026-10-23 联调主人指出来后才改成「工具栏 + 表头 + 月历」整体一张白卡，视觉上是一个完整的日历，而不是卡里套卡。

### 2.4 点某天：状态弹层

点任意格子 → 小弹层（`rounded-[2px] bg-white p-3`，锚定在被点的格子下方）：

```
┌─────────────────────────────┐
│ 10月24日 周六 · 农历九月十五   │
│ [上班]  [休息]  [跟随自动]     │
└─────────────────────────────┘
```

规则（这一节是整份文档最关键的交互契约）：

| 点的是哪一天 | 三个按钮的含义 |
|---|---|
| **任何一天（含周六）** | 「上班 / 休息」= 写 `attendance_overrides`，**只改这一天** |
| **任何一天** | 「跟随自动」= 删掉这天的覆盖行，回到推算值（周六按制度、其余按星期） |
| **任何一天** | 「上班 / 休息」如果点的正好是**推算值**，等价于「跟随自动」：不写覆盖、已有的覆盖删掉（见下） |
| **想改全年** | 不在弹层里改，走「设置」里的周六制度（§2.5） |

- 按钮当前命中哪个状态，该按钮就是黑底白字（`bg-[#000000] text-white`），其余灰底（`bg-[#F5F5F5] text-[#666666]`）
- **没有「还没设置」这一步**：没设过制度时走内置默认（单双休），界面直接有答案，所以这一版删掉了首版那条「还没选周六制度」的提示条
- **覆盖永远最优先**：改了就一直是它，之后换制度也冲不掉（2026-10-23 联调时主人的原话：「就算重新选择了双休，单休逻辑有冲撞，也是手动改的最优先」）

**点回推算值等于「跟随自动」**（2026-10-23 联调修的 bug）：上一版不管点什么都写一行覆盖，
于是「改成班 → 再改回休」之后库里还留着一条等于推算值的覆盖，界面上那根「已手动调整」
小横条一直挂着，主人以为没改回去。现在 `setDayStatusAction` 先算一遍「不看覆盖」的推算值，
选的就是它 → 删覆盖，不再写。

**为什么弹层里没有「只改这一天」勾选框**（2026-10-23 联调删掉）：上一版让「点周六」默认承载「设定整周类型」，所以需要一个勾选框区分两种语义。现在「全年怎么排」由设置里的制度决定，周六就没有第二种含义了——同一件事留着两个入口会互相打架。

### 2.5 周六制度设置

工具栏最右侧一个「设置」文字按钮（`text-xs text-[#666666]`），弹出：

```
┌────────────────────────────────────────┐
│ 周六制度                                │
│  [单休]  [双休]  [单双休]                │
│  单休 = 每周六上班；双休 = 每周六休息；    │
│  单双休 = 单休周与双休周交替（大小周）      │
│                                        │
│  （只有选中「单双休」时多这一行）           │
│  本周（10月19日–25日）是：               │
│  [单休周]  [双休周]                      │
│                                        │
│ [保存]  [恢复默认]                      │
│ 恢复默认 = 单双休（大小周）；手动改过的      │
│ 日子不受影响。                            │
└────────────────────────────────────────┘
```

- **单休**：每个周六都算上班；**双休**：每个周六都算休息。周日、周一~周五不受影响
- **单双休（大小周）**：单休周与双休周交替（主人原话「本周单休，下周就双休」）
- **问题永远问「本周」**：面板显示的是这一周（周一到周日）的日期范围，不管上次是多久以前设的。
  主人 2026-10-23 的原话：「如果过了很久很久之后来调整，他还是显示 10 月 24 日？我早都不记得那天上不上班了啊」
  —— 问「上周刚过完的那一周」谁都答得上来，问「三个月前某个周六」没人答得上来
- **默认值 = 按当前制度推算出来的本周六状态**：所以「不改直接保存」相位不跳；
  没设过制度时默认「单休周」
- **保存时锚点重设到本周**（存的是本周六 + 本周类型）。锚点只是实现细节：
  它让「历史与未来」的单双周都由同一个起点算出来，用户永远只需要回答「这周是哪种」
- **默认制度**：没设过制度时按内置默认算——单双休，从 `2026-10-24` 那一周起是双休周。所以新账号打开就有答案，不会出现「未定」；数据库里没有行 ≠ 界面上没有制度
- **面板默认选中 = 当前生效的制度**：没设过时就是「单双休 + 本周双休周」，主人原话「默认激活单双休、10月19日–25日是双休周」
- 「恢复默认」→ 删掉 `attendance_settings` 那一行，回到内置默认制度；已有的手动覆盖**保留**（它们照样生效）
- 选中态：命中当前制度的那颗按钮黑底白字，其余灰底

### 2.6 响应式

| 断点 | 工作日历页 | 首页工作日历卡 |
|---|---|---|
| ≥ 1024px | 7 列全宽版：格高 76px，日期 `text-base`，农历/节日显示 | 430px，格高 28px，只有日期 + 角标 |
| 640–1023px | 同上，格高收到 68px；农历/节日保留 | 430px 或满宽（< 430 时） |
| < 640px（手机） | 格高 56px；**农历/节日行隐藏**，只留日期 + 角标；角标缩小到 `text-[9px]`；工具栏「今天」缩成图标按钮 | 满宽，格高 26px |

- 手机端**不隐藏功能，只隐藏次要信息**（农历/节日）：工具页点开弹层仍能看到农历与节日全名；**首页卡的弹层只有日期 + 星期**（首页卡不算农历，省掉 42 次换算——要看农历从「管理 ›」进工具页）
- 首页卡在手机上满宽（卡片 343px、内容宽 303px），7 列每格 43px，日期 `text-[11px]`

## 三、数据模型

两张表，都按 `user_id` 隔离。

```sql
CREATE TABLE IF NOT EXISTS attendance_settings (
  user_id         INTEGER PRIMARY KEY REFERENCES users(id) ON DELETE CASCADE,
  saturday_mode   TEXT    NOT NULL CHECK (saturday_mode IN ('work', 'off', 'alternate')),
  anchor_saturday TEXT,                    -- 仅 'alternate' 用：交替从哪个周六起算
  anchor_is_work  INTEGER CHECK (anchor_is_work IN (0, 1)),
  created_at      INTEGER NOT NULL,
  updated_at      INTEGER NOT NULL,
  -- 交替模式必须带锚点；单休 / 双休时两列为 NULL
  CHECK (saturday_mode <> 'alternate'
         OR (anchor_saturday IS NOT NULL AND anchor_is_work IS NOT NULL))
);

CREATE TABLE IF NOT EXISTS attendance_overrides (
  user_id    INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  day_key    TEXT    NOT NULL,                         -- 'YYYY-MM-DD'
  status     TEXT    NOT NULL CHECK (status IN ('work', 'off')),
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  PRIMARY KEY (user_id, day_key)
) WITHOUT ROWID;
```

**设计要点**

| 列 / 约束 | 为什么长这样 |
|---|---|
| `saturday_mode` 存三个字面量 | 说的是「周六这一天算不算上班」，不是制度名：`'work'` = 单休（周六上班）、`'off'` = 双休（周六休息）、`'alternate'` = 单双休（大小周）。`CHECK` 钉死三个值，写不进第四种 |
| `anchor_saturday` / `anchor_is_work` 可空 | 只有单双休需要「从哪一周起算、那一周算哪种」。表级 `CHECK` 保证：选了 `alternate` 就必须带锚点，单休 / 双休时两列必须是 NULL（不给没在用的数据留位置） |
| `user_id` 同时是主键 | 一个人只有一份制度；换制度就 `UPSERT` 覆盖，不会堆出第二行 |
| `attendance_settings.updated_at` | 有这个写入路径：换制度时确实会改 |
| `attendance_overrides` 复合主键 | 「某人的某一天」天然唯一；`WITHOUT ROWID` 省掉一层索引，查询键就是主键本身 |
| `day_key` 用 TEXT 不存时间戳 | 这是一**天**不是一个**时刻**；`'2026-10-24'` 可读、能 `BETWEEN '2026-10-01' AND '2026-10-31'` 一次捞整月，也不会因为时区换算漂到前一天 |
| **没有 `note`（备注）列** | 2026-10-24 删掉了。原因：这列建出来却没有任何写入路径（弹层里没有备注输入框），永远是 `NULL`，而文档还写着「带备注的日子显示小字」——一个永远为空的列 + 一句不成立的话，比没有这个功能更糟。真要备注时再加：那时得先定清楚它是「给自己看的」还是「说明给别人看的」，两条路的长度限制与显示位置都不一样 |
| 不给 `status` 存 `'auto'` | 「跟随自动」= 这行不存在。用一个字符串表达「没有这条记录」，查询时到处要额外判断 |
| 锚点为什么不复用「今天的周」 | 每次读取都拿「今天」当起点，排出来的单双周会随着日子往前走而漂移；必须存一个固定的周六当锚点 |
| 为什么表里可以「没有行」 | 没设过 ≠ 没有制度：`resolveDayStatus` 用 `DEFAULT_SETTING` 兜底。表里有没有行只影响「能不能改」，不影响「界面上有没有答案」 |

**老库怎么跟上**：已经跑过这一版的库里，`attendance_overrides` 是带 `note` 列建的。`initSchema()` 里追加一条**幂等**迁移：`PRAGMA table_info(attendance_overrides)` 里看到 `note` 就 `ALTER TABLE attendance_overrides DROP COLUMN note`；看不到就什么都不做。用 SQLite 3.35+ 的 `DROP COLUMN`（better-sqlite3 12 内置的版本远高于它），`note` 既不是主键也不是索引列，删它不影响 `WITHOUT ROWID` 与复合主键。查库语句也一并去掉这个列名（`SELECT` 明确列出来，不写 `SELECT *`），否则老库能跑、新库直接报「no such column」。

**推算函数**（`lib/attendance/schedule.ts`，纯函数）：

```
输入：dayKey（'YYYY-MM-DD'）、setting（可空）、override（可空）

0. setting 为空                      → 用 DEFAULT_SETTING（单双休、2026-10-24 那周双休）
1. override 有值                    → 用它（source: "manual"）——永远最优先
2. 周六：
   - 单休 / 双休                    → setting.saturdayMode（source: "saturday-mode"）
   - 单双休                        → 与 anchor_saturday 算周差 w
                                    w 为偶数 → 与基准周同类型 → anchor_is_work
                                    w 为奇数 → 相反类型        → 1 - anchor_is_work
                                    （负数周差取模后先归一化再判奇偶）
   - alternate 但锚点缺失           → 退回 DEFAULT_SETTING 的锚点
3. 其余日子：周日 → "off"，周一 ~ 周五 → "work"（source: "weekday"）
```

## 四、关键决策

| 决策点 | 选择 | 理由 | 否决的备选 |
|---|---|---|---|
| 数据来源 | **纯本地推算 + 手动覆盖**，不接任何第三方 | 公司不按国家安排放假（主人 2026-10-23 原话），导进来的国定假期反而是错的；一年只需手点十几个休假日 | 接 holiday-cn 的放假数据（已实测可用，但与公司口径不一致，还多出缓存 / 失败降级两条路径） |
| 存储模型 | **一个制度开关 + 一张覆盖表** | 制度只有「周六上不上班」两种取值，一行就够；覆盖表只装用户真正改过的日子 | 直接存 52 周的排班（一年要录 104 个格子）· 只存覆盖不存制度（「下周六上不上班」永远答不出来） |
| 制度怎么来 | **设置里三选一：单休 / 双休 / 单双休** | 2026-10-23 联调时主人定下：「如果我选择单休，就所有日历都按单休来算」；第二轮又补了「单双休 = 本周单休、下周双休」这一档。一句话说完、一个动作改全年，不需要先学「基准周」 | 只给单休 / 双休（主人公司是大小周，缺这一档就没法用）；点周六改全年（和设置里的制度是同一件事，两个入口会打架） |
| 单双休从哪一周起算 | **永远问「本周」**：面板显示这一周（周一~周日）的日期范围，让人选这周是单休周还是双休周；保存时把锚点重设到本周 | 隔几个月再打开，问「三个月前某个周六上不上班」没人答得上来（主人原话）；问「上周刚过完的那一周」谁都答得上来。默认值按当前制度推算，所以不改直接保存相位不跳 | 显示存着的锚点日期（2026-10-23 的第一版就是这样，被主人当场指出「我早都不记得那天上不上班了」）；每次读取拿「今天」当起点（相位会随日子漂） |
| 没设过制度时怎么办 | **内置默认制度**：单双休，从 2026-10-24 那周起双休周 | 首版是「没设置 → 周六显示未定」，主人一打开就是一片空白（「星期六的标识呢？」）；给默认之后新账号打开就有答案，想改再去设置 | 首屏空着（被读成漏数据）· 强制跳设置页（多一道墙） |
| 工具页版式 | 与便签 / 待办 / 工具详情页同一套：`PageHeader`（上一级「工具」）+ `ToolHeader` + 概览条 + 工具栏 + 月历 | 主人 2026-10-23 的原话「详情页过于简陋，丰富起来，也要参考其他工具的统一风格」；工具名只出现一次，概览条把「本周六上不上班」顶到最上面 | 只有一条工具栏 + 一大张月历（首版，被说简陋）· 保留 PageHeader 写工具名（与 ToolHeader 重复） |
| 覆盖和制度谁说了算 | **覆盖永远最优先**，换制度也冲不掉 | 主人的原话：「就算重新选择了双休，单休逻辑有冲撞，也是手动改的最优先」。调休 / 请假是事实，制度只是默认值 | 换制度时清空覆盖（把用户手动记的事抹掉）；覆盖只对当周有效（过期就失效） |
| 月历几何 | **周一起始 / 7 列 / 固定 42 格** | 固定 6 行，切月时页面高度不变，不跳 | 4–6 行自适应（切月高度跳一下，看着像卡顿）· 周日起始（中国日历习惯是周一） |
| 农历/节日在哪算 | **只在服务端算**，作为 props 传下去 | `lunar-javascript` 是 436KB 单文件 CJS，进浏览器是纯浪费；而且一天只变一次（《日期时间面板》已有同一决策） | 客户端算（436KB 进 bundle）· 客户端再引一个轻量农历库（多一个依赖、口径还可能跟面板不一致） |
| 切月份怎么实现 | **URL 参数 `?ym=2026-11`，服务端算整月** | 零客户端计算、零体积，链接可分享、刷新不丢月份 | 客户端一次性算整年 12 个月（props 大、首屏慢）· 客户端实时算（库进 bundle） |
| 每格节日放几个 | **只放一个**（法定 > 农历传统 > 节气 > 其它） | 一格只有一行高度；同时出现三个的日子真实存在（清明 + 节气） | 全部渲染并换行（格子高度不齐、整月高度跳） |
| 首页要不要塞完整月历 | **不塞，只塞紧凑版** | 430px 里每格 56px（手机 43px），农历和节日名必然被挤丢；不如把「今天上不上班」做到极致清晰 | 首页放完整月历（要撑到 900px 宽，跟四块卡的宽度体系打架） |
| 「休/班」怎么表达 | **两档都用右上角小角标**：班（黑底白字）/ 休（浅灰底灰字）/ 未定（白底虚线「未定」，首页卡写「?」）；都不上颜色 | 《界面设计规范》§九 禁止彩色徽章，只能走黑白。整格黑底会把一周糊成一条黑杠（2026-10-23 联调主人原话「黑一片」）；改成角标后 430px 的卡也放得下「班」和「休」（主人明确要求「上班的班字标识还是带上吧」） | 照抄参考图的红「休」/蓝「班」（违反 §九）· 首页卡整格黑底（联调当场否掉）· 只标休息（主人看过之后否掉） |
| 覆盖掉的日期怎么标 | 日期下方一个 1px 小黑点 | 用户必须能区分「推出来的」和「我改过的」，否则改过的日子永远不知道自己改过 | 不加标记（改过的日子看起来跟推算的一样，下次怀疑自己记错）· 改整格颜色（跟休/班的语义打架） |
| 首页卡能不能改状态 | **能改单天；不能切年月、不能设制度、不能清制度** | 主人 2026-10-23 的原话：「总览只负责展示跟一些快捷操作，管理就跳转到工具页面，它应该被当成一个单独的工具来使用」。改一天是高频小动作，跟待办卡直接勾、便签卡直接删同一性质 | 首页卡只读（连改这一天都要跳页，多一次往返）· 首页卡全功能（430px 放不下工具栏，等于把工具页塞进卡片） |

## 六、验收标准

1. 从没设过制度的账号打开 `/tools/attendance-calendar` → **没有**提示条，周六直接按默认制度（单双休、2026-10-24 那周双休）挂角标：10-03 班、10-10 休、10-17 班、10-24 休、10-31 班；所有周日「休」、周一~周五「班」；设置面板默认选中「单双休」+「双休周」
2. 设置 → 选「单休」→ 保存 → **连着两周的周六都是「班」**（不是隔周）；周日仍「休」；查库 `saturday_mode = 'work'`
3. 单休制度下手动点 `2026-10-24`（周六）→ 选「休息」→ 该日变「休」并出现已改小黑点；`2026-10-31`（同制度下的周六）**仍然是「班」**——只改了这一天
4. 接着在设置里切「双休」→ `2026-10-24` **仍是「休」且仍带小黑点**（手动改的最优先，换制度冲不掉）；`2026-10-31` 变「休」、不带小黑点
5. 对 `2026-10-24` 点「跟随自动」→ 该日回到制度值「休」、小黑点消失；直接查库 `SELECT COUNT(*) FROM attendance_overrides WHERE user_id=? AND day_key='2026-10-24'` 为 `0`
6. 设置 → 选「单双休」→ 面板显示「本周（…）是：」，选「单休周」→ 保存 → `2026-10-24`（本周六）「班」、`2026-10-31`「休」、`2026-11-07`「班」、`2026-10-17`（上一周）「休」——单双周真的在交替；查库 `saturday_mode = 'alternate'`、`anchor_saturday = '2026-10-24'`、`anchor_is_work = 1`
7. 同一面板把本周改成「双休周」→ 保存 → 相位整体翻转：`2026-10-24`「休」、`2026-10-31`「班」；查库 `anchor_is_work = 0`
8. 点 `2026-10-25`（周日）→ 选「上班」→ 该日变「班」；设置 →「恢复默认」→ 日历回到内置默认制度（单双休、10-24 那周双休），而 `2026-10-25` 的覆盖**仍然生效**
9. 跨月补齐的格子（本月 1 号之前的几天、最后一天之后的几天）**同样挂「休 / 班」角标**、也能点开弹层；它们的日期是灰的（`#D0D0D0`），用来区分「这不是本月」
10. 连点月份切换 12 次（跨年）→ 月历高度始终一致（42 格 × 固定格高，无 4 行 / 5 行的月份）
11. 切到 `?ym=2026-02` → 页面直接渲染 2 月，农历与节日跟着变；刷新页面仍是 2 月
12. 每格节日只显示一个：`2026-10-01` 显示「国庆节」；`2026-10-08` 显示「寒露」；`2026-10-18` 显示「重阳节」
13. 手机宽度 375px → 日历页格子内**不出现农历/节日文字**，只有日期 + 角标；点开弹层后能看到该日农历与节日全名
14. 首页 `/` 顺序为「日期时间面板 → 工作日历卡 → 待办卡 → 便签卡 → 每日一句卡」，工作日历卡宽度 430px；卡上「管理 ›」进入 `/tools/attendance-calendar`，月份参数等于卡片当前显示的月份

## 七、已知的坑

| 坑 | 机制 | 对策 |
|---|---|---|
| 月历高度跳 | 不同月份 4~6 行，切月时页面整体上下窜 | 固定 42 格（6 行），缺的格子用上月/下月日期补满并置灰 |
| 农历库进浏览器包 | 它是 436KB 未压缩 CJS，client 组件里 import 会整包打进去 | 只在 Server Component / 服务端函数 import；客户端要农历就走 props 或点开弹层时由服务端给 |
| 时区漂一天 | 线上容器跑 UTC，`new Date().getDate()` 在 16:00 UTC 就已经是「明天」 | 日期一律走 `lib/datetime/shanghai.ts`；`day_key` 用东八区拼字符串，不用 `toISOString()` 切前 10 位 |
| 覆盖被制度冲掉 | 同一天既可能来自制度推算，也可能有覆盖行；切制度时如果按制度重算就丢了用户记的事 | 读取顺序固定：**覆盖 > 制度 > 星期兜底**。「跟随自动」= 删覆盖行，不碰制度 |
| 清制度后覆盖还活着 | 用户以为「清除」= 全清 | 清制度只删 `attendance_settings`，覆盖保留；按钮文案写「清除」，下面写清「手动改过的日子仍然生效」 |
| 没设过制度时周六一片空白 | 「还没选过」如果空着不挂角标，会被读成漏数据（主人原话「星期六的标识呢？」） | 内置默认制度（单双休、2026-10-24 那周双休）兜底，`resolveDayStatus` 在 `setting = null` 时用它——界面永远有答案；「未定」这一态随之退场，只在数据异常时才会出现 |
| 跨月的格子看不到状态 | 42 格里补齐的上月末 / 下月初原本只是灰占位，跨月那几格没有「休 / 班」，看着像漏了数据（2026-10-23 主人指出） | 42 格全部按制度算状态、挂角标、可点开弹层；只用「日期灰一档」区分本月与跨月 |
| 首页卡整格黑底 | 一版把上班日整格涂黑，连成一条黑杠（2026-10-23 联调当场否掉「黑一片」） | 首页卡只给休息日挂「休」，上班日什么都不挂；工具页格子大，才用「班 / 休」双角标 |
| 紧凑卡「休」和两位数字挤在一起 | 手机上一格只有 43px，角标绝对定位到右上会压住日期 | 日期靠左、`休` 靠右，同一行左右分列（`justify-between`），两条信息互不重叠 |
| 每格节日挤爆 | 一格一行高度，清明那天可能同时是节气 + 传统节日 + 国际日 | 只取优先级最高的一个；其余信息进弹层 |
| 42 格里本月日期算错 | 月初补上月末几天，容易出现「9月31日」这种不存在的日期 | 用 `Date.UTC` 拿 1 号星期再按天回推；纯函数单测覆盖 2 月、31 天月、跨年 |
| 点弹层后关不掉 | 弹层锚定在格子下方，点外面要能关 | 弹层带独立遮罩层（点外部关闭），`event.target === event.currentTarget` 守卫；Esc 也关（《web-feature-delivery》遮罩规则） |
| 首页卡点进去月份不对 | 卡片显示 10 月，链接进的是「本月」，跨月后不一致 | 卡片链接带上 `?ym=`，与卡片渲染用的是同一个 `dateKey` |
| 切月用 `<Link>` 导致整页闪 | 服务端渲染整月，每次导航重新取数据 | 用 `router.push` + `useTransition`，旧数据留到新数据到（可接受的一次往返，RSC 很快） |
| 换表结构丢用户的设置 | 上一版的 `attendance_cycles`（基准周六 + 那周类型）跟新版对不上 | `initSchema()` 里做幂等迁移：把 `anchor_is_work` 搬成 `saturday_mode`（1 → `'work'`），搬完删旧表；新库里没有旧表就直接跳过 |
| 加了「单双休」档却存不进去 | 老表的 `CHECK (saturday_mode IN ('work','off'))` 会直接拒掉 `'alternate'`（`SqliteError: CHECK constraint failed`），而 **SQLite 改不了已有的 CHECK** | `migrateAttendanceModeCheck()`：检查建表语句里有没有 `'alternate'`，没有就整表重建（改名 → 按新列定义建表 → 搬行 → 删老表），全程一个事务；幂等 |
| 单双休的相位会漂 | 如果每次读取都拿「今天所在那周」当起点，日子往前一走到下周，整年的单双周就整体错一位 | 锚点存成一个固定的周六（`anchor_saturday`）+ 那周类型（`anchor_is_work`）；面板重开时**回填存着的锚点**，而不是重新取「今天」 |
