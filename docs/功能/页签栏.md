# 页签栏

| 状态 | 开始日期 | 最近更新 |
|---|---|---|
| ✅ 已上线 | 2026-10-24 | 2026-10-24 |

> 一句话：把「走过的页面」变成一条看得见、点得着的横条——在深层页面之间互相跳转，不用一层层退回再进来。

---

## 一、要什么

在便签详情页想去待办，现在必须「回工具中心 → 再点进去」。页签栏把每次访问记成一个标签，点一下就过去。

**做：**

- 桌面（≥ lg）应用顶部常驻一条页签栏，高 40px，位于页头上方、主内容区之外（不随页面内容滚动）
- 每访问一个「登记过的」路由，追加一个标签，文字取该路由的页面名
- 点标签 = 跳到那个路由；当前所在路由的标签为激活态
- 标签右侧 `×` 可关闭；**总览（`/`）是固定标签，不显示 `×`，永远存在**
- 关闭当前激活的标签 → 跳到它右边的邻居；右边没有就跳左边；只剩总览时回 `/`
- 刷新浏览器后，这一排标签还在（只在本次会话内有效）
- 标签多到放不下时横向滚动，切换后自动把激活标签滚进视野

**主动放弃（本版不做，不是遗漏）：**

| 放弃项 | 原因 |
|---|---|
| 页面状态缓存（Vue 的 `keep-alive`：切回来输入框里的草稿、滚动位置还在） | App Router 的页面是服务端组件，没有「藏起来但还活着」的挂载位。而两个真工具的数据本来就即时落库，切回来重新拉一次看到的就是最新的；真正会丢的只有「还没保存的输入」，为它把每个页面改造成客户端组件 + API 取数，成本远大于收益。等真的出现「写了半篇切走就没了」再单独做 |
| 标签右键菜单（关闭其他 / 关闭右侧 / 固定） | 先只验证「能跳」这一件事；标签数量在个位数时右键菜单是纯负担 |
| 移动端（< lg）的页签栏 | 手机宽度放不下一排可点的标签，横排标签配 8px 的 `×` 是误触机器。移动端本来就有系统级返回手势，那比页签栏更快 |
| 七个一级入口全部固定成标签 | 九个标签一开始就铺满，等于「钉住」不再传递任何信息——只有一个固定标签才说明「这是家」。其余入口点过才出现 |
| 同一页面不同查询参数开多个标签 | 现在没有任何页面用查询参数区分内容；按 pathname 精确匹配即可 |

## 二、界面

全站生效，不是某一页。外观类名见《界面设计规范》§7.22，这里只说结构与行为。

**位置**（外壳新增的一条横带，位于页头之上）：

```
┌────────┬──────────────────────────────────────────┐
│        │  页签栏 TabBar（h-10，bg #F5F5F5）          │
│ 侧边栏  ├──────────────────────────────────────────┤
│  w-20  │  页头 PageHeader（h-16，吸顶，bg #F5F5F5）  │
│ 常驻   ├──────────────────────────────────────────┤
│        │  主内容区（overflow-y-auto，bg #ECECEC）    │
│        ├──────────────────────────────────────────┤
│        │  页脚 Footer                               │
└────────┴──────────────────────────────────────────┘
```

挂在 `AppShell` 里、`<main>` 外：它必须比主内容区活得久（切页面不重建），也不能跟着内容一起滚。

**哪些路由会开标签**（白名单，写死在 `tab-routes.ts`）：

| 路径 | 标签文字 |
|---|---|
| `/` | 总览（固定，不可关） |
| `/agent` | Agent |
| `/knowledge` | 知识 |
| `/tools` | 工具 |
| `/tools/sticky-notes` | 便签 |
| `/tools/todo-list` | 待办清单 |
| `/tools/attendance-calendar` | 工作日历 |
| `/tools/vault` | 保险库 |
| `/tools/image-compress` | 图片压缩 |
| `/files` | 文件 |
| `/automation` | 自动 |
| `/settings` | 设置 |

不在表里的路径（404、登录页、以后新增但没登记的页面）**不开标签**——页面照常显示，只是栏里没有对应的激活项。新页面要进页签栏 = 在表里加一行，这是显式决策，不是自动推断。

**断点**（结构性切换一律 `lg`，见《界面设计规范》§6）：

| 档位 | 页签栏 |
|---|---|
| < 1024px | 整条不渲染（`hidden lg:flex`） |
| ≥ 1024px | 常驻一栏，横向滚动 |

用 CSS 类而不是 JS 判断断点：JS 判断会让服务端输出和客户端首帧不一致。

## 三、数据模型

不涉及。标签列表只活在前端：`{ path: string }[]`，存在 `sessionStorage` 的 `nexus-os:tabs` 键下。

**只存路径、不存标题。** 标题由白名单查出来，菜单改名后标签自动跟着变；存了标题就会出现「菜单改了、标签还是旧名」。

**用 `sessionStorage` 而不是 `localStorage`。** 它管的是「这一次工作还没结束」，关掉浏览器就该清空；留着昨天的标签，第二天打开是一排不认识的页面。

## 四、关键决策

| 决策点 | 选择 | 理由 | 否决的备选 |
|---|---|---|---|
| 缓存 | 不做 `keep-alive`，只做导航 | 两个真工具的数据在 SQLite，切回来重新拉就是最新的；丢的只是未提交的输入，为它翻掉取数架构不划算 | React 19.2 的 `<Activity>`（隐藏而不卸载，但要求整页变成客户端组件 + API 取数） |
| 固定标签 | 只有「总览」一个 | 「钉住」的价值在于「这是我随时能回去的那一个」；九个全钉住等于没钉住，还把栏占满 | 七个一级入口全固定（栏一开始就满） · 一个都不固定（要额外处理「最后一个不能关」的边界） |
| 标签来源 | 白名单映射表 | 标题只有一个真相源；404 和未登记页面不会污染栏；加页面是一次显式决策 | 读 `document.title`（客户端拿到的时机不可靠，会闪） · 按布局段自动推断（`/tools/[slug]` 这类动态段推不出中文名） |
| 关掉当前标签后去哪 | 右邻居 → 左邻居 → `/` | 与浏览器关标签的行为一致，用户不用学第二套 | 回首页（跳得太远，关一个标签像被弹出去） · 停在空白页（要多设计一个空态） |
| 跳转方式 | 点标签用 `Link`；关标签后用 `router.replace` | `replace` 让浏览器历史里不留一条指向已关页面的记录；`Link` 才有预取和「按住 Cmd 新窗口打开」 | 全部 `router.push`（历史堆满已关闭的页面，按返回会回到幽灵页） |
| 持久化位置 | `sessionStorage` | 见第三节 | `localStorage`（跨天残留） |
| 移动端 | 整条不渲染 | 见主动放弃表 | 横滑标签条 · 页头「最近」下拉 |

## 五、文件落点

| 文件 | 职责 |
|---|---|
| `src/components/layout/nav-items.ts` | 从 `sidebar.tsx` 抽出的导航项数组（`href / label / icon`），侧栏与页签栏共用同一份文字 |
| `src/components/layout/tab-routes.ts` | 路径 → 标签文字的白名单解析（工具页从 `tool-catalog` 取 `name`，不重抄一遍名字） |
| `src/lib/navigation/tabs.ts` | 纯函数：登记、关闭、算邻居、序列化；不 import 组件、不碰 `window` |
| `src/lib/navigation/tabs.test.ts` | 上面那组纯函数的测试 |
| `src/components/layout/tab-bar.tsx` | 页签栏组件（客户端）：管状态、持久化、渲染 |
| `src/components/layout/app-shell.tsx` | 挂载点：`<main>` 上方插入 `<TabBar />` |
| `src/components/layout/sidebar.tsx` | 改为从 `nav-items.ts` 取导航项，行为不变 |

分层的原因：**「怎么算」和「长什么样」分开**。邻居怎么选、重复怎么去重这类规则放在 `lib` 里的纯函数里，能不启动浏览器就测；组件只负责把数组画出来。

## 六、验收标准

- [ ] 桌面宽屏打开 `/`，页签栏出现且只有一个「总览」标签，无 `×`，激活态
- [ ] 依次访问 `/tools` → `/tools/sticky-notes` → `/tools/todo-list` → `/tools/attendance-calendar`，栏里按这个顺序变成 5 个标签，最后一个是激活态
- [ ] 点「工具」标签 → 回到 `/tools`，「工具」变激活、「待办清单」变回未激活
- [ ] 当前在 `/tools/todo-list` 且它是最右一个标签，点它的 `×` → 落到左邻居「便签」，标签数减 1，地址栏同步变成 `/tools/sticky-notes`
- [ ] 待办清单右边还有别的标签时点它的 `×` → 落到右邻居（右邻居优先，不是固定落便签）
- [ ] 只剩「总览」时，该标签内 `button` 元素数量为 0（没有 `×`）
- [ ] 在 `/settings` 刷新浏览器 → 之前打开的标签全部还在，「设置」仍是激活态
- [ ] 手动访问 `/tools/not-a-tool` → 标签总数不变（不新增），页面照常显示
- [ ] 打开 8 个以上标签 → 栏出现横向滚动；切到一个滚出视野的标签后它自动滚进来
- [ ] 视口缩到 900px → 页签栏不可见（`display:none`）、高度为 0、主内容区顶边贴到窗口顶（不吃 40px）；缩回 1280px → 重新出现且标签不丢

> `< lg` 用 `hidden lg:flex`（规范 §7.22），元素仍在 DOM 里、只是 `display:none`。判据是「看不见 + 不占高度」，不是「DOM 里没有」。
- [ ] 关掉一个标签后按浏览器「后退」→ 不回到刚关掉的那个页面
- [ ] 点当前已激活的标签 → 标签数量不变，浏览器历史长度不变
- [ ] `pnpm exec next typegen` → `pnpm typecheck` → `pnpm lint` → `pnpm test` → `pnpm build` 全绿

## 七、已知的坑

- **水合报错**：`sessionStorage` 在服务端不存在。首帧只能给「只有总览」的一张表，水合后再切到真实快照；不要把它写进 `useState` 的初始值。
  - 实现上**没有**用「`useEffect` 里 setState 合并」：本项目 lint 的 `react-hooks/set-state-in-effect` 是 error 级，那写法过不了门禁。实际做法是把 `sessionStorage` 当外部存储、用 `useSyncExternalStore` 订阅（服务端快照 = 只有总览，且必须是模块级常量，每次返回新数组会让 React 认为快照一直在变）。代价：刷新时当前页的标签比其它标签晚一帧出现。
- **预取风暴**：栏里每个标签都是一个 `Link`，不给 `prefetch={false}`，开 8 个标签就是 8 个后台请求。
- **重复登记**：点当前激活的标签时 `pathname` 没变，不要重复追加，也不要往历史里再压一条。
- **关标签后的路由**：`setState` 之后立刻读 `pathname` 拿到的是旧值。新激活路径要用刚算出来的结果直接跳，不能等下一帧。
- **占位空间**：页签栏在 < lg 不渲染，主内容区不能因此留出 40px 的空白——高度由它自己撑，不要给 `<main>` 加固定 padding。
- **别再造一个 Context**：状态住在 `TabBar` 自己身上就够（它常驻不卸载，没有第二个消费者）。外壳已有的 `AppShellContext` 只管抽屉。
