# 工具详情页

| 状态 | 开始日期 | 最近更新 |
|---|---|---|
| ⏸ 搁置 | 2026-10-17 | 2026-10-22 |

> 一句话：给 58 张死卡片接上「点开之后」——每个工具有一个稳定地址、一张能进的页面；工具本身一个都不实现，先只把地基打对。
>
> **2026-10-22 现状（暂缓）**：便签 / 待办两个真工具已按**显式路由**落地（`/tools/sticky-notes`、`/tools/todo-list`），没有走 `/tools/[slug]` 动态路由，也没有 PageHeader；工具卡仍不可点。本设计保留，等其余工具开始落地时重新评估「显式路由 vs 动态路由」。

---

## 一、要什么

### 做

- 目录里每个工具多一个 **slug**（网址标识，见《关键决策》第 2 条）：手写英文，全小写 + 连字符，全目录唯一
- 一条动态路由 `/tools/[slug]`：按 slug 去目录里查工具，查到就渲染，查不到就 **404**
- 工具卡（`/tools` 列表）从死 `<div>` 变成可点链接，**视觉与交互效果一个字不改**（灰卡、hover 抬升、黑底白图标全部保留）
- 详情页三段：**页头**（返回入口 + 工具名）、**工具信息**（图标 / 名称 / 描述 / 分类 / 状态）、**内容占位**
- 所有工具当前都是「未实现」，内容区统一给「该工具开发中...」占位（规范 §7.12 的虚线框）
- 详情页能回到 `/tools`

### 主动放弃（本版不做，不是遗漏）

| 放弃项 | 原因 |
|---|---|
| 任何一个工具的真实功能 | 本单是地基单。工具逐个另开需求，一个工具一张卡 |
| 工具「可用 / 开发中」的列表页视觉区分 | 列表页仍统一外观（《功能/工具中心》2026-10-16 迭代结论）；状态只在详情页露出 |
| 工具目录进数据库 | 58 条静态数据还用不上数据库；等目录需要后台维护时再迁，本单只保证数据结构以后搬得动 |
| 工具收藏 / 最近使用 / 面包屑导航 | 旧界面没有，本版不加 |
| 详情页的分享 / SEO 优化 | 独立路由已经天然可分享；元信息等真有内容时再补 |

## 二、界面

路由 `/tools/[slug]`，套用应用外壳（侧边栏 + 页头 + 页脚）。

```
页头（PageHeader，§7.10）
├─ < lg：汉堡按钮（打开侧栏抽屉）
├─ ← 返回箭头 → 链接到 /tools
└─ 标题：「工具」

内容区（px-4 py-4 md:px-6 md:py-6）
├─ 工具信息条
│   ├─ 图标块（h-12 w-12，黑底白图标 —— 进入详情页的图标是「定妆照」，反色到黑底）
│   └─ 右侧：工具名（text-lg font-semibold）+ 描述（text-sm text-[#8A8A8A]）
│           + 分类标签（§7.9 chip）+ 状态点（§7.5）
└─ 内容占位：虚线框（rounded-[2px] border-dashed border-[#D9D9D9]）
    └─ 文案「该工具开发中...」（p-8，§7.12）
```

**页头为什么写「工具」而不是工具名**：工具名在内容区的信息条里有一个更大的落位，页头再写一遍就重复了；页头写上一级名字，正好承担面包屑的职责，也解释得清「← 回哪去」。

**三档响应式**（规范 §六：每档都得有为之定制的版式，不能只把桌面压扁）：

| 档位 | 版式 |
|---|---|
| 移动 < lg | 工具信息条**纵向**：图标块在上、文字在下，分类 chip 与状态点并排一行；两个图标按钮（汉堡 + 返回）都在，间距收紧到 `gap-1`；占位框内边距 `p-8` |
| 平板 / 窄屏 PC 1024–1279 | 工具信息条**横向**：图标左、文字右，`gap-4`；无汉堡，只剩返回箭头 |
| 宽屏 ≥ 1280 | 同上，工具信息条与占位框之间的间距放大到 `space-y-6`；图标块 `h-14 w-14` |

**返回箭头单独成按钮**：和汉堡一样是 `h-10 w-10` 的图标按钮，hover 底色 `#ECECEC`；不用浏览器自带的返回，因为用户可能是从收藏/分享链接直接进来的，历史上没有上一页。

## 三、数据模型

**不涉及数据库**。本功能只改动前端静态目录（`tool-catalog`）的结构。

每个工具新增一个字段：

```
slug: string   // 例："image-compress"
```

设计要点：

- **唯一**：58 条里不许重名。它是这条记录对外的「门牌号」，重了就有页面永远访问不到
- **不改**：一旦定下就不再变。中文名、描述随便改，slug 不动——否则旧链接全废
- **全小写 + 连字符**：不用大写、下划线、中文、空格。大写会被某些工具/系统自动转小写，等于造出两个地址指向同一页
- **英文而不是拼音**：`image-compress` 比 `tupian-yasuo` 短、也更容易被一眼读懂；代价只是写的时候要想一下

## 四、关键决策

| 决策点 | 选择 | 理由 | 否决的备选 |
|---|---|---|---|
| 工具页的形态 | 独立路由 `/tools/[slug]` | 每个工具有自己的地址：能分享、能存收藏、浏览器返回键行为自然；手机上整页放得下（以后文件类工具要列清单）；以后进数据库时 slug 直接当查询键 | 弹窗（无独立地址、手机空间挤、文件类工具在里面撑不开）；侧滑面板（同上，且移动端手势与抽屉导航冲突） |
| slug 的形态 | 手写英文，如 `image-compress` | 稳定（改名不断链）、干净（可读可粘贴）、以后能直接当数据库唯一键 | 拼音（要引库、还长）；中文直出（URL 编码成 `%E5%9B%BE…`，粘贴出去不成样） |
| 未实现的工具能不能点 | 全部能点，进去是占位 | 「点不动」是死路，用户不知道是不会做还是要上线；占位页至少能看进度。也避免每上一批工具就回头改一次列表页 | 不可点（要改列表，且体验是死的）；点了弹 Toast「开发中」（比占位页信息更少，还多一个全局组件） |
| slug 对不上怎么办 | `notFound()` 走 404 | 地址与数据自洽：不存在的工具就该是 404，链接写错能立刻暴露 | 回退到工具列表（把错链接悄悄掩盖掉，以后排查更难） |
| 代码结构（文件怎么拆） | **不预设，由实现者自己判断** | 写功能文档的人看不到全部代码，隔着层去圈文件只会圈错；约束（不引依赖、lib 不 import 组件、路由必须在 `/tools` 段下）写在验收里把关 | 预先列出要新增/修改的文件清单（容易圈错，且让实现者失去重排结构的空间） |

## 五、文件落点

**不预设具体文件**，只给三条硬约束（其余由实现者判断，验收会核对）：

1. 不新增运行时依赖（`package.json` 的 `dependencies` 不变）
2. `src/lib/` 下不许 import React 组件（目录数据若搬进 `lib`，图标引用必须留在组件层）
3. 路由文件必须落在 App Router 的 `src/app/` 下的 `/tools` 段里，不许另起一套路由前缀

## 六、验收标准

**正常路径**

1. 打开 `/tools`，点任意一张卡 → 地址变为 `/tools/<该工具的 slug>`，页面信息条显示的工具名、描述与卡片一致
2. 58 张卡片逐一点击，全部能进对应页；无 404、无白屏、无控制台报错
3. 详情页点「←」→ 回到 `/tools`，列表位置与搜索条件不要求保留，但不报错
4. 目录中 58 条 slug 彼此不重复（可用 `grep -c 'slug:'` 与去重计数对照）
5. 每个详情页的内容区都出现「该工具开发中...」虚线框占位
6. 工具卡原有 hover 效果（抬升 + 白卡 + 图标块反黑）在改成链接后仍然存在，且链接不带下划线

**负面路径**

7. 访问 `/tools/not-a-real-tool` → 404 页面（不是空白、不是跳回列表）
8. 访问 `/tools/Image-Compress`（大写）→ 404（slug 大小写敏感，不做容错）
9. 直接访问 `/tools` → 列表页正常（不能被动态路由吃掉）

**响应式**

10. 375px 宽下：汉堡与返回箭头并排不重叠，标题不换行、不被截断
11. ≥ 1280px：工具信息条横向排列，图标块为 `h-14 w-14`

**门禁**

12. `pnpm typecheck` / `pnpm lint` / `pnpm test` / `pnpm build` 四项全过

## 七、已知的坑

| 坑 | 机制 | 对策 |
|---|---|---|
| 58 条 slug 手写重名 | 人眼很难保证 58 个不重复 | 验收第 4 条机械去重；写完先自查一遍 |
| 卡片从 `div` 变 `Link` 后视觉走样 | `<a>` 默认带下划线、颜色被改；原来的 `group-hover` 需要父元素保持 `group` | 保持外层类名原样，只把最外层元素换成 `Link`；检查下划线 |
| 服务端组件直接读带图标的目录 | 目录若已搬进 `lib`，图标是 React 组件，搬进去就破了「lib 不 import 组件」红线 | 要么目录留在组件层，要么把图标映射留在组件层，元数据进 `lib` |
| 查不到 slug 时返回 `null` | Next 会渲染一张空白 200 页面，用户以为是「坏掉了」 | 必须调 `notFound()` |
| 动态路由吃掉 `/tools` 本身 | `[slug]` 段不会匹配空串，正常不会出问题；但如果有人写错成 catch-all（`[...slug]`）就会 | 用 `[slug]`，不要用 `[...slug]` |
| 手机页头两个按钮挤压标题 | 汉堡 40px + 返回 40px + gap + 内边距 ≈ 100px | 375px 下实测；必要时 `gap-1`、标题 `truncate` |
