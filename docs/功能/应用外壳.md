# 应用外壳

| 状态 | 开始日期 | 最近更新 |
|---|---|---|
| ✅ 已完成 | 2026-10-16 | 2026-10-16 |

> 一句话：让登录之后的每一页都长在同一副骨架上——左侧导航、统一页头、页脚、路由骨架；内容页先以「开发中」占位。

---

## 一、要什么

让所有受保护页面共享一副统一框架：用户进到哪儿都知道「我在哪、我能去哪」。本阶段只立骨架，不实现页面内容。

**做：**

- 桌面（≥ lg）常驻图标侧边栏：七个一级入口（总览 / Agent / 知识 / 工具 / 文件 / 自动 / 设置），当前项高亮，点击播放涟漪过渡（规范 §12.4）
- 手机（< lg）汉堡按钮 + 抽屉导航：遮罩、打开时锁背景滚动、点任一导航后自动关闭
- 每页统一页头（规范 §7.10）：手机显示短标题、桌面显示完整标题；右侧只放页面级控件
- 账户区进侧边栏底部（规范 §7.18）：桌面 = 用户图标、手机 = 抽屉底部整行（图标 + 用户名），点开向上弹出用户菜单（用户名 + 退出登录）
- 页脚：版权 + 备案行（备案号当前为占位，nexusos.work 真实备案号下来后替换）
- 七个一级路由全部可访问；除「工具」外内容为「开发中」虚线占位框（规范 §7.12）
- 未登录访问任意页面 → 跳登录页；登出 → 回登录页

**主动放弃（本版不做，不是遗漏）：**

| 放弃项 | 原因 |
|---|---|
| 二级栏（对话页 / 知识页的页内左栏） | 属于那两个页面自身，随页面功能一起设计 |
| 头像与资料编辑 | 底部用户区用通用用户图标（规范 §7.18）；等真的要做头像上传或资料编辑时再进菜单 |
| 边缘滑出的抽屉手势 | 汉堡按钮先行；手势是锦上添花 |
| 导航项按权限显隐 | 单用户系统，七个入口固定 |

## 三、数据模型

不涉及。外壳不建表；底部用户区显示的用户名来自会话——由 `(app)/layout` 取一次、经 `AppShell` 传给侧栏（**纯显示用途**；登录检查仍由各页面 `requireUser()` 承担，见《功能/登录注册》）。

## 四、关键决策

| 决策点 | 选择 | 理由 | 否决的备选 |
|---|---|---|---|
| 受保护页面归到哪个路由分组 | 新建 `(app)` 分组，组内 layout 渲染外壳 | `(auth)` 已确立「入口页不进外壳」的先例；根布局保持中立（只有 html/body/字体），两个组互不打扰 | 把 AppShell 放进根布局（登录 / 注册页会被裹进外壳）；每个页面手动包一层 AppShell（重复且容易漏） |
| 登录检查放哪 | 每个页面自己 `requireUser()` | 延续登录注册期的定论：检查贴着要保护的数据；Next 16 的 layout 在客户端导航时不重新渲染、也拦不住子页面 | 放进 `(app)/layout.tsx`（假安全）；靠 `proxy.ts`（读不了本地 SQLite） |
| 涟漪动效 | 完整复刻，且先补进规范 §12.4 再写代码 | 它是旧界面手感的一部分；规范里原本没有这一条——按「先改本文再改代码」，规范先行 | 省略（丢失手感）；只写代码不写规范（规范与实现脱节） |
| 占位页长什么样 | 统一虚线框 +「该功能开发中...」（规范 §7.12） | 一处写法、五页同构；「开发中」的表达沿用旧界面的既有语言 | 各页自由发挥（不一致）；白屏（看起来像坏了） |
| 账户区的放法（2026-10-16 修订） | 侧边栏底部：桌面 = 用户图标（`UserRound`，36 款候选评审后由用户选定）、手机 = 抽屉整行，点开向上弹用户菜单（规范 §7.18） | 账户是跨页面的「全局域」：放底部是恒定位置、不随页面变；页头右侧留给页面级控件（工具页搜索 + 筛选已占满）；参考扣子 / Linear 等成熟产品的同构做法 | 继续放页头（与页面控件争位，且手机端本来就显示不下）；窄栏里放文字用户名（80px 放不下、像贴纸）；首字母徽标（初版试做后否掉：观感不好、与导航图标不同风格）；circle 系 / contact 系等其余候选（评审落败）；头像下拉（过度设计） |

## 五、文件落点

- `src/app/(app)/layout.tsx` —— 组布局：套 AppShell；取一次用户名交给外壳（纯显示）
- `src/app/(app)/` 七个页面：`page.tsx`（总览）、`agent/`、`knowledge/`、`tools/`、`files/`、`automation/`、`settings/`

## 六、验收标准

| # | 操作 | 期望 |
|---|---|---|
| 1 | 未登录访问 `/` 或 `/agent` | 跳转到 `/login` |
| 2 | 登录成功 | 落在 `/`：看到外壳（侧栏 + 页头 + 页脚）与总览页的真实内容（日期时间面板 → 工作日历 → 待办卡 → 便签卡 → 每日一句，逐块一行、五块统一 430px） |
| 3 | 点击侧栏「知识」 | 跳到 `/knowledge`，该项高亮为浅蓝，页头标题正确 |
| 4 | 点击导航的瞬间 | 目标项上播放涟漪过渡，随后完成跳转 |
| 5 | ≥ lg 宽度 | 侧边栏常驻图标栏；页头无汉堡按钮 |
| 6 | < lg 宽度 | 侧边栏消失；页头出现汉堡按钮；点开抽屉可导航，点遮罩关闭；抽屉开着时背景不滚动 |
| 7 | 桌面（≥ lg）侧边栏底部 | 显示用户图标（悬停提示用户名）；点开 → 向上弹出用户菜单（用户名 + 退出登录） |
| 8 | 手机（< lg）抽屉底部 | 显示「用户图标 + 用户名」整行；点开 → 同一用户菜单 |
| 9 | 用户菜单里点「退出登录」 | 会话删除 → 回到 `/login` |
| 10 | 页脚 | 显示 © 与备案行；手机竖排、桌面横排 |
| 11 | 五个占位页（Agent / 知识 / 文件 / 自动 / 设置） | 内容区为虚线框「该功能开发中...」（工具页已是真实页面，总览页已无占位框） |
| 12 | 刷新任意页面 | 仍处于登录状态（会话 30 天） |
| 13 | 工具页 | 见《功能/工具中心》验收表 |

## 七、已知的坑

| 坑 | 机制与对策 |
|---|---|
| 抽屉打开时背景跟着滚 | 打开时锁 `document.body.overflow`，关闭恢复（AppShell 里的 effect） |
| 导航高亮判断 | `/` 用精确匹配（`pathname === "/"`），其余用前缀匹配（子路由也算激活）；由客户端 `usePathname()` 自己算——layout 在客户端导航时不重渲染，靠不了它 |
| 手机抽屉点导航后不关 | 客户端导航不会卸载抽屉，`onNavigate` 手动关闭 |
| 涟漪依赖组件不重挂载 | Sidebar 常驻在布局里、跨导航不卸载，动画才能在跳转前后连续播放 |
| 登出按钮的约束 | 它是 Server Action；菜单挂在客户端组件（`Sidebar`）里，所以 `user-menu.tsx` 声明为客户端组件——Server Action 在客户端组件里照样以「服务端函数」执行，浏览器只拿到引用 |
| 窄栏里菜单会挤成一条 | Base UI 弹层默认宽度跟随锚点（`--anchor-width`）：图标栏里的锚点只有 56px——菜单需显式 `min-w-56`，否则宽度贴着锚点 |
| 矮屏把底部用户区挤没 | 导航区 `min-h-0 overflow-y-auto`、底部块 `shrink-0`：导航可滚动、账户块必在（横屏手机 / 小窗口） |
