# 每日一句

| 状态 | 开始日期 | 最近更新 |
|---|---|---|
| ✅ 已完成 | 2026-10-22 | 2026-10-22 |

> 一句话：总览页第四块每天显示一句正能量的句子，按上海日界换；点「换一句」可以当场再看一条。

命名约定：中文「每日一句」，代码 `quote`（领域目录）/ `quote-card`（组件）。

---

## 一、要什么

**做：**

- **一块白卡**，放在总览页（`/`）逐块一行里的第四块（面板 → 待办 → 便签 → 每日一句），限宽 430px
- **标题行**：3px 黑竖条 + 「每日一句」；右侧灰色「每天更新」+ 一个「换一句」图标按钮
- **每天一句正能量的话**，下方署名 `—— 作者`
- **按天轮换**：句子库 365 条，按「今年第几天」取；同一天不换，跨零点自动换，一年不重复
- **换一句**：点一下当场换一条；刷新回到当天那句

**不做（主动放弃，附原因）：**

| 放弃项 | 原因 |
|---|---|
| 接一言等外部 API | 一言没有「正能量」分类：实测文学 / 哲学 / 诗词里第一条就是太宰治「胆小者连幸福都害怕」，方向正好是反的。还要处理超时、边缘缓存、失败兜底——为每天一句不值得 |
| 收藏、历史、按日期回看 | 需要新表与列表界面；这是首页的氛围信息，不是内容产品 |
| 让用户选分类 / 换句子库 | 又一处一年也调不了一次的设置项 |
| 定时任务 / 每日推送 | 按日期取就够了，零点后第一次访问自然是新句子 |
| 分享图、复制按钮 | 当前没需求；一个「换一句」已经够了 |

## 二、界面

### 2.1 位置

总览页 `page.tsx` 的竖列里，排在便签卡之后：

```
[日期时间面板 max-w-372px]
[待办卡 max-w-430px]
[便签卡 max-w-430px]
[每日一句卡 max-w-430px]   ← 本次新增
（屏宽不足时各自满宽）
```

与上面两块同宽，竖列右边缘对齐；不与日期面板并排——两块都矮，并排后右边会空一大截。

### 2.2 卡片内部

```
┌────────────────────────────────────────────┐
│ ▍每日一句                     每天更新  ↻  │
│                                            │
│ 每一个不曾起舞的日子，都是对生命的辜负。    │
│ —— 尼采                                     │
└────────────────────────────────────────────┘
```

- 卡片：`rounded-[2px] bg-white p-5`（《界面设计规范》§7.1）
- 标题：分组标题 §7.2，`text-sm font-semibold`
- 右上「每天更新」：`text-xs text-[#8A8A8A]`
- 「换一句」：`h-7 w-7` 纯图标按钮（`RefreshCw h-3.5 w-3.5`），默认 `text-[#8A8A8A]`、hover `bg-[#ECECEC] text-[#000000]`，`aria-label="换一句"`
- 正文：`mt-4 text-[15px] leading-7 text-[#000000]`
- 署名：`mt-2 text-xs text-[#8A8A8A]`，格式 `—— {作者}`
- 正文块 `min-h-[3.5rem]`（两行）：换句时卡片高度不跳

### 2.3 响应式

卡片宽 `max-w-[430px]`：宽屏恒为 430px，窄屏满宽。内部是单列文本，没有分栏，任何宽度同一版式；正文 15px 不下调——这张卡的价值就在「读一句」，手机端多占一行比缩字更合适。

| 卡片宽度 | 内容宽 | 每行字数 |
|---|---|---|
| 430px | 390px | ≈ 26 字 |
| 343px（375 手机满宽） | 303px | ≈ 20 字 |

### 2.4 内容规则

| 元素 | 规则 |
|---|---|
| 句子库 | 代码内常量 365 条，中文古典 + 公认的中外名言；出处不确定的标「佚名」，不硬安作者 |
| 句子长度 | 全部 ≤ 40 字（约两行），入库时人工过一遍 |
| 每天取哪条 | `(今年第几天 - 1) % 365`；日期键用 `Asia/Shanghai`，与日期面板同一个 `dateKey` |
| 跨天 | 页面整夜开着时，由日期面板的时钟在零点触发 `router.refresh()`，本卡随整页换成新一天 |
| 换一句 | 从库里取**下一条**（索引 +1）；不落库，刷新回到当天那句 |
| 署名 | 有作者写作者，没有写「佚名」 |

## 四、关键决策

| 决策点 | 选择 | 理由 | 否决的备选 |
|---|---|---|---|
| 句子从哪来 | **代码内 365 条常量** | 零网络、零失败、零缓存；内容是自己的，「正能量」才有保证 | 一言 API（无正能量分类，实测抽到消极句；还要处理超时与边缘缓存）· 数据库（为一个数组建表） |
| 每天怎么取 | `(今年第几天 - 1) % 365`，纯函数 | 同一天任何人、任何设备都是同一句；跨天自然变化，不需要定时任务，也不用存「今天抽到了哪条」 | 随机（刷新就变，违背「每天更新」）· 定时任务写库（多一个常驻进程） |
| 换一句怎么实现 | Server Action 取下一条 | 句子库只在服务端，客户端不背 365 条常量；调用不碰网络，几毫秒 | 客户端直接拿整份库（几十 KB 进浏览器包）· 新建 API 路由（一句话不值得） |
| 换一句要不要落库 | **不落库**，只换当前显示 | 刷新后的行为可预期；「看看别的」不需要写状态 | 点一次就改当天记录（多写路径与并发问题） |
| 放哪、多宽 | 总览第四块，430px | 与待办 / 便签同宽，竖列右边缘对齐 | 与日期面板并排（右侧会空）· 横跨整宽（一句话拉太长） |
| 日界时区 | `Asia/Shanghai` | 与日期面板同源，两块在同一个零点翻页；线上机器是 UTC | 系统默认时区（早上 8 点才换句） |

## 六、验收标准

1. 访问 `/` → 第四块是「每日一句」，430px、与待办 / 便签左对齐；窄屏满宽
2. 卡片显示「▍每日一句」、右上「每天更新」、正文、「—— 作者」
3. 同一天连续刷新 10 次 → 正文不变
4. 把日期改到第二天 → 正文换成下一条；与日期面板在同一次刷新里一起变
5. 用纯函数连跑 365 天 → 365 条各出现一次，第 366 天回到第 1 条
6. 点「换一句」→ 换成下一条；连点直到走完一轮，不会重复当前这条
7. 刷新页面 → 回到当天那句（换一句不落库）
8. 430px 与 343px 两个宽度：任意一条都在两行内、不溢出、不出现横向滚动
9. 浏览器 Network 里没有任何外部请求
10. 读屏：卡片有可读名称；换句后新句子被朗读一次（`aria-live="polite"`）
11. 句子库 365 条：正文非空、≤ 40 字、作者非空
12. 门禁五项全绿（typegen / typecheck / lint / test / build）

## 七、已知的坑

| 坑 | 机制 | 对策 |
|---|---|---|
| 闰年多一天 | 按「今年第几天」取，闰年是 366 | 索引按 `(dayOfYear - 1) % 365` 取模，第 366 天回到第 1 条 |
| 日界算错 | 用 `Date.now()` 本地时区，线上是 UTC | 只用 `dateKey`（`Asia/Shanghai`）算第几天，纯函数、可单测 |
| 换句重复当前条 | 顺序取下一条时可能绕回当前条 | 步进 1 取模；库长 > 1，天然不会等于当前 |
| 句子库进浏览器包 | 在客户端组件里 import 句子库会把 365 条全打进去 | 客户端只 import Server Action |
| 长句撑高卡片 | 某条超过两行会改变卡片高度 | 入库时统一压到 40 字内；正文块 `min-h-[3.5rem]` 兜住一行与两行的差异 |
| 署名不确定 | 网上大量名言是误传（伪托的「爱因斯坦语录」之类） | 只收有明确出处的；拿不准标「佚名」，不硬安作者 |
