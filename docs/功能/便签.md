# 便签

| 状态 | 开始日期 | 最近更新 |
|---|---|---|
| ✅ 已上线 | 2026-10-17 | 2026-10-30 |

> 一句话：把「随手贴」做成第一个真能用的工具——写、改、置顶、删，并让首页那张常驻便签卡显示真实数据。

---

## 一、要什么

**做：**

- **工具页** `/tools/sticky-notes`：便签的完整增删改 + 置顶；新建 / 编辑走弹窗，删除走原位确认
- **落库**：新表 `sticky_notes`，每条便签归属到用户；正文上限 1000 字；置顶同时记 `pinned` 与 `pinned_at`
- **首页常驻卡**：总览页左侧主区立起「便签」卡，显示置顶优先的最近 3 条；右上「管理 →」直接进 `/tools/sticky-notes`
- **目录同步**：`tool-catalog` 里便签的状态从「开发中」改为「可用」
- 工具页与首页卡各自做响应式（见第二节）

**主动放弃（本版不做，不是遗漏）：**

| 放弃项 | 原因 |
|---|---|
| 搜索 / 筛选 | 个人便签量级小；有了搜索它就开始像笔记系统（边界见「关键决策」第 1 条） |
| 标题 / 颜色 / 富文本 | 便签的价值是「少想一步」，多一个字段就多一次决定；颜色还会破坏黑白灰基调 |
| 自动保存 | 便签极易误改；在没有撤销的前提下，自动保存会把原稿悄悄覆盖 |
| 删除撤销 / 回收站 | 要引入软删除状态与清理策略；原位二次确认已经把误删挡在前面 |
| 拖拽排序 / 手动排序 | 排序规则只有一条（置顶优先 + 置顶时间 / 更新时间倒序），够用且不必存位置 |
| 多端同步 / 分享 | 单机 SQLite、个人使用；等真有跨设备需求再谈 |
| 首页显示全部便签 / 分页 | 首页是摘要，3 条封顶；看全部去工具页 |
| 便签归档 / 分类 | 同上——那是笔记系统的能力，属于「知识」页 |

## 二、界面

### 2.1 工具页 `/tools/sticky-notes`

与待办工具页同构：**没有 PageHeader**，工具名与状态在内容区的信息条里；手机上「汉堡 + 新建」住在页面顶部那一行。

```
移动端导航行（< lg）：汉堡 + 新建便签
内容区（px-4 py-4 md:px-6 md:py-6）
├─ 工具信息条（黑底白图标 h-12 w-12 + 名称 / 描述 / 分类 chip / 状态点「可用」）
│   └─ 右侧「新建便签」（≥ lg；< lg 的入口在顶部导航行）
├─ 吸顶工具栏（ToolBar，与待办页共用）
└─ 列表
   ├─ 「全部便签 N」分组标题
   ├─ 便签网格（正方形卡片）
   └─ 空态（无便签时）：虚线框「还没有便签」+「新建便签」按钮（§7.12）
```

**网格与卡片尺寸**：

```
grid grid-cols-2 gap-3
     md:grid-cols-4 lg:grid-cols-5 xl:grid-cols-6
     [@media(min-width:1400px)]:grid-cols-7
```

- 每张卡 `aspect-square`（宽 = 高）；实测边长约 166px（375）/ 171px（768）/ 185px（1100）/ 190px（1280）/ 177px（1440）/ 189px（1520）。
- 1280–1399 保持 6 列、1400 起 7 列：再密一档会让底部「时间 + 置顶文案 + 删除」挤出卡片。
- 卡片内边距 `p-3 md:p-4`；正文最多 5 行（`line-clamp-5`），超出省略。

**便签卡三态**：

| 态 | 长什么样 |
|---|---|
| 阅读 | 正方形白卡 `rounded-[2px] bg-white`；正文 `whitespace-pre-wrap break-words text-[13px] leading-relaxed text-[#000000]`，占满整卡宽度；底部固定一行：左侧时间 `YYYY-MM-DD HH:mm` + 「已置顶 / 未置顶」文字按钮，右侧删除按钮（桌面 hover 才显、触屏常显） |
| 编辑 | **弹窗**（`NoteDialog`）：无边框 `textarea`、自动长高、`maxLength=1000`；`Enter` 换行、`⌘/Ctrl + Enter` 保存、`Esc` 取消；编辑时左下角显示「创建于 …」；底部按钮：**删除**（仅编辑态，点了直接删、无二次确认，文字用错误色 `#B91C1C`）/ 取消 / 置顶保存 / 保存 |
| 删除确认 | 卡片内容换成「删除这张便签？」+「删除 / 取消」两个小按钮，仍是正方形；不弹全局对话框 |

- **点卡片任意位置（正文 / 时间 / 空白）打开编辑弹窗**；「已置顶 / 未置顶」文字按钮和删除按钮浮在上层，点它们不触发编辑。
- **置顶不用图钉图标**：底部一行直接写「未置顶」或「已置顶」，点文字切换（带 `aria-pressed`）。状态与动作是同一个东西，不用再猜图标含义。
- **置顶排序**：最近置顶的排最前（`pinned_at DESC`）；取消置顶后回到按更新时间该在的位置，且**不碰 `updated_at`**。
- **置顶保存**：弹窗里保存与置顶合成一步（同一事务），新建 / 编辑完不用再滚回列表里找它、再点置顶。
- **底部按钮只有两层样式**：删除 / 取消 / 置顶保存都是灰底 `#F5F5F5`，同高、同圆角、同字号、无图标无描边；保存是黑底白字，只有它 hover 加深。
- **删除成功会弹全局提示**（2026-10-22 起）：`便签「正文摘要」已删除`（`formatDeletedMessage()`，正文压成一行、超 24 字符截断）；桌面右下角、手机居中，3 秒自动消失（§7.13）。卡片上的删除同样会提示。
- **删除按钮**（2026-10-22 起）：只在**编辑**已有便签时出现，新建态没有。点它先弹出**确认条**（灰底内嵌块：`删除后无法恢复，确定删除这条便签？` + 「取消」灰底、「确认删除」黑底），确认后才真删并关闭弹窗；**删除不可撤销**（不做「撤销」Toast）。文字用错误色 `#B91C1C`，是它在按钮行里的唯一提示。列表卡片上的删除是另一条路径（卡片内二次确认），互不影响。
- **为什么删除按钮按 hover 分档**：桌面鼠标有 hover，按钮可以收起来保持卡片干净；触屏没有 hover，收起等于永远按不到（见「已知的坑」）。

### 2.2 首页常驻卡 `/`

总览页目前是**「逐块一行、左对齐」**的过渡形态（五块统一 430px，屏宽不足时各自满宽；日期时间面板原本 372px，2026-10-23 联调时改成与其它卡同宽）；旧版的「主区 2/3 + 常驻栏 1/3」要等拼图补齐再拼回去，见《界面设计规范》§7.17。

- 便签卡沿用旧界面形态：白卡 `p-5` + 分组标题「便签」（§7.2）+ 右上「管理 →」链接（`text-xs text-[#8A8A8A] hover:text-[#000000]` + `ArrowRight h-3 w-3`，指向 `/tools/sticky-notes`）。
- **点哪一条就看哪一条**：首页每条便签都链到 `/tools/sticky-notes?note=<id>`，工具页落地即打开这条的编辑弹窗（`NoteDialog`，编辑态）——只跳列表的旧做法在便签一多之后根本找不到刚点的那条（2026-10-22 联调要求）。打开后地址栏里的 `?note=` 会被 `router.replace` 抹掉，关掉弹窗再刷新不会又弹回来；id 找不到（已被删）就当没传，正常显示列表。
- 卡内 3 条灰色便签块 `rounded-[2px] bg-[#F5F5F5] px-3 py-2.5`，**一条只占一行**：正文 `text-[13px] truncate` 单行截断，时间 `shrink-0 text-[10px] tabular-nums text-[#999999]` 放正文右侧；块间距 `gap-2`。**卡内分栏按卡片自身宽度（容器查询）：容器 ≥ 448px（`@md`）排 2 列，否则单列**——2026-10-22 起首页这张卡固定约 430px，所以是单列三行（与旧版参考图一致）；卡片以后变宽（拼回主区 2/3）会自动回到 2 列。用视口断点会犯「窗口宽、卡片窄，照样 2 列」的错，每条被挤到约 200px。
- **「管理」指向 `/tools/sticky-notes`**，不是工具列表 `/tools`——管理的是便签本身。
- **显示哪 3 条**：置顶优先、置顶组内按 `pinned_at DESC`，其余按更新时间倒序——与工具页同一套排序，只是限量 3 条。
- **空态**：没有便签时，卡内显示一块 `#F5F5F5` 占位，「还没有便签」+「写一条 →」链接到 `/tools/sticky-notes`。

### 2.3 响应式

| 档位 | 工具页 | 首页 |
|---|---|---|
| 移动 < md（375 起） | 2 列正方形卡片（约 166px）；顶部有汉堡 + 新建；信息条纵向；卡片内边距 `p-3` | 单列第一块；3 条便签块；「管理 →」保留 |
| 平板 md ~ lg | 4 列（约 171px）；信息条仍纵向 | 单列（< xl） |
| 窄屏 PC lg ~ xl | 5 列（约 185px）；信息条与网格间距放大 | 同上（< xl） |
| 宽屏 ≥ xl | 6 列（约 190px）；≥ 1400 时 7 列（约 177–189px） | 网格 3 列：左 2 便签、右 1 待办 |

三档用互斥显隐（`hidden … lg:flex` / `lg:hidden`）而不是 JS 断点判断——首屏 SSR 不闪（同《工具中心》）。

## 三、数据模型

```sql
CREATE TABLE IF NOT EXISTS sticky_notes (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id    INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  body       TEXT    NOT NULL,
  pinned     INTEGER NOT NULL DEFAULT 0,   -- 0 / 1，SQLite 没有布尔类型
  pinned_at  INTEGER,                      -- 置顶时刻（毫秒）；NULL = 未置顶
  created_at INTEGER NOT NULL,             -- 毫秒时间戳
  updated_at INTEGER NOT NULL              -- 毫秒时间戳；只有改正文才刷新，置顶不刷新
);

CREATE INDEX IF NOT EXISTS idx_sticky_notes_user_id ON sticky_notes(user_id);
```

设计要点：

- **表名带领域词**：`sticky_notes` 而不是 `notes`——后者留给以后的笔记 / 知识条目。slug 也正好是 `sticky-notes`：库、路由、目录三处同名。
- **`user_id` 外键 + 级联删除**：单用户也把归属写进数据；删账号时便签跟着走。
- **`pinned` 与 `pinned_at` 是同一件事的两面**：`pinned` 回答「是不是」，`pinned_at` 回答「什么时候置顶的」（置顶组内排序用）。**只在 `setNotePinned` 一处一起写**：置顶写 `pinned=1, pinned_at=now`，取消置顶写 `pinned=0, pinned_at=NULL`。
- **置顶不碰 `updated_at`**：否则「更新时间」变成谎话，取消置顶后便签还会莫名其妙跳到最前。
- **老库补列**：`initSchema()` 里的 `migrateStickyNotePinnedAt()` 只在列不存在时 `ALTER TABLE`，并把已有的置顶行回填成 `pinned_at = updated_at`（保留它们原来的相对顺序）；列已存在就什么都不做，重复启动不会覆盖新值。
- **正文上限 1000 字**：服务端校验兜底（Server Action 是公开端点），客户端 `maxLength` 只是体验；`trim()` 后为空一律拒绝。
- **排序**：`ORDER BY pinned DESC, pinned_at DESC, updated_at DESC, id DESC`；未置顶的 `pinned_at` 为 NULL，组内仍按更新时间倒序；末尾 `id DESC` 兜底毫秒撞车。

字段逐个解释与常用查询见《数据库/便签表》。

## 四、关键决策

| 决策点 | 选择 | 理由 | 否决的备选 |
|---|---|---|---|
| 便签的产品边界 | 随手贴：写完就不管，找它靠时间与置顶 | 一旦加搜索 / 分类 / 标签，它就开始长成笔记系统，与「知识」页职责重叠 | 做成轻量笔记（功能诱惑大，但会拖成第二个知识库） |
| 编辑形态 | **弹窗**（`NoteDialog`） | 原地展开会把那张卡撑高，破坏正方形网格，也把下面所有卡片顶下去；弹窗把编辑态与列表分开 | 卡片原地变输入框（把网格撑乱）；独立编辑页（为几十字开一页太重） |
| 保存时机 | 显式「保存 / 取消」，另给「置顶保存」 | 便签易误改；没有撤销时自动保存会把原稿悄悄吃掉。置顶保存把「存完再回去点置顶」合成一步 | 自动保存 + 防抖（要配版本冲突与撤销）；只有保存（编辑完还得再找置顶） |
| 保存与置顶的原子性 | 同一个事务 | 「存了但没置顶」是半成品，用户以为成功了 | 先保存再单独置顶（中间失败会让界面与预期不一致） |
| 删除 | 原位二次确认（卡片自己变确认态） | 不引全局对话框；确认就在原地；误删代价高，值得多一次点击 | 直接删 + Toast 撤销（要软删除 / 恢复接口）；浏览器 `confirm` |
| 置顶的数据形态 | `pinned` + `pinned_at` 两列 | 既回答「是不是」，也回答「什么时候置顶的」；组内「最新置顶的在前」需要这个时间 | 只有 `pinned` 布尔（刚置顶的旧便签会沉到置顶区末尾，找都找不到） |
| 置顶组内排序 | `pinned_at DESC` | 用户刚置顶的那张应该在第一眼看到的位置；编辑正文不会改变置顶顺序 | 按 `updated_at`（置顶不刷新更新时间，刚置顶的旧便签会排到末尾） |
| 首页卡的数据来源 | 与工具页共用同一个查询函数，只传 `limit: 3` | 一处排序规则、两处使用 | 首页单独写一条 SQL（排序规则出现两份，早晚不一致） |
| 首页卡的空态 | 卡内空态块 +「写一条 →」 | 首页是新用户第一屏，空着像坏了；给一个动作比一句「暂无」有用 | 隐藏整张卡；只显示「暂无便签」 |
| 首页「管理」指向 | `/tools/sticky-notes` | 管理的是便签本身；旧界面指向工具列表，点进去还得再找一次 | 指向 `/tools`（多一跳） |
| 时间怎么显示 | **绝对时间 `YYYY-MM-DD HH:mm`**，按 UTC+8 计算 | 同一块列表里相对日期会随时间变化而跳，扫读还要换算；固定 +8 可预测、可单测 | 浏览器本地时区（首帧不一致）；「今天 / 昨天」（跨天会变） |
| 卡片尺寸 | **正方形**（`aspect-square`） | 便签本来就该方方正正，像贴纸；网格里视觉最整齐 | 固定高度矩形（长便签与短便签混排时高度不齐） |
| 卡片密度 | 2 / 4 / 5 / 6 / 7 列，1280–1399 收一档 | 正方形边长与底部行宽度互相牵制：再密一档，时间 + 置顶文案 + 删除会挤出卡片 | 一律 3 列（宽屏太稀）；一律 7 列（1280 下卡片过窄） |
| 工具页要不要信息条 | 保留，状态「可用」 | 工具页同构（同一条骨架），从列表点进来先确认「我在哪」 | 去掉信息条（与其余工具页不同构） |

## 五、文件落点

1. 不新增运行时依赖（`package.json` 的 `dependencies` / `devDependencies` 都不变；日期格式化手写）。
2. 表结构的唯一权威仍是 `src/lib/auth/db.ts` 的 `initSchema()`——`pinned_at` 的补列/回填也写在这里。
3. `src/lib/` 下不许 import React 组件（数据访问与 Server Action 可以，视图组件不行）。
4. 路由必须落在 `src/app/(app)/tools/sticky-notes/`；首页只改 `src/app/(app)/page.tsx`，不另建别名路由。

`src/lib/sticky-notes/`（notes / validate / actions / format）、`src/components/tools/sticky-notes/`（view / note-card / note-dialog / note-editor）；工具栏组件 `src/components/tools/tool-bar.tsx`、`tool-mobile-bar.tsx` 与待办页共用；时间格式化统一在 `src/lib/format.ts`（`formatDateTime`）。

## 六、验收标准

**正常路径**

1. 打开 `/tools/sticky-notes`：出现工具信息条（名称「便签」、状态「可用」）；没有便签时显示「还没有便签」空态。
2. 点「新建便签」→ 弹窗；输入「周一交周报」→ 保存 → 网格出现第一张正方形卡片，显示正文与时间（`YYYY-MM-DD HH:mm`）；刷新后仍在。
3. 点卡片正文 → 编辑弹窗，左下角显示「创建于 …」；改成「周一交周报（含截图）」→ 保存 → 卡片更新；再打开改回并按 `Esc` → 数据库不变。
4. 编辑时点「置顶保存」→ 保存成功且便签出现在置顶区第一条，底部文案变「已置顶」。
5. 点「未置顶」文字 → 变「已置顶」并移到最前；再点一次「已置顶」→ 回到按更新时间该在的位置，`updated_at` 不变。
6. 同时存在 2 条置顶：最近置顶的在前，与它们的 `updated_at` 无关。
7. 删除：点删除 → 卡片变「删除这张便签？」→「取消」保留；再走一次并点「删除」→ 卡片消失，刷新后确实没了。
8. 正文 1000 字可保存；1001 字被服务端拒绝（弹窗内提示，行数不变）。
9. 首页 `/`：便签卡显示置顶优先的最近 3 条；第 4 条及以后不出现在首页；时间与工具页一致；本页待办卡在右 1/3。
10. 首页卡「管理 →」→ 地址变为 `/tools/sticky-notes`（不是 `/tools`）。
11. 首页没有便签时：卡内「还没有便签」+「写一条 →」，点它进 `/tools/sticky-notes`。

**负面路径**

12. 未登录直接访问 `/tools/sticky-notes` → 跳 `/login`。
13. 提交只有空格 / 换行的正文 → 保存失败并给字段级提示，数据库行数不变。
14. 正文写 `<img src=x onerror=alert(1)>` → 页面按原文字面显示，无弹窗、无图片请求。
15. 用 A 用户去更新 / 删除 B 用户的便签（数据层单测，两个不同 `user_id`）→ 影响行数为 0，B 的便签不变。
16. 便签不存在时调用更新 / 置顶 / 删除 → 不抛未捕获异常，页面不白屏。
17. 保存请求还在飞时重复点保存 → 只落一条。

**响应式**

## 七、已知的坑

| 坑 | 机制 | 对策 |
|---|---|---|
| 服务端时区不是 +8 | 线上容器多为 UTC，日期会跟用户的日期差 8 小时 | 格式化不复用默认时区，显式按 UTC+8 计算 |
| 毫秒撞车导致顺序不稳 | 同一毫秒内的两条便签 `updated_at` 相等 | 排序末尾补 `id DESC` |
| 置顶顺手改了 `updated_at` | 取消置顶后便签会跑到最前，「更新时间」也变成谎话 | 置顶只写 `pinned` / `pinned_at`，不碰 `updated_at` |
| 置顶按更新时间排，刚置顶的旧便签沉底 | 置顶动作不刷新 `updated_at` | 增加 `pinned_at`，组内按置顶时间倒序 |
| 老库没有 `pinned_at` | `CREATE TABLE IF NOT EXISTS` 不会给已存在的表加列 | `initSchema()` 里幂等 `ALTER TABLE` + 只回填已置顶行；列已存在则不执行 |
| 触屏上删除按钮永远不出现 | `group-hover` 在触屏没有 hover | 默认可见；只在 `@media (hover: hover)` 设备上收起 |
| 卡片右侧被图标占掉一整列 | 按钮在右上角时正文要 `pr-14` | 图标移到右下角、与时间同一行，正文占满宽度 |
| 底部一行在窄卡上挤爆 | 时间 + 置顶文案 + 删除都有最小宽度 | 166px 起才放得下；1280–1399 退一列 |
| `textarea` 不会自动长高 | 原生 textarea 固定行高 | 每次输入把 `style.height` 设为 `scrollHeight`，并设最小高度 |
| 打开弹窗时手机键盘顶走内容 | 移动端键盘弹出会改变视口 | 弹窗内滚动，不要把页面用 `h-screen` 硬撑 |
| 长英文 / URL 撑破卡片 | 没有 `break-words` 时字符串不换行 | 正文加 `break-words`，卡片 `overflow-hidden` |
| 全角空格 / 换行绕过空校验 | 只判断 `=== ""` 挡不住 | 服务端 `trim()` 后再判空 |
| 首页卡与工具页各写一套排序 | 两份 SQL 迟早不一致 | 共用同一个查询函数，首页传 `limit` |
| 确认态刷新后残留 | 确认态是纯前端状态 | 刷新即回阅读态 |
| Server Action 被直接调用 | 它是公开 HTTP 端点，`maxLength` 不是防线 | 服务端再校验：长度、非空、归属用户 |
| 勾选 / 置顶时整卡闪一下 | `pending` 触发 `disabled:opacity-50`，几十毫秒内来回切 | 卡片内按钮去掉这层变暗，`disabled` 逻辑保留 |
| 首页从占位页改成真实页面时，漏掉登录检查 | 检查在页面里而不在 layout | 保留首页自己的 `requireUser()` |
| 演示数据残留 | 手动测过的便签会被当成真数据 | 验收结束前清掉测试行 |
