# 便签

| 状态 | 开始日期 | 最近更新 |
|---|---|---|
| 🚧 设计中 | 2026-10-17 | 2026-10-17 |

> 一句话：把「随手贴」做成第一个真能用的工具——写、改、置顶、删，并让首页右栏那张常驻便签卡显示真实数据。

---

## 一、要什么

**做：**

- **工具页** `/tools/sticky-notes`：便签的完整增删改 + 置顶；新建、编辑、删除确认都在页内完成，不弹全局对话框
- **落库**：新表 `sticky_notes`，每条便签归属到用户；正文上限 1000 字；置顶是一个布尔值
- **首页常驻卡**：总览页右栏立起「便签」卡（沿用旧界面形态），显示置顶优先的最近 3 条；右上「管理 →」直接进 `/tools/sticky-notes`
- **目录同步**：`tool-catalog` 里便签的状态从「开发中」改为「可用」
- 工具页与首页卡各自做三档响应式（见第二节）

**主动放弃（本版不做，不是遗漏）：**

| 放弃项 | 原因 |
|---|---|
| 搜索 / 筛选 | 个人便签量级小；有了搜索它就开始像笔记系统（边界见「关键决策」第 1 条） |
| 标题 / 颜色 / 富文本 | 便签的价值是「少想一步」，多一个字段就多一次决定；颜色还会破坏黑白灰基调 |
| 自动保存 | 便签极易误改；在没有撤销的前提下，自动保存会把原稿悄悄覆盖（决策表第 3 条） |
| 删除撤销 / 回收站 | 要引入软删除状态与清理策略；原位二次确认已经把误删挡在前面 |
| 拖拽排序 / 手动排序 | 排序规则只有一条（置顶优先 + 更新时间倒序），够用且不必存位置 |
| 多端同步 / 分享 | 单机 SQLite、个人使用；等真有跨设备需求再谈 |
| 首页显示全部便签 / 分页 | 首页是摘要，3 条封顶；看全部去工具页 |
| 便签归档 / 分类 | 同上——那是笔记系统的能力，属于「知识」页 |

## 二、界面

### 2.1 工具页 `/tools/sticky-notes`

套用应用外壳（侧边栏 + 页头 + 页脚），是 58 个工具里第一个真实页面。

```
页头（PageHeader，§7.10）
├─ < lg：汉堡按钮
├─ ← 返回箭头 → 链接到 /tools
├─ 标题：「工具」（与其他工具详情页一致）
└─ 右侧：「新建便签」按钮（§7.3 主操作；< md 收成 40×40 图标按钮）

内容区（px-4 py-4 md:px-6 md:py-6）
├─ 工具信息条（沿用工具详情页同构：黑底白图标 h-12 w-12 + 名称 / 描述 / 分类 chip / 状态点）
│   └─ 状态显示「可用」（绿点，§7.5）
├─ 便签网格（grid grid-cols-1 gap-3 md:grid-cols-2 xl:grid-cols-3）
│   └─ 便签卡（白卡 p-4：正文 + 时间 + 置顶 / 删除）
└─ 空态（无便签时）：虚线框「还没有便签」+「新建便签」按钮（§7.12）
```

便签卡三态：

| 态 | 长什么样 |
|---|---|
| 阅读 | 白卡 `rounded-[2px] bg-white p-4`；正文 `whitespace-pre-wrap break-words text-[13px] leading-relaxed text-[#000000]`；底部时间 `text-[10px] text-[#999999]`；右上角两个图标按钮（置顶 / 删除），**桌面 hover 才显、触屏常显** |
| 编辑 | 同一张卡原地换成 `textarea`（无边框、`bg-white`、`text-[13px]`、自动长高）+ 底部「保存 / 取消」；`⌘/Ctrl + Enter` 保存、`Esc` 取消；右下角字数提示 `n/1000`，只在 ≥ 900 时出现 |
| 删除确认 | 卡片内容换成「删除这张便签？」+「删除 / 取消」两个小按钮；不弹全局对话框 |

- **新建**：点「新建便签」→ 网格**第一格**插入一张空卡并进入编辑态；保存才落库，取消则整张消失（不留空便签）。
- **置顶**：点图钉立即生效（不必先进编辑态）；置顶时图钉实心黑，未置顶为 `#A0A0A0` 空心。图标按钮都带 `aria-label`（`置顶` / `取消置顶` / `删除便签`）。
- **为什么按钮按 hover 分档**：桌面鼠标有 hover，按钮可以收起来保持卡片干净；触屏没有 hover，收起等于永远按不到（见「已知的坑」）。

### 2.2 首页常驻卡 `/`

总览页此前只有一个「开发中」占位框（§7.17）。本单**不改总览整体设计**，只先把右栏那张便签卡立起来：

```
内容区（px-4 py-4 md:px-6 md:py-6）
└─ 网格（grid grid-cols-1 gap-4 xl:grid-cols-3）
   ├─ 左列（xl:col-span-2）：虚线占位框「总览其余板块开发中...」
   └─ 右列（xl 第 3 列）：便签卡
```

- **手机 / 平板（< xl）**：单列，**便签卡在前、占位框在后**——首页目前只有这一块真内容，压在占位框下面等于藏起来；`xl` 起回到「左 2 / 右 1」的旧界面布局。
- 便签卡沿用旧界面形态：白卡 `p-5` + 分组标题「便签」（§7.2）+ 右上「管理 →」链接（`text-xs text-[#8A8A8A] hover:text-[#000000]`，`ArrowRight h-3 w-3`）；卡内 3 条灰色便签块 `rounded-[2px] bg-[#F5F5F5] p-3`，正文 `text-[13px] leading-relaxed`，时间 `mt-1.5 text-[10px] text-[#999999]`，块间距 `space-y-2`。
- **「管理」指向 `/tools/sticky-notes`**，不是工具列表 `/tools`——旧界面这里指向列表页是错的：管理的是便签，就该进便签本身。
- **空态**：没有便签时，卡内显示一块 `#F5F5F5` 占位，「还没有便签」+「写一条 →」链接到 `/tools/sticky-notes`。
- **显示哪 3 条**：置顶优先，其次按更新时间倒序——与工具页同一套排序，只是限量 3 条。

### 2.3 三档响应式

| 档位 | 工具页 | 首页 |
|---|---|---|
| 移动 < md（375 起） | 单列；页头「新建」收成 40×40 图标按钮（只有 `Plus` 图标）；信息条纵向（图标上、文字下）；卡片操作按钮常显 | 单列第一块；3 条便签块；「管理 →」保留 |
| 平板 md ~ lg | 两列；「新建便签」恢复文字按钮；信息条横向 | 单列（< xl），便签卡在占位框之前 |
| 窄屏 PC lg ~ xl | 两列；页头无汉堡，只剩返回箭头 | 同上（< xl） |
| 宽屏 ≥ xl | 三列；信息条与网格间距放大到 `space-y-6` | 网格 3 列：左 2 占位、右 1 便签卡 |

三档用互斥显隐（`hidden md:flex` / `md:hidden`）而不是 JS 断点判断——首屏 SSR 不闪（同《工具中心》）。

## 三、数据模型

```sql
CREATE TABLE IF NOT EXISTS sticky_notes (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id    INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  body       TEXT    NOT NULL,
  pinned     INTEGER NOT NULL DEFAULT 0,   -- 0 / 1，SQLite 没有布尔类型
  created_at INTEGER NOT NULL,             -- 毫秒时间戳
  updated_at INTEGER NOT NULL              -- 毫秒时间戳；编辑正文时更新，置顶不更新
);

CREATE INDEX IF NOT EXISTS idx_sticky_notes_user_id ON sticky_notes(user_id);
```

设计要点：

- **表名带领域词**：`sticky_notes` 而不是 `notes`——后者留给以后的笔记 / 知识条目（同 `auth_sessions` 让出「会话」）。slug 也正好是 `sticky-notes`：库、路由、目录三处同名，排查时不用翻译。
- **`user_id` 外键 + 级联删除**：现在单用户，但每条便签从第一天起就归属到人；删账号时便签跟着走，不留孤儿行。所有查询都带 `WHERE user_id = ?`，不是「反正只有一个用户」的自觉。
- **`pinned` 存 0/1**：能直接参与 `ORDER BY pinned DESC`。**只置顶不碰 `updated_at`**——否则「更新时间」变成谎话，取消置顶后位置也会乱。
- **正文上限 1000 字**：服务端校验兜底（Server Action 是公开端点），客户端 `maxLength` 只是体验；`trim()` 后为空一律拒绝。
- **时间戳毫秒**：与 `users` / `auth_sessions` 一致（《数据库/README》§二）。
- **排序**：`ORDER BY pinned DESC, updated_at DESC, id DESC`；末尾 `id DESC` 是稳定排序的兜底——毫秒会撞车，SQL 不保证等值行的顺序。

字段逐个解释与常用查询见《数据库/便签表》。

## 四、关键决策

| 决策点 | 选择 | 理由 | 否决的备选 |
|---|---|---|---|
| 便签的产品边界 | 随手贴：写完就不管，找它靠时间与置顶 | 一旦加搜索 / 分类 / 标签，它就开始长成笔记系统，与「知识」页职责重叠；先把一条路走通 | 做成轻量笔记（功能诱惑大，但会拖成第二个知识库） |
| 编辑形态 | 卡片原地变输入框 | 便签要「顺手」：不跳页、不弹窗、不多一次点击；卡片本身就是编辑器的外壳 | 弹窗（多一层，手机键盘顶掉半屏）；独立编辑页（为几十字开一页太重） |
| 保存时机 | 显式「保存 / 取消」 | 便签易误改；没有撤销时自动保存会把原稿悄悄吃掉。显式保存还给「取消」一个明确语义 | 自动保存 + 防抖（要配版本冲突与撤销，成本远超收益） |
| 删除 | 原位二次确认（卡片自己变确认态） | 不引全局对话框；确认就在原地，手指不用换位置；误删代价高，值得多一次点击 | 直接删 + Toast 撤销（要软删除 / 恢复接口）；浏览器 `confirm`（样式与全站不搭） |
| 置顶的数据形态 | `pinned` 布尔，排序时优先 | 只有「置顶 / 不置顶」两种状态；组内仍按更新时间排，符合直觉 | `pinned_at` 时间戳（多一个时间语义，组内排序还得再定规则） |
| 首页卡的数据来源 | 与工具页共用同一个查询函数，只传 `limit: 3` | 一处排序规则、两处使用；以后总览换成正式设计时不用重写查询 | 首页单独写一条 SQL（排序规则出现两份，早晚不一致） |
| 首页卡的空态 | 卡内空态块 +「写一条 →」 | 首页是新用户第一屏，空着像坏了；给一个动作比一句「暂无」有用 | 隐藏整张卡（首页又变回空白）；只显示「暂无便签」 |
| 首页「管理」指向 | `/tools/sticky-notes` | 管理的是便签本身；旧界面指向工具列表，点进去还得再找一次 | 指向 `/tools`（多一跳，像走错了路） |
| 时间怎么显示 | `今天 09:42` / `昨天 21:15` / `8月11日`，按 **UTC+8** 计算 | 与旧界面文案一致；单时区项目里固定 +8，「今天」的边界可预测、可单测 | 浏览器本地时区（服务端与客户端首帧不一致）；显示完整日期（扫读慢，且不像旧界面） |
| 工具页要不要保留信息条 | 保留，状态改「可用」 | 58 个工具页同构，从列表点进来先确认「我在哪」；只有便签删掉信息条会显得它不像工具 | 去掉信息条、页头标题改成「便签」（省一屏，但与其余 57 页不同构） |

## 五、文件落点

结构由实现者判断（写代码的人更清楚代码），只给四条硬约束：

1. 不新增运行时依赖（`package.json` 的 `dependencies` / `devDependencies` 都不变；日期格式化手写，不引 dayjs / date-fns）。
2. 表结构的唯一权威仍是 `src/lib/auth/db.ts` 的 `initSchema()`——新表加在那份 `SCHEMA` 里，不另起建表脚本、不写迁移框架。
3. `src/lib/` 下不许 import React 组件（数据访问与 Server Action 可以，视图组件不行）。
4. 路由必须落在 `src/app/(app)/tools/sticky-notes/`；首页只改 `src/app/(app)/page.tsx`，不许另建 `/home` 之类的别名路由。

`src/lib/auth/` 目前装着认证；便签的数据访问按《项目目录结构说明》另开领域目录，不要塞进 `auth/`。

## 六、验收标准

**正常路径**

1. 打开 `/tools/sticky-notes`：出现工具信息条（名称「便签」、状态「可用」）与空态「还没有便签」。
2. 点「新建便签」→ 网格第一格出现空卡并进入编辑态；输入「周一交周报」→ 保存 → 卡片显示正文与时间（今天 HH:mm）；刷新后仍在。
3. 点卡片正文 → 进入编辑态；改成「周一交周报（含截图）」→ `⌘/Ctrl + Enter` 保存 → 卡片更新，`SELECT body FROM sticky_notes` 与页面一致。
4. 编辑态按 `Esc`（或点「取消」）→ 卡片恢复原正文，数据库不变。
5. 新建后直接「取消」→ 空卡消失，`SELECT COUNT(*) FROM sticky_notes` 不变。
6. 点置顶 → 卡片移到最前、图钉转实心；刷新后仍置顶；再点一次，回到按更新时间的位置。
7. 同时存在 2 条置顶：组内按更新时间倒序（刚编辑过的那条在前）。
8. 点删除 → 卡片变「删除这张便签？」→「取消」保留；再走一次并点「删除」→ 卡片消失，刷新后确实没了。
9. 首页 `/`：便签卡显示置顶优先的最近 3 条；第 4 条及以后的便签不出现在首页；正文与时间与工具页一致。
10. 首页卡「管理 →」→ 地址变为 `/tools/sticky-notes`（不是 `/tools`）。
11. 首页没有便签时：卡内「还没有便签」+「写一条 →」，点它进 `/tools/sticky-notes`。
12. `/tools` 列表里的便签状态为「可用」；详情页信息条显示绿点「可用」。

**负面路径**

13. 未登录直接访问 `/tools/sticky-notes` → 跳 `/login`。
14. 提交只有空格 / 换行的正文 → 保存失败并给字段级提示，数据库行数不变。
15. 正文 1001 字 → 保存失败（服务端拒绝），行数不变；1000 字可以保存成功。
16. 正文写 `<img src=x onerror=alert(1)>` → 页面按原文字面显示，无弹窗、无图片请求。
17. 用 A 用户去更新 / 删除 B 用户的便签（数据层单测，两个不同 `user_id`）→ 影响行数为 0，B 的便签不变。
18. 便签不存在时调用更新 / 置顶 / 删除 → 不抛未捕获异常，页面不白屏。

**响应式**

19. 375px：工具页单列；页头右侧是 40×40 图标按钮（无文字）；无 hover 也能看到并使用卡片操作按钮；信息条纵向。
20. 768px：工具页两列；「新建便签」为文字按钮。
21. 1100px：工具页两列、页头只剩返回箭头。
22. 1440px：工具页三列；首页为「左 2 列占位 + 右 1 列便签卡」，便签卡贴右列顶部。
23. 首页在 375 / 768 / 1100px 下：便签卡在占位框**之前**，整宽显示。

**门禁**

24. `pnpm typecheck` / `pnpm lint` / `pnpm test` / `pnpm build` 四项全过。
25. 单测覆盖：排序（置顶优先 + 更新时间倒序 + id 兜底）、正文校验（空 / 超长 / 边界 1000）、时间格式化（今天 / 昨天 / 更早 / 跨年）、`user_id` 隔离（对应验收 17）。

## 七、已知的坑

| 坑 | 机制 | 对策 |
|---|---|---|
| 服务端时区不是 +8 | 线上容器多为 UTC，「今天」会跟用户的今天错开 8 小时 | 格式化不复用默认时区，显式按 UTC+8 计算日界 |
| 毫秒撞车导致顺序不稳 | 同一毫秒内的两条便签 `updated_at` 相等 | 排序末尾补 `id DESC` |
| 置顶顺手改了 `updated_at` | 取消置顶后便签会跑到最前，「更新时间」也变成谎话 | 置顶只写 `pinned` |
| 触屏上操作按钮永远不出现 | `group-hover` 在触屏没有 hover | 默认可见；只在 `@media (hover: hover)` 设备上收起（`[@media(hover:hover)]:opacity-0` + `group-hover:opacity-100`） |
| `textarea` 不会自动长高 | 原生 textarea 固定行高，长便签出内部滚动条 | 每次输入把 `style.height` 设为 `scrollHeight`（或 `field-sizing-content`），并设最小高度 |
| 新建时自动聚焦把手机页面顶走 | 移动端键盘弹出会改变视口 | 聚焦后 `scrollIntoView({ block: "center" })`；页面不要用 `h-screen` 硬撑 |
| 长英文 / URL 撑破卡片 | 没有 `break-words` 时字符串不换行 | 正文加 `break-words` |
| 全角空格 / 换行绕过空校验 | 只判断 `=== ""` 挡不住 | 服务端 `trim()` 后再判空 |
| 首页卡与工具页各写一套排序 | 两份 SQL 迟早不一致 | 共用同一个查询函数，首页传 `limit`；单测覆盖两种调用 |
| 确认态刷新后残留 | 确认态是纯前端状态 | 刷新即回阅读态，不产生半删除数据 |
| Server Action 被直接调用 | 它是公开 HTTP 端点，`maxLength` 不是防线 | 服务端再校验：长度、非空、归属用户 |
| 首页仍是占位页，改造时漏掉登录检查 | 检查在页面里而不在 layout | 保留首页自己的 `requireUser()`，便签卡只是渲染 |
| 演示数据残留 | 手动测过的便签会被当成真数据 | 验收结束前清掉测试行 |
