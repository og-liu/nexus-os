# Markdown 编辑器

| 状态 | 开始日期 | 最近更新 |
|---|---|---|
| 🚧 设计中 | 2026-10-30 | 2026-10-30 |

> 一句话：一个**能存多篇**的 Markdown 写作工具——左边是文档列表，中间写原文，右边实时看到渲染结果；写完能复制走或导出 `.md` 文件。

---

## 一、要什么

**做：**

- **工具页** `/tools/markdown-editor`：三栏布局——左栏文档列表、中栏编辑区、右栏实时预览
- **落库**：一张新表 `md_documents`，按 `user_id` 隔离；一篇文章一行（标题 + 正文原文）
- **多篇**：新建 / 切换 / 删除；列表按「最近修改」倒序（`updated_at DESC`）
- **标题**：编辑区顶部单独一个输入框；留空存成「未命名文档」，重名自动补序号（「未命名文档 2」……）
- **自动保存**：停手约 0.8 秒自动存，状态栏显示「保存中… / 已保存 / 保存失败」；切换文档、删除、离开页面前立刻补存一次
- **格式工具栏**：9 个按钮——粗体 / 斜体 / 行内代码 / 标题 / 无序列表 / 有序列表 / 引用 / 代码块 / 链接；点一下改写选区的 Markdown 语法
- **实时预览**：右边半屏渲染，支持表格、任务列表、删除线（GitHub 风格），**不渲染原始 HTML**
- **导出**：状态栏右侧「复制 Markdown」、「导出 .md」（浏览器下载，文件名取标题）
- **字数**：状态栏显示字数（按字符数算，emoji 记 1 个）
- **目录同步**：`tool-catalog` 新增一条 `markdown-editor`（分类「开发」、状态「可用」），工具卡可点；`tab-routes` 的 `TOOL_TAB_SLUGS` 加同一个 slug

**主动放弃（本版不做，不是遗漏）：**

| 放弃项 | 原因 |
|---|---|
| 代码块语法高亮 | 要多一个高亮包（+ 几十 KB）和一套主题色；现在是自己写文档，代码块等宽 + 灰底就够读。哪天要「贴代码给人看」再单独加 |
| 图片粘贴 / 上传 | 要存储、上传接口、图片渲染规则三样，是一个独立功能，不是本工具的顺手项 |
| 目录导航（TOC） | 要先定标题锚点规则；现在文档都在几百行内，右栏自己滚两下就到了 |
| 关闭页面兜底保存 | 浏览器直接关掉可能丢最后不到 1 秒的输入。要兜住它得用 `sendBeacon` / keepalive `fetch` 绕开 Server Action 自己写请求，收益只是「少丢几个字」——接受这个损失，写进「已知的坑」 |
| 全文搜索 | 只搜标题（前端过滤）。搜正文要 SQLite FTS5 + 中文分词，《数据库/README》§八已把它排到知识库 |
| 版本历史 / 回收站 | 没有「上一次写的什么样」这种需求；软删除会让每条查询都得带 `deleted_at IS NULL`。硬删 + 二次确认更便宜 |
| 文件夹 / 标签 | 多篇按时间排就够；分类要先定层级、拖拽、删除时子项归哪，属于「知识」模块的范围 |
| 实时协同 / 多端同步 | 这是单机个人工作台，没有第二个客户端 |
| 导出 HTML / PDF | 导出目标是「能喂给别的系统」的 Markdown 原文；HTML / PDF 要另定样式与分页规则 |
| 滚动同步（预览跟着光标走） | 要做「原文位置 ↔ 渲染位置」的映射加滚动监听，第一版不值这个复杂度 |
| 阅读模式（预览占满全屏） | 手机上已经有整屏预览；桌面上把编辑区收起来反而少了「边写边看」这个唯一理由 |

## 二、界面

### 2.1 工具页 `/tools/markdown-editor` 整体骨架

和保险库一样是**应用型页面**：三栏各自滚动、整页不滚。

- 页面根 `flex h-full overflow-hidden`
- **没有 `ToolHeader`**：页签栏（`Markdown 编辑器 ×`）已经说明「我在哪、怎么切走」，再叠一条工具头就是同一件事说两遍（《界面设计规范》§7.24.1 的结论，主人原话「上面已经有多页签导航了，没必要多整这么一行」）
- 代价：原来住在页头里的**手机汉堡按钮**（打开全局侧边栏）跟着消失，所以它挪到编辑区顶行的最左边（`md:hidden`；≥ md 有列表栏 / 抽屉，汉堡仍在，用于全局导航）
- 三栏行 `flex min-h-0 flex-1 overflow-hidden`——**`min-h-0` 不能省**，flex 子项默认 `min-height: content`，不写会被内容撑破、整页开始滚

```
页签栏（外壳的 TabBar，页面自己不再画标题行）
┌─ 列表 240 ─┬──────────── 编辑区（弹性） ────────────┬──── 预览（弹性） ────┐
│ [+ 新建]   │ [标题……                    ] [🗑]      │                     │
│ [搜索标题] │ B  I  `code`  H  列表  1.  引用  </>  🔗│  # 渲染出来的内容    │
│ ────────── │ ┌───────────────────────────────────┐ │                     │
│ 周报       │ │  # 这周做了什么                   │ │  这周做了什么        │
│ 10-30 16:12│ │  - 上线了保险库                   │ │  ─ 上线了保险库      │
│            │ │  - 修了三个 bug                   │ │  ─ 修了三个 bug      │
│ 灵感       │ │                                   │ │                     │
│ 10-29 21:03│ └───────────────────────────────────┘ │                     │
│            │ 已保存 · 128 字      [复制] [导出 .md] │                     │
└────────────┴───────────────────────────────────────┴─────────────────────┘
```

### 2.2 左栏：文档列表

- 宽度 240px（`w-60`），`bg-white`，右边缘一条 `border-[#F0F0F0]`
- 顶行：**新建按钮**（`h-8 bg-[#000000] px-3 text-[12px] text-white`，文案「新建」）+ 下方一行**搜索框**（`h-8`，左 `Search` 图标、有输入时右侧出现清除 `×`，占位「搜索标题」）
- 每行：标题（`truncate text-[13px]`）+ 下面一行修改时间（`text-[11px] text-[#999999]`，`formatDateTime` 出 `MM-DD HH:mm`）
- 选中行：`bg-[#F5F5F5]`（与保险库一致：不用彩色高亮，全站黑白灰）
- 行是手型光标（`cursor-pointer`），点击 = 切换文档
- 排序：`updated_at DESC, id DESC`；**不显示「删除」按钮**——删除只在编辑区右上角，列表里放删除会误触
- 空态：「还没有文档」+ 小字「点上面的「新建」写第一篇」
- 搜索无结果：「没有标题包含「xxx」的文档」+ 灰字「换个词试试」

### 2.3 中栏：编辑区

**顶行**（`h-11`，`border-b`）：

- 最左：手机汉堡（`md:hidden`，打开全局侧边栏）+ 手机「文档」按钮（`md:hidden`，打开列表抽屉，`FileText` 图标）
- 中间：**标题输入框**，无边框、`text-[18px] font-semibold`，占位「未命名文档」，宽度 `flex-1`
- 最右：**删除按钮**（`Trash2` 图标，`h-7 w-7`，颜色 `#8A8A8A`、hover 变 `#B91C1C`），二次确认

**工具栏**（`h-9`，`bg-[#FAFAFA]`，`border-b`，一行放得下，放不下时横向滚动不换行）：

| 顺序 | 图标 | 作用 | 结果 |
|---|---|---|---|
| 1 | `Bold` | 粗体 | `**选中**`；再点一次去掉 |
| 2 | `Italic` | 斜体 | `*选中*` |
| 3 | `Code` | 行内代码 | `` `选中` `` |
| 4 | `Heading` | 标题 | 行首 `# ` 循环 → `## ` → `### ` → 去掉 |
| 5 | `List` | 无序列表 | 行首 `- ` |
| 6 | `ListOrdered` | 有序列表 | 行首 `1. ` |
| 7 | `Quote` | 引用 | 行首 `> ` |
| 8 | `Code2` | 代码块 | 插入三行：```` ``` ````、空行、```` ``` ````，光标落在空行 |
| 9 | `Link` | 链接 | 有选中 → `[选中](url)` 且光标落在 `url` 上；无选中 → `[](url)` 同理 |

- 按钮 28×28、图标 14px、颜色 `#666666`、hover 背景 `#ECECEC`
- 按钮 `type="button"`，**`onMouseDown` 里 `preventDefault()`**——不这么做，点按钮的瞬间 textarea 失焦、选区丢失，格式就打到了光标位置而不是选中的文字
- 没有按钮的语法（表格、任务列表、分割线、脚注）手打，预览照样渲染
- **工具栏最右端常驻一个「预览」开关**（`Eye` 图标，`ml-auto`）：点一下收起 / 展开右栏预览。它不属于上面 9 个格式按钮，是版式开关——≥ 768 每个档位都有（1280 宽屏也想安静写一段时用得上）；< 768 不出现（手机上靠顶部的「编辑 / 预览」分段切换）

**正文输入区**：原生 `<textarea>`，撑满剩余高度（`flex-1`），无边框、`resize-none`、`outline-none`。

- 字体：`sm:` 起 `font-mono text-[13px] leading-[1.7]`；**`< sm` 用 `text-[16px]`**（iOS 对小于 16px 的输入框聚焦时会缩放整页，见「已知的坑」）
- 内边距 `px-4 py-3`；`whitespace-pre-wrap` 是 textarea 默认行为，不用额外处理
- 按 `Tab` 插入两个空格（缩进是编辑器里的通用预期）；`Shift+Tab` 不拦截
- 不做行号（视觉噪音，本工具不是 IDE）

**状态栏**（`h-8`，`text-[11px] text-[#999999]`，`border-t`）：

- 左：「保存中…」/「已保存」/「保存失败，重试」——失败时文字变 `#B91C1C` 且整条可点（点一下立刻重存）
- 右：「128 字」+「复制」按钮 +「导出 .md」按钮（`h-6 px-2 text-[11px]`，透明底 hover `#F5F5F5`）

### 2.4 右栏：实时预览

- `bg-white`，内容区 `px-5 py-4`，自己滚（`overflow-y-auto`）
- 渲染结果外面包一层 `<div className="markdown-body">`，样式**只作用在预览区**（Tailwind 的 preflight 会把 h1 / ul / blockquote 的默认样式全清掉，不写这组样式，渲染出来的标题和正文一样大、列表没有点）：

| 元素 | 样式 |
|---|---|
| `h1` / `h2` / `h3` | `text-[22px]/[18px]/[15px] font-semibold`，上间距依次 24 / 20 / 16px，`leading-snug` |
| `p` | `text-[14px] leading-[1.7]`，段间距 12px |
| `ul` / `ol` | `list-disc` / `list-decimal` + `pl-5`，项间距 4px |
| `blockquote` | `border-l-2 border-[#DDDDDD] pl-3 text-[#666666]` |
| `code`（行内） | `rounded-[2px] bg-[#F5F5F5] px-1 py-0.5 font-mono text-[12px]` |
| `pre` | `overflow-x-auto rounded-[2px] bg-[#F5F5F5] p-3 font-mono text-[12px] leading-[1.6]`（**无高亮**） |
| `table` | `w-full border-collapse text-[13px]`，`th` / `td` `border border-[#ECECEC] px-2 py-1`，`th` `bg-[#FAFAFA] text-left` |
| `a` | `text-[#000000] underline underline-offset-2`（全站黑白灰，不给链接加蓝色） |
| `hr` | `my-4 border-[#F0F0F0]` |
| `input[type=checkbox]`（任务列表） | `mr-1.5 accent-[#000000]`，`li` 去掉 `list-none` |

- 空正文时预览区显示灰字「预览会显示在这里」（`text-[13px] italic text-[#C4C4C4]`）
- 不做滚动同步、不做目录、不做高亮

### 2.5 响应式（四档，都是独立版式，不是压缩）

全局侧边栏是 `lg`(1024) 起常驻、宽 80px。所以内容区宽度 = 视口 − 80（≥1024）/ 视口（<1024）。

| 档位 | 视口 | 版式 |
|---|---|---|
| 宽屏 | ≥ 1280 | **三栏**：列表 240 / 编辑 弹性 / 预览 弹性（编辑与预览各占一半，`md` 起固定 1:1） |
| 窄屏 PC | 1024 – 1279 | **两栏**：编辑 + 预览；列表收进抽屉（编辑区顶行的「文档」按钮打开） |
| 平板 | 768 – 1023 | **两栏**：编辑 + 预览（各最小 300）；列表走抽屉；工具栏按钮间距收紧、`Heading` 之后的按钮允许横向滚动 |
| 手机 | < 768 | **单栏 + 分段切换**：顶行「编辑 / 预览」两个 tab（分段控件，`rounded-[2px]` 底槽 `#F5F5F5`、选中项白底描边）；「文档」按钮打开**全屏列表**（不是抽屉叠在下面，是整页替换），顶部「← 返回」；左上角保留汉堡 |

- 三档以上用**互斥显隐**（`hidden xl:flex` / `xl:hidden`）而不是 JS 读视口——首屏 SSR 不闪（同《工具中心》的做法）
- 手机上「编辑 / 预览」是**二选一**，不是上下堆叠：375px 上下堆叠时两栏各只有 180px 高，谁都读不了
- 手机端的预览区字号整体上调一档（`p` 15px），远看才不费劲

## 三、数据模型

```sql
CREATE TABLE IF NOT EXISTS md_documents (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id    INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  title      TEXT    NOT NULL,
  body       TEXT    NOT NULL DEFAULT '',
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);

CREATE INDEX IF NOT EXISTS idx_md_documents_user_id ON md_documents(user_id);
```

设计要点：

- **`body` 存 Markdown 原文，不存渲染结果**：渲染结果是从原文算出来的派生物，存一份就有了「两份真相」，改了一处另一处不同步。渲染永远在客户端现算
- **`title` 是独立一列，不从正文推导**：列表要靠它显示，排序、搜索也都只认它。正文里写不写 `# 标题` 与它无关（写了只是渲染成一个大标题）
- **没有 `deleted_at`**：硬删 + 二次确认（同便签 / 保险库）。软删除会让这张表以后每条查询都带 `WHERE deleted_at IS NULL`
- **`updated_at` 每次保存都刷新**：它就是列表的排序依据，也是「这篇什么时候动过」的唯一事实
- **排序 `ORDER BY updated_at DESC, id DESC`**：末尾 `id DESC` 是毫秒撞车时的稳定兜底（《数据库/README》§六第 5 条）
- 长度上限：标题 60 字、正文 100000 字符——**只在校验层**（`lib/markdown/validate.ts`），表里 TEXT 不给约束（SQLite 的长度约束在改表时很麻烦，而这两个值以后可能调）

## 四、关键决策

| 决策点 | 选择 | 理由 | 否决的备选 |
|---|---|---|---|
| 页面形态 | **三栏、整页不滚、各栏自滚** | 写文档要同时看见「有哪些篇」「正在写什么」「写出来什么样」；滚动整页会让预览跟着原文跑掉 | 列表页 + 编辑页两跳（每次写都要走一次跳转）；只有编辑区没有列表（多篇就找不回来） |
| 编辑控件 | **原生 `<textarea>`** | 纯文本和 Markdown 是同一个东西，输入就是输出，不需要互转 | `contenteditable`（要维护 HTML↔Markdown 双向转换，是重写一个编辑器）；CodeMirror / Monaco（几十万行依赖，为一个个人笔记工具不值） |
| 预览渲染 | **`react-markdown` + `remark-gfm`** | 输出的是 React 元素树，**不需要 `dangerouslySetInnerHTML`**，所以原始 HTML 天然不渲染、没有 XSS 面 | 手写解析器（Markdown 规则远比想象多，还要自己管转义）；`markdown-it` + `dangerouslySetInnerHTML`（快，但要自己接一层 HTML 消毒）；服务端渲染预览（每次停手都要一次往返，实时感就没了） |
| 代码块高亮 | **不做** | 多一个高亮包 + 一套主题色，只为「把代码给外人看」这个场景服务 | `react-syntax-highlighter`（+ 几十 KB）；`shiki`（更重，还要加载主题） |
| 标题从哪来 | **独立输入框**，留空 →「未命名文档」 | 列表要显示标题、搜索也搜它；只从正文第一个 `#` 推导的话，不写 H1 的文档全叫未命名 | 只认正文 H1（用户不写 H1 就失控）；新建时弹窗先起名（多一步，名字往往是写完才想出来的） |
| 保存方式 | **防抖 800ms 自动保存** | 写作时脑子里不该有「保存」这个动作；800ms 是「一句话打完」与「别每个字都发请求」之间的折中 | 手动保存按钮（丢内容、多一个要想的动作）；每个按键都存（中文输入法一次拼字会触发多次，服务端被打爆） |
| 切换文档 | **切换前 `flush()` 立即补存** | 否则最后不到 0.8 秒的输入直接丢，而这类丢失用户不会立刻发现 | 只靠防抖（切走的那一下最容易丢）；弹「有未保存改动」确认（主人明确反感这类拦截：「我都要取消了，为什么还要保存」） |
| 删除 | **编辑区右上角垃圾桶 + 二次确认，硬删** | 删的是整篇文档，误删代价比便签大，所以确认框要带标题 | 列表行悬停下拉菜单（多一层菜单，悬停区域窄、误触率高）；回收站（软删除的代价见数据模型） |
| 排序 | **`updated_at DESC`，列表不可手动排** | 只有一个需求：「最近写的那篇在最上面」。自动保存天然让它浮到顶 | 按标题排（写的时候根本想不起名字）；手动拖拽排序（要给 `position` 列 + 批量重排） |
| 工具栏实现 | **9 个按钮 + 纯函数改写选区** | `applyFormat(text, selection, kind)` 是纯函数，能单测（含「已加粗再点一次取消」这种反向）；不弹窗、不引编辑器库 | 富文本工具条（内容就不是纯 Markdown 了，导出的 `.md` 会失真）；不做工具栏（主人明确要） |
| 工具栏按钮的焦点 | `onMouseDown` 里 `preventDefault()` | 点按钮会让 textarea 失焦、选区归零，格式就打到光标处而非选中的字上 | 用 `onClick`（选中的文字会被丢掉，表现为「粗体只作用在空处」） |
| Tab 键 | **插入两个空格** | 编辑器里 Tab 缩进是通用预期（Typora / VS Code 都这样），写列表缩进用得上 | 让焦点跳走（符合无障碍规范，但在正文里按 Tab 跳出去会很意外） |
| 手机预览 | **「编辑 / 预览」二选一** | 375px 上下堆叠时每栏只有 180px 高，两样都读不了 | 手机也双栏（文字挤成一条缝）；手机只给编辑（主人要的就是「实时预览」，砍掉等于砍需求） |
| 字数统计 | 做（状态栏一行） | 状态栏右边本来就是空的，`[...body].length` 一行代码；中文按字符数、emoji 记 1 个 | 做整页统计面板（要多一栏）；不做（顺手就有，没有理由拒绝） |

## 六、验收标准

**正常路径**

1. 打开 `/tools/markdown-editor`：三栏出现；列表空态「还没有文档」；编辑区标题框占位「未命名文档」、正文空；预览区「预览会显示在这里」；状态栏「已保存 · 0 字」。
2. 点「新建」→ 列表出现一行「未命名文档」，编辑区清空且标题框**获得焦点**（直接打字就是起名），地址栏不变（不跳路由）。
3. 标题框输入「周报」→ 停手约 1 秒 → 左栏那一行标题变成「周报」；刷新页面后仍叫「周报」。
4. 正文输入 `# 标题`、换行 `- 一`、换行 `- 二` → 预览区出现一个 `<h1>标题</h1>` 和一个含两项的 `<ul>`（检查 DOM 是标签，不是字面量）。
5. 正文输入两行表格（`| a | b |` / `| --- | --- |` / `| 1 | 2 |`）→ 预览渲染出 `<table>`（`remark-gfm` 生效的证据）。
6. 选中正文里的「标题」两个字，点 **B** → 原文变成 `# **标题**`，选区仍包住「标题」；再点一次 B → 恢复成 `# 标题`。
7. 光标停在空行点「标题」→ 行首出现 `# `；连点三次依次是 `## `、`### `；第四次回到无前缀。
8. 光标停在空行依次点「无序列表 / 有序列表 / 引用」→ 行首分别是 `- `、`1. `、`> `（每次先把上一行前缀删掉再点）。
9. 点「代码块」→ 正文插入三行（```` ``` ````/空行/```` ``` ````），**光标落在中间那行**（直接打字就是在代码块里写）。
10. 选中「链接文字」点「链接」→ 变成 `[链接文字](url)`，光标落在 `url` 上（直接打字即替换）。
11. 输入后状态栏先显示「保存中…」，约 1 秒后变「已保存」；右下角字数随输入变化（中文按字数、emoji 记 1）。
12. 点「复制 Markdown」→ 剪贴板里是**原文**（含 `#`、`-`、`**` 这些符号，不是渲染后的文字）；toast「已复制」。
13. 点「导出 .md」→ 下载 `<标题>.md`，内容与正文逐字一致；标题为空时文件名是「未命名文档.md」。
14. 建第二篇（标题「灵感」）→ 列表两行、「灵感」在最上面；先在「灵感」里打一段字，**立刻**点「周报」（不等保存）→ 再点回「灵感」，那段字还在（切换前已 flush）。
15. 点右上角垃圾桶 → 确认框写明「删除「灵感」？删除后无法恢复。」→ 确认 → 那一行消失、选中落到列表第一条；删光后回到空态。
16. 刷新页面：列表按「最近修改」倒序，每篇的标题与正文都在。

**负面路径**

17. 未登录直接访问 `/tools/markdown-editor` → 跳 `/login`。
18. 数据层单测：A 用户建两篇、B 用户查列表 → B 拿到 0 篇；B 用 A 的文档 id 保存 / 删除 → 影响行数 0，A 的行没变。
19. 正文里写 `<img src=x onerror=alert(1)>` → 预览区按**原文字面**显示这一段（不生成 img 元素），页面无弹窗、console 无报错。
20. 正文输入 100001 个字符 → 保存被服务端拒绝，状态栏显示「保存失败，重试」（红字）；删回 500 字后再输入一次 → 能存成功（不会卡死在失败态）。
21. 标题输入 61 个字 → 服务端拒绝，**输入不被清空**，状态栏显示失败；改短后能存成功。
22. 直接调 Server Action 传一个不存在的 id → 返回「文档不存在」，不抛未捕获异常。
23. 断网状态下输入 → 状态栏「保存失败」；恢复网络后再输入一个字 → 变回「已保存」，内容完整。

**响应式**

24. 1440px：三栏并排（列表 240 / 编辑 / 预览各半）；滚编辑区时整页不动（只有编辑区滚）。
25. 1100px：列表消失、编辑区顶行出现「文档」按钮；点它抽屉滑出、选一篇后抽屉自动关闭并切换。
26. 900px：仍是双栏；点工具栏右端的「预览」开关 → 预览收起、编辑区占满；再点恢复。
27. 375px：单栏 + 顶部「编辑 / 预览」分段切换；切到「预览」看到渲染结果、切回「编辑」内容还在；「文档」按钮打开全屏列表，顶部「← 返回」能回到编辑；左上角有汉堡并能打开全局侧边栏。
28. 375px 聚焦正文输入框：**页面不放大**（输入框 `font-size` 是 16px）。

**门禁**

29. `pnpm exec next typegen` / `pnpm typecheck` / `pnpm lint` / `pnpm test` / `pnpm build` 全过；`build` 不因 `react-markdown` 是纯 ESM 包报错。
30. 单测覆盖：`applyFormat` 的 9 种语法（选区为空 / 有选区 / 已加粗再点取消 / 选区跨多行）、标题为空补「未命名文档」且重名补序号、标题 60 与正文 100000 的边界、`user_id` 隔离、排序（`updated_at` 倒序 + id 兜底）、保存只刷新 `updated_at` 不动 `created_at`。

## 七、已知的坑

| 坑 | 机制 | 对策 |
|---|---|---|
| `react-markdown` 不接受 `className` | v9 起收紧了 props，`className` 传不进去（类型报错或静默忽略） | 外面包一层 `<div className="markdown-body">`，样式挂在这个 div 上 |
| 预览样式被 Tailwind preflight 抹平 | preflight 把 `h1` 字号、`ul` 的 `list-style`、`blockquote` 缩进全清零了，渲染出来和正文一样大、列表没点 | 预览区用 `.markdown-body` 作用域写一组元素样式（§2.4 的表），只影响预览区，不污染全站 |
| 手机上聚焦输入框整页放大 | iOS 对 `font-size < 16px` 的输入控件聚焦时会自动缩放 | 标题与正文在 `< sm` 用 16px，`sm:` 起回到 18px / 13px mono |
| 点工具栏按钮后格式打到光标处 | 按钮拿到焦点、textarea 失焦，`selectionStart/End` 归零 | 按钮 `onMouseDown` 里 `preventDefault()`，让 textarea 保持焦点与选区 |
| 切换文档丢最后一段 | 防抖计时器还没到就已经切走 | hook 暴露 `flush()`；切换 / 删除 / 卸载前都先调它；用 ref 持有最新 timer 与内容 |
| 保存请求乱序覆盖 | 慢请求后到，旧内容盖掉新内容 | 客户端串行：有请求在飞时不发新的，落地后若内容又变了再补一次；每次带递增 `revision`，丢弃过期响应 |
| 中文输入法把半截拼音存进去 | 拼字过程中 `onChange` 就会触发 | `compositionstart` 期间暂停防抖、`compositionend` 后再启动 |
| 长文档预览卡顿 | 每个字符都重新解析整篇 Markdown | 预览只吃「防抖后的文本」，用 `useMemo` 按快照算，不跟每个按键 |
| 保存后列表整条重拉打断输入 | 重新拉列表会让正在编辑的行卸载重挂，焦点与滚动位置丢失 | 保存成功后**只本地更新那一行**（标题 + 时间 + 提到最前），不重拉整个列表 |
| 自动保存让列表每 0.8 秒跳一次 | 正在编辑的这篇 `updated_at` 一直刷新 | 它本来就在最前，不跳；但 `id DESC` 兜底必须写，否则同一毫秒内两篇会互换 |
| Tab 键把键盘用户困住 | 正文里 Tab 被吃掉，无法移出输入框 | 只在正文 textarea 的 keydown 里拦截 Tab；工具栏按钮仍能用 Tab 遍历，`Esc` 后可用鼠标离开 |
| 导出文件名带非法字符 | 标题里可能有 `/`、`:`、`?` | 文件名里 `\ / : * ? " < >` 与竖线一律替换成 `-`，为空则「未命名文档」 |
| 时间显示跨时区漂移 | 服务端容器是 UTC | 复用 `src/lib/format.ts` 的 `formatDateTime`，不自己拼 |
| 纯 ESM 包构建报错 | `react-markdown` v10 只发 ESM | 先在客户端组件里直接 import 跑 `pnpm build`；只有在报错时才去 `next.config.ts` 加 `transpilePackages`（能不配就不配） |
| 演示数据残留 | 手测时建的「周报」会被当成真文档 | 验收结束前删掉测试文档（或换测试账号） |

## 八、依赖变更

**新增两个运行时依赖**（先登记进《技术栈说明》，再安装）：

| 包 | 版本（安装时锁定） | 用途 |
|---|---|---|
| `react-markdown` | `10.1.0` | Markdown → React 元素树（不经过 HTML 字符串，天然无 XSS 面） |
| `remark-gfm` | `4.0.1` | GitHub 风格扩展：表格、任务列表、删除线、自动链接 |

两者都是纯前端、纯 JS、无原生模块，只在工具页的客户端组件里 import（不放进公共组件，避免拖累全站首屏）。

**不引入**：代码高亮（`react-syntax-highlighter` / `shiki`）、编辑器内核（CodeMirror / Monaco）、拖拽库——理由见「关键决策」与「主动放弃」。
