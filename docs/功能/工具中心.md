# 工具中心

| 状态 | 开始日期 | 最近更新 |
|---|---|---|
| ✅ 已完成 | 2026-10-16 | 2026-10-30 |

> 一句话：工具目录**只收真能用的工具**（当前 5 个），没实现的干脆不进目录；分类筛选条保留七个分类当路线图，选到还没做的那一类时给一句占位提示，不留空白。

---

## 一、要什么

`/tools` 是外壳里的第一个真实页面：工具中心的**界面与「搜索 / 分类筛选」功能**。工具卡统一链到 `/tools/<slug>`，五个工具（便签 / 待办 / 工作日历 / 保险库 / 图片压缩）各有自己的静态路由。

**做：**

- 工具目录**只收已实现的工具**（当前 5 个）：名称、描述、Lucide 图标、分类（图片 / 文件 / 文本 / 开发 / 媒体 / AI / 生活）
- 搜索：匹配名称、描述、分类三处，忽略大小写，输入即时过滤
- 分类筛选：8 个选项（全部 + 7 类），选中项黑底反白
- 三档响应式（严格照旧界面）：
  - ≥ xl：页头右侧完整搜索胶囊（白底输入框）+ 分类按钮并排
  - lg ~ xl：搜索收成一个图标按钮（点开才出现输入框）、分类收成黑底下拉菜单
  - < lg：页头只剩搜索图标；内容区顶部出现分类 chips 横滑条，点搜索图标在下方展开搜索条
- 分组展示：按分类分组，组标题带计数（黑色短竖条 + 计数）
- 空态分两种（见 §二）：搜不到 →「未找到匹配的工具」；选中的分类本来就没工具 →「这个分类还没有可用的工具」，并给一个「看全部工具」的出口

**主动放弃（本版不做，不是遗漏）：**

| 放弃项 | 原因 |
|---|---|
| 收藏 / 排序 / 最近使用 | 旧界面没有，不加 |
| 服务端搜索 | 5 条静态数据，客户端即时过滤足够；等工具目录进数据库时重新评估 |

## 二、界面

路由 `/tools`。页头（规范 §7.10）右侧按上表三档放搜索控件；内容区结构：

```
内容区（px-4 py-4 md:px-6 md:py-6，分组式长页面 space-y-8）
├─ 分组 section（space-y-3）
│   ├─ 组标题：黑竖条 + 分类名 + 计数
│   └─ 网格（grid-cols-1 → sm:2 → lg:3 → xl:4，gap-3）
│       └─ 工具卡（白卡 p-4：图标块 h-10 w-10 + 名称 + 描述）
└─ 空态（虚线框，两种情况见下）
```

工具卡图标为黑白单色（浅灰图标块 + `text-[#1F1F1F]` 图标，hover 反色为黑底白图标）；**默认灰卡**：`bg-[#F5F5F5]` 卡 + `bg-[#ECECEC]` 图标块，文字保持全对比；**hover 转白卡**（`hover:bg-white`）。**卡片不带任何状态角标**——目录里全是能用的工具，没有区分的对象。

**空分类的占位块**（2026-10-30 起）：选中一个还没有工具的分类时，组标题照常显示（含「0」计数），下面是一个 `rounded-[2px] border border-dashed border-[#D9D9D9] bg-white px-6 py-10 text-center` 的虚线框：主句 `text-sm text-[#666666]`「这个分类还没有可用的工具」，副句 `mt-1.5 text-xs text-[#A0A8B4]`「工具会一个个做出来，先看看别的分类」，再加一个 `mt-3 text-xs font-medium text-[#000000] underline-offset-2 hover:underline` 的「看全部工具」文字按钮（点了回到「全部」）。

搜索无结果时是另一句话：**「未找到匹配的工具」**，不带副句和按钮——「没做」和「没搜到」是两件事，不该共用一句文案。

## 三、数据模型

不涉及。工具目录暂为**前端静态数据**，住在 `src/components/tools/tool-catalog.ts`（含类型）。

**为什么暂不进 `lib/`**：这份数据里带着 React 组件引用（Lucide 图标），而 `lib/` 的红线是不许 import 组件。等目录变成数据库数据时，数据访问进 `lib/tools/`，组件层只读不写。

## 四、关键决策

| 决策点 | 选择 | 理由 | 否决的备选 |
|---|---|---|---|
| 工具卡图标的颜色 | **黑白单色**，与运行中的旧界面一致 | 2026-10-16 实测旧界面：卡片是「灰底 #F5F5F5 + 深图标 #1F1F1F、hover 反色」；旧数据里的色板字段（`-500`～`-800`）从未被渲染。规范 §10 原写「一工具一色为唯一彩色例外」与现实不符，已按实物修正 | 按 §10 旧文做彩色图标（与实物不符、违反黑白灰基调） |
| 搜索在哪过滤 | 客户端即时过滤（`useMemo`） | 数据量小、零请求、跟手；旧界面即如此 | 服务端搜索（当前无库表，徒增接线） |
| 过滤 / 分组逻辑放哪 | 拆成纯函数 `tool-filter.ts` + 单元测试 | 逻辑可被测试锁定（字面量、大小写、空结果边界），不靠手点 | 内联在组件里（不可测） |
| 选中分类但该分类没有工具 | 保留分组标题与「0」计数，下面给占位块（说明 + 「看全部工具」） | 组标题还在，用户知道自己没点错分类；一句话说明「这一类还没做」，比一块留白诚实 | 只剩一个空网格（看着像加载失败）；自动跳回「全部」（用户点了个分类又被弹回去，更困惑） |
| 手机搜索框字号 | 16px（`text-base`，md 起回落 14px） | 规范 §7.16 的 iOS 规则：输入框 < 16px 时聚焦会放大整页。旧界面此处是 14px，属**刻意修正**（桌面无感，手机受益） | 照抄 14px（iOS 聚焦缩放，体验差） |
| 目录要不要留占位条目 | **不留**：没实现的工具不进目录 | 60 条里 55 条是占位，点进去只有一句「该工具开发中...」——卡片长得一模一样，用户分不出哪个能用，等于每次都要试错一遍。**「能不能用」应该在目录这一层就筛掉，而不是画个角标让用户自己认** | 保留占位 + 角标区分（试过两版角标：图标块上的黑圆白对勾、卡片右上角的「可用」文字标签，都被否——「还是太丑」）；占位卡标灰（55 张灰卡把整片网格弄脏） |
| 七个分类留不留 | **全留**，选到空分类给占位提示 | 分类是**路线图**不是货架：删掉「文件」「AI」这些空分类，等于顺手把「以后做不做这一类工具」的决定也删了。空着不给话才是最难看的状态 | 分类条只显示当前有工具的分类（分类数随工具增减而变，用户下次找不到「文件」在哪）；空分类直接留白（像加载失败） |

## 六、验收标准

| # | 操作 | 期望 |
|---|---|---|
| 1 | 打开 `/tools` | 5 个工具按分类分组显示：**图片 1**（图片压缩）、**文本 2**（待办 / 便签）、**生活 2**（工作日历 / 保险库）；其余四个分类不出现分组 |
| 2 | 搜索「图片」 | 只剩名称 / 描述 / 分类命中「图片」的项；分组与计数随之更新 |
| 3 | 分类 =「全部」时搜索不存在的词 | 空态：「未找到匹配的工具」 |
| 4 | 先选分类「文件」再搜索无结果的词 | 仍显示「文件」组标题、计数 0，占位块文案是**「未找到匹配的工具」**（搜索无结果，不是这一类没做） |
| 5 | 点分类「生活」 | 只剩生活组 2 项（工作日历 / 保险库）；点「文本」是待办 / 便签 2 项 |
| 6 | 缩到 lg ~ xl（如 1100px） | 页头搜索收成图标；点开出现输入框；分类变成黑底下拉，点选生效 |
| 7 | 缩到 < lg（如 390px） | 页头只剩搜索图标；内容区出现 chips 横滑条；点搜索图标展开搜索条；点分类 chip 过滤 |
| 8 | 大小写混合搜索（如 `gif` / `GIF`） | 结果一致（大小写不敏感） |
| 9 | 点击任一工具卡 | 地址变成 `/tools/<slug>`，进对应的真页面（5 个都有静态路由）；手工改成不存在的 slug → 404 |
| 9b | 点分类「文件」（空分类） | 出现占位块：「这个分类还没有可用的工具」+「工具会一个个做出来，先看看别的分类」+「看全部工具」；点「看全部工具」回到「全部」，5 个工具重新出现 |
| 10 | 未登录直接访问 `/tools` | 跳转到 `/login` |

## 七、已知的坑

| 坑 | 机制与对策 |
|---|---|
| 手机 chips 横滑条露出滚动条 | 隐藏滚动条（`[scrollbar-width:none]` + `[&::-webkit-scrollbar]:hidden`），并左右出血到屏边（`-mx-4 px-4`） |
| 搜索匹配包含分类名 | 是旧行为：搜「图片」会把整个「图片」分类全捞出来。复刻，不当 bug 改 |
| 空分类只有组标题、没有内容 | `groupTools` 在选中具体分类时**总是返回该组**（哪怕为空），所以空分类会渲染出一个组标题 + 空网格 | 组内 `items.length === 0` 时渲染占位块（文案按是否在搜索分两种）；顶层「无任何分组」的空态仍然管搜索无结果的另一条路径 |
| 三个响应式档位互相嵌套 | 用互斥显隐（`hidden xl:flex` / `hidden lg:flex xl:hidden` / `lg:hidden`）而不是 JS 断点判断——首屏 SSR 就不会闪 |
| 全角 / 空格输入 | 搜索词先 `trim()` 再匹配（空串 = 不过滤） |
