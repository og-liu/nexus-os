# 工具中心

| 状态 | 开始日期 | 最近更新 |
|---|---|---|
| ✅ 已完成 | 2026-10-16 | 2026-10-16 |

> 一句话：把旧界面的「小工具集合」页按原样迁移进来——工具目录展示、分类筛选、搜索；工具卡本身仍不可点，便签 / 待办两个真工具的入口在首页常驻卡。

---

## 一、要什么

`/tools` 是外壳里的第一个真实页面：完整迁移旧界面工具中心的**界面与「搜索 / 分类筛选」功能**，工具卡片保持不可点。便签 / 待办两个工具已有真实功能，入口在首页常驻卡的「管理 →」；工具详情页与卡片点击留给后续统一设计。

**做：**

- 58 个工具的目录：名称、描述、Lucide 图标、状态（可用 / 开发中）、分类（图片 / 文件 / 文本 / 开发 / 媒体 / AI / 生活）
- 搜索：匹配名称、描述、分类三处，忽略大小写，输入即时过滤
- 分类筛选：8 个选项（全部 + 7 类），选中项黑底反白
- 三档响应式（严格照旧界面）：
  - ≥ xl：页头右侧完整搜索胶囊（白底输入框）+ 分类按钮并排
  - lg ~ xl：搜索收成一个图标按钮（点开才出现输入框）、分类收成黑底下拉菜单
  - < lg：页头只剩搜索图标；内容区顶部出现分类 chips 横滑条，点搜索图标在下方展开搜索条
- 分组展示：按分类分组，组标题带计数（黑色短竖条 + 计数），空搜索无结果给空态（虚线框「未找到匹配的工具」）

**主动放弃（本版不做，不是遗漏）：**

| 放弃项 | 原因 |
|---|---|
| 工具执行本身（除便签 / 待办外的工具） | 本阶段只迁移界面；每个工具是一个独立功能，随用随做 |
| 卡片点击动作 | 统一不给点击效果——与旧界面一致（旧界面同样点击无动作） |
| 收藏 / 排序 / 最近使用 | 旧界面没有，不加 |
| 服务端搜索 | 58 条静态数据，客户端即时过滤足够；等工具目录进数据库时重新评估 |

## 二、界面

路由 `/tools`。页头（规范 §7.10）右侧按上表三档放搜索控件；内容区结构：

```
内容区（px-4 py-4 md:px-6 md:py-6，分组式长页面 space-y-8）
├─ 分组 section（space-y-3）
│   ├─ 组标题：黑竖条 + 分类名 + 计数
│   └─ 网格（grid-cols-1 → sm:2 → lg:3 → xl:4，gap-3）
│       └─ 工具卡（白卡 p-4：图标块 h-10 w-10 + 名称 + 描述）
└─ 空态（无匹配时）：虚线框「未找到匹配的工具」
```

工具卡图标为黑白单色（浅灰图标块 + `text-[#1F1F1F]` 图标，hover 反色为黑底白图标）；**默认灰卡**：`bg-[#F5F5F5]` 卡 + `bg-[#ECECEC]` 图标块，文字保持全对比；**hover 转白卡**（`hover:bg-white`）。不按「可用 / 开发中」做视觉区分（2026-10-16 迭代）。

---

## 三、数据模型

不涉及。工具目录暂为**前端静态数据**，住在 `src/components/tools/tool-catalog.ts`（含类型）。

**为什么暂不进 `lib/`**：这份数据里带着 React 组件引用（Lucide 图标），而 `lib/` 的红线是不许 import 组件。等目录变成数据库数据时，数据访问进 `lib/tools/`，组件层只读不写。

## 四、关键决策

| 决策点 | 选择 | 理由 | 否决的备选 |
|---|---|---|---|
| 工具卡图标的颜色 | **黑白单色**，与运行中的旧界面一致 | 2026-10-16 实测旧界面：卡片是「灰底 #F5F5F5 + 深图标 #1F1F1F、hover 反色」；旧数据里的色板字段（`-500`～`-800`）从未被渲染。规范 §10 原写「一工具一色为唯一彩色例外」与现实不符，已按实物修正 | 按 §10 旧文做彩色图标（与实物不符、违反黑白灰基调） |
| 搜索在哪过滤 | 客户端即时过滤（`useMemo`） | 数据量小、零请求、跟手；旧界面即如此 | 服务端搜索（当前无库表，徒增接线） |
| 过滤 / 分组逻辑放哪 | 拆成纯函数 `tool-filter.ts` + 单元测试 | 逻辑可被测试锁定（字面量、大小写、空结果边界），不靠手点 | 内联在组件里（不可测） |
| 选中分类且搜索无结果时 | 保留分组标题与「0」计数 | **照搬旧行为**（旧代码：选分类时始终返回该组）——迁移期以「一模一样」优先 | 统一显示空态（与旧界面不一致） |
| 手机搜索框字号 | 16px（`text-base`，md 起回落 14px） | 规范 §7.16 的 iOS 规则：输入框 < 16px 时聚焦会放大整页。旧界面此处是 14px，属**刻意修正**（桌面无感，手机受益） | 照抄 14px（iOS 聚焦缩放，体验差） |
| 「可用 / 开发中」要不要视觉表达 | 不上：卡片统一为同一种呈现（2026-10-16 迭代：默认实灰卡 + 全对比文字，hover 转白卡） | 灰白之分容易被误读成「可用 / 不可用」两档。便签 / 待办已有真实动作，但其余工具仍是占位；状态字段保留在数据里，不靠颜色区分，等可用工具多到需要筛选时再设计 | 状态圆点 / 角标（当前只有一个「可用」档，做出来也只能表达「这两个不一样」） |

## 六、验收标准

| # | 操作 | 期望 |
|---|---|---|
| 1 | 打开 `/tools` | 58 个工具按 7 个分类分组显示，组标题含计数（12 / 8 / 10 / 8 / 6 / 5 / 9） |
| 2 | 搜索「图片」 | 只剩名称 / 描述 / 分类命中「图片」的项；分组与计数随之更新 |
| 3 | 分类 =「全部」时搜索不存在的词 | 空态：「未找到匹配的工具」 |
| 4 | 先选分类「文件」再搜索无结果的词 | 仍显示「文件」组标题、计数 0（复刻旧行为，不是 bug） |
| 5 | 点分类「媒体」 | 只剩媒体组 6 项 |
| 6 | 缩到 lg ~ xl（如 1100px） | 页头搜索收成图标；点开出现输入框；分类变成黑底下拉，点选生效 |
| 7 | 缩到 < lg（如 390px） | 页头只剩搜索图标；内容区出现 chips 横滑条；点搜索图标展开搜索条；点分类 chip 过滤 |
| 8 | 大小写混合搜索（如 `gif` / `GIF`） | 结果一致（大小写不敏感） |
| 9 | 点击任一工具卡 | 无任何动作（预期如此——本版不给点击效果） |
| 10 | 未登录直接访问 `/tools` | 跳转到 `/login` |

## 七、已知的坑

| 坑 | 机制与对策 |
|---|---|
| 手机 chips 横滑条露出滚动条 | 隐藏滚动条（`[scrollbar-width:none]` + `[&::-webkit-scrollbar]:hidden`），并左右出血到屏边（`-mx-4 px-4`） |
| 搜索匹配包含分类名 | 是旧行为：搜「图片」会把整个「图片」分类全捞出来。复刻，不当 bug 改 |
| 工具卡的状态 | 便签 / 待办已可用，但卡片仍**不做视觉区分**（全部同一种呈现）——「可用 / 开发中」只留在数据里；两个真工具的入口在首页常驻卡，工具卡本身仍不可点 |
| 三个响应式档位互相嵌套 | 用互斥显隐（`hidden xl:flex` / `hidden lg:flex xl:hidden` / `lg:hidden`）而不是 JS 断点判断——首屏 SSR 就不会闪 |
| 全角 / 空格输入 | 搜索词先 `trim()` 再匹配（空串 = 不过滤） |
