## 一、产品定位

Nexus OS 是一个面向个人用户打造的智能工作空间（Personal Digital Operating System），将日常工具、自动化流程、知识管理以及 AI Agent 能力整合到统一平台中。

> 让工具成为能力，让 AI 成为助手，让个人数据真正服务于自己。

它不是六个独立功能的拼盘，而是一条围绕「个人信息」运转的流水线：**信息进来 → AI 加工 → 沉淀成知识 → 随时调取与对话 → 自动运转**。工具中心、文件管理是手脚，知识库是记忆，AI Agent 是大脑，自动化是神经。

---

## 二、核心理念：人和 AI 一起管知识

整条产品流水线里，人和 AI 的分工是确定的：

1. **采集（AI 主导）**：从网页、订阅源、手动粘贴把信息抓进来
2. **审查（人主导）**：快速过一遍，拍板"留还是弃"——这是人的把关价值
3. **整理（AI 主导）**：提炼要点、自动分类打标签、关联已有内容、去重
4. **入库**：沉淀为结构化知识
5. **阅读 + 微调（人主导）**：日常主要是读，需要时改几笔，而不是从头写

> 编辑器是次要的，采集和整理才是流水线主角。用户干的主要是"阅读"和"微调"。

## 三、四个目的（分两个时间层）

### 当前这一版就要落地
1. **面试作品** —— 跳槽转岗展示 Agent 开发能力，要专业，不做粗糙 demo。
2. **学透 Agent 开发** —— 把 Agent 各模块真正用一遍、走通全流程，融会贯通。
3. **真实可用** —— 自己正学 AI 知识，拿它采集、整理、翻阅，能扛事，不是空架子。

### 远期愿景（当前版不交付）
4. **上线盈利** —— 未来做成可上线、多人使用的成熟产品。

## 四、已定决策

- **载体与客户端**：纯 Web 端，响应式 + 移动端样式，电脑和手机都能看；不做独立 App、不做小程序
- **登录注册**：第一版完全不碰，单用户；未来若追第四目的再扩展多用户
- **视觉风格**：macOS 原生浅色系，沿用项目现落地的黑白灰极简风
- **AI 能力来源**：第一版不自研大模型，接入已备案的第三方大模型 API（以服务商备案号 + 合同过审）
- **包管理与工程规范**：pnpm（`packageManager: pnpm@10.34.5`），禁用 npm/yarn；编码遵循 AGENTS.md，Next.js 16 有 breaking changes，写码前先读 `node_modules/next/dist/docs/`

## 五、模块与能力地图

Nexus OS 现有六个模块。下表把产品要做的事落进每个模块，标注它在流水线中的位置和对标的 AI/Agent 技术。

### 工具中心 `/tools` —— 能力底座
已落地 59 个工具卡片（当前均为 mock），未来承载：
- 图片处理、文件批处理、OCR、格式转换、文本处理等效率工具
- 统一的工具注册 / 参数校验 / 执行调度引擎（v0.2.0）
- 作为 AI Agent 的"手"——Agent 自动选择并调用这里的工具
- 远期 Skill / 插件能力（造、装、对外发布）

### 文件管理 `/files` —— 数据底子
- 本地目录浏览（树 / 列表）、文件预览（图片 / 文本 / PDF）、批量操作
- 文件名 + 内容搜索、以图找图
- 是知识库内容、工具产物、配置的物理存储底座

### 知识库 `/knowledge` —— 产品主阵地
对应核心理念的采集→审查→整理→阅读，是信息沉淀与查阅的中心：
- **采集层**：网页/链接抓取、订阅源聚合（如技术晨报定时抓前端+AI 圈生成三分钟速览）、手动丢链接/粘贴
- **审查层（收件箱 Inbox）**：抓回的内容先入 Inbox，快速预览、"留/弃"拍板
- **整理层（AI 加工）**：长文压成结构化条目（要点+标签+待办）、自动归档打标签、新旧内容自动关联、重复内容去重合并、保鲜扫描标记过时内容
- **阅读层**：干净阅读视图、关键词检索 + 语义搜索、关联知识图谱、离线可读（PWA）
- **微调层**：轻量编辑，改 AI 初稿

### AI Agent `/agent` —— 大脑
不只是聊天机器人，而是能理解需求、调工具、执行多步任务的助手：
- **核心交互**：内置对话框，问答"知识库优先"——先查库，命中就基于库答（RAG），不够才联网
- **输出辅助**：基于库内内容写文章 / 总结 / 备稿
- **主动推荐**：记住关注点，主动推相关条目（长期记忆 / 个性化）
- **自主任务**：一句话多步整理（如"把这周采集的前端文章归类提炼落盘"，Agent 自己规划筛选→归类→提炼→落盘）
- 内部链路：意图理解 → 任务规划 → 工具调用协调 → 结果汇总（详见 agent-design.md）

### 自动化 `/automation` —— 神经
让机器定时自己转，对应所有"定时 + 判断 / 总结"类场景：
- 定时采集（订阅源 → 技术晨报）
- 保鲜扫描（定期标记过时/失效内容提示归档）
- 每日 / 每周综述（把近期采集自动生成小结）
- 智能复习（按遗忘曲线提示该回顾的条目）
- 测验自测（拿库内内容出题、闪卡，配遗忘曲线，形成学习闭环）

### 设置 `/settings` —— 配置中枢
- AI 模型接入与切换、API Key 配置
- 工具目录、数据源、用户偏好

## 六、各模块的协作关系

模块不是孤立的，一次典型使用会横跨多个模块：

```
订阅源更新 (automation 定时触发)
    → 抓取网页 (tools 网络能力)
    → 入 Inbox 等人审查 (knowledge)
    → 人点"保留"，AI 提炼/打标签/关联 (knowledge + agent 推理)
    → 沉淀为知识条目 (files 存储 + 向量索引)
    → 人在 agent 对话框提问，RAG 命中库内内容回答 (agent)
    → 到周末 automation 自动出综述、推遗忘曲线复习项 (automation)
```

这张图也是判断功能"该放哪个模块"的依据：**内容本身的进出与查阅在 knowledge，跟内容对话和多步操作在 agent，定时自动转的在 automation，文件物理存取在 files，可复用的原子能力在 tools。**

## 七、阶段路线图（产品视角）

技术版本节奏以 roadmap.md 为准（v0.1.0 → v1.0.0）。从产品学习主线看，推进顺序遵循「先扫盲、再决策、后动手，学习与开发绑定走」：

1. **是什么** ✅ 定位、模块地图、业务场景
2. **产出原型** ✅ 已做过高保真可交互原型，对齐了产品形态；并已将知识页 7 section（知识流/我的文章/收件箱/回收站/订阅源/自测/回顾）与 Agent 对话页落进 Nexus OS 为 UI mock（纯前端、无真实存储/AI）
3. **认知地图**：每个板块用什么技术、主流方案扫盲
4. **工具选型**：用什么来做这个项目（AI IDE / 框架等）
5. **交接方案**：定交接载体（文档 / 提示词 / spec），边聊边沉淀
6. **定地基**：数据存哪、内容格式、怎么组织（影响架构最大）
7. **定技术栈**：大模型 API、RAG 切块与向量方案、Agent 框架
8. **划 MVP + 排迭代**：圈第一版范围，分 MVP 内 / 后
9. **MVP 实现**：存储→检索→采集→整理串成一条（"存进去找得到"）
10. **迭代一**：灵魂闭环（RAG 知识库问答 + 测验自测）
11. **迭代二**：补边（保鲜归档 / 关联图谱 / 分享导出 / 离线可读）+ Skill 能力
12. **收尾**：作品整理 + 复盘（不急着上线）

> 这条产品主线与 roadmap.md 的工程版本是映射关系而非两套独立排期：MVP 实现主要落在 v0.5.0（知识库）并依赖 v0.3.0（文件）、v0.4.0（Agent）打底。
