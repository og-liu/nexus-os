## 一、产品定位（一句话）

Nexus OS 是一个面向个人用户打造的智能工作空间，将日常工具、自动化流程、知识管理以及 AI Agent 能力整合到统一的平台中。 让工具成为能力，让 AI 成为助手，让个人数据真正服务于自己。

---

## 二、核心工作流（产品的灵魂）

1. **采集**：AI 帮你从网上抓取好内容（网页、订阅源、你丢进来的链接）
2. **审查**：你快速过一遍，拍板"留还是弃"——这是人的价值所在（把关）
3. **整理**：AI 把散内容归纳成结构化条目、自动分类打标签、跟库里已有内容关联
4. **入库**：放进知识库
5. **阅读 + 微调**：你大部分时间就是读，需要时改几笔

> 关键：你干的主要是"阅读"和"微调"，不是"从头写"。编辑器是次要的，采集和整理才是这台"流水线"的主角。

---

## 三、四个目的（分两个时间层）

### 这一版就要落地
1. **面试作品** —— 跳槽转岗时展示 Agent 开发能力，要专业，不做粗糙 demo。
2. **学透 Agent 开发** —— 把 Agent 各个模块真正用一遍、走通全流程，融会贯通。
3. **真实可用** —— 自己正学 AI 知识，拿它采集、整理、翻阅，能扛事，不是空架子。

### 远期愿景（当前版不交付）
4. **上线盈利** —— 未来做成可上线、多人使用的成熟产品盈利，对标印象笔记类产品。

> 关键提醒：第四条是「远期愿景」，别拿它来要求第一版，否则需求会无限膨胀。

## 四、与 Nexus OS 的关系（融合映射）

知识库不再单独建站，而是作为 Nexus OS 工作台的一块核心拼图。Nexus OS 现有模块与知识库功能的对应关系如下：

| Nexus OS 模块 | 当前状态 | 承载的知识库功能 |
| --- | --- | --- |
| `/knowledge` 知识 | 空壳占位（PageHeader + "开发中..."） | 采集、审查收件箱、整理、阅读视图、关联图谱 |
| `/agent` Agent | 空壳占位 | 知识库优先问答（RAG）、自主任务（一句话多步整理） |
| `/automation` 自动 | 空壳占位 | 定时采集（技术晨报）、保鲜扫描、每日/每周综述、智能复习 |
| `/files` 文件 | 空壳占位 | 数据底子（条目存储、文件组织） |
| `/tools` 工具 | 已完成（59 工具 mock） | 未来承载 Skill / 工具挂载入口 |
| `/settings` 设置 | 框架（AI 模型 + 工具目录占位） | AI 模型配置、数据源配置 |

**几个结论**：
- 知识库的「数据底子」在 Nexus OS 里目前**还是空白**，需从零定地基（对应路线图「定地基」阶段）。
- 三个空壳模块（knowledge / agent / automation）正好对应知识库的「采集—问答—自动化」三条主线，是后续开发的主要落点。
- `/tools` 已有一批 mock 工具，可与「Skill 工作台 / 本地挂载」思路合并，作为能力扩展层。

## 五、已定决策

- **产品名**：智能知识库（2026-08-23 定名）；载体为 Nexus OS 工作台（2026-08-24）
- **客户端**：Web 端，并入 Nexus OS；**放弃 uniapp X 做独立 App**（2026-08-24）
- **响应式**：必须响应式 + 移动端样式，电脑和手机都能看、随时翻（保留，不做多端 App）
- **登录注册**：第一版完全不碰（2026-08-23 拍板）
- **数据模型**：第一版单用户；未来若追逐第四目的，可扩展多用户
- **视觉风格**：macOS 原生浅色系。⚠️ 原定「浅青白底 #F4FBFA + 主色 #2D8C87」与 Nexus OS 现落地「黑白灰」存在冲突，**待拍板**（见「待讨论清单」）
- **Skill 能力**：第一版做「Skill 工作台（造）+ 本地目录挂载（装）」，不做开放市场；支持把 Skill 发布到第三方平台（扣子商店 / ClawHub）

## 六、功能地图（含 Agent 技术对标）

> 每项功能后「→」标注它对标的 Agent / AI 技术；「［模块］」标注它在 Nexus OS 中的落点。

**采集层**［/knowledge］
- 网页 / 链接抓取 → 工具调用（联网）
- 订阅源聚合（技术晨报：定时抓前端+AI 圈 → 三分钟速览）→ 定时 + 工具调用 + 总结［/automation］
- 手动丢链接 / 粘贴内容 → 输入

**审查层（收件箱）**［/knowledge］
- Inbox 快速"留 / 弃" → 人把关
- 快速预览 → 界面

**整理层（AI 加工 · 价值重头）**［/knowledge］
- 自动提炼：长文 / 网页压成结构化条目（要点+标签+待办）→ LLM 总结 / 抽取
- 自动归档打标签 → 分类判断
- 自动关联：新旧内容自动串连 → 向量检索 / 知识关联
- 去重合并：重复内容自动识别合并 → 判断 / 去重
- 保鲜扫描：定期标记过时 / 失效内容，提示归档 → 定时 + 判断［/automation］

**阅读层（主动作）**［/knowledge］
- 干净阅读视图 → 界面
- 关键词检索 + 语义搜索 → 检索（关键词 + 向量）
- 关联图谱：可视化知识关联网络，点块跳转 → 向量检索 / 知识关联
- 离线可读：没网也能翻 → 本地缓存 / PWA

**对话问答层（核心交互）**［/agent］
- 内置对话框 → 界面
- 知识库优先问答（RAG：先查库，够用就基于库答，不够才联网）→ 检索增强 + 生成
- 输出辅助：基于库内内容写文章 / 总结 / 备稿 → 检索 + 生成
- 主动推荐：记住关注点，主动推相关条目 → 长期记忆 / 个性化

**回顾层（AI 主动喂你）**［/automation］
- 智能复习：按遗忘曲线提示该回顾的条目 → 记忆 / 计划
- 每日 / 每周综述：定期把近期采集生成小结 → 定时 + 总结
- 测验自测（学习闭环）：拿库内内容出题、出闪卡，配遗忘曲线考考自己 → 生成 + 记忆 / 计划

**自主任务层（最"Agent"）**［/agent］
- 一句话多步整理：说一句，Agent 自己规划"筛选→归类→提炼→落盘" → 规划 / 多步循环

**Skill 层（能力封装 · 扩展）**［/tools］
- Skill 工作台（造）：把库内知识 / 流程封装成 Skill → 结构化生成 + 打包
- 本地 Skill 挂载（装）：扫本地目录动态加载自定义 Skill，扩展采集 / 问答 / 输出能力 → Skill 运行 / 注册
- 对外发布（发）：导出 Skill 发布到第三方平台（扣子商店 / ClawHub）→ 打包 / 分发

**微调层（次动作）**［/knowledge］
- 轻量编辑（改 AI 初稿）→ 界面

**数据底子（贯穿）**［/files］
- 存储（本地 / 云端——待定）
- 分享 / 导出：Markdown / PDF / 排版后转发 → 界面 + 格式化输出

## 七、阶段路线图（总纲）

> 主线：第一目的 = **学透 Agent 开发**，慢聊边学、不追交付效率。阶段按「认知顺序」排——先扫盲、再决策、后动手，学习与开发始终绑在一起走。

1. **是什么** ✅ 功能地图、产品定位、业务场景（已完成）
2. **产出原型**：把一阶段内容做成高保真可交互原型，对齐产品形态
3. **认知地图**：每个板块用什么技术、主流方案扫盲
4. **工具选型**：用扣子 / Codex / AI IDE / 其他来做这个项目
5. **交接方案**：定交接载体（文档 / 提示词 / spec），让工具完全 get 我们聊的东西；边聊边沉淀
6. **定地基**：数据存哪、内容格式、怎么组织
7. **定技术栈**：大模型 API、RAG 切块与向量方案、Agent 框架、前端栈
8. **划 MVP + 排迭代路线**：圈第一版范围，把后续阶段分成 MVP 内 / MVP 后的迭代
9. **MVP 实现**：边学边做，存储→检索→采集→整理串成一条（"存进去找得到"）
10. **迭代一**：灵魂闭环（RAG 知识库问答 + 测验自测）
11. **迭代二**：Skill 层 + 补边（保鲜归档 / 关联图谱 / 分享导出 / 离线可读）
12. **收尾**：作品整理 + 复盘（不急着上线）
