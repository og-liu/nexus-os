# 待办清单

> 今天还剩什么：首页一张卡能直接勾、勾完留一拍再走；工具页是整块待办板，带已完成区。

| | |
|---|---|
| 入口 | `app/(app)/tools/todo-list/page.tsx`（一行薄壳）→ 实现住在本目录 `server/page.tsx` |
| 接口 | 无 HTTP 接口，数据入口是 Server Action（`server/actions.ts`） |
| 数据表 | `todos`（字段逐个解释见 `docs/数据库/待办表.md`） |
| 状态 | ✅ 已上线（2026-10-20 起） |

**这份 README 是这个工具唯一的文档**：代码结构在 §五，需求 / 界面 / 数据 / 决策 / 验收 / 坑在一～四、六、七。
原来的 `docs/功能/待办清单.md` 已于 2026-11-05 并入本文件，章节编号保持不变。

## 一、要什么

**做**

- **首页常驻卡**：显示未完成里最新的 3 条；卡上可直接勾，勾后**停留一拍再离场**，第 4 条自动补位。
- **工具页** `/tools/todo-list`：卡片网格 + 弹窗新建 / 编辑 + 原位删除 + 已完成折叠区 + 清除已完成。
- **落库**：新表 `todos`，每条归属到用户；标题上限 1000 字。
- **目录同步**：`tool-catalog` 里状态从「开发中」改为「可用」。

**主动放弃（本版不做，不是遗漏）**

| 放弃项 | 原因 |
|---|---|
| 到期日 / 提醒 | 一有日期就要回答逾期怎么标、时区怎么算、要不要推送；提醒还要定时任务 + 通知通道。卡名随之从「今日待办」改成「待办清单」——不假装有日期 |
| 优先级 / 标签 / 多清单 / 分组 | 都是「整理待办」而不是「做待办」；优先级一旦存在，全标高优先级就等于没有优先级 |
| 拖拽排序 | 排序规则只有一条（创建时间倒序），不必存位置 |
| 单项撤销 / 回收站 | 要软删除与清理策略；原位二次确认已经挡住误删。勾选后那 800ms 是「撤销窗口」，不是持久化回收站 |
| 搜索 / 筛选 | 个人待办量级小，一屏扫得完 |
| 多端同步 / 分享 | 单机 SQLite、个人使用 |
| 完成时间显示 | 卡片只显示**创建时间**；`completed_at` 仍存——它是完成状态的判据与已完成区排序依据，只是不展示 |

## 二、界面

### 2.1 首页常驻卡 `/`

骨架沿用旧界面的「主区 2/3 + 常驻栏 1/3」；当前是 2026-10-22 起的**过渡形态**（逐块一行、每块 430px），等拼图补齐再拼回栅格。

```
白卡 rounded-[2px] bg-white p-5
├─ 分组标题「待办清单」（§7.2）
├─ 右上：「管理 →」 + 完成计数「1/3」
└─ mt-3 space-y-1
   └─ 待办行（整行可点，点哪儿都能勾）
```

行内结构（**一条只占一行**：标题单行截断，创建时间放标题右侧）：

| 元素 | 类名 |
|---|---|
| 行 | `flex w-full items-center gap-2.5 rounded-[2px] p-2 text-left hover:bg-[#F5F5F5]` |
| 勾选框 | `h-4 w-4 rounded-[2px] border`；未完成 `border-[#D0D0D0] bg-white`，完成 `border-[#000000] bg-[#000000]` |
| 标题 | `min-w-0 flex-1 truncate text-sm`；完成 `text-[#999999] line-through` |
| 时间 | `shrink-0 text-[10px] tabular-nums text-[#999999]`，`YYYY-MM-DD HH:mm`（UTC+8） |

> 时间原来在标题下面，一条被撑成两行、3 条就把卡拉得很高；2026-10-22 联调改成右侧同行。

- 右上「管理 →」指向 `/tools/todo-list`；计数形如 `1/3`，**口径是全局的**（已完成数 / 全部待办数，与卡里显示几条无关——`3/10` 是对的）。
- 显示哪 3 条：未完成里创建时间最新的 3 条。
- **空态分两种**：一条都没有 → 「还没有待办」+「加一条 →」；有但全勾完 → 「都做完了」+「再加一条 →」。
- **卡上直接勾，勾完留一拍**：先原地变灰划线（计数暂不动）→ 停留 800ms（期间再点是撤销，连续勾选会顺延）→ 行淡出 200ms → 用 action 返回的**整块板**重取未完成前 3 条（第 4 条补位，计数在离场那一刻一起变）。
- 首页 `< xl` 时这张卡排在便签卡**之前**（「今天还剩什么」比「随手记」更该第一眼看到）。

### 2.2 工具页 `/tools/todo-list`

与便签工具页同构：**没有 PageHeader**，工具名与状态在信息条里；手机上「汉堡 + 新建」住在顶部那一行。

```
移动端导航行（< lg）：汉堡 + 新建待办
内容区（px-4 py-4 md:px-6 md:py-6）
├─ 工具信息条（黑底白图标 + 名称 / 描述 / 分类 chip / 状态点「可用」）
│   └─ 右侧「新建待办」（≥ lg）
├─ 吸顶工具栏（ToolBar，与便签页共用）
└─ 列表
   ├─ 「未完成 N」分组标题
   ├─ 卡片网格（grid-cols-1 gap-3 md:grid-cols-2 xl:grid-cols-3）
   └─ 「已完成 N」展开区（默认展开；没有已完成时整条不渲染）
```

**新建 / 编辑弹窗**（`TodoDialog` + `TodoEditor`）：

- 一块自动长高的 `textarea`，`maxLength=1000`；**回车保存、`Shift + Enter` 换行**、`⌘/Ctrl + Enter` 也保存、`Esc` 取消。
- 编辑已有待办时左下显示「创建于 `YYYY-MM-DD HH:mm`」，接近上限时与字数提示用 ` · ` 并列。
- 底部：删除（灰底 + 错误色 `#B91C1C`，**只在编辑态**）/ 取消 / 保存（黑底白字）。待办**没有**「置顶保存」。
- 删除要一次确认（内嵌确认条「删除后无法恢复，确定删除这条待办？」），确认后真删并关弹窗；不可撤销。
- 删除成功弹全局提示「待办『标题摘要』已删除」（24 字符截断，3 秒消失）。

**待办卡片**（`TodoTile`，96px 高，与便签卡同一套语言）：

- 白卡固定高、hover 出黑描边；点正文 = 编辑弹窗；**勾选框是独立按钮**，点它只切换完成态、不打开编辑。
- 左下创建时间；删除按钮在右上，桌面 hover 才显、触屏常显；删除走**原位二次确认**。
- 勾后先灰划线，800ms 后原地收起（网格行高 + 淡出 200ms），再移入已完成；离场中的卡不可再点。

**已完成区**：分组标题「已完成 N」+ `ChevronDown`（展开转 180°）+「清除已完成」；**默认展开**（2026-11-04 联调改的，原为收起）。卡片按 `completed_at DESC` 排、已勾灰划线；「清除已完成」走原位二次确认；折叠状态是纯前端 state，刷新回到展开。

**空态**：一条都没有 → 虚线框「还没有待办」+「新建待办」（§7.12）；只有已完成时，未完成区不渲染、已完成区仍在。

**勾选节奏（工具页与首页卡共用同一套）**

1. 勾选立刻给回执（黑勾 + 灰划线），卡片留在原位；
2. 停留 800ms（`TODO_LEAVE_DELAY_MS`）——期间再点是撤销，连续勾选重置计时器；
3. 到点后收起 / 淡出 200ms（`TODO_LEAVE_ANIMATION_MS`），动画结束才移入已完成；两个计数在这一刻一起变；
4. 离场中的卡片禁用；已完成区取消勾选**立刻**归位；
5. `prefers-reduced-motion` 下不做动画，但节奏不变。

### 2.3 三档响应式

| 档位 | 工具页 | 首页卡 |
|---|---|---|
| 移动 < md（375 起） | 单列；顶部汉堡 + 新建；信息条纵向；删除按钮**常显** | 单列第一块，在便签卡**之前**；最多 3 行；「管理 →」保留 |
| 平板 md ~ lg | 两列；信息条仍纵向；删除按钮常显（触屏平板无 hover） | 单列（< xl） |
| 窄屏 PC lg ~ xl | 信息条横向；导航行收起；新建移到信息条右侧；删除改 hover 显示 | 同上 |
| 宽屏 ≥ xl | 三列；间距放大到 `xl:space-y-6` | 右 1/3 独立成卡；便签卡在左 2/3 |

三档用互斥显隐（`hidden lg:flex` / `lg:hidden`），不做 JS 断点判断——首屏 SSR 不闪。
hover 分档用 `[@media(hover:hover)]:opacity-0` + `group-hover:opacity-100`，与便签卡同一套。

## 三、数据模型

```sql
CREATE TABLE IF NOT EXISTS todos (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id      INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  title        TEXT    NOT NULL,
  completed_at INTEGER,                    -- 完成时刻（毫秒）；NULL = 未完成
  created_at   INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_todos_user_id ON todos(user_id);
```

设计要点：

- **不存 `done` 布尔，只存 `completed_at`**：完成状态与完成时间是同一个事实。分两列就可能写出「`done = 1` 却没有完成时间」这种自相矛盾的行，且没有任何约束拦得住。查询写 `WHERE completed_at IS NULL`（未完成）/ `ORDER BY completed_at DESC`（已完成）。
- **便签的 `pinned` + `pinned_at` 是另一种情况**：置顶既有「是不是」，也有「什么时候置顶」的排序需求，所以是双列；两列只在 `setNotePinned` 一处一起写。
- **没有 `updated_at`**：本版不展示「最后编辑时间」，存一列永远不会被读的 `updated_at` 是谎话。将来需要时按《数据库/README》§六 的幂等 `ALTER` 补。
- **`title` 上限 1000 字**：服务端校验兜底，客户端 `maxLength` 只是体验；与便签正文同档。
- **排序**：未完成 `ORDER BY created_at DESC, id DESC`（新加的在上）；已完成 `ORDER BY completed_at DESC, id DESC`；末尾 `id DESC` 是稳定排序兜底。
- 表名 `todos` ↔ 路由 `todo-list` ↔ 工具目录 slug 三处对应。

## 四、关键决策

| 决策点 | 选择 | 理由 | 否决的备选 |
|---|---|---|---|
| 首页骨架 | 过渡形态：逐块一行（每块 430px） | 拼图只有四五块时硬拼成一行每块都被挤窄（2026-10-22 联调推翻 10-20 的两栏）；等补齐再拼回栅格 | 恢复「主区 2/3 + 常驻栏 1/3」；两卡各自满宽纵向叠（3 行跨 1360px，像横幅） |
| 完成状态怎么存 | 只存 `completed_at`，NULL = 未完成 | 一个事实一个地方，不可能自相矛盾；顺带白拿「什么时候做完的」 | `done` + `completed_at` 两列（能写出坏行）；只存 `done`（已完成区没有顺序可依） |
| 首页卡标题 | 「今日待办」→「待办清单」 | 旧卡没有任何日期字段，叫「今日」是文案不是行为；改一个字换掉一整片复杂度（逾期 / 时区 / 提醒） | 加 `due_date` 保住「今日」（拖进日程工具的地盘）；保留原名（标题继续撒谎） |
| 首页卡显示哪几条 | 未完成里最新的 3 条 | 与便签卡「3 条封顶」同构；已完成不占卡位——待办的价值是「还剩什么」 | 混排（真数据下卡里会长期挂着做完的事） |
| 首页卡怎么补位 | 离场后用 action 返回的**整块板**取 `open.slice(0, 3)` | 首页初始只有 3 条，第 4 条不在本地；服务端返回全量 open 最省事 | 首页一次查全量（摘要没必要）；只查 4 条（连续勾选补不满） |
| 勾选后怎么离场 | **留一拍再走**：800ms 停留（可撤销）→ 200ms 收起 → 移入已完成 | 立即移走会吞掉「勾上了」的回执，连续勾选时行还会在指针下面跳 | 立即重排（跳位、误勾）；等刷新才归位（像坏了） |
| 连续勾选怎么办 | 计时器重置（debounce），批量一起离场 | 手还在点时行不动；停下后一次结算，视觉更安静 | 各走各的计时器（行会在手边陆续消失） |
| 计数什么时候变 | 离场那一刻一起变 | 卡片还在原位时它仍属「未完成」；同一刻改两个数不会出现矛盾 | 勾选瞬间就改（短暂双算）；完全不改（以为没生效） |
| 新建 / 编辑在哪 | **弹窗** | 与便签一致；待办也可能写成一段，1000 字需要空间；列表高度不跳 | 页头「新建」+ 页内输入行（另做一套编辑态）；卡片原地展开（撑高卡片） |
| 删除 | 原位二次确认 +「清除已完成」 | 与便签卡同一套语言；已完成区给一个批量出口 | 只做单项删除（已完成会永远堆着）；软删除（要清理策略和一处不漏的过滤） |
| 完成时间显示 | 不显示 | 卡片只承担「还剩什么」；已完成区按它排序但不必印在卡上 | 显示（信息变密，与创建时间抢位置） |
| 已完成区默认开合 | **默认展开**（2026-11-04 联调改） | 「回头看做完的事」是常规动作（取消勾选、核对今天做了什么），默认收起每次多点一下 | 默认收起（把做完的事藏起来）；记住上次状态（多存 UI 状态只省一个点击） |
| 工具页要不要信息条 | 保留，状态「可用」 | 工具页同构，从列表点进来先确认「我在哪」 | 去掉（省一屏，但与其余工具页不同构） |

## 六、验收标准

**正常路径**

1. 打开 `/tools/todo-list`：出现工具信息条（「待办清单」/「可用」）；没有待办时显示空态。
2. 新建 → 输入「买牛奶」→ 回车 / 保存 → 列表出现卡片（标题 + 创建时间，分钟级）；弹窗关闭。
3. 点卡片正文 → 编辑弹窗（「创建于 …」）→ 改标题保存生效；再改回按 `Esc` → 数据库不变。
4. 1000 字保存成功；1001 字被服务端拒（弹窗内提示，行数不变）。
5. 勾选「买牛奶」→ 立刻黑勾 + 灰划线；800ms 内再点 = 撤销；不撤销则 200ms 收起后离开未完成区，两个计数同时变。
6. 已完成区**默认展开**，标题显示「已完成 N」；点标题可收起 / 再展开；展开时能取消勾选，取消后立刻回未完成区。
7. 连续快速勾 2–3 张：都留在原位，最后一次勾选后约 800ms 一起离场；动画期间不能重复点击。
8. 首页：待办卡显示未完成里最新 3 条、全局计数 `已完成/全部`，行上有创建时间。
9. 首页勾一条：立刻灰划线；800ms 后行淡出、第 4 条补进、计数同刻更新。
10. 首页卡全勾完 → 「都做完了」+「再加一条 →」；一条都没有 → 「还没有待办」+「加一条 →」。
11. 右上「管理 →」→ 地址变 `/tools/todo-list`。
12. 卡片删除：hover 出现垃圾桶 → 点 → 「删除这条待办？」→「取消」保留；再来一次「删除」→ 卡片消失，刷新确实没了。
13. 「清除已完成」→ 二次确认后已完成区清空，未完成一条不动。
14. `/tools` 列表里「待办清单」状态为「可用」。

**负面路径**

15. 未登录直接访问 `/tools/todo-list` → 跳 `/login`。
16. 提交只有空格 / 换行的标题 → 不落库（行数不变），弹窗内给提示。
17. 标题写 `<img src=x onerror=alert(1)>` → 按原文字面显示，无弹窗、无图片请求。
18. A 用户勾 / 删 B 用户的待办（数据层单测）→ 影响行数 0。

## 七、已知的坑

| 坑 | 机制 | 对策 |
|---|---|---|
| 勾选后立即移出会让手指点到下一行 | 列表在指针下方重排 | **留一拍再走**：800ms + debounce；连续勾选时行不动 |
| 首页只拿到 3 条，勾掉后没有第 4 条 | 初始数据是限量查询 | 用 action 返回的整块板取 `open.slice(0, 3)` 补位 |
| 卡片 / 行离场后键盘焦点落回 body | 被移除的元素持有焦点 | **已知未处理**；需要时把焦点移到下一张卡或「未完成」标题 |
| 勾选后 800ms 内打开删除确认，卡片仍会离场 | 离场计时器不感知确认态 | **已知未处理**；避免在离场窗口内删已勾选的卡片（可在已完成区删） |
| 触屏上删除按钮永远不出现 | `group-hover` 在触屏没有 hover | 默认可见；只在 `@media (hover: hover)` 收起 |
| `pending` 把整卡 / 头部按钮变半透明 → 闪烁 | 曾带 `disabled:opacity-50`，动作几十毫秒内来回切 | 卡片与头部按钮去掉这层变暗，`disabled` 逻辑保留 |
| 乐观更新与真实数据打架 | 全量刷新会让刚勾的条目闪回未勾 | 失败时只回滚这一行；离场时才用服务端板替换列表 |
| 连点保存 / 回车重复建条 | 请求在飞时又提交了一次 | 提交中禁用按钮、忽略重复提交 |
| 空标题绕过校验 | 全角空格、换行都不等于 `""` | 服务端 `trim()` 后判空 |
| Server Action 被直接调用 | 它是公开 HTTP 端点，`maxLength` 不是防线 | 服务端再校验长度、非空、归属用户 |
| 毫秒撞车导致顺序不稳 | 同毫秒两条 `created_at` 相等 | 排序末尾补 `id DESC` |
| 折叠区状态刷新后重置 | 纯前端 state，不落库 | 重置成**展开**（默认态）——收起是临时动作，不值得存 |
| 首页漏掉登录检查 | 检查在页面里而不在 layout | 保留首页自己的 `requireUser()` |
| 演示数据残留 | 手动测过的待办会被当成真数据 | 验收结束前清掉测试行 |
