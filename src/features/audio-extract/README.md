# 音频提取

> 把一个视频丢进来，把里面的音轨**原样**拿出来——能拷就拷（无损、几秒、体积不变），只有容器放不下的时候才转一次码。
> 这是「媒体」分类的第一个工具，也是全站第一个**在服务器上处理文件**的工具。

| | |
|---|---|
| 入口 | `app/(app)/tools/audio-extract/page.tsx`（一行薄壳）→ 实现住在本目录 `server/page.tsx` |
| 接口 | `POST /api/tools/audio-extract`（原始字节进 → 音频流出）——`app/api/` 下是薄壳，实现住在本目录 `server/api/extract.ts` |
| 数据表 | 无（视频与音频都不进数据库，服务器只留一份临时文件，响应结束即删） |
| 状态 | ✅ 已上线（v0.11.0，2026-11-02 起） |

**这份 README 是这个工具唯一的文档**：代码结构在 §五，需求 / 界面 / 数据 / 决策 / 验收 / 坑在一～四、六、七。
原来的 `docs/功能/音频提取.md` 已于 2026-11-05 并入本文件，章节编号保持不变。

## 一、要什么

**做**

- 工具页 `/tools/audio-extract`，分类「媒体」，工具目录与页签栏各登记一处。
- **一个视频进、一个音频出**：拖入 / 点选视频 → 点「提取音频」→ 等几秒 → 下载。
- **批量**：一次拖入 **2 个及以上**进列表，串行逐个上传提取、逐条下载，另有「下载全部（ZIP）」与「清空」。**1 个仍走单文件流程**——与图片压缩同一条分流规则。
- **输出规则：能拷就拷**。按**源音轨的编码**决定输出容器，不按输入文件的扩展名猜：

| 源音轨编码 | 输出文件 | 处理方式 | 界面标注 |
|---|---|---|---|
| AAC | `.m4a` | 流拷贝，一次解码都不做 | 无损提取 |
| MP3 | `.mp3` | 流拷贝 | 无损提取 |
| ALAC | `.m4a` | 流拷贝 | 无损提取 |
| FLAC | `.flac` | 流拷贝 | 无损提取 |
| Opus / Vorbis / AC3 / E-AC3 / DTS / AMR / 其它 | `.m4a`（AAC 192 kbps） | 转码一次 | 已转为 AAC |

- **单文件上限 500 MB**；**每批最多 10 个**；不落库、不留存。
- 失败要说人话：没有音轨 / 超过上限 / 不是视频 / 打不开。
- 三档响应式各自一套版式（§2.2）。

**主动放弃（本版不做，不是遗漏）**

| 放弃项 | 原因 |
|---|---|
| 「转成 MP3」的开关 | 主人要的是「无损提取」。MP3 是有损格式，从 AAC 转过去必然解码再编码——一首 4 分钟的歌，无损是 4 MB / 2 秒，转 MP3 变 7 MB / 10 秒、质量还退一代。能无损就不给这个开关 |
| 只提取某一段（填开始 / 结束时间） | 要的是「比剪映的音频分离更简单」：整段提取，不引入时间轴与区间校验 |
| 试听 / 波形预览 | 提取完下载到本地听更快；音频不进浏览器内存，也不用为它引解码器 |
| 多音轨选择 | 有多条音轨时只取第 1 条（`-map 0:a:0`）。真实场景几乎全是单音轨，加选择器等于为一个几乎不存在的情况造一套 UI |
| 提取历史 / 结果留存 | 结果直接下载走；留历史就要建表、定清理策略，而这个工具的价值就是「过一下就完」 |
| 客户端处理（ffmpeg.wasm / 浏览器解封装） | 见 §四 |

## 二、界面

### 2.1 工具页

与图片压缩同构：**没有 PageHeader**，工具名与状态在信息条里（`ToolHeader`，状态点「可用」）；手机上顶部是 `ToolMobileBar`（汉堡 + 「选择视频」，图标 `FileVideo`）。

```
移动端导航行（< lg）：汉堡 + 选择视频
内容区（px-4 py-4 md:px-6 md:py-6 space-y-4）
├─ 工具信息条（ToolHeader，状态「可用」）
└─ 工作区（左右两栏，与图片压缩同构）
   ├─ 左：文件
   │   ├─ 空态：拖入区（虚线框 + 图标 + 三行提示）
   │   ├─ 单个：文件卡（文件名 · 体积 ·「换一个」）+ 进度层（上传 N% / 提取中 + 已用秒数）
   │   └─ 批量（≥2）：列表（序号 · 文件名 · 体积 → 输出体积或进度/原因 · 逐条「下载」），
   │       表头「批量提取 · N 个」+「清空」
   └─ 右：操作 + 结果（同一张白卡）
       ├─ 标题「提取」+ 通栏按钮（单文件「提取音频 / 重新提取」；批量「开始提取（N 个）」）
       ├─ 单文件结果：空占位 / 源音轨 + 无损或已转码 + 时长 + 体积 +「下载音频」/ 失败一句人话
       ├─ 批量汇总：合计体积 → 合计输出、「N 个可下载」、通栏「下载全部（ZIP）」
       └─ 「能无损就无损」的说明（仅单文件模式）
```

颜色与控件照《界面设计规范》：虚线框 `rounded-[2px] border border-dashed border-[#D9D9D9] bg-white`，主按钮黑底直角，空态文案 `text-[#A0A8B4]`。

### 2.2 版式与断点

| 档位 | 版式 | 关键差别（不是缩放） |
|---|---|---|
| 移动 < md（375 起） | 单列：拖入区 / 文件卡 / 列表 → 按钮 → 结果 | 按钮通栏 `h-10`；空态内边距收到 `p-8`；批量时列表在上、按钮与汇总在下，列表自己滚（`max-h-[calc(100vh-26rem)]`），页面不滚 |
| 平板 md ~ lg（768–1023） | 并排两列：左 = 文件，右 = 操作 + 结果 | **空态时拖入区占满整行、右栏让位**——没有文件时右栏只有一个置灰按钮，没有存在的理由 |
| 窄屏 PC lg ~ xl（1024–1279） | 两栏：主区 `flex-1` + 右栏 `w-[300px]` | 右栏固定操作、结果与「能无损就无损」的说明，改文件不用上下滚 |
| 宽屏 ≥ xl（1280） | 两栏：主区 `flex-1` + 右栏 `w-[340px]` | 内容区**铺满、不设 max-width**，右栏固定 340px |

- 两栏的切换点是 **lg**（栏位方向属于结构性布局）。
- 三档用互斥显隐（`hidden lg:grid` / `lg:hidden`），不用 JS 读视口——首屏 SSR 不闪。
- 断点的实际高度**实现时在真机上量**，不许手算（踩过：`calc()` 里手填常量，1440×900 下内容被压成一条缝）。

### 2.3 状态与边界

| 状态 | 界面 |
|---|---|
| 初始 | 虚线拖入区：`Upload` +「把一个视频拖到这里」+「或者点击选择文件」+ 小字「MP4 / MOV / MKV / AVI / WEBM / TS 等，单个不超过 500 MB」；「提取音频」置灰 |
| 已选中 | 文件卡：文件名（过长中间截断）+ 体积 +「换一个」；「提取音频」可点 |
| 上传中 | 文件卡上盖进度层：`Loader2` +「正在上传 42%」+ 进度条；按钮禁用 |
| 提取中 | 同一层换文案「正在提取音频…」+ 已用秒数；**不给假进度条** |
| 完成 | 结果卡：`源音轨 AAC` +「无损提取」+ `03:42` + `5.2 MB` +「下载音频」；文件卡补一句「已经提取好了，下载在结果卡里」——不留一块空白 |
| 已转码 | 结果卡：`源音轨 Opus` +「已转为 AAC」+ 时长 + 体积 |
| 没有音轨 | 「这个视频没有声音」+「文件里没有音轨，换一个试试」+「换一个视频」 |
| 不是视频 / 超过 500 MB | 选中即拒（Toast），**不发起请求** |
| 批量（≥ 2） | 左列表逐条显示 待提取 / 上传 N% / 正在提取… / 已转 AAC 或无损 + 逐条「下载」；右栏是本批汇总与「下载全部（ZIP）」 |
| 批量中有被拒的文件 | 该行标「已跳过」并在副标题写明原因（不是视频 / 超过 500 MB / 超过每批 10 个），**不影响同批其它个** |
| 打不开 | 「这个视频打不开」+「文件可能损坏，或者编码 ffmpeg 认不出来」 |

## 三、数据模型

**不涉及。** 视频与音频都不进数据库、不在服务器留文件：唯一的磁盘痕迹是提取期间的一份临时文件，
响应结束即删（§四）。**这是本工具最重要的一条设计**，写在这里是为了让后来者一眼看到：这个功能没有持久层。

## 四、关键决策

| 决策点 | 选择 | 理由 | 否决的备选 |
|---|---|---|---|
| 在哪跑 | **服务器上的 ffmpeg**（Route Handler 里 spawn 子进程） | 输入是一个**容器**（mp4 / mkv / ts / mov…），要从里面取音轨，浏览器没有任何 API 能做；ffmpeg 一条命令就完成 | ffmpeg.wasm（首次加载约 30 MB、单线程慢十倍、文件要整个塞进 32 位地址空间，真 MV 直接内存墙）；浏览器里 mp4box.js 手工解封装（只认 mp4 / mov，mkv / avi / ts 全废） |
| 二进制从哪来 | **npm 包 `@ffmpeg-installer/ffmpeg`**（二进制随平台子包发布） | ① CI 构建时二进制就进产物，服务器**不需要联网装包**；② 版本跟着 `package.json` 走，回滚就是回滚依赖；③ 本地（macOS arm64）与线上（linux-x64）各取对应平台包 | `dnf install ffmpeg`（**实测：Alibaba Cloud Linux 3 + EPEL 8 里没有 ffmpeg 包**）；手工放静态包（脱离发布流水线）；RPM Fusion（境外源，国内基本不可用） |
| 默认输出什么 | **能拷就拷**：按源音轨编码选容器 | 「提取」的正确语义是把音轨搬出来，不是重新编码；拷贝路径一次解码都不做，几秒完事，体积与质量与源一致 | 一律转 MP3（白丢一代音质、多等十几秒、体积更大） |
| 转码什么时候发生 | 只在源编码放不进播放友好的容器时（Opus / AC3 / AMR 等） | 这类编码塞进 `.m4a` 大多数播放器不认，转 AAC 才是「拿回去能听」 | 原样输出 `.opus`（Windows 与部分车机不能放，用户以为文件坏了） |
| 单文件上限 | **500 MB** | MV 通常 50–200 MB；服务器磁盘 33 GB，500 MB 峰值安全 | 不设上限（4 GB 文件能把磁盘与上传时间一起拖垮）；100 MB（长一点的 1080p 就超） |
| 上传怎么进服务器 | **请求体直接流式写进临时文件**；`Content-Length` 超限立刻 413，边写边累计字节数 | 服务器内存只有 1.8 GB，把 500 MB 读进内存会让整个 Next 进程被系统杀掉——连带所有页面一起挂 | `await request.arrayBuffer()`（最省事，正是上面那个后果）；`multipart/form-data`（要额外解析器；单文件用 `application/octet-stream` + 自定义文件名头就够） |
| 临时文件怎么清 | 请求结束（含异常路径）`unlink`；每次请求开头顺手删掉目录里超过 1 小时的孤儿 | 进程被杀时 `finally` 不执行；一条扫描把累积的孤儿收掉，不需要常驻定时任务 | 定时任务（为一个私人工具多一个常驻进程）；不清理（磁盘迟早满） |
| 返回方式 | ffmpeg 写临时文件 → 流式响应回浏览器 → 流结束后删 | 浏览器拿到的就是文件本身，不需要再发一次「取结果」请求 | 生成可下载 URL 让前端再取一次 |
| 进度给到几分 | 上传给真实百分比；提取只给「已用秒数」 | 上传是浏览器知道的（XHR `upload.onprogress`），提取是服务器黑盒；编个假进度条比不给更糟 | 把 ffmpeg 的 `-progress` 转发给浏览器（要 SSE + 两段式接口） |
| 并发 | **不排队**：前端按钮锁死，服务器不设队列 | 私人工具，两个请求同时来的概率极低；真撞上就是 2 核各跑一半，慢一点但不崩 | 进程内队列（多一套状态与超时，收益为零） |
| 一次收几个 / 怎么分流 | **1 个走单文件，≥ 2 个进批量**；批量**串行**逐个跑 | 与图片压缩同一条规则，用户不用学第二套；服务器 2 核、同一时刻只有一个临时文件 | 并行（几个大文件一起挤）；只做单文件（批量是明确要求） |
| 批量上限 | **每批 10 个**，单文件仍 500 MB，**不设整批总大小** | 处理是「逐个上传、服务端逐个跑」：浏览器只存 File 引用与每首歌几 MB 的结果，服务器峰值永远只有一个文件——卡人的是上传时间 | 照抄图片压缩的 30 个 / 200 MB（那套数字是为了防浏览器内存爆掉，这里瓶颈不在这） |
| 批量怎么下载 | 逐条「下载」+「下载全部（ZIP）」 | 一次触发多个下载会被浏览器拦；ZIP 一步到位，`lib/zip.ts` 走 store 模式 | 循环 `<a download>`（被拦）；引第三方 zip 依赖（已有自家实现） |
| 鉴权 | 页面 `requireUser()` **加**接口二次校验 | 接口能被直接 POST，页面鉴权管不住它；这个接口吃 CPU 与磁盘 | 只靠页面（等于把上传接口敞开） |
| 输出文件名 | 源文件名去扩展名 + 新扩展名；路径分隔符与非法字符换成 `-` | 抖音下载的文件名常带 emoji、井号、空格；直接用会拼出坏路径或被截断 | 固定 `download.m4a`（用户下载一堆同名文件，分不清） |

## 五、代码结构（三层）

**这就是原来的「文件落点」一节。**

`client/` —— 浏览器（`"use client"`）。

| 文件 | 职责 |
|---|---|
| `extract-view.tsx` | 视图层：版式、单文件 / 批量分流与状态组合 |
| `video-dropzone.tsx` | 空态拖入区（一次可拖多个） |
| `extract-result.tsx` | 单文件的结果 / 失败块 |
| `batch-list.tsx` | 批量列表（序号 / 文件名 / 体积 → 输出或进度 / 逐条下载） |
| `batch-summary.tsx` | 批量汇总与「下载全部（ZIP）」 |
| `use-audio-extract.ts` | 单文件状态机 |
| `use-batch-extract.ts` | 批量状态机（串行循环、ZIP 打包、取消） |
| `extract-request.ts` | 发一次请求（XHR 上传进度、响应头解析、错误码），单文件与批量共用 |
| `failure-copy.ts` | 失败文案（两个状态机共用一份） |

`server/` —— 服务端。碰文件系统 / 子进程的模块开头有 `import "server-only"`。

| 文件 | 职责 |
|---|---|
| `page.tsx` | 页面接线（`requireUser()` + 渲染视图） |
| `api/extract.ts` | 上传接口（`runtime = "nodejs"`、`dynamic = "force-dynamic"`）：原始字节进、音频流出 |
| `ffmpeg.ts` | 定位二进制、spawn、流式写盘、临时文件与清理 |

`shared/` —— 两端共用，只碰纯数据。

| 文件 | 职责 |
|---|---|
| `constants.ts` | 上限、临时目录前缀、超时、错误码 |
| `accept.ts` / `accept.test.ts` | 选文件那一刻的准入判断（纯函数） |
| `batch-rules.ts` / `batch-rules.test.ts` | 批量准入（每批 10 个） |
| `plan-output.ts` / `plan-output.test.ts` | 源编码 → 容器 / 是否转码 / MIME |
| `filename.ts` / `filename.test.ts` | 输出文件名清洗与 `Content-Disposition` |

**从哪开始读**：`server/api/extract.ts`（一条请求的生命周期）→ `server/ffmpeg.ts`（怎么跑 ffmpeg）→ `client/use-audio-extract.ts`（界面状态）。

**边界与「不在本目录但属于本工具」的东西**

- **解析 ffmpeg 输出的纯函数不在本目录**：`parseProbe` 住在 `src/lib/shared/probe.ts`——音乐播放器上传时也要用，是全站唯一一处跨工具共用的运行时依赖。
- 路由薄壳 `app/api/tools/audio-extract/route.ts`，**`runtime` / `dynamic` 留在壳里**。
- `next.config.ts` 的 `outputFileTracingIncludes` 必须含 `/api/tools/audio-extract` 键——漏了的表现是「本地正常、线上必失败」（线上机器没有系统 ffmpeg）；`serverExternalPackages` 也要带上 `@ffmpeg-installer/ffmpeg`。
- 体积格式化 `lib/format-bytes.ts` 与 ZIP `lib/zip.ts` 已上移到基础设施层（图片压缩与本工具共用一份）。
- `deploy/nginx/nexus-os.conf` 的 `client_max_body_size` / `proxy_request_buffering`（见 §七）。
- `src/types/ffmpeg-installer.d.ts`（那个 npm 包不带类型声明）。

## 六、验收标准

| # | 操作 | 期望 |
|---|---|---|
| 1 | 上传音轨为 AAC 的 mp4，点「提取音频」 | 几秒内出结果卡：标注「无损提取」、时长与源视频一致、下载得到 `.m4a` |
| 2 | 用 `ffprobe` 检查第 1 条的文件 | `codec_name=aac`；音频数据量与源音轨一致（只差容器开销的几十字节） |
| 3 | 播放第 1 条的文件 | 声音正常、时长正确、能拖动进度条 |
| 4 | 上传音轨是 MP3 的 avi | 输出 `.mp3`，标注「无损提取」 |
| 5 | 上传音轨是 Opus 的 webm | 输出 `.m4a`，标注「已转为 AAC」，`ffprobe` 报 `codec_name=aac` |
| 6 | 上传没有音轨的静音视频 | 「这个视频没有声音」，**不出现**下载按钮，页面上没有英文报错 |
| 7 | 上传 600 MB 的视频 | 选中后立刻 Toast「超过 500 MB」，不上传（Network 里没有任何请求） |
| 8 | 绕过前端：已登录 cookie 下 `curl --data-binary @big.mp4`（505 MB，卡在「应用上限 500 MB」与「Nginx 上限 520 MB」之间） | 返回 413，body 是 JSON 文案，不是 Nginx 的 HTML 错误页 |
| 9 | 未登录直接请求该接口 | 401 JSON |
| 10 | 未登录打开 `/tools/audio-extract` | 跳 `/login` |
| 11 | 每跑完一次提取，看服务器临时目录 | 目录为空（没有残留的 `.mp4` / `.m4a`） |
| 12 | 上传文件名 `抖音_❤️测试#1.mp4` | 下载得到 `抖音_❤️测试-1.m4a`（井号被替换，中文与 emoji 保留） |
| 13 | 提取进行中再点一次「提取音频」 | 按钮已禁用，Network 里只有一个请求 |

## 七、已知的坑

| 坑 | 机制与对策 |
|---|---|
| Nginx 默认只放行 1 MB 请求体 | `client_max_body_size` 默认 **1 MB**，任何真视频都是 413，且返回的是 Nginx 的 HTML 错误页——前端 `.json()` 直接抛。对策：`deploy/nginx/nexus-os.conf` 加 `client_max_body_size 520m;`，前端把 413 也翻译成「文件太大」 |
| **`ffmpeg` 必须带 `-nostdin`** | 子进程没有 TTY 时 ffmpeg 会读 stdin 做交互（问是否覆盖），于是**永远不返回**，接口挂到超时。对策：所有调用都带 `-nostdin -y` |
| 用 `ffmpeg -i` 探测时退出码是 1 | 只给输入不给输出时，ffmpeg 打印完流信息就以非 0 退出。对策：探测那一步**不按退出码判失败**，按 stderr 里有没有 `Audio:` 判 |
| 容器与编码不匹配 | AAC 塞进 `.mp3` 写不了头（`Could not write header`），报错看着像文件坏了。对策：`plan-output` 按**源编码**选容器，不按输入扩展名 |
| 裸 `.aac`（ADTS）不要用 | 没有时间戳，部分播放器拖动进度条会错乱。对策：AAC 一律装进 `.m4a` |
| Next 的 standalone 产物不会自动带上 `node_modules` 里的二进制 | 发布包里没有 `ffmpeg`，本地能跑、线上 `spawn ENOENT`。对策：`outputFileTracingIncludes` 把 `node_modules/@ffmpeg-installer/**` 打进该路由 |
| `@ffmpeg-installer` 被打包器内联 | 它靠 `require` 定位 `node_modules/.../ffmpeg`，一旦被合进 chunk，路径就指向产物内部。对策：`serverExternalPackages: ["@ffmpeg-installer/ffmpeg"]` |
| 响应流没读完就删临时文件 | 用户下到一半的文件被截断。对策：在响应流的 `close` / `finish` 之后再 `unlink`，不要在 `finally` 里提前删 |
| 中文文件名 | `Content-Disposition` 的中文要按 RFC 5987 写成 `filename*=UTF-8''…`，否则浏览器存下来是乱码或 `download` |
| 不要把文件交给 shell | `spawn("ffmpeg", args)` 直接传数组，不要 `exec` 拼字符串——文件名里有引号或空格就会被当成命令的一部分 |
| 前端 `accept` 不是强制 | 用户可以选任意文件，iOS 还会给 `video/quicktime` 或空 MIME。对策：MIME 或扩展名任一命中白名单即放行，真正认不出的交给服务器报「打不开」 |
| `proxy_request_buffering` 默认开着 | Nginx 会把 500 MB 先落盘再转发给 Node，等于写两遍磁盘、还慢一拍。对策：这个 location 加 `proxy_request_buffering off;` |
| 转码时忘了剥掉其它流 | 视频 / 字幕 / 章节流混进音频文件会让 ffmpeg 报错或产出奇怪的东西。对策：`-vn -sn -dn -map 0:a:0` 只留第一条音轨 |
