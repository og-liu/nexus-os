# Markdown 编辑器

> 能存多篇、可用标签归类的 Markdown 写作工具：左边文档列表、中间写原文、右边实时看渲染结果；
> 写完能复制走或导出 `.md`，外部的 `.md` 也能导入（单篇 / 批量 / 整个文件夹）。

| | |
|---|---|
| 入口 | `app/(app)/tools/markdown-editor/page.tsx`（一行薄壳）→ 实现住在本目录 `server/page.tsx` |
| 接口 | 无 HTTP 接口，数据入口是 Server Action（`server/actions.ts`） |
| 数据表 | `md_documents`（`docs/数据库/Markdown文档表.md`）、`md_tags` / `md_document_tags`（`docs/数据库/Markdown标签表.md`） |
| 状态 | ✅ 已上线（v0.10.0，2026-10-30 起） |

**这份 README 是这个工具唯一的文档**：代码结构在 §五，需求 / 界面 / 数据 / 决策 / 验收 / 坑在一～四、六、七。
原来的 `docs/功能/Markdown编辑器.md` 已于 2026-11-05 并入本文件，章节编号保持不变。

## 一、要什么

**做**

- **三栏工具页**：左栏文档列表、中栏编辑区、右栏实时预览；整页不滚、各栏自滚（同保险库的「应用型页面」）。
- **落库**：`md_documents` 一篇一行（标题 + 正文原文），按 `user_id` 隔离。
- **多篇**：新建 / 切换 / 删除；列表按「最近修改」倒序。
- **标题**：编辑区顶部独立输入框；留空存成「未命名文档」，重名自动补序号。
- **自动保存**：停手约 0.8 秒自动存，状态栏显示「保存中… / 已保存 / 保存失败」；切换文档、删除、离开页面前补存一次。
- **格式工具栏**：9 个按钮——粗体 / 斜体 / 行内代码 / 标题 / 无序列表 / 有序列表 / 引用 / 代码块 / 链接；点一下改写选区的 Markdown 语法。
- **实时预览**：`react-markdown` + `remark-gfm`，支持表格 / 任务列表 / 删除线，**不渲染原始 HTML**。
- **导出**：状态栏「复制 Markdown」与「导出 `.md`」（浏览器下载，文件名取标题）；状态栏显示字数（按字符数，emoji 记 1）。
- **标签**（2026-10-30 追加）：一篇可挂多个标签（多对多，两张表）；标签名里的 `/` 表示层级（`工作/周报` 是 `工作` 的子标签），筛选 `工作` 时子标签一起命中；编辑区工具栏下方一条标签条 + 左栏下拉筛选 + 独立管理面板。
- **版式三档 + 拖拽分栏**（2026-10-31 追加，2026-11-04 改默认）：仅编辑器 / 编辑器 + 预览 / 仅预览（手机两档），默认**编辑器 + 预览**；并排档中间一条可拖拽分割条（比例不持久化）。
- **批量删除**：左栏「选择」进批量模式，可全选；搜索时全选只作用于可见项；确认框写数量。
- **导入**（2026-11-04 加）：左栏顶行 `Upload` → **导入文件**（多选 `.md` / `.markdown`）或**导入文件夹**（递归收子目录）；标题取文件名、撞名补序号、超 60 字截断；正文原样入库；逐文件串行并显示「导入中 3 / 12」。
- **目录与页签栏同步**：`tool-catalog` 新增一条（分类「开发」），`tab-routes` 的 `TOOL_TAB_SLUGS` 加同一个 slug。

**主动放弃（本版不做，不是遗漏）**

| 放弃项 | 原因 |
|---|---|
| 代码块语法高亮 | 多一个高亮包 + 一套主题色，只为「把代码给外人看」这个场景；等宽 + 灰底够读 |
| 图片粘贴 / 上传 | 要存储、上传接口、渲染规则三样，是独立功能 |
| 目录导航（TOC） | 要先定标题锚点规则；文档都在几百行内，右栏滚两下就到 |
| 关闭页面兜底保存 | 会丢最后不到 1 秒的输入。要兜住得用 `sendBeacon` / keepalive 绕开 Server Action 自己写请求，收益只是「少丢几个字」——接受这个损失并写进 §七 |
| 全文搜索 | 只搜标题（前端过滤）。搜正文要 SQLite FTS5 + 中文分词，《数据库/README》§八 已把它排到知识库 |
| 版本历史 / 回收站 | 没有「上一次写的什么样」的需求；软删除会让每条查询都得带条件 |
| 标签树 / 拖拽归类 | 层级只靠名字里的 `/`，不做 `parent_id` 树：树要递归改名、移动、删除策略，而前缀匹配已能表达「分类下还有分类」 |
| 实时协同 / 多端同步 | 单机个人工作台，没有第二个客户端 |
| 导出 HTML / PDF | 导出目标是「能喂给别的系统」的 Markdown 原文；HTML / PDF 要另定样式与分页 |
| 滚动同步 | 要做「原文位置 ↔ 渲染位置」映射加滚动监听，第一版不值 |
| 导入查重 | 同一批导两次会多一份；查重要把库里正文逐篇比对或建内容哈希，重复了删一遍就行 |
| 识别 YAML front matter | 只服务「从 Obsidian / Hexo 搬进来」，还要一套 YAML 解析；第一版按文件名起名，正文里的 front matter 原样保留 |
| `.txt` 等其它扩展名 | `.txt` 里可能是任意编码的日志，混进来只是一堆乱码文档 |
| 导入时转换编码（GBK → UTF-8） | `file.text()` 一律按 UTF-8 解码；做编码嗅探有误判风险（判错会改坏正文） |
| 导入可取消 / 断点续传 | 一次几十篇是秒级的事；要中断就得回答「已导入的半批留不留」 |
| 从网页 / 剪贴板粘贴导入 | 要处理 HTML → Markdown 转换，是另一个功能 |

## 二、界面

### 2.1 整体骨架

和保险库一样是**应用型页面**：三栏各自滚动、整页不滚。

- 页面根 `flex h-full overflow-hidden`：**左栏整列到底**；右侧一列里先是一条横跨「编辑 + 预览」的标题行，下面才是这两栏。
- **没有 `ToolHeader`**：页签栏已经说明「我在哪、怎么切走」，再叠一条工具头是同一件事说两遍。
- 手机汉堡按钮住在标题行最左（`lg:hidden`）。
- **标题行为什么要提出来**：版式有三档，其中「仅预览」会让编辑区整块让位。标题与版式开关要是住在编辑区里，那一档就一起消失——既看不到在编辑哪一篇，也切不回来。提到「编辑 + 预览」这列最上面后，任何版式下它们都在。
- **但它不压到左栏头上**：左栏是独立一列、整列到底，标题行只横跨右边两栏；左栏自己的「新建 / 搜索」就是它的顶行。
- 标题行自己撑高、不给下层留占位；下面那行 `flex min-h-0 flex-1 overflow-hidden`——**`min-h-0` 不能省**，否则被内容撑破、整页开始滚。

```
页签栏（外壳的 TabBar，页面自己不再画标题行）
┌─ 列表 240 ─┬───────────── 标题行（h-11，横跨右边两栏）─────────────┐
│ [+ 新建]   │ [☰] [🗂] 标题……        [▯ ◫ ▯ 版式开关]     [+ 新建]   │
│ [搜索标题] ├────────── 编辑区（弹性） ─────────┬─── 预览（弹性） ───┤
│ 周报       │ B  I  `code`  H  列表  1.  引用 🔗 │  # 渲染出来的内容   │
│ 10-30 16:12│ # 这周做了什么 / - 上线了保险库    │  这周做了什么        │
│            │ 已保存 · 128 字   [复制] [导出 .md]                    │
└────────────┴──────────────────────────────────┴─────────────────────┘
```

### 2.2 左栏：文档列表

**可收起**（2026-10-31）：默认展开；标题行左侧那枚 `FolderTree` 图标在**所有宽度**都显示。≥ 1280 收起的是布局里那一列；< 1280 打开 / 关闭的是浮层——**浮层默认是关的**（一进页面就盖住正文不叫「默认展开」）。

- 宽度 240px（`w-60`），右边缘一条细线。
- 顶行：**新建**（黑底白字）+ 两枚图标按钮：**导入**（`Upload`，见 §2.8）与**批量选择**（`ListChecks`）；下方一行**搜索框**（有输入时右侧 `×`，占位「搜索标题」）。
- 每行：标题（`truncate`）+ 下一行修改时间（`MM-DD HH:mm`）；选中行 `bg-[#F5F5F5]`（全站黑白灰，不用彩色高亮）；点击 = 切换文档。
- 排序：`updated_at DESC, id DESC`。
- **行尾删除按钮一直显示**（`Trash2`，hover 从灰变纯黑而非变红），点它弹二次确认。删除跟着「哪一篇」走，不在顶行——顶行那个位置删的是「当前打开的那篇」，一篇都没打开时还得留个灰按钮。
- **标签筛选（下拉，2026-10-31）**：搜索框下面一行 `[标签 全部 ▾]`；点开是带搜索的面板——`全部` / `无标签` / 各标签（名字 + 篇数，子标签缩进），底部「管理标签…」。**单选**，选 `工作` 时 `工作/周报` 也算命中，再选一次取消。
  - 为什么不是一排 chips：左栏只有 240px，chips 过三四个就得横滑，标签十几个时既翻不过来也看不到全貌。
  - 管理面板：`共 N 个 · M 个在用` + 搜索；列表按「在用 / 还没用上」分组，`工作/周报` 显示成「工作 / 周报」并缩进；每行「N 篇 / 未使用」+ 改名 + 删除；底部一行新建输入 + 「创建」（**没打开文档时这是唯一能建标签的地方**），新建时**先清空搜索词并滚到新标签**（否则名字不含当前搜索词会被过滤掉，看起来像没建成）。
- **批量删除**（2026-10-31）：`ListChecks` 进批量模式——顶行换成批量条（`已选 N / M` + 全选 + 删除 + 取消），行内出现复选框、行尾垃圾桶让位、点整行 = 勾选。**选中范围 = 当前搜索结果**（否则计数会出现「已选 5 / 1」这种自相矛盾的数字）。一次 Server Action 一条 SQL 删完，别人的 id 混进来只是命中 0 行。删完退出批量模式；删到正在编辑那篇就打开剩余第一篇。
- 空态：「还没有文档」+「点上面的『新建』写第一篇」；搜索无结果：「没有标题包含『xxx』的文档」+「换个词试试」。

### 2.3 贯穿整页的标题行

`h-11`、`border-b`、白底，横跨「编辑 + 预览」两栏，从左到右：

- **汉堡**（`lg:hidden`，打开全局侧边栏）。
- **左栏开关**（纯图标 `FolderTree`，所有宽度都显示，`aria-expanded` 跟着状态变）——与保险库中栏的「群组」按钮同一枚图标：图标跟着项目走，不跟着名词走。
- **标题输入框**（`flex-1`，无边框、18px 半粗，占位「未命名文档」；手机上 16px 防 iOS 缩放）。
- **版式开关**（三枚图标，见 §2.6）。
- **「新建」**（`xl:hidden`，黑底 + `Plus` + 文字，与保险库中栏新建同款、同在最右）。≥ 1280 左栏常驻时两个入口都藏起来，不会一屏两个「新建」。
- **删除不在这行**：删除跟着「哪一篇」走，住在左栏列表行尾。

### 2.4 中栏：编辑区

**工具栏**（`h-9`，浅灰底，一行放得下，放不下时横向滚动不换行）：

| # | 图标 | 作用 | 结果 |
|---|---|---|---|
| 1 | `Bold` | 粗体 | `**选中**`；再点一次去掉 |
| 2 | `Italic` | 斜体 | `*选中*` |
| 3 | `Code` | 行内代码 | `` `选中` `` |
| 4 | `Heading` | 标题 | 行首 `# ` 循环 → `## ` → `### ` → 去掉 |
| 5 / 6 | `List` / `ListOrdered` | 无序 / 有序列表 | 行首 `- ` / `1. ` |
| 7 | `Quote` | 引用 | 行首 `> ` |
| 8 | `Code2` | 代码块 | 插入三行（围栏 / 空行 / 围栏），光标落在空行 |
| 9 | `Link` | 链接 | 有选中 → `[选中](url)` 且光标落在 `url`；无选中 → `[](url)` |

- 按钮 `type="button"`、**`onMouseDown` 里 `preventDefault()`**——否则点按钮瞬间 textarea 失焦、选区丢失，格式打到光标处而不是选中的字上。
- 没有按钮的语法（表格、任务列表、分割线、脚注）手打，预览照样渲染。
- **工具栏最右端常驻「预览」开关**（`Eye`，`ml-auto`）：≥ 768 每个档位都有；< 768 不出现（手机靠顶部两枚版式按钮）。

**标签条**（`h-9`，白底）：`[标签] [工作/周报 ×] [重要 ×] [+ 标签]`

- 打标签**不刷新文档的 `updated_at`**（内容没变，列表顺序不该跳），且**立刻落库**，没有「保存标签」这一步。
- 点「+ 标签」**立刻列出已有全部标签**（按使用次数排、可滚动、每项带「N 篇」），不用先打字就能挑；也能边打边筛；列表里没有的词直接回车就建。
- 下拉**挂在标签条外层**：标签条自己是横滑容器（`overflow-x-auto`），下拉放里面会被裁掉（踩过一次）。
- 建议项用 `onMouseDown` 提交（先于输入框 blur，否则一点就被关掉）。
- 点标签上的 `×` 只从**这篇**摘掉它，标签本身还在。「仅预览」时整块编辑区隐藏，这条跟着不显示。

**正文输入区**：原生 `<textarea>` 撑满剩余高度，无边框、`resize-none`。

- 字体 `sm:` 起 `font-mono text-[13px] leading-[1.7]`；**`< sm` 用 16px**（iOS 对小于 16px 的输入框聚焦会缩放整页）。
- 按 `Tab` 插入两个空格；`Shift+Tab` 不拦截。不做行号（视觉噪音，本工具不是 IDE）。

**状态栏**（`h-8`，11px）：左「保存中… / 已保存 / 保存失败，重试」（失败变红且整条可点、点一下立刻重存）；右「128 字」+「复制」+「导出 .md」。

### 2.5 右栏：实时预览

- 白底、自己滚。样式用 react-markdown 的 **`components` 映射**给：每个元素在映射里直接带 Tailwind 类名，不包 `.markdown-body` 那种全局作用域（本仓库只有一份 `globals.css`）。
- **必须逐个元素给**：Tailwind 的 preflight 会把 `h1` / `ul` / `blockquote` 的默认样式全清掉，漏一个，那个元素就和正文一样大、列表没有点。要覆盖 `h1`–`h3`、`p`、`ul` / `ol`、`blockquote`、行内 `code`、`pre`、`table`（含 `th` / `td`）、`a`、`hr`、任务列表的 `input`。
- 链接是黑字下划线（全站黑白灰，不给链接加蓝色）；`pre` 无高亮、可横向滚。
- 空正文时显示灰字「预览会显示在这里」。不做滚动同步、不做目录、不做高亮。

### 2.6 版式开关与分割条

三枚图标按钮住在标题行里（`bg-[#F5F5F5]` 底槽 + 选中项白底阴影）：

| 图标 | 档位 | ≥ md | < md |
|---|---|---|---|
| `PanelLeft` | 仅编辑器 | 只有编辑区 | 只有编辑区 |
| `Columns2` | 编辑器 + 预览 | 各占一半 | **不出现**（手机上并排每栏只有 180px 高） |
| `PanelRight` | 仅预览 | 只有预览区 | 只有预览区 |

- 三枚是**一套「版面示意」**（左栏 / 左右各半 / 右栏），比「铅笔 + 眼睛」那套更不容易误读——眼睛只能表达「看不看得见」，表达不了「只看预览」。
- 默认 **编辑器 + 预览**（2026-11-04 主人定，两个编辑器统一；10-31 曾改成「仅编辑器」）。
- 切换靠 CSS 显隐，**不卸载编辑区**：卸载会丢焦点与滚动位置。
- < md 时若状态是并排档（从桌面缩窄过来），按「仅编辑器」显示。

**分割条**（只在并排档出现）：两栏之间 `w-1.5`（6px）热区、视觉是 1px 线（默认 `#F0F0F0`，hover `#8A8A8A`，拖动中 `#1F1F1F`，光标 `col-resize`）。

- Pointer Events + `setPointerCapture`（拖出容器也不丢事件）；比例用**百分比**（宽度变了按比例缩放），每帧 `requestAnimationFrame` 节流。
- 边界：编辑区 ≥ 360px、预览 ≥ 320px（算预览宽度时扣掉 6px）；容器不够宽时两个下限各自缩到一半的一半。
- 拖动中给 `body` 临时加 `cursor: col-resize` + `user-select: none`（否则拖出一片蓝色选区）；松手 / 指针取消 / 卸载都清掉。
- **比例不持久化**（刷新回 1:1），不做双击复位、不做键盘调整。

### 2.7 响应式（四档，都是独立版式）

全局侧边栏 `lg`(1024) 起常驻、宽 80px，所以内容区宽度 = 视口 − 80（≥ 1024）/ 视口（< 1024）。

| 档位 | 视口 | 版式 |
|---|---|---|
| 宽屏 | ≥ 1280 | 左栏 240 整列到底 + 右侧「标题行 / 编辑 + 预览」；版式三档 |
| 窄屏 PC | 1024–1279 | 版式三档；列表收进抽屉（标题行的文档图标打开），标题行最右是黑底「新建」 |
| 平板 | 768–1023 | 版式三档；列表走抽屉；工具栏按钮间距收紧、`Heading` 之后的按钮允许横向滚动 |
| 手机 | < 768 | 标题行占满（汉堡 / 文档图标 / 标题 / 两枚版式按钮 / 最右「新建」）；版式只两档；**文档切换走横滑 chip 条**（当前那篇黑底），全屏列表顶部「← 返回」 |

- 三档以上用**互斥显隐**而不是 JS 读视口——首屏 SSR 不闪。
- 手机上「编辑 / 预览」是**二选一**、不是上下堆叠：375px 堆叠时两栏各只有 180px 高，谁都读不了。
- **两级侧边栏的展开方式逐档对齐保险库**：一级（全局侧栏）`lg` 起常驻、`< lg` 汉堡抽屉；二级（文档列表）`xl` 起常驻（可手动收起）、`md–xl` 抽屉按钮、`< md` 横滑 chip 条。
- **浮层的起点与左栏一致**：抽屉与手机全屏列表都是 `absolute`（页面根 `relative`）而不是 `fixed`——`fixed` 会从窗口最顶上开始、把页签栏一起盖住，两者错位会「弹一下」。
- 手机端预览字号上调一档（`p` 15px），远看才不费劲。

### 2.8 导入（2026-11-04 加）

**入口**：左栏顶行 `Upload` 图标 → 按钮右下方小菜单（宽 144px、右对齐）两项：**导入文件** / **导入文件夹**。再点按钮、点外面、按 `Esc` 都能关。

| 菜单项 | 怎么拉起 | 结果 |
|---|---|---|
| 导入文件 | 隐藏 `<input type="file" accept=".md,.markdown" multiple>` | 选 1 个 = 单篇，选 N 个 = 批量 |
| 导入文件夹 | **优先 `showDirectoryPicker()`**；没有它（Safari / Firefox）或被拒时退回 `<input webkitdirectory>` | 选一个目录，递归收全部 `.md` |

- **为什么不用 `webkitdirectory` 当主路径**：它每次都先弹浏览器强制的「将 N 个文件上传到此网站？」确认框——样式文案跟全站黑白灰直角完全不搭，而且「上传」两个字会让人以为文件真的发出去了（实际上只在内存里读文本，一个字节都不发）。
- 代价是兼容性：`showDirectoryPicker` 只有 Chromium 系支持，Safari / Firefox 走回退、那个框还在——浏览器决定的，网页改不了。
- 每次选完必须把 `input.value` 清空，否则再选**同一批**文件不触发 `onChange`。
- 过滤后一个 md 都没有 → toast「没有可导入的 .md 文件」。

**过滤与读取**（全在客户端）

- 扩展名只认 `.md` / `.markdown`（大小写不敏感），其它**静默忽略**（文件夹里混着别的东西是常态）。
- 排序：多选按 `name`、文件夹按 `webkitRelativePath`，用 `Intl.Collator(..., { numeric: true })` 做**自然排序**（`序号2` 排在 `序号10` 前面）。
- 逐个 `file.text()` 读（一律按 UTF-8）；单文件 `> 5MB` 跳过（10 万字符的 Markdown 最多几百 KB，5MB 已是事故文件）；读失败记「读取失败」。

**标题与正文**

- 标题 = 文件名去扩展名、`trim()`；空名 →「未命名文档」；超 60 字**截断**（丢标题比丢正文便宜）；撞名**补序号**（与「新建」不同：用户自己起的名字允许重名，**导入是机器起名**，重名会让列表出现两行一模一样的字）。
- 正文 = 文件全文原样入库：不 `trim`、不转换、不解析 front matter。

**入库**

- **逐文件串行**：一篇一次 `importDocumentAction`，不等前一篇回来不发下一篇（Server Action 请求体默认 1MB，几十篇一次传就超；串行还能报进度）。
- 服务端照常 `requireUser()` → `validateTitle` / `validateBody` → `createDocument`（客户端的预检只是提前拦截）。
- **从文件列表末尾往前导**：每篇 `updated_at` 递增、列表按它倒序，逆序导入后列表顶部正好是文件顺序的第一篇。

**进度与结果**

- 导入中：左栏顶行换成状态条（与批量条同一位置，列表不下推）「导入中 3 / 12」+ 2px 细进度轨道；三枚按钮全禁用。
- 完成：全成功 → toast「已导入 N 篇」；有跳过 → warn toast「已导入 8 篇，2 篇跳过：a.md（超过 10 万字）、b.md（文件太大）」，最多列 2 个文件名。
- 列表：新文档按文件顺序插到最前；**正在编辑的那篇一个字不动**（导入前先 `flush()`）；空库时自动打开第一篇。
- 导入期间不重拉整表：每篇 action 返回那一篇，客户端自己插进列表（同自动保存的「只动本地那一行」）。

## 三、数据模型

```sql
CREATE TABLE IF NOT EXISTS md_documents (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id    INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  title      TEXT    NOT NULL,
  body       TEXT    NOT NULL DEFAULT '',
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
```

标签是两张表（`md_tags` + `md_document_tags`）：一篇挂任意多个标签，也可以一个都不挂；标签名的 `/` 表示层级，筛选按前缀匹配。

设计要点：

- **`body` 存 Markdown 原文，不存渲染结果**：渲染结果是派生物，存一份就有了「两份真相」。渲染永远在客户端现算。
- **`title` 是独立一列，不从正文推导**：列表靠它显示，排序、搜索也只认它。正文里写不写 `# 标题` 与它无关。
- **没有 `deleted_at`**：硬删 + 二次确认。软删除会让这张表以后每条查询都带条件。
- **`updated_at` 每次保存都刷新**：它就是列表排序依据，也是「这篇什么时候动过」的唯一事实。
- **排序 `ORDER BY updated_at DESC, id DESC`**：末尾 `id DESC` 兜住毫秒撞车。
- 长度上限：标题 60 字、正文 100000 字符——**只在校验层**（`shared/validate.ts`），表里 TEXT 不给约束（SQLite 的长度约束在改表时很麻烦）。

## 四、关键决策

| 决策点 | 选择 | 理由 | 否决的备选 |
|---|---|---|---|
| 页面形态 | **三栏、整页不滚、各栏自滚** | 写文档要同时看见「有哪些篇」「正在写什么」「写出来什么样」 | 列表页 + 编辑页两跳；只有编辑区没有列表 |
| 编辑控件 | **原生 `<textarea>`** | 纯文本与 Markdown 是同一个东西，输入就是输出，不需要互转 | `contenteditable`（要维护 HTML↔Markdown 双向转换，等于重写编辑器）；CodeMirror / Monaco（几十万行依赖） |
| 预览渲染 | **`react-markdown` + `remark-gfm`** | 输出 React 元素树，**不需要 `dangerouslySetInnerHTML`**，原始 HTML 天然不渲染、没有 XSS 面 | 手写解析器；`markdown-it` + `dangerouslySetInnerHTML`（要自己接消毒）；服务端渲染预览（每次停手都往返，实时感没了） |
| 代码块高亮 | **不做** | 多一个高亮包 + 一套主题色，只为「把代码给外人看」 | `react-syntax-highlighter`；`shiki`（更重） |
| 标题从哪来 | **独立输入框**，留空 →「未命名文档」 | 列表要显示标题、搜索也搜它；只从正文第一个 `#` 推导的话，不写 H1 的文档全叫未命名 | 只认正文 H1；新建时弹窗先起名（多一步，名字往往是写完才想出来的） |
| 保存方式 | **防抖 800ms 自动保存** | 写作时脑子里不该有「保存」这个动作；800ms 是「一句话打完」与「别每个字都发请求」的折中 | 手动保存按钮；每按键都存（中文输入法一次拼字触发多次） |
| 切换文档 | **切换前 `flush()` 立即补存** | 否则最后不到 0.8 秒的输入直接丢，而这类丢失用户不会立刻发现 | 只靠防抖；弹「有未保存改动」确认 |
| 归类方式 | **标签（多对多），不是分组（唯一归属）** | 写作时真正同时成立的是「这是工作」「这条重要」两件事，一个格子装不下；标签还可以只建不用 | 分组 / 文件夹（一篇只能放一处，久了会纠结「该放哪」）；两者混用 |
| 标签层级 | **靠名字里的 `/`**，筛选按前缀 | 不用建树表、不用维护父子指针 | 单独建 `parent_id` 树（多一层表 + 移动 / 递归删除）；只做扁平 |
| 打标签的位置 | **编辑区工具栏下方一条标签条** | 打标签是「这篇的属性」，挨着正文最顺手；放左栏会挤掉列表 | 左栏行内（240px 太挤）；单独管理页（打完要跳回来） |
| 标签筛选 | **单选** | 多选叠加后「现在到底筛了什么」很难看清 | 多选 + 与 / 或 |
| 批量删除 | **「选择」图标进批量模式 + 二次确认**（确认框写数量） | 一次清十几篇是真实需求；不做常驻复选框是因为左栏只有 240px | 复选框常驻；长按多选（触屏与时间轴冲突） |
| 删除 | **列表行尾垃圾桶 + 二次确认，硬删** | 删除要跟着「哪一篇」走，行尾是唯一能一眼看清「删的是谁」的位置 | 编辑区右上角（一篇都没打开时那里留个灰按钮，删的是「当前那篇」而非「你指的那篇」）；回收站 |
| 排序 | **`updated_at DESC`，不可手动排** | 只有「最近写的那篇在最上面」一个需求；自动保存天然让它浮到顶 | 按标题排；手动拖拽（要 `position` 列 + 批量重排） |
| 工具栏实现 | **9 个按钮 + 纯函数改写选区** | `applyFormat(text, selection, kind)` 能单测（含「已加粗再点取消」这种反向）；不弹窗、不引编辑器库 | 富文本工具条（内容就不是纯 Markdown，导出的 `.md` 会失真） |
| Tab 键 | **插入两个空格** | 编辑器里 Tab 缩进是通用预期（Typora / VS Code 都这样） | 让焦点跳走（正文里按 Tab 跳出去会很意外） |
| 版式开关 | **三档，住在贯穿整页的标题行里** | 三种用途都真实存在（安静写 / 边写边看 / 只看结果）；放标题行是因为「仅预览」时编辑区整块让位 | 一个「眼睛」开关（表达不了「只看预览」）；开关留在编辑区工具栏（那一档点不到） |
| 手机预览 | **「编辑 / 预览」二选一** | 375px 堆叠时每栏只有 180px 高，两样都读不了 | 手机也双栏；手机只给编辑（等于砍掉「实时预览」这个需求） |
| 导入的入口形态 | **左栏顶行一枚 `Upload` 图标 + 小菜单** | 「往列表里加文档」和「新建」是同一类动作，住同一行；240px 刚好放得下 | 一个按钮直接多选（**放不下文件夹导入**，而文件夹才是搬一批文档的主路）；放标题行（手机上那行已经很挤） |
| 导入的标题来源 | **文件名去扩展名** | 与「导出用标题当文件名」正好反向闭环：导出再导入，标题不变 | front matter 的 `title`（要多一套 YAML 解析）；正文第一个 `# `（要排优先级） |
| 导入的重名处理 | **自动补序号**（`周报 2`） | 导入是机器起名；补序号不丢任何一篇 | 覆盖（**丢内容**）；跳过（用户得自己一篇篇改名再导） |
| 导入的读取位置 | **浏览器读文本 → Server Action，不上传不落盘** | `.md` 是纯文本，`file.text()` 直接进内存；项目没有持久文件存储，上传要另建临时目录 + 清理策略 + 接口 | 上传文件到服务端再解析（多三层基建） |
| 导入的入库方式 | **逐文件串行、一篇一个 action** | Server Action 请求体默认 1MB；串行还能报进度、单篇失败不牵连其它 | 一次传整批（超限整批失败）；并发发 N 个（SQLite 写锁排队、进度跳着涨） |
| 导入的入库顺序 | **文件列表末尾往前导** | 列表按 `updated_at DESC` 排；逆序导入后列表顶部正好是文件顺序的第一篇 | 正序导入（顶部是最末一个文件，像把文件夹倒过来）；同批共用一个时间戳 |
| 文件夹选择器 | **优先 `showDirectoryPicker()`，回退 `webkitdirectory`** | 前者是原生目录选择器，没有「上传确认框」，还给真实目录结构 | 只用 `webkitdirectory`（那个框永远在）；只用 `showDirectoryPicker`（Safari / Firefox 没入口）；拖拽文件夹（手机用不了） |

## 五、代码结构（三层）

**这就是原来的「文件落点」一节。**

`client/` —— 浏览器（`"use client"`）。不碰 db、不 import `server/`。

| 文件 | 职责 |
|---|---|
| `markdown-editor-view.tsx` | 页面主视图：状态中枢（当前文档、列表、搜索、批量、版式、导入） |
| `editor-top-bar.tsx` | 贯穿「编辑 + 预览」的标题行（标题 / 版式开关 / 左栏开关 / 新建） |
| `view-mode-switch.tsx` | 版式三档开关 |
| `split-divider.tsx` | 可拖拽分割条（Pointer Events + rAF 节流 + 边界夹取） |
| `split-divider.test.ts` | 分割条夹取逻辑单测 |
| `document-list.tsx` | 左栏（新建 / 导入菜单 / 批量选择 / 搜索 / 标签筛选 / 行尾删除 / 空态） |
| `document-list-overlays.tsx` | md–xl 抽屉 + <md 全屏列表（贴页面根、不盖页签栏） |
| `document-chips.tsx` | <md 的文档切换 chip 条 |
| `import-menu.tsx` | 导入按钮 + 小菜单 + 两个隐藏 input + 读文件 |
| `editor-pane.tsx` | 中栏（工具栏 + textarea + 标签条 + 状态栏） |
| `format-toolbar.tsx` | 9 个格式按钮 |
| `preview-pane.tsx` | 右栏（`react-markdown` + `remark-gfm`，`components` 映射带类名） |
| `tag-bar.tsx` | 编辑区标签条（点开列已有标签 / 回车新建 / 失焦不误建） |

| `use-document-tags.ts` | 标签状态与动作（从主视图抽出） |

`server/` —— 服务端。碰 db 的文件开头有 `import "server-only"`。

| 文件 | 职责 |
|---|---|
| `page.tsx` | 工具页接线：`requireUser()` → 取文档列表与标签 → 渲染视图 |
| `actions.ts` | Server Actions（`"use server"`）：文档 6 个 + 标签 5 个，每个都先 `requireUser()` |
| `documents.ts` | 文档数据访问（`server-only`）：列表带标签一次聚合、读 / 建 / 存 / 删 / 批量删、未命名补序号 |
| `documents.test.ts` | 文档数据层单测（`user_id` 隔离、排序、只动 `updated_at`） |
| `tags.ts` | 标签数据访问（`server-only`）：建改删、批量删、使用计数、`/` 层级改名连子标签 |
| `tags.test.ts` | 标签数据层单测 |

`shared/` —— 两端共用，只碰纯数据。

| 文件 | 职责 |
|---|---|
| `tags.ts` | 标签类型与纯函数：归一化键、`/` 层级前缀匹配 |
| `validate.ts` | 校验：标题 60 字 / 正文 100000 字符 / id |
| `validate.test.ts` | 校验边界 |
| `format.ts` | 工具栏纯函数 `applyFormat(text, selection, kind)` |
| `format.test.ts` | 9 种语法 + 取消 + 跨行选区 |
| `export-name.ts` | 导出文件名清洗（非法字符替换、空标题兜底） |
| `export-name.test.ts` | 文件名清洗 |
| `import.ts` | 导入纯函数：扩展名判断 / 文件名 → 标题 / 撞名补序号 / 排序 |
| `import.test.ts` | 导入用例 |

**从哪开始读**：`server/page.tsx` → `client/markdown-editor-view.tsx`（状态都在这，最大的一个文件）→ `server/actions.ts`。

**混合体拆开**：`tags.ts` 原先纯函数与数据访问混在一个文件——碰库的留在 `server/tags.ts`
（带 `server-only`），纯的进 `shared/tags.ts`，因为客户端的 `tagKey` / `tagMatchesPrefix` 是运行时调用。

**工具接入是四处，不是两处**：工具目录条目、分类集合（「开发」本来就在，不用动）、静态路由薄壳、
**页签栏白名单**（`TOOL_TAB_SLUGS`）。第四处漏了，页面能用、卡片能点、地址也对，但顶部页签栏里没有它。

**约束**：`client/` 与 `shared/` 不 import `server/`（`import type` 与 `"use server"` 的 actions 除外）；
表结构唯一权威仍是 `initSchema()`；`react-markdown` / `remark-gfm` 只在客户端组件里 import，
不要从公共组件引。

## 六、验收标准

**正常路径**

1. 打开工具页：三栏出现；列表空态「还没有文档」；标题框占位「未命名文档」；预览区「预览会显示在这里」；状态栏「已保存 · 0 字」。
2. 「新建」→ 列表出现一行「未命名文档」，编辑区清空且标题框**获得焦点**，地址栏不变。
3. 标题框输入「周报」→ 停手约 1 秒 → 左栏那一行变成「周报」；刷新后仍叫「周报」。
4. 正文输入 `# 标题` / `- 一` / `- 二` → 预览出现 `<h1>` 与含两项的 `<ul>`（检查 DOM 是标签，不是字面量）。
5. 输入两行表格 → 预览渲染出 `<table>`（`remark-gfm` 生效）。
6. 选中「标题」点 **B** → 变成 `# **标题**`，选区仍包住；再点一次 → 恢复。
7. 空行点「标题」→ 行首 `# `；连点三次依次 `## ` / `### `，第四次回到无前缀。
8. 空行依次点「无序 / 有序 / 引用」→ 行首分别是 `- ` / `1. ` / `> `。
9. 「代码块」→ 插入三行，**光标落在中间那行**。「链接」→ `[链接文字](url)`，光标落在 `url` 上。
10. 输入后状态栏先「保存中…」约 1 秒后「已保存」；字数随输入变化（emoji 记 1）。
11. 「复制 Markdown」→ 剪贴板里是**原文**（含 `#` / `-` / `**`），toast「已复制」。
12. 「导出 .md」→ 下载 `<标题>.md`，内容与正文逐字一致；标题为空时是「未命名文档.md」。
13. 建第二篇「灵感」→ 两行、它在最上；在「灵感」打一段字后**立刻**切到「周报」再切回 → 那段字还在（切换前已 flush）。
14. 标签：点「+ 标签」输入「工作/周报」回车 → 标签条出现；再打「重要」→ 两个并存；切到另一篇，它的标签条是空的。

## 七、已知的坑

| 坑 | 机制 | 对策 |
|---|---|---|
| `react-markdown` 不接受 `className` | v9 起收紧了 props，`className` 传不进去（类型报错或静默忽略） | 不传 `className`、也不包 `.markdown-body`：样式全走 `components` 映射 |
| 预览样式被 Tailwind preflight 抹平 | preflight 把 `h1` 字号、`ul` 的 `list-style`、`blockquote` 缩进全清零 | `components` 映射必须覆盖**每一种**渲染出来的元素，漏一个就退回裸样式 |
| 手机上聚焦输入框整页放大 | iOS 对 `font-size < 16px` 的输入控件聚焦时会自动缩放 | 标题与正文在 `< sm` 用 16px，`sm:` 起回到 18px / 13px mono |
| 点工具栏按钮后格式打到光标处 | 按钮拿到焦点、textarea 失焦，`selectionStart/End` 归零 | 按钮 `onMouseDown` 里 `preventDefault()` |
| 切换文档丢最后一段 | 防抖计时器还没到就已经切走 | hook 暴露 `flush()`；切换 / 删除 / 卸载前都先调；用 ref 持有最新 timer 与内容 |
| 保存请求乱序覆盖 | 慢请求后到，旧内容盖掉新内容 | 客户端串行：有请求在飞时不发新的，落地后内容又变了再补一次；每次带递增 `revision` 丢弃过期响应 |
| 中文输入法把半截拼音存进去 | 拼字过程中 `onChange` 就会触发 | `compositionstart` 期间暂停防抖、`compositionend` 后再启动 |
| 长文档预览卡顿 | 每个字符都重新解析整篇 Markdown | 预览只吃「防抖后的文本」，用 `useMemo` 按快照算 |
| 保存后列表整条重拉打断输入 | 重拉列表会让正在编辑的行卸载重挂，焦点与滚动位置丢失 | 保存成功后**只本地更新那一行**（标题 + 时间 + 提到最前） |
| 自动保存让列表每 0.8 秒跳一次 | 正在编辑的这篇 `updated_at` 一直刷新 | 它本来就在最前；但 `id DESC` 兜底必须写，否则同毫秒内两篇会互换 |
| Tab 键把键盘用户困住 | 正文里 Tab 被吃掉，无法移出输入框 | 只在正文 textarea 的 keydown 里拦截 Tab；工具栏按钮仍可用 Tab 遍历 |
| 导出文件名带非法字符 | 标题里可能有 `/`、`:`、`?` | `\ / : * ? " < >` 与竖线一律替换成 `-`，为空则「未命名文档」 |
| 时间显示跨时区漂移 | 服务端容器是 UTC | 复用 `lib/format.ts` 的 `formatDateTime` |
| 纯 ESM 包构建报错 | `react-markdown` v10 只发 ESM | 先在客户端组件里直接 import 跑 `pnpm build`；只有报错时才去 `next.config.ts` 加 `transpilePackages` |
| 导入再选同一批文件没反应 | `<input type="file">` 认为 `value` 没变就不触发 `change` | 每次处理完就 `event.target.value = ""` |
| **清空 `value` 的顺序反了 → 一个文件都导不进来** | `event.target.files` 是**活的** `FileList`：先 `value = ""` 再读它，拿到空数组且不报错，界面上就是「点了导入没反应」（真机验收踩到） | 先 `[...event.target.files]` 拷成数组，**再** `event.target.value = ""` |
| `webkitdirectory` 在 React 类型里不存在 | `InputHTMLAttributes` 没这个属性（Chromium 扩展，不在标准里） | 用 spread 传（`{...{ webkitdirectory: "" }}`）或 `ref` 里 `setAttribute`，不加 `@ts-expect-error` 盖住 |
| 导入一整批时请求超限 | Server Action 默认请求体上限 1MB | 一篇一个 action、串行发；进度按「已完成 / 总数」算 |
| 文件夹选择器不认 `accept` | `webkitdirectory` 的 input 上写 `accept` 会被忽略 | 选完在客户端按扩展名过滤，**静默忽略**非 md |
| `showDirectoryPicker` 不在 TS 类型里 | 实验性 API，`lib.dom` 没覆盖 | 自己声明最小接口（`values()` / `getFile()` / `name`）再断言，不往全局补整块 API |
| 调 `showDirectoryPicker()` 报 `SecurityError` | 浏览器只认「用户手势」那一拍，先 `await` 别的东西再调就失效 | 在菜单 `onClick` 的同步栈里调用，放在第一个 `await` 之前 |
| 用户取消选目录被当成错误 | 取消时抛 `AbortError` | `name === "AbortError"` 一律静默返回；只有其它错误才回退到 input |
| GBK 编码的 `.md` 导进来是乱码 | `file.text()` 一律按 UTF-8 解码 | 第一版只承诺 UTF-8；不做编码嗅探（误判会把好好的正文改坏） |
| `FileList` 顺序随浏览器 / 系统变 | 多选时顺序不保证按名字，文件夹遍历顺序也不稳定 | 自己排序：多选按 `name`、文件夹按 `webkitRelativePath` |
| 导入到一半关掉页面 | 已入库的那几篇不会回滚，剩下的不会继续导 | 接受这个行为；文档写清「没有断点续传」，不假装有 |
| 演示数据残留 | 手测时建的「周报」会被当成真文档 | 验收结束前删掉测试文档（或换测试账号） |

## 八、依赖变更

**新增两个运行时依赖**（已登记进《技术栈说明》）：`react-markdown@10.1.0`（Markdown → React 元素树，
不经 HTML 字符串、天然无 XSS 面）、`remark-gfm@4.0.1`（表格 / 任务列表 / 删除线 / 自动链接）。
两者都是纯前端纯 JS、无原生模块，只在工具页的客户端组件里 import（不放进公共组件，避免拖累全站首屏）。

**不引入**：代码高亮（`react-syntax-highlighter` / `shiki`）、编辑器内核（CodeMirror / Monaco）、拖拽库。
