## 一、要什么

**做**

- 工具页 `/tools/sticky-notes`：便签的完整增删改 + 置顶；新建 / 编辑走弹窗，删除走原位确认。
- 落库：新表 `sticky_notes`，每条归属到用户；正文上限 1000 字；置顶同时记 `pinned` 与 `pinned_at`。
- 首页常驻卡：总览页立起「便签」卡，显示置顶优先的最近 3 条，右上「管理 →」直进工具页。
- 目录同步：`tool-catalog` 里状态从「开发中」改为「可用」。

**主动放弃（本版不做，不是遗漏）**

| 放弃项 | 原因 |
|---|---|
| 搜索 / 筛选、归档 / 分类 | 那会让它长成笔记系统，与「知识」页职责重叠 |
| 标题 / 颜色 / 富文本 | 便签的价值是「少想一步」，多一个字段就多一次决定；颜色还会破坏黑白灰基调 |
| 自动保存 | 便签极易误改，没有撤销时自动保存会把原稿悄悄覆盖 |
| 删除撤销 / 回收站 | 要引入软删除与清理策略；原位二次确认已经把误删挡在前面 |
| 拖拽排序 / 手动排序 | 排序规则只有一条（置顶优先 + 置顶时间 / 更新时间倒序），够用且不必存位置 |
| 多端同步 / 分享 | 单机 SQLite、个人使用；等真有跨设备需求再谈 |
| 首页显示全部 / 分页 | 首页是摘要，3 条封顶；看全部去工具页 |

## 二、界面

### 2.1 工具页 `/tools/sticky-notes`

与待办工具页同构：**没有 PageHeader**，工具名与状态在内容区的信息条里；手机上「汉堡 + 新建」住在页面顶部那一行。

```
移动端导航行（< lg）：汉堡 + 新建便签
内容区（px-4 py-4 md:px-6 md:py-6）
├─ 工具信息条（黑底白图标 h-12 w-12 + 名称 / 描述 / 分类 chip / 状态点「可用」）
│   └─ 右侧「新建便签」（≥ lg；< lg 的入口在顶部导航行）
├─ 吸顶工具栏（ToolBar，与待办页共用）
└─ 列表
   ├─ 「全部便签 N」分组标题
   ├─ 便签网格（正方形卡片）
   └─ 空态：虚线框「还没有便签」+「新建便签」按钮（§7.12）
```

**网格**：`grid grid-cols-2 gap-3 md:grid-cols-4 lg:grid-cols-5 xl:grid-cols-6 [@media(min-width:1400px)]:grid-cols-7`。
每张卡 `aspect-square`（实测边长约 166px / 375、171 / 768、185 / 1100、190 / 1280、177 / 1440）；
1280–1399 保持 6 列、1400 起 7 列——再密一档，底部「时间 + 置顶文案 + 删除」会挤出卡片。
卡片内边距 `p-3 md:p-4`，正文最多 5 行（`line-clamp-5`）。

**便签卡三态**

| 态 | 长什么样 |
|---|---|
| 阅读 | 正方形白卡 `rounded-[2px] bg-white`；正文 `whitespace-pre-wrap break-words text-[13px]`；底部一行：左「时间 + 已置顶 / 未置顶」文字按钮，右删除按钮（桌面 hover 才显、触屏常显） |
| 编辑 | **弹窗**（`NoteDialog`）：无边框 `textarea`、自动长高、`maxLength=1000`；`Enter` 换行、`⌘/Ctrl+Enter` 保存、`Esc` 取消；编辑时左下角显示「创建于 …」；底部：删除（仅编辑态）/ 取消 / 置顶保存 / 保存 |
| 删除确认 | 卡片内容换成「删除这张便签？」+「删除 / 取消」，仍是正方形；不弹全局对话框 |

交互定死的几条：

- **点卡片任意位置打开编辑弹窗**；置顶文字与删除按钮浮在上层，点它们不触发编辑。
- **置顶不用图钉图标**：底部直接写「未置顶 / 已置顶」，点文字切换（带 `aria-pressed`）——状态与动作是同一个东西，不用再猜图标含义。
- **置顶排序**：最近置顶的排最前（`pinned_at DESC`）；取消置顶后回到按更新时间该在的位置，且**不碰 `updated_at`**。
- **「置顶保存」**：保存与置顶合成一步（同一事务），新建 / 编辑完不用再滚回列表找它。
- **底部按钮只有两层样式**：删除 / 取消 / 置顶保存都是灰底同高同圆角，保存是黑底白字。
- **删除**：先弹确认条（「删除后无法恢复，确定删除这条便签？」），确认后才删并关弹窗；不可撤销，文字用错误色 `#B91C1C`。删除成功弹全局提示「便签『正文摘要』已删除」（24 字符截断，桌面右下 / 手机居中，3 秒消失）。
- 删除按钮按 hover 分档：桌面收起来保持卡片干净，触屏常显（否则永远按不到，见 §七）。

### 2.2 首页常驻卡 `/`

- 白卡 `p-5` + 分组标题「便签」+ 右上「管理 →」链到 `/tools/sticky-notes`（**不是** `/tools`——管的是便签本身）。
- **点哪一条就看哪一条**：每条链到 `/tools/sticky-notes?note=<id>`，工具页落地即打开这条的编辑弹窗；打开后 `?note=` 被 `router.replace` 抹掉，id 找不到（已删）就当没传。
- 卡内 3 条灰块（`rounded-[2px] bg-[#F5F5F5] px-3 py-2.5`），**一条只占一行**：正文 `truncate`、时间 `shrink-0 text-[10px]` 在右。
- 分栏按**卡片自身宽度**（容器查询）：容器 ≥ 448px（`@md`）排 2 列，否则单列。首页这张卡固定约 430px，所以是单列三行；以后拼回主区 2/3 会自动回到 2 列。用视口断点会犯「窗口宽、卡片窄，照样 2 列」的错。
- 显示哪 3 条：与工具页同一套排序，只是 `limit: 3`。
- 空态：`#F5F5F5` 占位块「还没有便签」+「写一条 →」。

### 2.3 响应式

| 档位 | 工具页 | 首页 |
|---|---|---|
| 移动 < md（375 起） | 2 列正方形卡片（约 166px）；顶部汉堡 + 新建；卡片 `p-3` | 单列第一块；3 条便签块；「管理 →」保留 |
| 平板 md ~ lg | 4 列（约 171px）；信息条仍纵向 | 单列（< xl） |
| 窄屏 PC lg ~ xl | 5 列（约 185px）；信息条转横向 | 同上 |
| 宽屏 ≥ xl | 6 列（约 190px）；≥ 1400 时 7 列 | 网格 3 列：左 2 便签、右 1 待办 |

三档用互斥显隐（`hidden … lg:flex` / `lg:hidden`），不做 JS 断点判断——首屏 SSR 不闪。

## 三、数据模型

```sql
CREATE TABLE IF NOT EXISTS sticky_notes (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id    INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  body       TEXT    NOT NULL,
  pinned     INTEGER NOT NULL DEFAULT 0,   -- 0 / 1，SQLite 没有布尔类型
  pinned_at  INTEGER,                      -- 置顶时刻（毫秒）；NULL = 未置顶
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL              -- 只有改正文才刷新，置顶不刷新
);
CREATE INDEX IF NOT EXISTS idx_sticky_notes_user_id ON sticky_notes(user_id);
```

设计要点：

- **表名带领域词**：`sticky_notes` 而不是 `notes`——后者留给以后的笔记 / 知识条目。库、路由、目录三处同名。
- **`pinned` 与 `pinned_at` 是同一件事的两面**：前者答「是不是」，后者答「什么时候置顶的」（组内排序用）。**只在 `setNotePinned` 一处一起写**。
- **置顶不碰 `updated_at`**：否则「更新时间」变成谎话，取消置顶后便签还会莫名其妙跳到最前。
- **老库补列**：`initSchema()` 里的 `migrateStickyNotePinnedAt()` 只在列不存在时 `ALTER TABLE`，并把已有置顶行回填成 `pinned_at = updated_at`（保留原相对顺序）；列已存在就什么都不做。
- **正文上限 1000 字**：服务端校验兜底（Server Action 是公开端点），`trim()` 后为空一律拒绝。
- **排序**：`ORDER BY pinned DESC, pinned_at DESC, updated_at DESC, id DESC`；末尾 `id DESC` 兜住毫秒撞车。

## 四、关键决策

| 决策点 | 选择 | 理由 | 否决的备选 |
|---|---|---|---|
| 产品边界 | 随手贴：写完就不管，找它靠时间与置顶 | 加搜索 / 分类就开始长成笔记系统，与「知识」页重叠 | 做成轻量笔记（会拖成第二个知识库） |
| 编辑形态 | **弹窗** | 原地展开会把卡撑高、破坏正方形网格，还把下面所有卡顶下去 | 卡片原地变输入框；独立编辑页（为几十字开一页太重） |
| 保存时机 | 显式「保存 / 取消」，另给「置顶保存」 | 没有撤销时自动保存会把原稿吃掉；置顶保存把「存完再回去点置顶」合成一步 | 自动保存 + 防抖（要配版本冲突与撤销） |
| 保存与置顶的原子性 | 同一个事务 | 「存了但没置顶」是半成品 | 先保存再单独置顶（中间失败界面与预期不一致） |
| 删除 | 原位二次确认 | 不引全局对话框，确认就在原地；误删代价高，值得多一次点击 | 直接删 + Toast 撤销（要软删除）；浏览器 `confirm` |
| 置顶的数据形态 | `pinned` + `pinned_at` 两列 | 既答「是不是」，也答「什么时候置顶」；组内「最新置顶在前」需要这个时间 | 只有 `pinned`（刚置顶的旧便签会沉到置顶区末尾） |
| 置顶组内排序 | `pinned_at DESC` | 刚置顶的那张应该第一眼看到；编辑正文不改变置顶顺序 | 按 `updated_at`（置顶不刷新它，刚置顶的旧便签会排到末尾） |
| 首页卡数据来源 | 与工具页共用同一查询函数，只传 `limit: 3` | 一处排序规则、两处使用 | 首页单写一条 SQL（两份迟早不一致） |
| 首页「管理」指向 | `/tools/sticky-notes` | 管理的是便签本身；指向工具列表还要再找一次 | 指向 `/tools`（多一跳） |
| 时间怎么显示 | **绝对时间 `YYYY-MM-DD HH:mm`**，按 UTC+8 算 | 相对日期会随时间跳、扫读还要换算；固定 +8 可预测、可单测 | 浏览器本地时区（首帧不一致）；「今天 / 昨天」（跨天会变） |
| 卡片尺寸 | **正方形**（`aspect-square`） | 便签本来就该方方正正，网格里视觉最整齐 | 固定高度矩形（长短混排高度不齐） |
| 卡片密度 | 2 / 4 / 5 / 6 / 7 列，1280–1399 收一档 | 正方形边长与底部行宽度互相牵制 | 一律 3 列（宽屏太稀）；一律 7 列（1280 下过窄） |
| 工具页要不要信息条 | 保留，状态「可用」 | 工具页同构，从列表点进来先确认「我在哪」 | 去掉（与其余工具页不同构） |

## 五、代码结构（三层）

垂直迁移后（2026-11-05），一个工具一个目录，按「谁在跑」分三层。**这就是原来的「文件落点」一节**。

`client/` —— 浏览器（`"use client"`）。不碰 db、不 import `server/`。

| 文件 | 职责 |
|---|---|
| `sticky-notes-view.tsx` | 工具页视图：版式、置顶 / 删除 / 新建的交互编排（状态中枢） |
| `note-card.tsx` | 一张便签卡（§2.1）：正文、时间、置顶与删除按钮 |
| `note-dialog.tsx` | 新建 / 编辑弹窗（`Modal` 壳 + 下面的编辑器） |
| `note-editor.tsx` | 原地编辑器：新建空卡与编辑已有便签共用，含字数与置顶开关 |

`server/` —— 服务端。碰 db 的文件开头有 `import "server-only"`。

| 文件 | 职责 |
|---|---|
| `page.tsx` | 工具页接线：`requireUser()` → 取全部便签 → 解析 `?note=<id>` 深链 → 渲染视图 |
| `actions.ts` | Server Actions（`"use server"`）：新建 / 保存 / 置顶 / 删除，写完全量回列表 |
| `notes.ts` | 数据访问（`server-only`）：`listNotes` / 增删改；排序只在 SQL 一处 |
| `notes.test.ts` | 数据层单测：`user_id` 隔离、置顶不动 `updated_at`、排序兜底 `id DESC` |
| `sticky-notes-card.tsx` | 首页便签卡（服务端组件）：标题 + 最近 3 条 + 深链 |

`shared/` —— 两端共用，只碰纯数据。

| 文件 | 职责 |
|---|---|
| `validate.ts` | 正文校验：去空后判空、按字符数（`Array.from`）算长度 |
| `validate.test.ts` | 校验边界：全角空格、换行、超长 |
| `format.ts` | 时间展示格式化（`formatNoteTime`，转口到 `lib/format`） |
| `format.test.ts` | 格式化用例 |

**从哪开始读**：`server/page.tsx`（怎么接线）→ `client/sticky-notes-view.tsx`（交互全在这）→ `server/actions.ts`（写入）。

**边界**：路由薄壳必须落在 `app/(app)/tools/sticky-notes/page.tsx`（只有一行 re-export）；首页只改
`app/(app)/page.tsx`，不另建别名路由。表结构的唯一权威仍 `src/lib/auth/db.ts` 的 `initSchema()`。
工具页工具栏复用 `components/tools/tool-bar.tsx` / `tool-mobile-bar.tsx`；时间格式化统一走 `lib/format.ts`。

## 六、验收标准

**正常路径**

1. 打开 `/tools/sticky-notes`：出现工具信息条（「便签」/「可用」）；没有便签时显示「还没有便签」空态。
2. 新建 → 输入「周一交周报」→ 保存 → 网格出现一张正方形卡（正文 + `YYYY-MM-DD HH:mm`）；刷新后仍在。
3. 点卡片 → 编辑弹窗（左下「创建于 …」）→ 改正文 → 保存生效；再改回并按 `Esc` → 数据库不变。
4. 「置顶保存」→ 保存成功且排在置顶区第一条，底部文案变「已置顶」。
5. 点「未置顶」文字 → 变「已置顶」并移到最前；再点一次 → 回到按更新时间该在的位置，`updated_at` 不变。
6. 两条置顶并存：最近置顶的在前，与它们的 `updated_at` 无关。
7. 删除 → 卡片变「删除这张便签？」→「取消」保留；再走一次点「删除」→ 卡片消失，刷新后确实没了。
8. 正文 1000 字可保存；1001 字被服务端拒绝（弹窗内提示，行数不变）。
9. 首页：便签卡显示置顶优先的最近 3 条，第 4 条起不出现；时间与工具页一致。
10. 首页「管理 →」→ 地址变为 `/tools/sticky-notes`。
11. 首页没有便签时：卡内「还没有便签」+「写一条 →」，点它进工具页。
12. 首页点某一条 → 工具页落地直接打开这条的编辑弹窗；关掉再刷新不会又弹回来。

**负面路径**

13. 未登录直接访问 `/tools/sticky-notes` → 跳 `/login`。
14. 提交只有空格 / 换行的正文 → 保存失败并给字段级提示，行数不变。
15. 正文写 `<img src=x onerror=alert(1)>` → 按原文字面显示，无弹窗、无图片请求。
16. A 用户更新 / 删除 B 用户的便签（数据层单测，两个 `user_id`）→ 影响行数 0。
17. 便签不存在时调用更新 / 置顶 / 删除 → 不抛未捕获异常，页面不白屏。
18. 保存请求还在飞时重复点保存 → 只落一条。

**响应式**

19. 375px：2 列（约 166px），顶部汉堡 + 新建，删除按钮常显。
20. 768px：4 列（约 171px），「新建便签」在信息条右侧。
21. 1100px：5 列（约 185px），信息条横向。
22. 1440px：7 列（约 177px）；首页逐块一行，便签卡 430px。
23. 首页在 375 / 768 / 1100px 下逐块一行，屏宽不足时各自满宽。

**门禁**

24. `next typegen` / `typecheck` / `lint` / `test` / `build` 全过。
25. 单测覆盖：排序（置顶优先 + `pinned_at` 倒序 + 更新时间 + id 兜底）、`pinned_at` 迁移回填、置顶不碰 `updated_at`、正文校验（空 / 边界 1000）、`user_id` 隔离、时间格式化（UTC+8 / 跨天 / 跨年）。

## 七、已知的坑

| 坑 | 机制 | 对策 |
|---|---|---|
| 服务端时区不是 +8 | 线上容器多为 UTC，日期会差 8 小时 | 格式化不复用默认时区，显式按 UTC+8 算 |
| 毫秒撞车导致顺序不稳 | 同毫秒两条 `updated_at` 相等 | 排序末尾补 `id DESC` |
| 置顶顺手改了 `updated_at` | 取消置顶后便签跑到最前，「更新时间」变谎话 | 只写 `pinned` / `pinned_at` |
| 刚置顶的旧便签沉底 | 置顶不刷新 `updated_at` | 加 `pinned_at`，组内按置顶时间倒序 |
| 老库没有 `pinned_at` | `CREATE TABLE IF NOT EXISTS` 不给已存在的表加列 | `initSchema()` 里幂等 `ALTER TABLE` + 只回填已置顶行 |
| 触屏上删除按钮永远不出现 | `group-hover` 在触屏没有 hover | 默认可见；只在 `@media (hover: hover)` 收起 |
| 卡片右侧被图标占掉一整列 | 按钮在右上角时正文要 `pr-14` | 图标移到右下角与时间同一行，正文占满 |
| 底部一行在窄卡上挤爆 | 时间 + 置顶文案 + 删除都有最小宽度 | 166px 起才放得下；1280–1399 退一列 |
| `textarea` 不会自动长高 | 原生 textarea 固定行高 | 每次输入把 `style.height` 设为 `scrollHeight`，并设最小高度 |
| 打开弹窗时手机键盘顶走内容 | 移动端键盘弹出会改变视口 | 弹窗内滚动，不要用 `h-screen` 硬撑页面 |
| 长英文 / URL 撑破卡片 | 没有 `break-words` 时字符串不换行 | 正文加 `break-words`，卡片 `overflow-hidden` |
| 全角空格 / 换行绕过空校验 | 只判 `=== ""` 挡不住 | 服务端 `trim()` 后再判空 |
| 首页卡与工具页各写一套排序 | 两份 SQL 迟早不一致 | 共用查询函数，首页传 `limit` |
| 确认态刷新后残留 | 确认态是纯前端状态 | 刷新即回阅读态 |
| Server Action 被直接调用 | 它是公开 HTTP 端点，`maxLength` 不是防线 | 服务端再校验长度、非空、归属用户 |
| 勾选 / 置顶时整卡闪一下 | `pending` 触发 `disabled:opacity-50`，几十毫秒内来回切 | 卡片内按钮去掉这层变暗，`disabled` 逻辑保留 |
| 首页漏掉登录检查 | 检查在页面里而不在 layout | 保留首页自己的 `requireUser()` |
| 演示数据残留 | 手动测过的便签会被当成真数据 | 验收结束前清掉测试行 |
