# 音乐播放器

> 把自己的音乐文件传上来，攒成一份只属于自己的曲库，在站点里点开就能听。
> 「媒体」分类的第三个工具，也是全站第一个**需要持久文件存储**的工具。
> 首页还有一块「正在播放」卡、右下角有一颗常驻悬浮球——两者都是**同一个播放器的遥控器**，不是第二个播放器。

| 数据表 | `music_tracks`（`docs/数据库/音乐曲目表.md`）、`playlists` / `playlist_tracks`（`docs/数据库/音乐歌单表.md`）、`music_playback`（`docs/数据库/音乐播放状态表.md`） |

## 一、要什么

**做**

- 工具页 `/tools/music-player`，分类「媒体」，工具目录与页签栏各登记一处。
- **上传（多选）**：拖入或点选一批音频文件，串行逐个上传，每条显示进度与结果。
- **曲库列表**：歌名 / 歌手 / 时长 / 体积 / 上传时间，点一行就开始播。
- **曲目编辑**：每首歌都能改歌名、歌手，并勾选它属于哪些歌单。
- **歌单**：建 / 改名 / 删；把歌加进歌单或从歌单移除；点歌单只看该歌单的歌，播放队列也跟着切。
- **批量操作**：列表头「批量」进入选择模式，每行变复选框，可选多首一次删掉或一次加进某个歌单；带全选 / 取消全选。
- **拖拽排序**：曲库与歌单各一套顺序，互不影响。
- **删除**：曲库里的歌能删（连磁盘文件一起删，**一律二次确认**）。
- **播放**：上一首 / 下一首 / 播放暂停 / 拖动进度 / 音量 / 顺序与随机。
- **切页面歌不停**：全站只有一个真正的播放器，挂在应用外壳上。
- **首页「正在播放」卡**：黑胶 + 歌名 + 进度 + 三按钮，接真实播放状态，右上还显示「正在放哪一摊」。
- **右下角悬浮球**：黑圆 + 白色 Logo，**去哪个页面都跟着**；点一下向上弹出小播放面板。
- **接着上次播**：刷新 / 换设备都接上「哪首 + 哪个歌单 + 第几毫秒 + 上次是不是在播」。
- **手机锁屏控制**：Media Session，锁屏 / 耳机线控能看到歌名并能切歌。
- 空曲库时说人话并给出口；三档响应式各自一套版式（§2.3）。

**主动放弃（本版不做，不是遗漏）**

> 下面带 ~~删除线~~ 的四条写「不碰」，后来都被真实使用推翻并实现了——保留它们是给后来者看「当初为什么判断错」。

| 放弃项 | 原因 |
|---|---|
| ~~歌单 / 收藏夹~~ → **已实现** | 当初的判断是「曲库够小的时候整库顺序播就是歌单」；曲目攒到几十上百首之后这条不成立了 |
| ~~歌单内拖拽排序~~ → **已实现** | 当初的判断是「加入时间已经能表达顺序」；真用起来才发现脑子里的顺序跟加进来的顺序完全对不上 |
| ~~重命名 / 编辑元数据~~ → **已实现** | 当初的判断是「上传前在本地把文件名改好更符合直觉」；实际是上传完才发现标签写错了，重传要再传几百 MB |
| ~~播放进度记忆~~ → **已实现** | 当初的判断是「重开从头放就行」；实际刷一下页面就回到 0，跟原生音乐 App 差太远 |
| 歌单封面 / 描述 | 第一版没有图片与富文本需求；封面还要多一套上传与裁剪 |
| 曲库搜索 | 几十首用滚轮比搜索快；搜索框一旦存在，焦点、空结果、高亮都得跟着做 |
| 在线搜歌 / 抓第三方平台 | 版权与反爬双重问题：接口要么要登录态、要么随时改签名，做出来也是一周就坏的工具 |
| 转码 / 统一格式 | 有损转码音质掉一代还占双倍 CPU；原样存，收的范围就是浏览器原生能放的格式（§四） |
| 封面 / 歌词 | 要从文件里提内嵌图并另存、歌词要时间轴对齐——都是「有更好、没有也能听」的事 |
| 单曲循环 | 顺序与随机之外再加一档，模式按钮就要点三下才循环 |
| 统计 / 听歌排行 | 没有消费场景的统计只是数字 |

## 二、界面

### 2.1 工具页

没有 PageHeader，工具名与状态在 `ToolHeader` 里；手机上顶部是 `ToolMobileBar`（汉堡 + 「添加音乐」）。

```
内容区（px-4 py-4 md:px-6 md:py-6）
├─ 工具信息条（ToolHeader）
└─ 工作区
   ├─ 顶部播放条（通栏）：歌名 · 进度条（可拖）· 时间 · 上一首/播放暂停/下一首 · 模式 · 音量
   └─ 三栏（≥ xl）
      ├─ 左：歌单栏（「全部歌曲」+ 各歌单 + 「+ 新建歌单」）
      ├─ 中：曲目列表（表头「<当前范围>」+「N 首 · 已用 X / 5 GB」+「添加歌曲」+「批量」）
      └─ 右：上传区 + 配额
```

- 点一行 = 立刻播这一首。**点正在播的那一行 = 暂停 / 继续**（不是「什么也不发生」）。
- 在「全部歌曲」里点 → 队列是全库；在某个歌单里点 → 队列就是那个歌单（顺序 / 随机都只在队列内走）。
- 正在播的那一行左侧是跳动的等化器图标，不是序号。
- 行尾两个图标（hover 才显形）：**编辑**（弹框改歌名 / 歌手 / 所属歌单）、**删除**（二次确认）。
- **批量模式**：每行左侧换成复选框，**点整行 = 勾选 / 取消，不再触发播放**；表头「已选 N 首」+「全选 / 取消全选」+「加入歌单」+ 红字「删除（N）」+「取消」。删除弹 `ConfirmDialog`；切页面 / 刷新后批量模式自动结束（临时态，不落库、不进 URL）。

### 2.1.1 编辑弹框

歌名 + 歌手两个输入框 +「所属歌单」一组复选框；保存一次把三样一起提交（`PATCH /tracks`）。

- **歌名不能为空**（空了退回原值并提示）；歌手可以留空。
- 一首歌都没有建过歌单时写「还没有歌单」，不给一个空框。

### 2.1.2 歌单栏

- 「全部歌曲」永远在第一条，选中态黑底白字。
- 每条歌单右侧显示曲目数；hover 出现「改名」「删除」。删除要确认，**文案写明「歌不会被删除」**。
- 新建：点「+ 新建歌单」就地出现输入框（回车确认 / Esc 取消），不弹框——只差一个名字。
- **建完自动选中新歌单**：用户建歌单的下一步永远是「往里放歌」，停在全库视图会让他以为「建了但没生效」。
- **选中态活在全站，不是活在这个页面里**：左栏高亮的是「当前播放队列的来源」（`queueSource`）。正在放「DJ」的歌时，去总览再回来、从首页卡点进来、从页签栏切回来，「DJ」都是选中的。**歌单被删掉时自动回退「全部歌曲」**。
- 重名被拒并提示「已经有同名歌单了」。

### 2.1.3 空态

| 场景 | 文案 |
|---|---|
| 曲库一首歌都没有 | 「曲库还是空的」+「把 mp3 之类的音频传上来」 |
| 某个歌单是空的 | 「这个歌单里还没有歌」+「点上面的『添加歌曲』，从曲库里挑几首放进来」 |
| 一个歌单都没建 | 歌单栏只有「全部歌曲」+「+ 新建歌单」 |

### 2.1.4 空间与配额

每人 **5 GB**（`USER_QUOTA_BYTES`），单文件 **200 MB**（`MAX_TRACK_BYTES`）。**三处都能看见**：

| 位置 | 显示什么 | 为什么放这 |
|---|---|---|
| 曲目列表表头右侧 | `2 首 · 已用 231 KB / 5.0 GB` | **主入口**。手机 / 平板 / 桌面都在同一位置——上传区在 `md` 以下整块不渲染，配额不能跟着它消失 |
| 上传区底部 | `曲库已用 X / 5 GB` + 进度条 + `还能传 Y` | 桌面右栏；传之前最直观的参照 |
| 上传被拒时 | 413 +「曲库已满（5 GB），删掉一些再传」 | 服务端兜底 |

- 用到 **80%** 就开始提醒：数字与进度条变红 `#B42318`、文案换「空间快用完了」。等到 100% 才说，那时用户已经传不进去了。
- 表头的**分子是全库已用**，不是当前视图的合计——在歌单里看到「3 首 · 已用 4.8 GB / 5 GB」才对。

### 2.1.5 拖拽排序

**两个地方都能拖**：曲库列表（「全部歌曲」视图）拖出来的是**全库顺序**，歌单视图拖出来的是**歌单内顺序**，两者互不影响。

- **拖哪儿松手就插哪儿**：被拖的行取出来、插到目标行的位置，其余行顺次移动。
- 拖动中那行 `opacity-40`，目标行顶部一条 2px 黑线。
- 行尾 `GripVertical` 手柄（**只在 `md` 以上显示**）——触摸设备上 HTML5 拖拽根本不触发，手机上不显示这个入口，免得用户按半天没反应。
- 批量模式下**不能拖**（那时「拖动」会被理解成「再勾选一行」）。
- 松手后立刻把**完整的新顺序**交给服务端（`PATCH .../order`），服务端全量重写 `position` 并回一份最新列表——前端不相信自己刚算的那份。

**为什么是全量覆盖而不是「把第 3 首挪到第 7 位」**：拖一次会影响中间所有行的位置，前端手里本来就有完整列表；让服务端去推算「移动了谁」等于两份状态各算一遍，「拖了没动」根本查不出是谁算错。

### 2.1.6 接着上次播

恢复的是：哪首歌、当时在哪个歌单（决定「下一首」往哪儿走）、播到第几毫秒、**上次离开时是不是正在播**。

- 上次是**暂停** → 只把歌和进度摆好，**一次 `play()` 都不调**；
- 上次**在播** → 尝试接着播。浏览器允许就继续（Chrome 在站点有足够媒体参与度时会放行），不允许就静默停在暂停态——这是浏览器的自动播放策略，网页绕不过去（§七 21）。

**存在服务端**（`music_playback`，一人一行），不用 localStorage：按用户隔离天然正确、换设备能接上。

**上报时机只有四个**（`timeupdate` 每秒四次，全写能把库写爆）：播放中每 15 秒 / 暂停那一刻 / `pagehide`（用 `fetch(keepalive)`）/ `visibilitychange → hidden`（手机切后台多数不触发 `pagehide`）。每次上报都带 `playing`（取 `audio.paused` 的真实状态，不看 React state）。

**恢复期间禁止上报**：从拿到进度到 `loadedmetadata` 那几十毫秒里 `audio.currentTime` 还是 0，这时写一次就把服务端的 45 秒覆盖成 0。用 `restoringRef` 拦住、seek 完才放开；另加 **3 秒时间兜底**——音频一直加载不出来时 `loadedmetadata` 永远不来，不能让上报被永久拦死。

### 2.2 首页「正在播放」卡

总览第七块，位置在**便签之后、每日一句之前**（陪伴类内容，但可操作，所以排在每日一句前面）。

- 标题行右侧显示**「正在放哪一摊」**：浅灰底小标签（`ListMusic` + 名字，最长 7.5rem 截断）。**「全部歌曲」也算一个歌单**——全库播放时写「全部歌曲」，不给空框也不隐藏；没有「正在播放」时才不渲染。名字每次从 `playlists` 现查，所以歌单改名后立刻是新名字。
- 卡片宽度与其他卡一致（430px 上限）。黑胶 `h-24 w-24` 黑底圆 + 白色 Logo，`isPlaying` 时 `animate-[spin_8s_linear_infinite]`。
- 歌名 / 歌手 / 时间都是真实数据；进度条可拖；右上模式按钮点一下切换（与工具页顶部同一状态）。
- **空曲库**：黑胶静止、歌名位写「曲库还没有歌」、副标题「去音乐播放器添加」、三按钮置灰；整卡点进工具页。

### 2.3 版式与断点

| 档位 | 版式 | 关键差别（不是缩放） |
|---|---|---|
| 移动 < md（375 起） | 单列：播放条 → 歌单**横滑条** → 上传按钮（顶部栏） → 曲目列表 | 歌单栏收成横向滚动 chip（「全部歌曲」+ 各歌单 + 「+」）；列表每行只留「歌名 + 时长」，体积与上传时间隐藏；行尾图标常显。**配额看列表表头**——上传区不渲染了，不能指望用户滑到别处找 |
| 平板 md ~ lg（768–1023） | 两栏：歌单栏 `w-[180px]` + 曲目列表 | 上传区在列表**上方**通栏（先把歌放进来，才谈得上分类） |
| 窄屏 PC lg ~ xl（1024–1279） | 三栏：歌单 180 + 曲目 `flex-1` + 上传 `w-[300px]` | 上传区固定右栏；曲目列表自己滚，页面不滚 |
| 宽屏 ≥ xl（1280） | 三栏：歌单 200 + 曲目 `flex-1` + 上传 `w-[340px]` | 内容区铺满、不设 max-width |

### 2.4 右下角悬浮球

跟首页卡、工具页播放条是**同一个播放器的第三个遥控器**，也是最方便的那个。

**视觉是照抄 Next 开发指示器那颗球的**（2026-11-03 从它的 DOM 里量出来的，不是凭眼睛估）：36×36（`h-9 w-9`）；底色 `rgba(0,0,0,0.8)` + 48px 背景模糊；全圆、`overflow: hidden`；三层阴影（外描边 + 内高光 + 下方柔影）；描边式 `N` 图标**整段 SVG 从 Next 的 DOM 原样抄下来、以 HTML 字符串注入**（`orb-mark.tsx` 的 `MARK_SVG` + `dangerouslySetInnerHTML`）——**不要翻译成 JSX 再手写属性**，每翻译一次就漏一样东西。

- `fixed` 在右下角（`bottom-5 right-5`）；手机加 `bottom: max(20px, env(safe-area-inset-bottom))`，避开 iOS 底部横条。
- **悬停**：底色从黑 80% 换成**叠在黑底上的白色 13%**（在浅灰页面上呈现为中灰）。直接把 `background` 换成白色 13% 会让整颗球「消失」在背景里（实测踩过），所以实现上是一层绝对定位的白膜盖在黑底上、只让它的 alpha 变化。
- **按下** `scale: 0.95`（150ms）。**播放时线条做极轻的呼吸**（opacity 0.7 ↔ 1，2.8 秒一轮），暂停时静止。**不用旋转**——转一个字母认不出是什么字。
- **点球展开面板**（向上弹，宽 300px，右边缘与球对齐，`bottom-12`）；再点球、点面板外、按 `Esc` 都收起。面板里：歌名 / 歌手 / 所属歌单标签 / 可拖进度条 / 上一首 · 播放暂停 · 下一首 / 模式 /「打开曲库 →」。
- **空曲库**时球照样在，点开只写「曲库还没有歌」+「去音乐播放器添加 →」——不给一个点了没反应的球。
- 层级 `z-40`：低于手机抽屉（`z-50`），抽屉拉开时球被盖住。

**Next 的开发指示器关掉了**（`next.config.ts` 的 `devIndicators: false`）：它是另一颗「深灰圆 + 白色 N」，跟这颗几乎一模一样；试过用 `devIndicators.position` 挪开，**在 Next 16.3.1 上不生效**，而它始终在左下角、正好压住侧边栏的用户菜单。生产环境本来就不渲染它，关掉没有视觉损失。

## 三、数据模型

```sql
CREATE TABLE IF NOT EXISTS music_tracks (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id     INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  title       TEXT    NOT NULL,          -- 展示名；优先文件自带标签，没有就用文件名去扩展名
  artist      TEXT,                      -- 文件自带的歌手标签；没有就是 NULL
  file_name   TEXT    NOT NULL,          -- 磁盘上的名字：<uuid>.<ext>，不含任何路径
  codec       TEXT    NOT NULL,          -- ffmpeg 探到的真实音频编码
  size_bytes  INTEGER NOT NULL,
  duration_ms INTEGER,                   -- 探不出就 NULL（界面显示 --:--）
  position    INTEGER NOT NULL,          -- 曲库顺序（可拖拽），迁移时按 created_at 回填
  created_at  INTEGER NOT NULL
);

CREATE TABLE IF NOT EXISTS playlists (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id    INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  name       TEXT    NOT NULL,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  UNIQUE (user_id, name)
);

CREATE TABLE IF NOT EXISTS playlist_tracks (
  playlist_id INTEGER NOT NULL REFERENCES playlists(id) ON DELETE CASCADE,
  track_id    INTEGER NOT NULL REFERENCES music_tracks(id) ON DELETE CASCADE,
  position    INTEGER NOT NULL,          -- 歌单内顺序；跟曲库的 position 互不影响
  added_at    INTEGER NOT NULL,
  PRIMARY KEY (playlist_id, track_id)    -- 同一首不会被加进同一个歌单两次
) WITHOUT ROWID;

CREATE TABLE IF NOT EXISTS music_playback (
  user_id     INTEGER PRIMARY KEY REFERENCES users(id) ON DELETE CASCADE,
  track_id    INTEGER REFERENCES music_tracks(id) ON DELETE SET NULL,
  playlist_id INTEGER REFERENCES playlists(id) ON DELETE SET NULL,
  position_ms INTEGER NOT NULL DEFAULT 0,
  is_playing  INTEGER NOT NULL DEFAULT 0,
  updated_at  INTEGER NOT NULL
);
```

**设计要点**

- **`file_name` 存 `<uuid>.<ext>`，不是原文件名。** 原文件名可能是 `../etc/passwd`、可能带 `?` `%` `\`，直接拼路径就是路径穿越；两个同名文件还会互相覆盖。用户看到的歌名在 `title` 列，两者分开——磁盘名只负责唯一，展示名只负责好看。
- **`codec` 是 ffmpeg 探出来的，不是扩展名推的。** `.mp3` 改名成 `.m4a` 上传，扩展名会撒谎，编码不会；浏览器的播放能力跟的是编码。
- **不存 `mime`**：它完全由 `codec` 决定，存一列等于让同一件事有两个真相。
- **`duration_ms` 可空**：探不出时长不该拦住上传——能播就行，列表显示 `--:--`。
- **`position` 显式存**：用户能拖之后，顺序不能再靠 `created_at` 推导。曲库与歌单各一套。
- 磁盘路径不进库：库里只有文件名，目录由代码推导（§四 4）。换机器、换目录时库不用改。

## 四、关键决策

| 决策点 | 选择 | 理由 | 否决的备选 |
|---|---|---|---|
| 歌存哪 | **存服务器磁盘**，按用户分目录 `<music>/<userId>/<uuid>.<ext>` | 需求是「换设备也能听」；存本地（IndexedDB / File API）换台机器就空了 | 浏览器本地播：零后端成本，但「曲库」这个词就不成立了 |
| 存进去要不要转码 | **原样存**，只收浏览器原生能放的格式 | 转码有损、费 CPU、占双倍空间；而用户传的本来就是他愿意听的版本 | 统一转 mp3（把无损文件降级）；统一转 opus（Safari 上不稳） |
| 播放器放在哪 | **一个，挂在 `AppShell`**；首页卡与工具页都是遥控器 | 需求写明「切页面歌不停」。`<audio>` 挂在页面级组件里，路由一变就卸载，歌必停 | 每个页面各挂一个（切页面必断，状态无法同步） |
| 文件夹在哪 | **从 `DATABASE_PATH` 的目录推导**：`<db 所在目录>/music/` | 两者都是「必须活过部署」的持久数据，天然同源：本地 `data/music`，线上 `shared/data/music`。**不新增环境变量**——少一个上线失败点 | 新增 `MUSIC_PATH`：更灵活，但线上要在 `shared/.env.production` 补一行，漏了就是「传了文件不知道去哪」 |
| 时长怎么来 | 上传时**服务端 ffmpeg 探一次**，存进库 | 列表在点播之前就要显示时长；项目里本来就有 ffmpeg 二进制，探一次几十毫秒 | 前端懒探（几十首就是几十个请求） |
| 音频怎么鉴权 | **同源 `<audio src>` + 会话 cookie**，接口里 `getCurrentUser()` | `<audio>` 发的是普通同源 GET，cookie 自动带上，与页面同一套登录态 | 签名 URL / token query（多一套密钥与过期逻辑，收益只是「链接分享出去别人能听」——恰恰不想让人分享） |
| 上传进度 | 前端用 **`XMLHttpRequest`** 的 `upload.onprogress` | `fetch` 至今没有上传进度事件；200 MB 文件没有进度条，用户会以为卡死并重传 | `fetch` + 假进度（骗人，重传时更糟） |
| 首页卡进不进「常用工具」 | **不进** | 常用工具的规矩是「只放总览没有自己卡的真工具」 | 列进去（同一个入口说两遍） |
| 悬浮球放在哪一层 | **挂在 `AppShell`**，跟 `PlayerProvider` 同一层，`fixed` 定位 | 需求是「不管去哪个页面一直悬浮」；放进 `PlayerProvider` 里会让「播放器」和「遥控器」耦合 | 放进页面里（会被路由切走）；放进 layout 的单独一层（要多传一次 props） |
| 批量操作怎么进 | **表头一个「批量」按钮切进选择模式**，不是每行常显复选框 | 曲库日常动作是「点一行就播」；常显复选框会让每行多一块可点区域，误点一次就是「想播却选中了」 | 常显复选框（每行误触率翻倍） |
| 删除要不要确认 | **全部都要**（2026-11-03 改），文案必须写清「音频文件也会一起删掉」与「它还在 N 个歌单里」 | 原来的「单删不确认」在歌单出现之后不成立了：删一首歌会同时把它从好几个歌单抽走，重传回来是一首「不在任何歌单里的新歌」，歌单里那个位置永远补不回来 | 只在批量时确认（省一次点击，代价是「一按就没了」） |
| 一首歌能不能属于多个歌单 | **能**，多对多（`playlist_tracks`） | 「通勤」和「收藏」同时收同一首歌是常态；单归属一旦定死，想同时归两类只能复制一份，而复制会产生两份元数据 | 单归属（`music_tracks` 加一列 `playlist_id`） |
| 播放队列跟谁走 | **跟当前视图走**；切左栏也算换队列，但**正在播的那首不打断**；左栏选中态**由队列来源派生** | 在歌单里点歌，期待的就是「在这个歌单里往下放」；选中态若是局部 state，一离开页面就丢 | 队列永远是全库（歌单变成纯过滤器）；切歌单顺手换歌（会打断正在听的）；选中态存本地（跨页面必丢） |
| 顺序怎么存 | **显式 `position` 列**，曲库与歌单各一套 | 用户能拖之后，顺序不能再靠 `created_at` 推导；两份 position 分开，是为了「在歌单里排顺序」不把「全部歌曲」也搅乱 | 一份 position 全库共享（歌单一拖全库跟着变）；间隙法（多一套「什么时候重排」的判断） |
| 播放进度存哪 | **服务端**（`music_playback`，一人一行） | 按用户隔离天然正确（localStorage 是「这台浏览器」的，换账号就串）、换设备能接上、数据量极小 | localStorage（要自己解决「浏览器的哪个用户」，换设备就丢） |
| 记不记「是否正在播」 | **记**（`is_playing`，2026-11-04 补） | 原来的判断是「浏览器不许无手势自动播，记了也用不上」，结果恢复路径借道了「切歌就播」的 effect：**暂停着刷新会自己响** | 不记、恢复一律不播（满足不了「播放中刷新接着播」） |
| 改歌名会不会动磁盘文件 | **不会**，只改 `title` | 磁盘名是 `<uuid>.<ext>`，只负责唯一、不承载语义；真去改名就多出「改名成功、改文件失败」的失败面 | 连带重命名文件（多一次失败面，收益为零） |

- 首页卡的位置改在 `app/(app)/page.tsx`（便签后、每日一句前）；工具目录与页签白名单各登记一处。

## 六、验收标准

**曲库与播放**

1. `/tools` 的「媒体」下出现「音乐播放器」，点进去到工具页；页签栏出现同名标签。
2. 拖入 3 个 mp3 → 逐条显示进度，完成后列表 3 首；歌名 = 文件自带标题（没有则文件名去扩展名），时长与体积与真实值相符。
3. 点第 2 行 → 立刻播它，播放条显示它的歌名、进度在走；点第 3 行再点「上一首」→ 回到第 2 首。
4. 拖进度条到中段 → 从该位置继续播、**不跳回起点**（Range 生效的证据）。
5. 播放中从工具页点进保险库再回总览 → **歌没中断**，首页卡显示同一首且黑胶在转。
6. 音量拖到 30% → 变小；刷新 → 回到 100%（本版不记忆音量）。
7. 切「随机」连点两次下一首 → 播的不是列表下一行；切回「顺序」→ 下一首就是列表下一行。
8. 删除一首**正在播**的歌 → 自动跳下一首继续播，列表消失、磁盘文件也没了（`ls` 确认）。
9. 曲库清空回总览 → 首页卡「曲库还没有歌」、黑胶不转、三按钮置灰、点卡进工具页。
10. 5 分钟的歌自动播完 → 顺序模式接下一首；最后一首播完就停（不循环）。

**批量 / 编辑 / 歌单**

11. 点表头「批量」→ 每行出现复选框、表头换「已选 0 首」；**点一行不会播放**、只勾选；「全选」/「取消全选」计数正确。
12. 勾 2 首点删除 → 确认框带「2 首」→ 确认后两首同时消失、磁盘文件也没了、批量模式退出；删到正在播的那首 → 接下一个还在的歌。
13. 点行尾「编辑」→ 弹框回填三项；改歌名保存 → 列表与播放条**立刻**显示新名字（不用刷新）；改**正在播**那首 → 播放条与悬浮球面板同时变、播放不中断、进度不回零。
14. 歌名清空保存 → 被拒并提示「歌名不能为空」，原值不丢。
15. 「+ 新建歌单」→ 就地输入「通勤」回车 → 左栏多一条并**自动跳进这个空歌单**；再建同名 → 被拒并提示。
16. 歌单改名 → 左栏立刻变、歌一首不少；删歌单 → 确认框写明「歌不会被删除」→ 确认后左栏消失、**曲库一首没少**。
17. 编辑一首歌勾「通勤」，再勾「收藏」→ 两个歌单都有它（多对多）；左栏计数各自 +1。
18. 点左栏「通勤」→ 列表只剩它的歌、表头写「通勤 · N 首」；在歌单里点第 2 首再点下一首 → **只在歌单内走**；点「全部歌曲」→ 队列切回全库、当前这首继续播不中断。
19. **反向也要对**：先在「全部歌曲」播第 1 首 → 点某歌单 → 歌不断、进度不回零、列表换成该歌单 → 下一首跳**歌单里的第 1 首**；再切回全库 → 按全库顺序走。
20. 批量勾 3 首 →「加入歌单」选「收藏」→ 3 首进收藏、计数 +3，已在里面的不会重复加。
21. 进歌单 → 表头「添加歌曲」→ 列出**不在这个歌单里**的曲目 → 勾 2 首确认 → 歌单多 2 首，顺序是勾选顺序；都已在歌单里时写「曲库里的歌都已经在这个歌单里了」。
22. 删一首在歌单里的歌 → 歌单计数 -1、歌单里不再有它（关联被级联清掉）。

**首页卡 / 悬浮球 / 范围标签**

23. 右下角一颗黑圆 + 白色 Logo 的球；从总览点进工具页再点保险库，**球一直都在**。
24. 点球 → 向上弹出 300px 面板（歌名与进度）；点面板外 / `Esc` / 再点球 → 收起；播放中能暂停、能切歌、进度条能拖且拖动时不跳回。
25. 空曲库时球仍在，点开写「曲库还没有歌」+「去音乐播放器添加 →」。
26. 手机上球贴在安全区上方；拉开侧边抽屉时球被遮罩盖住。
27. 在「DJ」里播着歌 → 首页卡右上出现「♪ DJ」、悬浮球面板歌名下也有 → 切「全部歌曲」→ **两处都变「♪ 全部歌曲」**（全库也算一个歌单）。
28. 歌单改名（DJ → 夜跑）→ 两处标签**立刻变成「夜跑」**（名字现查）。一首都没播时不显示这枚标签。
29. **选中态跨页面**：在「DJ」播着歌 → 去总览 → 切回工具页，左栏「DJ」仍选中、列表仍是 DJ、歌没断。
30. 删掉**正在放**的歌单 → 左栏自动回「全部歌曲」、列表变全库、歌继续播、首页标签变「全部歌曲」。

**配额 / 排序 / 进度记忆**

31. **点正在播的那一行 = 暂停**（进度停原处），再点从原处继续。
32. 配额：列表表头右侧写「N 首 · 已用 231 KB / 5.0 GB」，**手机上也在同一位置**；桌面上传区底部另有进度条与「还能传 X」；塞到 80% 以上 → 数字与进度条变红 + 「空间快用完了」。
33. **拖拽改顺序（全库）**：把第 1 首拖到第 3 行松手 → 列表变 [2,3,1]；**刷新后顺序还在**。
34. **拖拽改顺序（歌单）**：歌单里排一下 → 切到「全部歌曲」，那边顺序没变。
35. 手机上**不显示**拖拽手柄，按住行拖动是滚动页面；批量模式下行拖不动。
36. **暂停刷新保持暂停**：播到 4 秒 → 暂停 → 刷新 → 还是那首、进度约 4 秒、状态暂停、**页面不发声**；点播放从 4 秒继续。
37. **接着上次播（歌单）**：某歌单里播到 5 秒 → 暂停 → 刷新 → 左栏那个歌单仍选中、列表是它的歌、进度也在 5 秒。
38. **播放中刷新接着播**：播到 4 秒直接刷新 → 进度约 4 秒且**自动继续播**（浏览器放行时；被拒就停在暂停态，不弹错误）。
39. 换设备 / 换浏览器登录同一账号 → 也能接上（进度存服务端）。
40. 删掉上次播的那首歌 → 刷新不报错、回到「还没有选中歌曲」；删掉它所在的歌单（歌还在）→ 恢复成「全部歌曲」里的那首、进度还在；从没播过的新账号 → 刷新是空态、不报错。

**负面 / 门禁**

41. `POST /api/tools/music-player/tracks` 不带 cookie → 401，磁盘不新增文件；未登录访问工具页 → 跳 `/login`。
42. 上传 `.txt` 改名成 `.mp3` → 拒绝（探不出音频流），列表与磁盘都不留痕；超过 200 MB → 413。
43. 用 B 的 cookie 删 A 的曲目 / 歌单 / 拉 A 的流 → 404，A 的数据不变；把不属于自己的歌加进自己歌单 → 404。
44. `DELETE ?ids=` 空 / `ids=abc` → 400；混进别人的 id → 只删自己的、别人的留着。
45. 批量模式下切页面再回来 → 回到普通模式；勾选后不确认就关确认框 → 一首没删、勾选保留。
46. `next typegen` / `typecheck` / `lint` / `test` / `build` 全过。

## 七、已知的坑

1. **`<audio>` 只能有一个，且必须在 `AppShell` 里。** 放在首页卡里，用户从首页切到任何页面它就被卸载、歌立刻停——而「切页面歌不停」正是这个功能的核心。首页卡、工具页播放条都只读 Context，不许自己写 `<audio>`。
2. **Safari 不支持 Range 就完全不播。** Safari 对音频发 `Range: bytes=0-`，服务端回 200 全量时它会自己放弃播放（Chrome 能容忍）。所以流接口必须实现 206 + `Content-Range` + `Accept-Ranges: bytes`——这条在 Chrome 上测不出来。
3. **拖动进度条会被 `timeupdate` 拽回去。** `timeupdate` 每秒四次，拖动期间仍在写 `position`。必须有 `isSeeking` 标志：按下置真、松手请求 `seek` 后置假，期间不回写滑块。
4. **`fetch` 没有上传进度。** 前端必须用 `XMLHttpRequest` 才能拿到 `upload.onprogress`；用 `fetch` 的话 200 MB 文件全程只有「处理中」三个字。
5. **文件必须落在 `shared/` 那一层。** 线上是 `releases/<时间戳>` + `current` 软链，部署只切软链、不搬数据。写进发布目录的文件下一次上线就被换掉——而这个功能的全部价值就是「歌一直在」。
6. **两个标签页同时开着会同时播。** 两套 `<audio>` 各放各的。本版不处理（要做就得用 `BroadcastChannel` 或 localStorage 抢锁），写在这里是为了不再被当成 bug 报一次。
7. **`Content-Length` 可以是假的。** 体积检查必须两道：先看声明值，再在流式写盘时边写边数（音频提取已踩过，照它的做法）。
8. **iOS 的自动播放限制。** `play()` 必须由用户手势触发；「一首播完自动接下一首」在部分 iOS 版本会被拒——被拒时不要报错弹窗，静默停在「暂停」态即可。
9. **删歌要删两处，且顺序不能反。** 先删数据库行、再删磁盘文件：反过来一旦中间失败，库里会留下一条指向不存在文件的记录，点播放就是 404。文件删失败只留垃圾文件，不影响使用。
10. **`ON DELETE CASCADE` 不删文件。** 删账号（目前没这功能）时数据库行会级联删掉，磁盘文件不会——真要支持删账号得先删目录。
11. **悬浮球跟 Next 开发指示器长得一模一样。** `devIndicators.position` 在 Next 16.3.1 上**不生效**（试过 top-right，它始终在左下角、压住侧边栏用户菜单），所以直接 `devIndicators: false`。生产环境本来就不渲染，没有视觉损失。
12. **点面板外关闭不能用「整页遮罩」。** 透明遮罩会把球本身也盖住（第二次点球变成点遮罩），还会吞掉页面上其它交互的 hover。正确做法是监听 `document` 的 `pointerdown`，判断点击目标是否在球或面板内部。
13. **三层 `box-shadow` 别用 Tailwind 的 `shadow-[...]` 任意值写。** 阴影值里夹着 `rgba(255,255,255,0.14)` 这种带逗号的函数，Tailwind 会按逗号拆成多个 shadow 段、每段都解析失败，**生成的是一串空 shadow**——球看上去是一张没有描边的扁圆，而且不报任何错（`getComputedStyle` 才看得出是 `rgba(0,0,0,0) 0 0 0 0` ×4）。写在 `style={{ boxShadow }}` 里。
14. **批量模式下「点整行」的含义必须换掉。** 平时点一行是播放、选择模式里是勾选；不写清楚用户会连着放歌又取消勾选。所以行内不再渲染播放按钮（换成 `role="checkbox"` 的按钮 + `aria-checked`），表头必须有明显的「取消」出口。
15. **改歌名只改 `title`，不动磁盘文件。** 磁盘上是 `<uuid>.<ext>`，本来就不承载语义。真去重命名文件，就多出「改名成功、改文件失败」的失败面。
16. **删歌单不删歌。** 歌单表只是关联，`ON DELETE CASCADE` 删的是 `playlist_tracks` 里的行。任何时候都别在 `DELETE FROM playlists` 附近顺手写 `DELETE FROM music_tracks`。
17. **`UNIQUE (user_id, name)` 的报错要翻译成人话。** SQLite 抛的是 `UNIQUE constraint failed: playlists.user_id, playlists.name`，直接冒到界面上没人看得懂。数据层捕获后抛 `PlaylistNameTakenError`，接口回 409 +「已经有同名歌单了」。
18. **切歌单不能打断正在播的歌，但必须同步队列，而且选中态要跟着活。** 只换列表不换队列是错的（切到「DJ」再点下一首会走到全库下一首）；顺手 `pause()` 或重设 `src` 也是错的（会断）。正确做法是 `switchQueue`（只改队列来源、不换歌）与 `playPlaylist`（换队列 + 换歌）分成两个方法。**另外：左栏选中态必须直接由 `queueSource` 派生，不能存成页面的 `useState`**——局部 state 会随页面卸载。
19. **HTML5 拖拽在触摸屏上根本不触发。** 所以手柄 `hidden md:flex`；要真上移动端排序，得换 pointer 事件手写。
20. **Firefox 不在 `dragstart` 里 `setData` 就不会开始拖。** Chrome 里不设也能拖（只在 Chrome 测会漏）。`effectAllowed = "move"` 和 `setData("text/plain", id)` 两行都要写。
21. **浏览器不许网页无手势自动播。** 恢复「上次在播」时 `play()` 会被拒（`NotAllowedError`）。两层兜底：① **静音自动播是允许的**——被拒时先 `muted = true` 播起来，成功后再恢复原静音状态；② **不许把「上次在播」写回 0**——那不是用户暂停，写回去下次刷新就再也不尝试了（`resumePendingRef`，播成功后由 `onPlay` 清掉）。反过来，恢复「上次是暂停」时一次 `play()` 都不该调。
22. **恢复期间千万别上报进度。** 从服务端拿到位置到 `loadedmetadata` 之间 `audio.currentTime` 还是 0；这期间只要跑一次「暂停就上报」，库里的 45 秒就被写成 0。`restoringRef` 是这道闸，`loadedmetadata` 里 seek 完才放开，`error` 时也要放开，再加一条 3 秒时间兜底（音频一直加载不出来时那个事件根本不来）。
23. **`GET /tracks` 一次要把歌单归属带回来。** 编辑弹框要勾「这首歌在哪些歌单里」，如果每个弹框再发一次请求，就会出「打开弹框时歌单还没回来、复选框一片空白」。列表与归属同一份响应。
24. **`Readable.toWeb` 在客户端断开后会抛 `ERR_INVALID_STATE: Controller is already closed`**（2026-11-04 线上事故）。`<audio preload="metadata">` 只关心文件头，浏览器拿完前几 KB **就断开连接**，而 `createReadStream` 还在继续读——adapter 往已关闭的 controller 写，Node 抛 uncaughtException，**那个请求会一直挂着**（线上实测刷新要等 15 秒）。修法：`request.signal` abort 时 `destroy()` 文件流、`cancel()` 里同样 destroy、吞掉关闭后的那一次写入。**别用 `Readable.toWeb` 直出**，用 `stream/route.ts` 里的 `toWebStream`。
25. **M4A 的 `moov`（时长、seek 表）默认在文件末尾——大文件不重排就没法播。** 浏览器要下完整个文件才知道多长：线上 46 MB 的歌实测 7 秒只下 532 KB、`readyState` 一直是 0。上传时统一 `-movflags +faststart` 重排（`-c copy` **不转码**，只挪 atom）。坑：输出临时名没有 `.m4a` 后缀时 ffmpeg 猜不出容器、直接报 `Invalid argument`，必须显式 `-f ipod`；重排失败要静默退回原文件，不能因为重排失败就让上传失败。
26. **音频流不能用 `Cache-Control: max-age`。** 文件会被重排 / 替换（faststart），URL（`?id=N`）却不变——`max-age=3600` 会让浏览器抱着旧的 46 MB 不放，**修好的文件永远到不了浏览器**。用 `private, no-cache` + `Last-Modified`，并处理 `If-Range`：文件没变继续用缓存，变了按规范回**整个文件**——拿旧缓存的位置去拼新文件会花屏、放不出声。
27. **`preload` 只在播放器页给 `metadata`，别的页面给 `none`。** 46 MB 的歌 `moov` 有 510 KB，在窄上行下占住带宽一秒多，**期间点侧边栏导航就得排队**（2026-11-04「点不动」的最后一环）。改 `preload` 属性浏览器**不会**重新加载，回播放器页要显式 `audio.load()`；`load()` 会把 `currentTime` 归零，所以先把位置记进 `reloadSeekRef`，`loadedmetadata` 里 seek 回来。
