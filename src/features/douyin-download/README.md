# 抖音下载

> 贴一条抖音分享链接，把这条视频**无水印**地存到本地。
> 这是「媒体」分类的第二个工具，也是全站第一个**向外部服务付费调用**的工具（TikHub，$0.001/次）。

| | |
|---|---|
| 入口 | `app/(app)/tools/douyin-download/page.tsx`（一行薄壳）→ 实现住在本目录 `server/page.tsx` |
| 接口 | `POST /api/tools/douyin-download`（解析）、`GET /api/tools/douyin-download/file?id=`（代理下载）——`app/api/` 下是薄壳，实现住在本目录 `server/api/` |
| 数据表 | `douyin_videos`（`docs/数据库/抖音缓存表.md`）、`douyin_links`（`docs/数据库/抖音链接映射表.md`） |
| 状态 | ✅ 已上线（v0.12.0，2026-11-02 起） |

**这份 README 是这个工具唯一的文档**：代码结构在 §五，需求 / 界面 / 数据 / 决策 / 验收 / 坑在一～四、六、七。
原来的 `docs/功能/抖音下载.md` 已于 2026-11-05 并入本文件，章节编号保持不变。

## 一、要什么

**做**

- 工具页 `/tools/douyin-download`，分类「媒体」，工具目录与页签栏各登记一处。
- **一条链接进、一个视频出**：贴分享链接（整段分享文案也认，链接夹在中间能抠出来）→ 点「解析」→ 显示封面、标题、作者、时长 → 通栏「下载视频」。
- **解析结果落库缓存**：同一个视频 **24 小时内**再解析直接读库，不再调外部接口（每次调用都是真金白银）。
- 失败要说人话：不是抖音链接 / 视频不存在或已删除 / **是图文作品（本版只做视频）** / 未配置 API Key / 外部接口超时或额度不足。
- 三档响应式各自一套版式（§2.2）。

**主动放弃（本版不做，不是遗漏）**

| 放弃项 | 原因 |
|---|---|
| 图集（一个链接出多张图） | 一个链接变多张图，下载要变成多选或打包，是另一种交互形态。第一版只把视频主链路跑通 |
| 批量（一次贴多条链接） | 一次一条，验收简单、失败定位也简单；批量等第二版 |
| 视频转文字 | 下载 + ffmpeg + 语音识别，是独立功能 |
| 历史记录界面 | 库里存了记录，但这一版**不展示历史列表**——它是缓存，不是收藏夹 |
| 收藏夹（用户维度的存视频） | 要下载文件并长期占用服务器磁盘，是另一个需求；本版只把文件给到浏览器 |
| 自建解析（不用外部 API） | 见 §四 |

## 二、界面

### 2.1 工具页

沿用音频提取的壳子：**没有 PageHeader**，工具名与状态在信息条里（`ToolHeader`，状态点「可用」）；手机上顶部是 `ToolMobileBar`（汉堡 + 「抖音下载」）。

```
移动端导航行（< lg）：汉堡 + 抖音下载
内容区（px-4 py-4 md:px-6 md:py-6 space-y-4）
├─ 工具信息条（ToolHeader，状态「可用」）
├─ 输入卡
│   ├─ 标题「抖音链接」
│   ├─ 多行输入框（2 行，能贴整段分享文案；占位「把抖音的分享链接贴进来」）
│   └─ 通栏按钮「解析」（有内容才可点；解析中变「解析中…」）
└─ 结果卡
    ├─ 空占位：虚线框 + 图标 +「还没有解析过链接」
    ├─ 已解析：缩略图（90×120，3:4 裁切）+ 标题（最多两行）+ 作者 + 时长 +「下载视频」
    └─ 失败：虚线框 + 一句人话 + 「换一条链接」
```

颜色与控件照《界面设计规范》：主按钮黑底直角，空态文案 `text-[#A0A8B4]`。

### 2.2 版式与断点

| 档位 | 版式 | 关键差别（不是缩放） |
|---|---|---|
| 移动 < md（375 起） | 单列：汉堡行 → 信息条 → 输入卡 → 结果卡 | 侧栏收进抽屉；输入框 16px（小于它 iOS 聚焦会放大整页）；下载按钮占满信息区 |
| 平板 md ~ lg（768–1023） | 单列，内容区铺满 | 下载按钮收成自然宽度（`w-auto px-6`）——宽屏下拉满的按钮像一条黑杠 |
| 窄屏 PC lg ~ xl（1024–1279） | 单列，内容区铺满 | 侧栏常驻、汉堡消失（与外壳同一个 `lg` 档） |
| 宽屏 ≥ xl（1280） | 单列，内容区铺满 | 卡片间距 16px → 24px |

- **这一页天然是单列**，不硬凑两栏：它没有「文件区 / 操作区」的区分，照搬两栏会空掉一栏。断点影响的是侧栏显隐、按钮宽度与间距，**不是栏数**——别为凑「四档四版式」造一个没有意义的并排。
- 结果卡缩略图**固定 90×120**，不随栏宽放大。第一版做过 280×350 大封面 + 右侧信息，实测卡片被撑到 400px 高、右侧只剩一行字、下面一大片空白。
- 档位用互斥显隐（`hidden lg:flex` / `lg:hidden`），不用 JS 读视口——首屏 SSR 不闪。断点的实际高度**实现时在真机上量**，不许手算。

### 2.3 状态与边界

| 状态 | 界面 |
|---|---|
| 初始 | 输入框空，结果卡虚线占位；「解析」置灰 |
| 有内容 | 「解析」可点 |
| 解析中 | 按钮变「解析中…」并禁用；结果区保留上一次的内容（不闪白） |
| 解析成功 | 封面 + 标题 + 作者 + 时长；「下载视频」可点 |
| 下载中 | 按钮变「下载中…」约 1 秒后恢复；**页面里不做进度条**——下载交给浏览器，进度在浏览器下载面板里 |
| 链接不认识 | 「这不是抖音链接」+「发分享链接过来，文案里带链接也行」 |
| 视频没了 | 「这条视频找不到了」+「可能已经删除或设为私密」 |
| 未配 Key | 「你还没配置 TikHub 的 Key」+「去设置里填 Key」链接（《功能/用户密钥》） |
| 额度不足 / 外部故障 | 「解析服务暂时不可用」+「稍后再试；如果一直这样，可能是额度用完了」 |
| 图文作品 | 「这是图文作品，暂时只支持视频」 |
| 下载 403（直链过期） | 自动重新解析一次再下；第二次仍失败才报「这条视频的地址失效了，再解析一次试试」 |

## 三、数据模型

```sql
CREATE TABLE douyin_videos (
  aweme_id    TEXT PRIMARY KEY,
  title       TEXT    NOT NULL,
  author      TEXT    NOT NULL,
  cover_url   TEXT    NOT NULL,
  duration_ms INTEGER NOT NULL,
  play_url    TEXT    NOT NULL,
  fetched_at  INTEGER NOT NULL
);
```

另有 `douyin_links`（短链 → `aweme_id` 的映射表）：短链 `v.douyin.com/xxx` 本身看不出是哪个作品，
不查映射，同一个短链贴第二次就又是一次计费。

**设计要点**

- **主键是 `aweme_id`，不是自增 id**：一个抖音视频就是一个 id，天然唯一；缓存的意义就是「同 id 不重复取」。
- **不建 `user_id` 列**：这张表不是用户资产，是**外部接口响应的本地副本**，全站共用一份。按用户存会让同一个视频被存两遍，而每个人看到的都是同一份公开数据。将来做收藏夹时另建一张用户维度的表。
- **`play_url` 会过期，可以接受**：抖音 CDN 直链有时效，`fetched_at` 就是判断依据。24 小时内直接用；下载时若 403 就重解析一次并把新直链写回这一行。
- **不存视频文件**：文件直接流给浏览器，服务器只在转发期间持有字节流。磁盘只有 33 GB 可用，存视频会把发布环境撑爆。
- **没有 `updated_at`**：这张表的行只有「被新解析结果覆盖」一种变化，`fetched_at` 已记录它何时被刷新，再加一列只会出现两列互相矛盾。

## 四、关键决策

| 决策点 | 选择 | 理由 | 否决的备选 |
|---|---|---|---|
| 解析谁来干 | **买 TikHub 的现成接口** | 2026-11-02 实测：抖音 Argus 网关对「不是真实浏览器发出的请求」逐层拒绝——缺 `x-tt-argus` 报 Uifid Not Found，补上又报 Signature Not Found，再补纯 Python 算出的 `x-secsdk-web-signature` 后仍然 Validate Error。把签名和身份池啃下来是没有终点的军备竞赛，而每次调用只要 $0.001 | 自建逆向（要维护 a_bogus 签名 + ttwid/msToken/uifid 身份池，抖音一改版就全废）；免费公共接口（实测服务已下线，寿命按月计）；自建开源全家桶（PostgreSQL + Redis + 无头浏览器要 3–4 GB 内存，本机 ECS 只有 1.87 GB） |
| 调哪个接口 | `/api/v1/douyin/app/v3/fetch_one_video_by_share_url` | 直接吃分享链接，一次调用出全部字段；官方文档写明 App V3 最稳定。**用真 token 实测通过**：HTTP 200 / 7 秒，字段齐全，地址下回来是能播的 mp4 | web 系列（回退用）；先自己解析 `aweme_id` 再调 `fetch_one_video`（白白两次调用） |
| 下载怎么走 | **服务端代理流式转发** | 第三方给的是抖音 CDN 直链，带防盗链且有时效，浏览器直接跳过去大概率 403。服务器带 `Referer` 去拉、边拉边吐，同时能设好文件名 | 浏览器直接打开直链（403 + 文件名乱码）；先整下到服务器再给浏览器（多占一份磁盘，还要设计清理） |
| 下载动作怎么交给浏览器 | **原生 `<a download>` 直接指向服务端路由** | 浏览器接管后有进度条、有「正在下载」，几十 MB 也不会先整块读进内存。实测按钮 1.4 秒恢复 | 先 `fetch` 成 blob 再存盘（失败能在页面上报错，但**整块读完才开始写盘**——实测一次 14–16 秒、按钮一直转圈零进度，看着像卡死）；失败响应文件名给成「下载失败.txt」，用户能看到中文原因 |
| 缓存策略 | 元数据 + 直链一起存，TTL 24 小时 | 每次调用都是钱；24 小时内直链通常还有效，命中就不花钱 | 不缓存（反复点反复扣费）；永久缓存（直链必过期，用户会下到 403）；只缓存元数据（照样要调一次拿直链） |
| 缓存按不按用户 | 不按 | 它是接口响应副本，不是谁能独占的资产 | 加 `user_id`（语义不对，还多存几份） |
| Key 从哪来 | **当前登录用户自己的**（`user_secrets`） | 站点不替任何人付钱。**门槛在查缓存之前**：没配 Key 一律不给用——「有没有配」是权限，「这次要不要花钱」是成本，两件事不能混 | 站点统一的 `.env` Key（等于替所有人付钱）；先查缓存再查 Key（等于给没配 Key 的人开后门，**实测踩过**） |
| 解析失败要不要留缓存 | 不留 | 失败没有可缓存的内容；留下「失败」行会让用户以为视频存在 | 缓存失败结果（视频后来恢复了也不给重试） |

## 五、代码结构（三层）

**这就是原来的「文件落点」一节。**

`client/` —— 浏览器（`"use client"`）。

| 文件 | 职责 |
|---|---|
| `download-view.tsx` | 整页视图：链接输入卡、解析 / 下载交互、三态编排 |
| `result-card.tsx` | 结果卡：空 / 成功 / 失败三态 |

`server/` —— 服务端。碰 db / 网络的模块开头有 `import "server-only"`。

| 文件 | 职责 |
|---|---|
| `page.tsx` | 工具页接线：`requireUser()` + 渲染视图 |
| `client.ts` | **唯一**碰 TikHub HTTP 的地方（`server-only`）：拼请求、15 秒超时、把响应翻译成本项目的形状 |
| `store.ts` | 缓存读写（`server-only`）：视频信息 + 短链 → `aweme_id` 映射 |
| `store.test.ts` | 缓存层单测 |
| `api/download.ts` | 解析接口：先查缓存、再查 Key、最后调上游 |
| `api/file.ts` | 下载接口：带 `Referer` 拉流、边拉边吐、403 时自动重解析一次 |

`shared/` —— 两端共用，只碰纯数据。

| 文件 | 职责 |
|---|---|
| `parse-share-url.ts` | 从整段分享文案里抠出链接与 `aweme_id` |
| `parse-share-url.test.ts` | 各种分享文案形态的用例 |
| `filename.ts` | 下载文件名清洗（非法字符、超长、表情符号、孤立代理项） |
| `filename.test.ts` | 文件名用例 |

**从哪开始读**：`server/api/download.ts`（先查缓存再花钱）→ `server/client.ts`（上游怎么调）→ `client/download-view.tsx`（界面）。

**边界**：`server/client.ts` 是**唯一**碰 TikHub HTTP 的地方，业务代码只调它——将来换供应商只改这一个文件。
路由薄壳必须留在 `app/api/tools/douyin-download/{route.ts,file/route.ts}`，**`runtime` / `dynamic` 两个
segment config 留在壳里**（它们是 Next 读的路由段配置，放进 features 里不生效）。工具页薄壳是
`app/(app)/tools/douyin-download/page.tsx`。

## 七、已知的坑

1. **抖音 CDN 直链会过期，而且过期后是 403 不是 404。** 下载路由拿到 403 要**自动重解析一次**再重试；不能直接把 403 抛给用户——用户看到的应该只是「再试一次就好了」。
2. **分享文案里不只有链接。** 典型形态是「7.43 pda:/ 复制此链接… https://v.douyin.com/xxxx/ 复制此链接，打开抖音搜索」。抠链接必须用正则匹配 `v.douyin.com` 或 `douyin.com/` 的片段，**不能把整段当 URL**。
3. **文件名里有一批字符在 Windows 上非法**：反斜杠、正斜杠、冒号、星号、问号、双引号、尖括号、竖线。标题里还常带 `#话题` 和表情。统一替换成短横线并截断到 60 个字符，空标题回退 `douyin-<aweme_id>`。标题截断正好切在 emoji 中间会造出孤立代理项，`encodeURIComponent` 抛 `URIError` 让下载 500（实测踩过）。
4. **「有没有配 Key」的门槛必须排在缓存查询之前，而且保存时就要验活。** 只验「存在」不验「有效」的话，填一串乱码也能命中别人解析过的缓存、顺利下载（**实测踩过两次**：先是不配 Key 也能用，再是 6 字符乱码也能用）。现在两道闸：① 解析与下载入口用 `hasSecret()`（只查行、不解密）先拦；② 保存 Key 时问上游一次（TikHub `/tikhub/user/get_user_info`，免费），`401/403` 当场拒。
5. **每次调用都扣钱，所以缓存查询必须在调外部接口之前。** 判断依据是 `fetched_at`，不是「库里有没有这一行」。
6. **服务器在国内（杭州），TikHub 在境外。** 必须设超时（15 秒）并给人话错误；不能让默认的无限超时把 Route Handler 挂住。
7. **代理下载不能设 `Content-Length`。** 上游给的响应长度可能不准（分片、压缩），照抄会让浏览器下到一半断掉；交给流式转发，让浏览器按实际字节数收尾。
8. **下载路由也要验登录。** 页面那层拦不住直接 `curl` 接口的人。
9. **必须带一个正常的浏览器 UA。** TikHub 前面挡着 Cloudflare，`urllib` 或裸 `curl` 的默认 UA 会被 `Error 1010 browser_signature_banned` 拒掉，响应体长得像「token 无效」，其实是客户端指纹被拦（实测：不带就 403，带上就 200，token 完全没变）。模板在 `lib/http.ts` 的 `BROWSER_UA`。
10. **图文作品混在视频接口里，它的「播放地址」是配乐 mp3。** `aweme_type = 68` 是图文，响应里 `video.play_addr.url_list` 指向 `*.douyinstatic.com/obj/ies-music/*.mp3`，照下载会得到一个 1 MB 的 mp3。判据：`aweme_type === 0` 才是视频，同时看 `images` 数组是否为空。
11. **`has_watermark: true` 不代表这条流带水印，不要拿它做判断。** 实测：返回 `true` 的视频下载后截帧看画面是干净的。这个字段描述原片状态，不是我们拿到的这条地址，写了提示反而误导用户。
12. **`fetch_multi_video_high_quality_play_url` 单价很高。** 免费额度只剩 $0.046 时调它直接 402。主链路只走 `fetch_one_video_by_share_url`。
13. **分享链接接口返回的是数组不是对象。** `data` 里是 `aweme_details`（数组）而不是 `aweme_detail`（单对象），视频被平台过滤时还会给出 `filter_list: [{ aweme_id, reason }]` 且数组为空——两种形态都要处理，别只按成功路径取第一条。
14. **演示数据残留**：手测解析过的视频会进缓存，验收结束前清掉测试行（或换测试账号）。

## 八、依赖变更

- **npm 依赖**：不新增。调外部接口用 Node 内置 `fetch`，下载转发用 `ReadableStream`。
- **外部服务**：新增 **TikHub**（社交媒体数据 API 聚合商，抖音视频接口 $0.001/次），已登记在《技术栈说明》的外部服务表里。
- **环境变量**：**不需要**。Key 由每个用户在「设置 → API 密钥」里自己填，代码按 `user_id` 从 `user_secrets` 取。
