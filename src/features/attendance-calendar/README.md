# 工作日历

> 一张月历，把「这天到底上不上班」按**周六制度（单休 / 双休 / 单双休）**自动推出来，跟制度对不上的日子点一下覆盖；
> 首页有一块本月紧凑月历，打开就能看到今天和这周的状态。

| | |
|---|---|
| 入口 | `app/(app)/tools/attendance-calendar/page.tsx`（一行薄壳）→ 实现住在本目录 `server/page.tsx` |
| 接口 | 无 HTTP 接口，数据入口是 Server Action（`server/actions.ts`）；月份走 URL 参数 `?ym=2026-11` |
| 数据表 | `attendance_settings`（`docs/数据库/出勤设置表.md`）、`attendance_overrides`（`docs/数据库/出勤覆盖表.md`） |
| 状态 | ✅ 已上线（v0.8.5，2026-10-23 起） |

**命名约定**：中文「工作日历」（2026-10-23 由「出勤日历」改名），代码标识仍是 `attendance-calendar`——slug、
路由、表名没跟着中文名改（URL 已联调过）。首页那块叫「工作日历卡」（`attendance-card`），工具页叫「工作日历页」。

**这份 README 是这个工具唯一的文档**：代码结构在 §五，需求 / 界面 / 数据 / 决策 / 验收 / 坑在一～四、六、七。
原来的 `docs/功能/工作日历.md` 已于 2026-11-05 并入本文件，章节编号保持不变。

## 一、要什么

**需求原文（ogliu 2026-10-23）**

> 我公司是单双休机制，另外加上各种节假日可能还会调休，也就是说星期六、星期天到底上不上班，我总是记不住，
> 每周都要去问同事。能不能做一个工具来做记录，让我打开 Nexus OS 一眼就能看到，休息还是上班？

**做**

- **月历视图**：周一起始、7 列、固定 42 格（6 行），一屏看完一个月。
- **每格显示**：日期数字 + 农历 / 节日名（工具页）+ 状态角标「班 / 休」（两档都挂）。
- **周六制度自动推算**：设置里选「单休」「双休」或「单双休（大小周）」，全年周六按它算；单双休要指定从哪一周起算。
- **手动覆盖**：任意一天可点成「上班」或「休息」，**优先级最高**——改了就一直是它，换制度也冲不掉。
- **一键还原**：覆盖掉的日期可选「跟随自动」，回到推算值。
- **首页工作日历卡**：本月紧凑月历（日期 + 班 / 休角标 + 今天圆点）；点某一格可当场改这一天；「管理 ›」进工具页。
- **工具中心登记**：作为独立工具出现在 `/tools`（`attendance-calendar`，分类「生活」），走显式路由。
- **工具页控件**：年 / 月切换、「今天」、点某天改状态、周六制度设置。

**主动放弃（附原因）**

| 放弃项 | 原因 |
|---|---|
| 全国法定节假日 / 调休数据（第三方 API） | 公司不按国家安排放假，导进来反而是噪音。国定假期那几天自己点「休」——一年十几个动作，比维护一条数据通道便宜得多（主人明确砍掉） |
| 放假天数、调休补班、假期余额 | 属于 HR 系统范畴，与「这天去不去」无关；塞进来会让月历变成排班表 |
| 打卡、工时、迟到早退、请假 | 同上 |
| 消息提醒 / 每天早上推一句 | 需求是「打开就能看到」，不是「被通知」；且需要常驻进程（本项目现在没有） |
| 农历节日以外的国际日、纪念日 | `getOtherFestivals()` 一天几十条（「国际地雷行动日」这种），进月历就是噪音 |
| 跨月视图、周视图、日程视图 | 首版只要「这个月哪几天休」，多视图会把组件撑成通用日历库 |
| 多人共享 / 团队排班 | 每个账号各存各的 |

## 二、界面

### 2.1 两个入口，两种密度

| 位置 | 路由 | 密度 | 能做什么 |
|---|---|---|---|
| 首页工作日历卡 | `/` | 紧凑：日期 + 班 / 休角标 + 今天圆点 | 看 + **改某一天**；年月切换、制度设置不出现 |
| 工作日历页 | `/tools/attendance-calendar` | 完整：日期 + 农历 / 节日 + 双角标 + 年月切换 + 今天 | 看 + 改 + 管（切年月、设制度、恢复默认） |

分工口径与便签 / 待办一致：**总览卡是「展示 + 高频小动作」，管理动作跳工具页**。改一天是高频小动作（和待办卡直接勾、便签卡直接删同一性质），切年月 / 设制度 / 恢复默认是低频管理动作。
为什么拆两档：卡片宽 430px，7 列每格约 56px（手机 43px），放得下日期与小角标，放不下农历与节日名（那要每格约 120px，只有整页有）——参考截图是**整页**形态，先说明这个落差。

### 2.2 首页工作日历卡

宽度 `max-w-[430px]`，与待办 / 便签 / 每日一句卡同宽；**插在日期时间面板之后、待办卡之前**（它是「今天」的即时信息，跟面板同属页头级信息）。

```
┌────────────────────────────────┐
│ 工作日历                 管理 › │
│ 今天 周五 · 休息                 │
│  一  二  三  四  五  六  日      │
│  5班 6班 7班 8班 9班 10班 11休 │
│ …（6 行，固定 42 格）…          │
└────────────────────────────────┘
```

- 角标两态：**班**（黑底白字）/ **休**（浅灰底灰字）。默认制度自动生效，所以不会出现「未定」。
- 标题行：「工作日历」+ 右侧「管理 ›」（与便签卡同一模式），点它进 `/tools/attendance-calendar?ym=<卡片当前月份>`。
- 第二行 `今天 周五 · 休息`：「休息 / 上班」用全对比黑字。
- **点任意日期格 → 弹出与工具页完全相同的状态弹层**（§2.4），改完两处读同一份数据。
- 卡片上**不出现**年月切换、「今天」、制度设置、恢复默认——这些只在工具页。
- 整卡不再「点哪都跳」：格子里有真实操作，跳转只能靠「管理 ›」。
- 几何：表头 7 个单字星期；白格 + `border-[#F0F0F0]` 细网格（容器画左 / 上边、格子画右 / 下边，相邻只 1px）；日期 `text-xs`（手机 `text-[11px]`）靠左上。
- 今天：格子**右下角 1.5px 黑圆点**（2px 黑框在两个月的交界处太抢眼），不加「今」字（放不下第二个元素）。
- 跨月补齐格：日期 `text-[#D0D0D0]`，但**照样按制度挂「休 / 班」**——42 格都是真日子，只用日期灰一档区分。
- 整卡高度 ≈ **275px，任何月份都一样**（42 格固定）。

**为什么是角标而不是整格底色**（2026-10-23 联调改的）：上一版「整格黑底 = 上班」做完一看，工作日连成一条黑杠，主人原话「这也太丑了吧，黑一片」。改成与工具页同一套「白格 + 右上角小角标」，班 / 休 都标——黑白里去色之后，小角标是唯一不糊成一片的做法。

### 2.3 工作日历页

**版式与便签 / 待办完全一致**（2026-10-23 联调第四轮改的）：

1. 手机一行 `ToolMobileBar`（汉堡 + 主操作「今天」）；桌面同一个动作住在 `ToolHeader` 右侧。**不再有 `PageHeader`**——上一版「‹ 工具 + 返回」的页头跟别的工具页长得不一样，被主人一眼看出来。
2. `ToolHeader`：图标块 + 「工作日历」+ 描述 + 分类「生活」/ 状态「可用」。
3. 内容区两栏（≥ xl）：**左**工具栏 + 表头 + 月历（100% 铺满、不设 max-width）；**右** 300px 侧栏放概览与图例。小屏单列，顺序「概览 → 图例 → 日历」。
   （上一版限宽 820px 左对齐，1440 屏幕上右边空一大片，主人原话「大屏幕的时候全部堆在左边」。）
4. **主区一张白卡包住「工具栏 + 表头 + 月历」**：只把月历留白、工具栏与表头落在页面灰底上时，中间那一横条像被掏空（主人原话「给个白色背景试试？现在中间镂空不好看」）。
5. 概览按**卡片自己**的宽度排（容器查询）：窄卡片一行一条「标签 …… 值」（三行），`@lg` 起转三列（标签在上、值在下）。用视口断点会犯「窗口宽、卡片窄却排三列」的错。
6. 图例：班 / 休 / 今天（右下圆点）/ 手动改过（日期下方小横条）四个小样 + 一行操作说明。
7. 工具栏药丸用 `#F5F5F5`（它在白卡里，按 §2.1 内嵌块规则）。

| 元素 | 规格 |
|---|---|
| 工具栏 | 年切换、月切换、右侧「设置」（`Settings2` 图标）；药丸 `bg-[#F5F5F5]`、hover `bg-[#ECECEC]`。主操作「今天」不在这里 |
| 表头 | `一 二 三 四 五 六 日`，`text-xs text-[#8A8A8A]`，居中 |
| 格子 | `min-h-[76px]`，白底，`border border-[#F0F0F0]`，`p-2`，内容左对齐靠上 |
| 日期 | `text-base tabular-nums`；休息日 `text-[#666666]`、上班日 `text-[#000000]` |
| 农历 / 节日行 | 日期下方 `text-[10px]`，**只有一行**，放不下就 `truncate` |
| 角标 | 右上角 `absolute`：休 → `bg-[#F5F5F5] text-[#666666]`；班 → `bg-[#000000] text-white` |
| 已改标记 | 手动覆盖的日期，数字下方一根 `h-1 w-3` **小横条** + `title="已手动调整"`。用横条不用圆点：今天已占一个黑圆点，两个分不清 |
| 今天 | 日期旁「今」+ 格子右下角 `h-1.5 w-1.5` 黑圆点 |
| 整月高度 | 42 格 × 76px + 表头 + 工具栏 ≈ **560px**，恒定 |

### 2.4 点某天：状态弹层

点任意格子 → 小弹层（`rounded-[2px] bg-white p-3`，锚定在被点格子下方）：`10月24日 周六 · 农历九月十五` + `[上班] [休息] [跟随自动]`。

**这一节是整份文档最关键的交互契约**

| 点的是哪一天 | 三个按钮的含义 |
|---|---|
| 任何一天（含周六） | 「上班 / 休息」= 写 `attendance_overrides`，**只改这一天** |
| 任何一天 | 「跟随自动」= 删掉这天的覆盖行，回到推算值 |
| 任何一天 | 「上班 / 休息」如果点的正好是**推算值**，等价于「跟随自动」：不写覆盖、已有的覆盖删掉 |
| 想改全年 | 不在弹层里改，走「设置」里的周六制度（§2.5） |

- 命中当前状态的按钮黑底白字，其余灰底。
- **没有「还没设置」这一步**：没设过制度走内置默认（单双休），界面直接有答案。
- **覆盖永远最优先**：改了就一直是它，换制度也冲不掉（主人原话「就算重新选择了双休，单休逻辑有冲撞，也是手动改的最优先」）。
- **点回推算值等于「跟随自动」**（2026-10-23 修的 bug）：上一版不管点什么都写覆盖，于是「改成班 → 再改回休」之后库里还留着一条等于推算值的覆盖，「已手动调整」小横条一直挂着。现在 `setDayStatusAction` 先算一遍不看覆盖的推算值，选的就是它 → 删覆盖、不写。
- **弹层里没有「只改这一天」勾选框**：全年怎么排由制度决定，周六没有第二种含义了，两个入口会互相打架。

### 2.5 周六制度设置

工具栏右侧「设置」→ 面板：`[单休] [双休] [单双休]` + 说明 +（只有单双休时）`本周（10月19日–25日）是：[单休周] [双休周]` + `[保存] [恢复默认]`。

- **单休** = 每个周六上班；**双休** = 每个周六休息；**单双休** = 单休周与双休周交替（大小周）。周日、周一~周五不受影响。
- **问题永远问「本周」**，不管上次是多久以前设的。主人原话：「如果过了很久很久之后来调整，他还显示 10 月 24 日？我早都不记得那天上不上班了啊」——问「上周刚过完的那一周」谁都答得上来。
- **默认值 = 按当前制度推算出的本周六状态**，所以「不改直接保存」相位不跳；没设过制度时默认「单休周」。
- **保存时锚点重设到本周**（存本周六 + 本周类型）。锚点只是实现细节，用户永远只需要回答「这周是哪种」。
- **内置默认制度**：单双休，从 `2026-10-24` 那周起是双休周。新账号打开就有答案，不会出现「未定」；库里有没行 ≠ 界面上有没有制度。
- 「恢复默认」→ 删掉 `attendance_settings` 那一行，回到内置默认；已有的手动覆盖**保留**。
- 选中态：命中当前制度的按钮黑底白字。

### 2.6 响应式

| 断点 | 工作日历页 | 首页卡 |
|---|---|---|
| ≥ 1024px | 7 列全宽：格高 76px，日期 `text-base`，农历 / 节日显示 | 430px，格高 28px，只有日期 + 角标 |
| 640–1023px | 同上，格高收到 68px；农历 / 节日保留 | 430px 或满宽 |
| < 640px（手机） | 格高 56px；**农历 / 节日行隐藏**，只留日期 + 角标；角标 `text-[9px]` | 满宽，格高 26px |

手机端**不隐藏功能，只隐藏次要信息**：工具页点开弹层仍能看到农历与节日全名；**首页卡弹层只有日期 + 星期**（首页卡不算农历，省掉 42 次换算——要看农历从「管理 ›」进工具页）。

## 三、数据模型

两张表，都按 `user_id` 隔离。

```sql
CREATE TABLE IF NOT EXISTS attendance_settings (
  user_id         INTEGER PRIMARY KEY REFERENCES users(id) ON DELETE CASCADE,
  saturday_mode   TEXT    NOT NULL CHECK (saturday_mode IN ('work', 'off', 'alternate')),
  anchor_saturday TEXT,                    -- 仅 'alternate' 用：交替从哪个周六起算
  anchor_is_work  INTEGER CHECK (anchor_is_work IN (0, 1)),
  created_at      INTEGER NOT NULL,
  updated_at      INTEGER NOT NULL,
  CHECK (saturday_mode <> 'alternate'
         OR (anchor_saturday IS NOT NULL AND anchor_is_work IS NOT NULL))
);

CREATE TABLE IF NOT EXISTS attendance_overrides (
  user_id    INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  day_key    TEXT    NOT NULL,                         -- 'YYYY-MM-DD'
  status     TEXT    NOT NULL CHECK (status IN ('work', 'off')),
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  PRIMARY KEY (user_id, day_key)
) WITHOUT ROWID;
```

**设计要点**

| 列 / 约束 | 为什么长这样 |
|---|---|
| `saturday_mode` 存三个字面量 | 说的是「周六这一天算不算上班」而不是制度名：`'work'` 单休、`'off'` 双休、`'alternate'` 单双休。`CHECK` 钉死三个值 |
| 锚点两列可空 | 只有单双休需要「从哪一周起算、那周算哪种」。表级 `CHECK` 保证：选 `alternate` 必须带锚点，单休 / 双休时两列必须 NULL |
| `user_id` 同时是主键 | 一个人只有一份制度；换制度 `UPSERT` 覆盖，不会堆第二行 |
| `attendance_overrides` 复合主键 | 「某人的某一天」天然唯一；`WITHOUT ROWID` 省一层索引 |
| `day_key` 用 TEXT 不存时间戳 | 这是一**天**不是一个**时刻**；`'2026-10-24'` 可读、能 `BETWEEN` 一次捞整月，也不会因时区换算漂到前一天 |
| **没有 `note` 列** | 2026-10-24 删掉了：建了列却没有任何写入路径（弹层里没有备注输入框），永远是 `NULL`，而文档还写着「带备注的日子显示小字」——一个永远为空的列 + 一句不成立的话，比没这功能更糟 |
| 不给 `status` 存 `'auto'` | 「跟随自动」= 这行不存在。用字符串表达「没有记录」，查询到处要额外判断 |
| 锚点为什么不复用「今天的周」 | 每次读取拿「今天」当起点，单双周会随日子往前走而漂移；必须存固定周六当锚点 |
| 为什么表里可以「没有行」 | 没设过 ≠ 没有制度：`resolveDayStatus` 用 `DEFAULT_SETTING` 兜底 |

**老库怎么跟上**：`initSchema()` 里三条幂等迁移——① `PRAGMA table_info` 看到 `note` 就 `DROP COLUMN`（`note` 既不是主键也不是索引列，删它不影响 `WITHOUT ROWID` 与复合主键）；查库语句明确列出列名，不写 `SELECT *`，否则新库直接报 `no such column`；② 上一版的 `attendance_cycles`（基准周六 + 那周类型）把 `anchor_is_work` 搬成 `saturday_mode`（1 → `'work'`），搬完删旧表；③ 老表的 `CHECK` 只允许 `work` / `off`，SQLite 改不了 CHECK → 检查建表语句里有没有 `'alternate'`，没有就整表重建（改名 → 新列定义建表 → 搬行 → 删老表），同一事务、幂等。

**推算函数**（`shared/schedule.ts`，纯函数）

```
输入：dayKey（'YYYY-MM-DD'）、setting（可空）、override（可空）

0. setting 为空                      → 用 DEFAULT_SETTING（单双休、2026-10-24 那周双休）
1. override 有值                    → 用它（source: "manual"）——永远最优先
2. 周六：
   - 单休 / 双休                    → setting.saturdayMode（source: "saturday-mode"）
   - 单双休                        → 与 anchor_saturday 算周差 w
                                    w 偶数 → 与基准周同类型 → anchor_is_work
                                    w 奇数 → 相反类型        → 1 - anchor_is_work
                                    （负数周差取模后先归一化再判奇偶）
   - alternate 但锚点缺失           → 退回 DEFAULT_SETTING 的锚点
3. 其余日子：周日 → "off"，周一 ~ 周五 → "work"（source: "weekday"）
```

## 四、关键决策

| 决策点 | 选择 | 理由 | 否决的备选 |
|---|---|---|---|
| 数据来源 | **纯本地推算 + 手动覆盖** | 公司不按国家安排放假（主人原话），导进来的国定假期反而是错的；一年只需手点十几个休假日 | 接 holiday-cn（已实测可用，但口径不一致，还多出缓存 / 失败降级两条路径） |
| 存储模型 | **一个制度开关 + 一张覆盖表** | 制度只有「周六上不上班」两种取值，一行就够；覆盖表只装真正改过的日子 | 直接存 52 周排班（一年录 104 个格子）；只存覆盖不存制度（「下周六上不上班」永远答不出来） |
| 制度怎么来 | **三选一：单休 / 双休 / 单双休** | 主人定下「如果我选择单休，就所有日历都按单休来算」；第二轮补上「单双休 = 本周单休、下周双休」。一句话说完、一个动作改全年 | 只给单休 / 双休（公司是大小周，缺这档没法用）；点周六改全年（与设置里同一件事，两个入口打架） |
| 单双休从哪周起算 | **永远问「本周」**，保存时把锚点重设到本周 | 隔几个月再打开，问「三个月前某个周六」没人答得上来；问「上周刚过完的那一周」谁都答得上来。默认值按当前制度推算，不改直接保存相位不跳 | 显示存着的锚点日期（第一版就是这样，被当场指出）；每次读取拿「今天」当起点（相位会漂） |
| 没设过制度时 | **内置默认**：单双休，从 2026-10-24 那周起双休 | 首版「没设置 → 周六显示未定」，主人一打开就是一片空白（「星期六的标识呢？」）；给默认后新账号就有答案 | 首屏空着（被读成漏数据）；强制跳设置页（多一道墙） |
| 工具页版式 | 与便签 / 待办同一套：`ToolMobileBar` / `ToolHeader` + 概览 + 工具栏 + 月历 | 主人原话「详情页过于简陋，丰富起来，也要参考其他工具的统一风格」；工具名只出现一次 | 只有一条工具栏 + 一大张月历（首版，被说简陋）；保留 `PageHeader`（与 `ToolHeader` 重复） |
| 覆盖和制度谁说了算 | **覆盖永远最优先**，换制度也冲不掉 | 调休 / 请假是事实，制度只是默认值 | 换制度时清空覆盖（把用户手动记的事抹掉）；覆盖只对当周有效 |
| 月历几何 | **周一起始 / 7 列 / 固定 42 格** | 固定 6 行，切月时页面高度不变、不跳 | 4–6 行自适应（切月高度跳，像卡顿）；周日起始（中国日历习惯是周一） |
| 农历 / 节日在哪算 | **只在服务端算**，作为 props 传下去 | `lunar-javascript` 是 436KB 单文件 CJS，进浏览器纯浪费；一天只变一次 | 客户端算（436KB 进 bundle）；再引一个轻量农历库（口径可能跟面板不一致） |
| 切月份怎么实现 | **URL 参数 `?ym=2026-11`，服务端算整月** | 零客户端计算、零体积，链接可分享、刷新不丢月份 | 客户端一次算整年 12 个月（props 大、首屏慢）；客户端实时算（库进 bundle） |
| 每格节日放几个 | **只放一个**（法定 > 农历传统 > 节气 > 其它） | 一格只有一行高度；同时出现三个的日子真实存在（清明 + 节气） | 全部渲染并换行（格子高度不齐、整月高度跳） |
| 首页要不要塞完整月历 | **不塞，只塞紧凑版** | 430px 里每格 56px，农历和节日名必然被挤丢；不如把「今天上不上班」做到极致清晰 | 首页放完整月历（要撑到 900px，与四块卡的宽度体系打架） |
| 「休 / 班」怎么表达 | **右上角小角标**，班（黑底白字）/ 休（浅灰底灰字），都不上彩色 | 《界面设计规范》§九 禁止彩色徽章。整格黑底会把一周糊成一条黑杠（主人原话「黑一片」）；改成角标后 430px 的卡也放得下 | 照抄参考图的红「休」/ 蓝「班」（违反 §九）；首页卡整格黑底（联调当场否掉）；只标休息（看过之后否掉） |
| 覆盖掉的日期怎么标 | 日期下方一根 **1px 小横条** | 用户必须能区分「推出来的」和「我改过的」，否则改过的日子永远不知道自己改过 | 不加标记；改整格颜色（与休 / 班语义打架）；小圆点（与「今天」的圆点分不清） |
| 首页卡能不能改状态 | **能改单天；不能切年月、不能设制度、不能恢复默认** | 主人原话「总览只负责展示跟一些快捷操作，管理就跳转到工具页面，它应该被当成一个单独的工具来使用」 | 首页卡只读（连改一天都要跳页）；首页卡全功能（430px 放不下工具栏） |

## 五、代码结构（三层）

**这就是原来的「文件落点」一节。**

`client/` —— 浏览器（`"use client"`）。不碰 db、不 import `server/`。

| 文件 | 职责 |
|---|---|
| `month-grid.tsx` | 两档密度的月历（工具页完整版 / 首页紧凑版），点格子开弹层 |
| `calendar-toolbar.tsx` | 年月切换 + 回到今天 + 打开制度设置面板 |
| `day-dialog.tsx` | 点开某天的状态弹层：上班 / 休息 / 跟随自动 |
| `setting-panel.tsx` | 出勤制度设置面板（单休 / 双休 / 单双休 + 本周类型） |
| `attendance-mobile-bar.tsx` | 移动端顶部行（< lg）：汉堡 + 「今天」 |

`server/` —— 服务端。碰 db 的文件开头有 `import "server-only"`。

| 文件 | 职责 |
|---|---|
| `page.tsx` | 工具页接线：读 `?ym=` → 查数据 → 算整月（含农历 / 节日）→ 渲染 |
| `attendance-card.tsx` | 首页紧凑月历卡（服务端组件）：42 格 + 今天状态 |
| `actions.ts` | Server Actions（`"use server"`）：改某天、还原某天、存制度、恢复默认 |
| `data.ts` | 两张表的数据访问（`server-only`）：设置读写、按区间取覆盖 |
| `data.test.ts` | 数据层单测：`user_id` 隔离、区间查询、老表迁移 |

`shared/` —— 两端共用，只碰纯数据。

| 文件 | 职责 |
|---|---|
| `schedule.ts` | 出勤状态推算：制度 + 覆盖 → 这一天到底上不上班 |
| `schedule.test.ts` | 推算法用例（单双休轮换、优先级） |
| `month-grid.ts` | 月历几何与日期算术：42 格、周几、`dayKey` 解析、月份键 |
| `month-grid.test.ts` | 几何用例（跨年、闰年 2 月、月末对齐） |
| `month-view.ts` | 把「42 格几何 + 周六制度 + 覆盖」拼成月历要渲染的数据 |
| `day-label.ts` | 每格的农历 / 节日 / 节气标注（**全项目碰 `lunar-javascript` 的地方之一**） |
| `day-label.test.ts` | 标注用例（一格放几个节日、优先级） |

**从哪开始读**：`server/page.tsx`（怎么算整月）→ `shared/schedule.ts`（上不上班的规则）→ `client/month-grid.tsx`（怎么画）。

**两条与最初设想不同的落地方式**：① `month-grid.tsx` 是**客户端组件**而不是服务端组件——格子里有真实点击、弹层要按格子实测位置定位；农历 / 节日仍是服务端算好的 props，客户端一次也没 import 农历库（构建产物 `grep getJieQi` 无输出）。② 单测放在**源码同目录**，不是 `__tests__/`。

**硬约束**：不新增运行时依赖（`lunar-javascript` 已在）；`lunar-javascript` 只允许出现在服务端模块里；
日期口径一律用 `lib/datetime/shanghai.ts`，不碰系统默认时区；路由薄壳必须落在
`app/(app)/tools/attendance-calendar/page.tsx`（只有一行 re-export）；首页卡的位置改在 `app/(app)/page.tsx`。

## 六、验收标准

1. 从没设过制度的账号打开 `/tools/attendance-calendar` → **没有**提示条，周六直接按默认制度（单双休、2026-10-24 那周双休）挂角标：10-03 班、10-10 休、10-17 班、10-24 休、10-31 班；周日「休」、周一~周五「班」；设置面板默认选中「单双休」+「双休周」。
2. 设置 →「单休」→ 保存 → **连着两周的周六都是「班」**（不是隔周）；周日仍「休」；查库 `saturday_mode = 'work'`。
3. 单休制度下手动点 `2026-10-24`（周六）→「休息」→ 该日变「休」并出现已改小横条；`2026-10-31` **仍「班」**——只改了这一天。
4. 接着切「双休」→ `2026-10-24` **仍是「休」且仍带横条**（手动改的最优先，换制度冲不掉）；`2026-10-31` 变「休」、不带横条。
5. 对 `2026-10-24` 点「跟随自动」→ 回到制度值、横条消失；查库该 `day_key` 行数为 `0`。
6. 设置 →「单双休」→ 选「单休周」→ 保存 → `10-24` 班、`10-31` 休、`11-07` 班、`10-17` 休——单双周真的在交替；查库 `saturday_mode = 'alternate'`、`anchor_saturday = '2026-10-24'`、`anchor_is_work = 1`。
7. 把本周改成「双休周」→ 相位整体翻转：`10-24` 休、`10-31` 班；查库 `anchor_is_work = 0`。
8. 点 `2026-10-25`（周日）→「上班」→ 变「班」；再「恢复默认」→ 日历回内置默认制度，而该日的覆盖**仍然生效**。
9. 跨月补齐的格子同样挂角标、也能点开弹层；日期是灰的，用来区分「这不是本月」。
10. 连点月份切换 12 次（跨年）→ 月历高度始终一致。
11. 切到 `?ym=2026-02` → 直接渲染 2 月，农历与节日跟着变；刷新仍是 2 月。
12. 每格节日只显示一个：`2026-10-01`「国庆节」、`2026-10-08`「寒露」、`2026-10-18`「重阳节」。
13. 375px → 日历页格子内**不出现农历 / 节日**，只有日期 + 角标；点开弹层能看到全名。
14. 首页顺序「面板 → 工作日历卡 → 待办卡 → 便签卡 → 每日一句卡」，卡宽 430px；「管理 ›」进入工具页且月份参数等于卡片当前月。
15. 首页卡在 10 月与 2 月的高度相同（±0px）。
16. 首页卡上**没有**年月切换、「今天」、制度设置入口。
17. 首页卡**每格都挂角标**、**没有整格黑底**；点 `2026-10-26` → 弹层 →「休息」→ 该格变「休」；打开工具页看同一天状态一致。
18. A 设制度并改 3 天 → B 打开按**内置默认制度**显示，A 改的那 3 天在 B 眼里仍是推算值。
19. 构建产物里不含农历库：`grep -rl "getJieQi\|getMonthInChinese" .next/static/chunks` 无输出。
20. 跨天：东八区 23:59:30 等到 00:00 → 首页卡「今天」圆点移到次日，第二行换成新的一天。
21. `/tools` 出现「工作日历」卡（分类「生活」），状态「可用」。
22. 工具页版式与便签 / 待办一致：**没有** `PageHeader`；手机顶栏「汉堡 + 今天」、桌面「今天」在信息条右上；≥ xl 时右侧 300px 侧栏放概览与图例；工具栏药丸在白卡内看得出来。
23. 设置面板打开时**默认选中当前生效的制度**：没设过 →「单双休」+「双休周」。
24. 「恢复默认」→ 设置行被删、日历回内置默认，手动改过的日子仍然生效。
25. 门禁五项全绿（`next typegen` / `typecheck` / `lint` / `test` / `build`）。
26. 老库迁移一：带旧表 `attendance_cycles`（`anchor_is_work = 1`）的库启动 → `saturday_mode = 'work'`、旧表已消失。
27. 改成与推算值不同的状态 → 出现「已手动调整」小横条；再点回**推算值** → 横条消失、该日覆盖行 0 条。
28. 「今天」在工具页与首页卡上都是右下角黑色圆点（工具页另在日期旁写「今」），不再有 2px 黑框。
29. 隔很久再打开设置：库里锚点是三个月前 → 面板仍显示**本周**，默认高亮的那一周等于「按当前锚点推算出的本周六状态」。
30. 老库迁移二：上一版 `attendance_settings`（没有锚点列、`CHECK` 只允许 work / off）启动 → 锚点两列补上、表重建成三档、原行还在；重复启动不报错、不重复搬行。

## 七、已知的坑

| 坑 | 机制 | 对策 |
|---|---|---|
| 月历高度跳 | 不同月份 4~6 行，切月时页面上下窜 | 固定 42 格，缺的格子用上月 / 下月日期补满并置灰 |
| 农历库进浏览器包 | 436KB 未压缩 CJS，client 里 import 会整包打进去 | 只在服务端模块 import；客户端要农历走 props 或点开弹层由服务端给 |
| 时区漂一天 | 线上容器跑 UTC，`new Date().getDate()` 在 16:00 UTC 已是「明天」 | 日期一律走 `lib/datetime/shanghai.ts`；`day_key` 用东八区拼字符串，不用 `toISOString()` 切前 10 位 |
| 覆盖被制度冲掉 | 同一天既可能来自制度推算，也可能有覆盖行 | 读取顺序固定：**覆盖 > 制度 > 星期兜底**；「跟随自动」= 删覆盖行，不碰制度 |
| 恢复默认后覆盖还活着 | 用户以为「清除」= 全清 | 只删 `attendance_settings`，覆盖保留；按钮写「恢复默认」并在下面写清「手动改过的日子仍然生效」 |
| 没设过制度时周六一片空白 | 「还没选过」如果空着不挂角标，会被读成漏数据 | 内置默认制度兜底，`resolveDayStatus` 在 `setting = null` 时用它——界面永远有答案 |
| 跨月的格子看不到状态 | 42 格里补齐的跨月格原本只是灰占位 | 42 格全部按制度算状态、挂角标、可点开弹层；只用「日期灰一档」区分 |
| 首页卡整格黑底 | 一版把上班日整格涂黑，连成一条黑杠 | 改成白格 + 右上角小角标，班 / 休 都标 |
| 紧凑卡「休」和两位数字挤在一起 | 手机上一格只有 43px，角标绝对定位会压住日期 | 日期靠左、`休` 靠右，同一行 `justify-between` |
| 每格节日挤爆 | 一格一行高度，清明那天可能同时是节气 + 传统节日 + 国际日 | 只取优先级最高的一个；其余进弹层 |
| 42 格里本月日期算错 | 月初补上月末几天，容易出现「9月31日」这种不存在的日期 | 用 `Date.UTC` 拿 1 号星期再按天回推；纯函数单测覆盖 2 月、31 天月、跨年 |
| 点弹层后关不掉 | 弹层锚定在格子下方，点外面要能关 | 独立遮罩层（点外部关闭）+ `event.target === event.currentTarget` 守卫 + `Esc` 关 |
| 首页卡点进去月份不对 | 卡片显示 10 月，链接进的是「本月」，跨月后不一致 | 链接带上 `?ym=`，与卡片渲染用同一个 `dateKey` |
| 切月用 `<Link>` 导致整页闪 | 服务端渲染整月，每次导航重新取数据 | 用 `router.push` + `useTransition`，旧数据留到新数据到 |
| 换表结构丢用户的设置 | 上一版的 `attendance_cycles` 跟新版对不上 | 幂等迁移：`anchor_is_work` 搬成 `saturday_mode`（1 → `'work'`），搬完删旧表 |
| 加了「单双休」却存不进去 | 老表 `CHECK (saturday_mode IN ('work','off'))` 直接拒 `'alternate'`，而 SQLite **改不了已有 CHECK** | `migrateAttendanceModeCheck()`：建表语句里没有 `'alternate'` 就整表重建（改名 → 新表 → 搬行 → 删老表），同一事务、幂等 |
| 单双休的相位会漂 | 每次读取都拿「今天所在那周」当起点，日子往前走到下周就整体错一位 | 锚点存固定周六 + 那周类型；面板重开时**回填存着的锚点**，不重新取「今天」 |
